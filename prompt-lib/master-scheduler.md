# 知识库构建调度主控规则
## 基础固定路径
前端总根: ./ERP_frontend/lanjing-erp-admin-web
后端总根: ./ERP_backend
产品需求库根目录: ./ERP_product
知识库路径规则: ./ERP_product/{{系统名}}/知识库/（各系统知识库与需求文档同目录，系统名用中文，如「客服系统」）

## 路径解析规则
- **系统名**：与 `./ERP_product/` 下一级目录一致，直接用中文系统名（如「客服系统」）
- **知识库根（kb_root）**：`./ERP_product/{{系统名}}/知识库/`
- **配置文件**：`./ERP_product/{{系统名}}/知识库/system-config.md`
- **进度文件**：`./ERP_product/{{系统名}}/知识库/run-progress.md`
- **需求文档**：`./ERP_product/{{系统名}}/vX.Y.Z/`（与知识库并列，不在知识库目录内）

## 全局约束
1. 单对话同一时间仅绑定1个ERP子系统，初始化指令确定系统后，所有操作仅限该系统。
2. 目录创建严格按时机执行：一级目录在阶段0创建，页面子目录在阶段2批量创建；后续所有阶段仅写入文件，禁止新建目录。
3. 所有内容必须面向产品经理输出，**禁止大段讲解代码实现、技术原理、框架细节**，只用业务语言描述功能、规则、交互、权限。
4. 执行顺序：阶段0 → 阶段1 → 阶段2 → 阶段3(逐模块循环) → 阶段4(逐页面循环) → 阶段5 → 阶段6，不可跳序。
5. 每完成【一个阶段 / 一个模块 / 一个页面】，必须固定反问，等待用户指令再推进，禁止自动连续执行。

## 用户指令集
① 继续 → 执行下一项
② 跳过 → 跳过当前项，处理下一个
③ 终止 → 结束本次构建
④ 初始化XX系统知识库构建 → 切换绑定新系统（系统名与 `./ERP_product/` 下一级目录一致，如「客服系统」）
⑤ 同步XX系统知识库 → 进入增量同步模式，基于拉取的最新代码维护已有知识库

## 反问话术规范
1. 阶段完成反问：
「XX阶段执行完毕，文档已保存。是否继续执行下一阶段？回复【继续】进入下一步，回复【终止】结束。」
2. 单个模块完成反问：
「模块【XXX】梳理完成。当前已完成X/Y个模块。是否处理下一个模块【XXX】？回复【继续】处理下一个，回复【跳过】跳过本模块，回复【终止】结束。」
3. 单个页面完成反问：
「页面【XXX】详情梳理完成。当前模块已完成X/Y个页面。是否处理本模块下一个页面【XXX】？回复【继续】处理下一个，回复【跳过】跳过本页面，回复【终止】结束。」
4. 模块全部页面跑完反问：
「当前模块所有页面梳理完毕。是否进入下一个模块【XXX】的页面梳理？回复【继续】，回复【终止】结束。」
5. 全流程收尾话术：
「【{{系统名}}】全流程知识库构建全部完成，所有文档归档完毕。可发送新初始化指令梳理其他ERP子系统。」

## 进度文件规则
每次执行完毕自动更新对应系统 `./ERP_product/{{系统名}}/知识库/run-progress.md`，记录：
当前所处阶段、已完成阶段列表、待处理模块队列、当前处理模块、当前模块待处理页面队列、当前处理页面。
中断后再次初始化同系统，自动读取进度断点续跑。

## 调用逻辑
收到初始化指令 → 读取 step0-init.md 执行初始化；
用户回复继续 → 按顺序读取对应 stepX 模板执行；
收到同步指令 → 读取 step7-incremental-sync.md 进入增量同步模式（独立于阶段0→6线性流程）；
禁止一次性加载全部模板、禁止多页面合并输出、禁止超大文件单文件输出。
页面级为最小执行单元，一个页面对应一个独立MD文件。

## 增量同步模式说明
- 定位：知识库首次构建完成后的日常维护；每次拉取前后端最新代码后使用。
- 基线：每个系统的同步基线（前后端上次同步到的 commit）记录在该系统 run-progress.md 的【同步状态】区。
- 原则：只处理当前绑定系统范围内的代码变更，只增量更新受影响文档，git 全程只读不改代码，逐项确认后再写入。
