# 大项目 PRD

大项目开工规格。产出 **一份 PRD**，**不产出 HTML 原型**。开发、测试读完应能做、能测，不必再问取值、前置、点完看到什么。

规则真源与本目录同步：`/Users/ckw/Documents/erp/本地/prompt-lib/large-project-prd/`。改本 Skill 时两处一起改。

## 与其它 Skill 的边界（MUST）

本 Skill 是加项。 **禁止**修改、覆盖、调用任何已有 Skill； **禁止**改写已有 Skill 的默认落盘。

本流程 **禁止写 HTML、禁止建 `原型/` 目录**。用户若还要原型：停，告诉用户走原来的原型相关流程，不要在本 Skill 里顺手做，也不要替它启动其它 Skill。

出现下面任一情况 → **立即停、不产出、不转去执行其它 Skill**。一句话告诉用户走原来的流程：

| 用户实际在要 | 原流程（只提示，不要替它启动） |
|--------------|--------------------------------|
| 需求输出、变更说明、小需求、CKW 编号、迭代需求 | 日常需求输出 |
| 会议需求分析、会议转需求 | 会议转需求 |
| 系统项目知识库、项目知识库落盘/重建 | 系统项目知识库 |
| 初始化知识库、同步知识库、阶段 0–7 | 系统知识库构建 |

只说「PRD」「需求」「原型」不够，不要自行升级成本流程。

未 @ 本 Skill、也未使用上表以外的专用口令（大项目PRD / 新项目PRD / 大项目需求文档 / 完整项目说明书）→ 不执行。

**禁止默认写入**（除非用户把该路径 **逐字指定** 为本次落盘目录）：

- `ERP_product/{{系统}}/迭代需求/`
- 产品组「项目知识库」目录
- `ERP_product/{{系统}}/知识库/`

即使落盘目录被指定到上述位置：只写 **一份** `{{项目名}}-PRD.md`，不生成原型、领域逻辑、贯穿算例、按页拆开的需求文档，也不改已有变更说明编号规则。

## 启动（缺一项就停）

1. **判定规模**（即使用户已 @ 本 Skill）：
   - **走本 Skill**：新模块或新主路径，或 ≥3 个页面/弹窗，或改跨页主流程。
   - **停、不产出**：单字段、单按钮、单弹窗文案/显隐/校验。告诉用户这是日常小需求，走原来的需求输出，不要在本对话里改走那个 Skill。
   - **中间态**：用选择题问用户是否按大项目开工；未确认前不写文件。
2. **问齐再动笔**（已给出的不要重复问）：
   - 项目名称
   - 所属系统（中文名）
   - **落盘目录**（必须用户指定）
   - 需求输入（描述、会议、草稿、范围）
3. 范围会影响菜单挂载、页面清单或主流程时，先用选择题对齐（带推荐项）：改存量还是全新、侧栏挂在哪个模块下哪些页、哪些角色、明确不做哪些、是否含导入/导出/批量。未对齐前不写 §3。

未拿到落盘目录：禁止创建文件。

## 工作流

```
范围对齐（冻结 §1.4 菜单结构、§1.5 页面清单）→ §1 + §2 → 按页写该页 PRD → 附录与自检 → 回报路径
```

禁止：对照完全体现状后一次性糊完整份文档。禁止写原型。

### 0. 修订已有大项目 PRD

- 用户点名的是 **本 Skill 产出的** `*-PRD.md`：只改点名的章节，重跑相关必须项；禁止整份重写；不要补 HTML。
- 用户点名的是迭代需求变更说明、项目知识库文档、知识库页面详情：**停，不改这些文件**。

### 1. 对照现状（只为填 §2，只读）

读现网逻辑，**不要把代码写进 PRD，也不要回写知识库。**

若路径存在则只读，不存在就跳过：

1. 产品组项目知识库里该系统相关项目与页面说明
2. `ERP_product/{{系统}}/知识库/` 的模块概要、页面详情
3. 对得上的前后端实现，核对「现在到底怎么做」

证据冲突：页面详情明显是空壳（多处待确认、千篇一律「视字段而定」）→ 以现网实现为准，缺口进 §1.8。不要为了写 PRD 去改知识库。

§2 表格只要：位置、当前怎么做、本次怎么改、影响谁。一两句，不写字段细节。新页面写「当前没有此能力」。无变化的区域不占行。

### 2. 写 PRD（按页）

读取 [prd-template.md](prd-template.md)，在用户指定目录写入 **一个** Markdown，建议文件名：`{{项目名}}-PRD.md`。先落 §1（含 §1.4 菜单结构）、§2 和 §1.5 清单，再逐页追加 §3。

硬性要求：

- 弹窗写在同一份文档的页面小节里，不另开需求文件
- 字段按区一张大表，列与模板一致；空格子写「无」（禁止「—」、禁止「见原型」）
- 枚举有「说明」列；固定选项列全
- 每个字段有取值逻辑；每个可点操作有前置、过程、成功输出、失败输出（含文案原文）
- 有计算公式：必须在该区下用 **1 组具体数字**跑通；不另建领域逻辑或算例文件
- 验收用「场景 + 操作 + 预期结果」，操作列不得空；不要改成 Given/When/Then
- 全文通顺中文，**禁止代码类描述**（接口名、参数名、组件名、权限码、表名、判断语句、驼峰字段、状态数字码、文件路径）
- **必须有 §1.4 菜单结构**：只画本系统现网侧栏（哪个模块下挂哪些菜单页）；标明新增 / 迁入 / 下线 / 不占菜单；**禁止**把外系统适配页画进同一张树。§1.5 页面清单含弹窗和详情，用来对章节，不能代替菜单树
- 权限只写中文角色 + 能做什么/不能做什么，不写权限码
- 阻塞开发的待确认未拍板：状态只能是「草稿」
- **不写原型、不链到 HTML、不把规则推给「见原型」**

章节缺失、用「见原型 / 视情况 / 以后端为准」充数，视为未完成。

文档状态：

| 状态 | 何时 |
|------|------|
| 草稿 | 有阻塞待确认，或 §1.4 菜单结构 / §1.5 页面清单未冻结，或仍有页未写完 |
| 评审中 | 无阻塞待确认，必须项尚未全部通过（或用户还在看） |
| 可开发 | 必须项全部通过，且无阻塞待确认 |

### 3. 对齐与收尾

1. 填满 PRD「附录 C」完整性对照
2. 按 [qa-checklist.md](qa-checklist.md) 做必须项；失败则改正文，不要带着缺口交差
3. 对话里只报：落盘路径、菜单结构、页面清单、改动点摘要、仍阻塞的待确认。不要把 PRD 全文贴进聊天
4. 只有必须项全部通过、且无阻塞待确认，才把状态写成「可开发」
