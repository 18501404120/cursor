# 大项目 PRD 自检清单

写完大项目 PRD 后必须过一遍。单点小改动不要套本清单。本清单不要求、也不检查 HTML 原型。

判定：下面「必须」项全部勾上，才能把状态改成「可开发」。没参加讨论的开发、测试只靠本文，应能知道怎么做、怎么测，而不再来问取值、前置、点完看到什么。

每写完一页（含该页弹窗），先过 D–G 里该页相关项，再写下页。

---

## A. 边界与文风（必须）

- [ ] 全文只有一份 Markdown；弹窗是章节，不是第二份需求文档
- [ ] 不依赖另一份领域逻辑、算例文件或原型才能看懂
- [ ] 落盘目录是用户本次指定的；没有默认写到迭代需求或项目知识库
- [ ] 没有改写其它 Skill 的产出（变更说明、项目知识库、系统知识库）
- [ ] **没有产出 HTML 原型**，也没有 `原型/` 目录
- [ ] **通篇没有代码类描述**（接口名、参数名、组件名、权限码、表名、判断表达式、驼峰字段、状态数字码、文件路径）
- [ ] 句子通顺，像讲解规则，不是缩写堆砌
- [ ] 条件都写成业务话，并写全条件本身，没有「视情况」「以后端为准」「见原型」
- [ ] 空格子是「无」，没有「—」

---

## B. 项目说明（必须，保持短）

- [ ] §1 能较快看完：要做、不做、角色入口、菜单结构、页面清单、主流程
- [ ] 「不做什么」写了，并指向相邻页面
- [ ] **§1.4 菜单结构**是现网侧栏树：只含本系统会挂在菜单上的页面；新增 / 迁入 / 下线 / 不占菜单已标明
- [ ] 外系统适配页（如其它系统的管理页、计划页）没有画进本系统同一张树
- [ ] 页面清单（§1.5）行数 = PRD 页面章节数（弹窗计入）；清单不能代替菜单树
- [ ] 跨页规则写在本文 §1.7
- [ ] 会改变实现的待确认已清零，或标明不阻塞开发

---

## C. 改动点（必须）

- [ ] 写 PRD 前对照过当前系统：知识库 + 必要的前后端现网逻辑（只读，未回写）
- [ ] §2 用表格列出改动点：位置、当前怎么做、本次怎么改、影响谁
- [ ] 只写到位置和方向，没有把字段字典糊进改动点表
- [ ] 新页面标了「当前无此能力」；老页面只列真正变化的区域
- [ ] 改动点表里同样没有代码描述

---

## D. 字段、取值、枚举（必须）

- [ ] 按区一张大表，列齐全；没有的格子写「无」，没有「—」、没有「见原型」
- [ ] 用户能看到或能改的项都有行
- [ ] 每行有取值逻辑：从哪来、怎么算或怎么选、何时更新、没有数据时怎么办
- [ ] 有计算公式的，在该区下有短说明，并用一组具体数字跑通
- [ ] 固定枚举列出全部选项，且有「说明」列
- [ ] 动态枚举写了来源、何时重载、空列表原文
- [ ] 展示格式写清（日期、小数、单位），需要的列都有

---

## E. 操作闭环（必须）

页面上每个可点动作都要能回答下面五个问题：

- [ ] 谁可以点
- [ ] 前置条件是什么（状态、已填项、不能在加载中等）
- [ ] 点下去过程中界面怎样（是否转圈、是否禁止连点）
- [ ] 成功后输出是什么（提示原文、字段或列表变化、跳转还是停留）
- [ ] 失败后输出是什么（提示原文、已填是否保留、按钮是否恢复）

另外：

- [ ] 二次确认的原文、点确定和点取消分别怎样，都写了
- [ ] 有单据状态时，有状态与按钮（可点 / 禁用 / 隐藏）对照，禁用有说明文案
- [ ] 进入方式与带入信息写了；缺带入时的提示和能否继续写了
- [ ] 查询、重置、分页、默认排序、进入是否自动查，有则写了
- [ ] 未保存离开是否拦截，有则写了确认原文

---

## F. 校验与文案（必须）

- [ ] 校验表覆盖提交、保存、会丢数据的切换、弹窗确认
- [ ] 写清何时校验（离开输入框还是点按钮）
- [ ] 每条有提示原文、是否阻断、阻断后停在哪
- [ ] 空态、加载、失败、无配置、提交失败的原文都是完整句子
- [ ] 附录 B 能对上正文出现过的提示、确认、空态、按钮

---

## G. 验收（必须）

- [ ] 每页至少：主路径成功、条件显隐、校验失败、空态或异常、取消或确认选否
- [ ] 每条是「场景 + 操作 + 预期结果」，操作列有具体动作，预期是可观察的界面或原文
- [ ] 没有「符合预期」这种空话
- [ ] **不要求**写成 Given / When / Then

---

## H. 可读性抽查（必须）

把文档给一个没参加讨论的人，只靠本文应能回答：

- [ ] 相对现在系统，大概改了哪些地方
- [ ] 现网侧栏哪个模块下挂哪些页面，哪些不占菜单
- [ ] 从哪进、带什么进来、缺了怎么办
- [ ] 这个数或选项是怎么来的
- [ ] 每个下拉有哪些项、分别什么意思、没有项时显示什么
- [ ] 这个按钮什么条件下才能点，点成功、点失败各看到哪句话
- [ ] 提交前查什么、提示原句是什么、失败后表单还在不在
- [ ] 哪些角色看不见或不能点
- [ ] 本页不做的事谁做

还有要靠口头对齐才能答的 → 未完成，不要标「可开发」。

---

## I. 建议有、不强制

- [ ] 多页共用枚举收进附录 A
- [ ] 复杂弹窗验收不少于 3 条
- [ ] 导入、导出、批量、刷新计算等若存在，按操作表写全前置和输出

---

## 反例（出现即不合格）

- 字段表缺列，或大量「—」「见原型」「条件」二字后面没有条件
- 有控件、必填，但没有取值逻辑（这个值怎么来、何时变）
- 有公式却没有一组具体数字
- 只写「点击创建」，没有前置、没有成功/失败文案、没有失败后停在哪
- 没有改动点表，或改动点里开始贴接口、文件名、判断语句
- 文案写成「给出提示」「报错」，没有界面原文
- 验收只有标题、操作列为空，或没有预期结果
- 顺手写了 HTML 原型，或把规则推给「见原型」
- 默认写进了迭代需求或项目知识库，或改了其它 Skill 的产出
- 没有菜单结构，或把弹窗/详情/外系统页面画进本系统侧栏树
