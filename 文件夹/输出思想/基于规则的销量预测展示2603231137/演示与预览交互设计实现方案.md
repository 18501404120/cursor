# 演示与预览交互设计与实现方案

## 1. 交互目标

- 让用户 3 分钟内理解“规则预测如何计算、为何可信、如何调参”。
- 支持从概览到细节逐层浏览，减少一次性信息负荷。
- 支持快速试算，实时看到预测变化与因子贡献。

## 2. 页面信息架构

- 顶部总览：方案定位、核心价值、关键 KPI。
- 公式与因子区：统一预测范式 + 7 因子说明卡片。
- 分层讲解区：背景、规则、验证、实施四层 Tab 切换。
- 流程与规则区：端到端流程图 + 规则表示例。
- 试算区：输入基准销量和因子乘数，实时计算预测值。
- 上线清单区：落地检查项，支持项目推进与验收。

## 3. 核心交互设计

### 3.1 分层 Tab 切换

- 用户点击 Tab 后，显示对应层内容并高亮当前标签。
- 价值：将复杂方案拆成可逐步理解的内容块。
- 实现：按钮绑定 `data-id`，通过 `active` 类控制显示与样式。

### 3.2 实时试算

- 用户修改任意输入后立即刷新预测结果。
- 价值：支持“如果我调价/加投会怎样”的快速模拟。
- 实现：监听 `input` 事件，执行乘数连乘并 `Math.round` 输出。

### 3.3 自适应布局

- 桌面端采用多列卡片；移动端降级为单列。
- 价值：保障跨设备预览体验一致。
- 实现：通过 CSS `@media` 在 980px、560px 两个断点调整网格。

## 4. 前端实现要点

- 技术栈：原生 HTML + CSS + JavaScript（单文件可离线打开）。
- 可维护性：将样式变量集中在 `:root`，便于主题快速调整。
- 可扩展性：试算器字段可映射真实规则配置，支持后续接 API。
- 性能：无需外部依赖，首屏加载快，适合方案评审场景。

## 5. 演示脚本建议

- 第 1 步：展示总览和 7 因子框架，说明规则预测价值。
- 第 2 步：切换四层 Tab，讲清每层“问题-方案-价值”。
- 第 3 步：在试算器把价格乘数从 1.06 调到 0.94，展示预测即时变化。
- 第 4 步：回到流程图，强调可解释输出与规则版本治理。

## 6. 验收标准

- 能完整展示四层内容，逻辑顺序清晰。
- 试算器输入变更后结果即时更新且计算正确。
- 页面在主流浏览器可正常打开，移动端布局无明显错位。
- 内容与《基于规则的销量预测设计说明》核心口径一致。
