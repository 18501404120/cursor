# 产品信息筛选区 — 全局 UI 规范

> **适用范围**：凡页面包含「产品信息」相关查询条件（如 model、SKU、SPU 等）的列表页、看板、配置页，其**顶部筛选条**均须遵循本规范。  
> **设计参照**：Ant Design / Element Plus 类后台组件风格；布局与交互以仓库内参考图为唯一视觉基准（见下方「参考图」）。  
> **生效说明**：本文件与项目根目录 `.cursor/rules/product-filter-bar.mdc` 配套使用，便于在 Cursor 中生成/改版页面时自动对齐。  
> **字段含义**：model、SPU、SKU、MSKU、品线、场景、品类、渠道、店铺等业务定义见 **`销售主数据-全局业务规范.md`**（model/SPU = SKU 前 5 位；明细唯一键 = msku + 店铺名称）。

---

## 1. 整体结构

| 项目 | 要求 |
|------|------|
| 布局 | 筛选项**单行横向**排布；标签在左、控件在右；**垂直居中对齐**。 |
| 背景 | 筛选区背景为浅色（通常为白底 `#fff`）。 |
| 分隔 | 筛选区底部一条**浅灰横线**，与下方表格/内容区明确分区。 |
| 间距 | 不同筛选项（「项组」）之间保持**明显水平间距**（建议 ≥ 24px，与业务页面密度一致时可略调，但须统一）。 |

---

## 2. 控件类型与行为

### 2.1 普通下拉（示例：model 查询）

- **业务含义**：**model = SPU = 当前 SKU 的 8 位编码之前 5 位**；选项来自 `基础数据/销售主数据索引_v1.json` 或接口去重列表（见《销售主数据-全局业务规范》§2）。
- **标签文案**：如「model查询」，颜色为**中灰**，勿与主文案同色。
- **控件**：标准 **Select**，占位符为「**请选择**」。
- **样式**：浅灰描边、**圆角**（约 4～6px）；右侧 **下拉箭头（chevron）**。
- **状态**：未聚焦为浅灰边框；聚焦/展开时可使用品牌主色描边（见第 4 节）。

### 2.2 SKU：模式选择 + 文本输入（组合控件）

用于 **生产 SKU / MSKU** 检索时，**必须**采用「左侧模式 + 右侧输入」的**一体组合**，不得拆成两个独立、无关联的控件。与 **model** 下拉 **互不级联缩选项**（见《销售主数据-全局业务规范》§12.3）。

- **标签**：「SKU」，样式同其他筛选项标签（中灰）。
- **左侧（模式）**：下拉，选项至少包含：
  - **模糊** — 对 **8 位生产 SKU** 子串/模糊匹配。
  - **精确** — 对 **MSKU** 精确匹配（非 SKU 全等；业务口径见《销售主数据-全局业务规范》§12.3）。
  - **8位搜索** — 按 **8 位生产 SKU** 规则检索。
- **右侧（输入）**：单行文本框，占位符「**请输入SKU**」（与参考图一致；精确模式语义为 MSKU 时占位符是否改为「请输入MSKU」由单页 PRD 约定，全局默认不改）。
- **一体表现**：
  - 外轮廓为一组控件：左侧下拉与右侧输入**视觉连续**（无断裂感）。
  - **聚焦**任一子控件时，**整组外边框**使用品牌主色描边（与参考图一致）。
- **下拉菜单**：选项列表圆角、轻阴影；**当前选中项**用主色底 + 白字/对勾，未选中为默认文字色。

## 3. 扩展其它「产品维度」时的规则

在保持本规范不变的前提下，可增加其它筛选项（如平台、仓库、类目），但须满足：

1. **同一行内**标签 + 控件对齐方式与参考图一致。  
2. 若某字段也是「模式 + 输入」类（如订单号精确/模糊），**复用与 SKU 相同的组合形态**，仅改标签与占位符文案。  
3. 新增项不得破坏「底部分隔线 + 下方内容区」的层级关系。  
4. 若筛选项为**多选枚举且须懒加载下拉**（默认不加载选项、展开后加载；支持搜索与默认「全部」；SKU/MSKU 等大数据例外见该文档），见 **`多选下拉筛选-全局UI规范.md`** 与 `规范/assets/multi-select-filter.js`。

## 4. 颜色与圆角（建议 token）

以下为与常见后台组件库兼容的推荐值，实现时优先与团队设计 token 对齐。

| 用途 | 建议值 |
|------|--------|
| 主色（聚焦边框、选中项背景） | `#1677ff`（或与现有 ERP 主色一致） |
| 标签文字 | `#595959`～`#8c8c8c` |
| 占位符 | `#bfbfbf`～`#d9d9d9` |
| 默认边框 | `#d9d9d9` |
| 底部分隔线 | `#f0f0f0` 或 `#e8e8e8` |
| 圆角 | `4px`～`6px`（与全站 Input/Select 统一） |

## 5. 技术实现提示（可选）

- **Ant Design**：`Select`；SKU 可用 `Input.Group` 紧凑组合 `Select` + `Input`，或 `AutoComplete` 按产品定义封装。  
- **Element Plus**：`el-select`；SKU 使用 `el-input` 的 prepend 插槽承载模式下拉。  
- **纯 HTML 原型**：用 flex 容器包裹左侧 `<select>` 与右侧 `<input>`，统一 `:focus-within` 描边以模拟「整组聚焦」。

---

### 2.3 品线（4 位编码）：多选 Tag + 下拉勾选（Ant Design `Select mode="multiple"` 风格）

用于**品线 / 产品线可多选**的筛选或表单时（**亚马逊品线，4 位编码**；**产品线与品线同义**），推荐采用与 Ant Design 多选 `Select`（`mode="multiple"`）一致的交互；视觉与交互以需求附图或 Ant Design 官方示例为准，与「普通单选下拉」区分。

| 项目 | 要求 |
|------|------|
| 触发区 | 外框为**圆角矩形**；**已选项**以 **Tag** 展示（浅灰底、细边框、编码等宽字体）；每个 Tag 右侧 **×** 可移除。 |
| 溢出 | 当 Tag 超过展示宽度时，采用 **`+ N`**（N 为隐藏数量）示意更多已选，避免撑破单行筛选条。 |
| 搜索 | 框内保留**可输入光标**，用于在下拉列表中**过滤可选编码**（本地过滤即可）。 |
| 下拉 | 白底浮层、轻阴影、圆角；**已勾选项**为**主色字 + 右侧 ✓**；悬停行浅灰底；列表过长时**纵向滚动**。 |
| 展开态 | 展开或聚焦时外框使用与 2.1 相同的**主色描边 + 外发光**；右侧 **chevron** 可旋转表示展开/收起。 |
| 与「仅全品线」 | 若页面另有「仅全品线活动」等**互斥语义**，与多选品线二选一或联动规则须在页面文案中写清；实现上避免同一条件重复筛选。 |

**纯 HTML 原型**：可用「隐藏原生多选 + 自定义 Tag 区 + 绝对定位下拉列表」模拟；须保证键盘与无障碍最小可用（`aria-label`、`aria-expanded`）。

### 2.4 区域-国家联动（强制）

用于所有含「区域」「国家」筛选项的页面（含历史页面改造与新页面）：

1. 区域与国家数据源统一使用：`规范/基础数据/区域国家基础数据_v1.json`（或其后续版本）。
2. 区域下拉默认值为「全部」，国家下拉默认值为「全部」。
3. 当区域=全部时：国家下拉展示全量国家（去重后按基础数据顺序）。
4. 当区域=某一区域时：国家下拉仅展示该区域下的国家。
5. 区域变更时：国家自动重置为「全部」并刷新候选列表。
6. 禁止页面内硬编码一套与基础数据不一致的区域/国家选项；如需扩展必须先更新基础数据文件。
7. 历史项目筛选框需按本规则统一改造，后续涉及区域/国家筛选的新需求同样强制遵循。

### 2.5 渠道-店铺联动（强制）

用于所有含「渠道」「店铺」筛选项的页面（含历史页面改造与新页面）：

1. 渠道与店铺数据源统一使用：`规范/基础数据/渠道店铺基础数据_v1.json`（或其后续版本）。
2. 渠道下拉默认值为「全部」，店铺下拉默认值为「全部」。
3. 当渠道=全部时：店铺下拉展示全量店铺（去重后按基础数据顺序）。
4. 当渠道=某一渠道时：店铺下拉仅展示该渠道下的店铺。
5. 渠道变更时：店铺自动重置为「全部」并刷新候选列表。
6. 禁止页面内硬编码一套与基础数据不一致的渠道/店铺选项；如需扩展必须先更新基础数据文件。
7. 历史项目筛选框需按本规则统一改造，后续涉及渠道/店铺筛选的新需求同样强制遵循。

## 7. 跨项目复用

若其它代码仓库也需要同一规范：

1. 复制本文件（或同步至团队知识库）。  
2. 复制 `.cursor/rules/product-filter-bar.mdc` 至对应项目的 `.cursor/rules/`，并视需要调整 `alwaysApply` 或 `globs`。  
3. 前端脚手架或组件库中若有「业务筛选条」封装，应将 **SKU 组合控件**与 **model 下拉**作为标准示例写入 Storybook/文档。
