# 多选下拉筛选 — 全局 UI 规范

> **适用范围**：ERP / 管报 / 配置类页面中，用于**筛选条件**的「多选枚举」控件（如零售商、场景、品类、MSKU 列表等）。  
> **不适用**：表单内非筛选用途的复杂树形选择、品线 Tag 多选（仍以《产品信息筛选区》2.3 为准）、以及产品单独声明的控件。  
> **配套实现**：`文件夹/规范/assets/multi-select-filter.js`（`MultiSelectFilter.mount`）；与仓库 `.cursor/rules/multi-select-filter.mdc` 配套使用。

---

## 1. 行为总则（MUST）

| 项目 | 要求 |
|------|------|
| **懒加载** | **默认不向 DOM 写入选项列表**；用户**首次点击**展开下拉后，再调用数据源（`getOptions` 或接口）并渲染选项。 |
| **多选** | 面板内使用**复选框**多选；触发器上展示「请选择」占位或「已选 N 项」等摘要。 |
| **搜索** | 面板顶部提供**搜索框**，对当前已加载的选项做**本地过滤**（正式环境若数据极大可改为服务端搜索，但交互形态不变）。 |
| **全部** | **默认**提供首行 **「全部」**：勾选表示选中**当前搜索条件下可见的全部选项**；取消则取消这些项。若页面/产品明确排除（见第 3 节），可不展示「全部」。 |
| **关闭** | 点击面板外区域关闭下拉；再次打开保留已选（除非业务主动 `clear`）。 |

---

## 2. 视觉与布局（SHOULD）

- 触发器：与单选 `Select` 一致的单行框、浅灰边、圆角、右侧下拉暗示；展开时主色描边 + 外发光（与《产品信息筛选区》主色一致时可对齐 `#1677ff`）。
- 面板：白底、轻阴影、圆角；列表区域 `max-height` 可配置（建议 240～320px），内部纵向滚动。
- 与《产品信息筛选区》同屏时：标签在左、控件在右、单行筛选项间距与底部分隔线保持一致。

---

## 3. 例外：不提供「全部」的场景

以下情况**不展示**首行「全部」，并在页面说明或 PRD 中**单独写明**：

- **大数据量 / 全选风险**：如 **SKU、MSKU** 等动辄上万条，一键全选易导致性能与误操作问题。
- **语义与「全部」冲突**：如选项已包含「全场景」「全品类」等业务专用项时，由产品决定是否与「全部」并存。

未列入例外清单的筛选多选，**默认必须有「全部」**。

---

## 4. 技术约定（原型 / 前端）

- **原型 HTML**：优先引用 `../../../规范/assets/multi-select-filter.js`（相对路径以具体页面所在目录为准）。  
- **API**：`MultiSelectFilter.mount(container, { placeholder, showSelectAll, getOptions, zIndex, onChange, ... })`；`getOptions` 支持同步数组或 `Promise`。  
- **刷新选项**：数据源随其它筛选变化时，调用实例 `refreshOptions()`，并在需要时 `clear()` 已选。

---

## 5. 与其它规范的关系

- **产品信息筛选区**（`产品信息筛选区-全局UI规范.md`）：SKU **模式 + 输入框**组合、品线 Tag 多选等**仍按该文档**；本规范覆盖「枚举型多选筛选」的**下拉懒加载**形态。  
- **渠道–店铺、区域–国家** 等联动下拉若为**单选**，仍按对应规范；其中「店铺多选」等若为多选枚举，则适用本规范。
