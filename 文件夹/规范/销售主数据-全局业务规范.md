# 销售主数据 — 全局业务规范

> **适用范围**：ERP、管报、销量预测、促销、GTM、费用规划等所有涉及 **场景 / 品类 / model(SPU) / SKU / MSKU / 店铺 / 渠道 / 品线** 的需求、原型与实现。  
> **配套数据**：`规范/基础数据/` 下 JSON（见 §7）。  
> **与 UI 规范关系**：筛选区布局与控件形态仍遵循《产品信息筛选区》《多选下拉筛选》等；**字段含义与层级以本文为准**。

---

## 1. 维度层级（产品侧）

自上而下：

```text
场景
 └── 品类（须落在某场景下；跨场景同名品类以「场景 + 品类」区分）
      └── model（= SPU，见 §2）
           └── SKU（8 位生产编码）
                └── MSKU（渠道可售编码，见 §3）
                     × 店铺名称 → 唯一业务行（见 §4）
```

**标准下钻路径**（分析、报表逻辑推荐顺序）：

**场景 → 品类 → model → SKU →（店铺 +）MSKU**

- 全渠道管报既有页面**暂不强制改版**交互顺序；新页面与新需求默认采用上述路径。
- **品线（4 位）** 为亚马逊侧沿用维度，与场景树**并列**，用于筛选/分摊，不插入上述层级中间（见 §5）。

---

## 2. model 与 SPU（强制统一定义）

| 项 | 规则 |
|----|------|
| **定义** | **model = SPU = SKU 的前 5 位字符**（生产 SKU 为 8 位时，model 为左 5 位）。 |
| **废弃** | 其它「型号主数据」「独立 model 表名」若与「前 5 位」不一致，以本文为准；新需求不得再引入第二套 model 定义。 |
| **推导** | `model = sku.substring(0, 5)`；无需单独维护 model 编码表，除非产品另立 **与 SKU 前 5 位一一对应** 的展示名映射。 |
| **筛选区** | 标签可用「model查询」或「model」；选项来自主数据去重后的 model 列表（见 `销售主数据索引_v1.json` 或接口）。 |

**示例**：SKU `H6065301` → model `H6065`。

---

## 3. SKU 与 MSKU

### 3.1 SKU

- **粒度**：公司 **8 位生产 / 产品 SKU**（会议与文档中的「8 位 SKU」「生产 SKU」均指此字段，**不是 MSKU**）。
- **属性稳定性**：同一 SKU 下 **场景、品类** 在主数据中应一致；**研发状态、产品定位** 可在不同 MSKU 行上不同（见 §6）。
- **检索**：筛选区须使用《产品信息筛选区》**模式 + 输入**（模糊 / 精确 / 8 位搜索）。

### 3.2 MSKU

- **含义**：渠道 / 店铺维度的 **可售 Listing 编码**，通常由 SKU + 后缀构成。
- **长度**：常 **长于 8 位**（含渠道、国家、返修等后缀）；禁止将「8 位」用于描述 MSKU。
- **命名惯例**（解析与展示参考，历史数据允许不规范）：

| 片段 | 含义 |
|------|------|
| `-ZY`、`-APP`、`-GL` 等 | **渠道体系**（如独立站 Shopify、App 商城、独立站 GL 等） |
| `-US`、`-DE`、`-UK` 等 | **国家 / 站点区域** |
| `-T` | **返修品** Listing（与 §6 产品定位相关，但非 100% 一一对应） |
| 无后缀 | 多见于 `Govee_US` 等亚马逊店，实质常省略 `-US`；**规范写法应带国家后缀**；清洗前展示层可兼容 |

- **后缀与国家**：泛欧等场景下，**同一 MSKU 字符串可挂在多个店铺**；**不能**仅凭后缀 `-DE` 判定唯一国家，须结合 **店铺名称** 与 `区域国家基础数据_v1.json`。

## 4. 唯一键与汇总规则（强制）

| 粒度 | 唯一键 | 说明 |
|------|--------|------|
| **明细主数据行** | **`msku` + `店铺名称`** | 销售基础信息、管报明细、促销明细等**一行一 MSKU×店铺**。 |
| **MSKU 字符串** | 非全局唯一 | 同一 `msku` 可对应多个店铺（如泛欧多站）；不得假设「一个 MSKU 全世界一行」。 |

**交互与展示（管报 / 促销等）**：

- 当业务要求「**唯一 MSKU**」或「**单个 MSKU**」才能展示某指标（如成交价、促销力度）时：在**未限定店铺**的情况下，应将 **该 MSKU 下各店铺数据汇总**（或按产品定义的默认汇总口径聚合），**不得**按「MSKU 全局唯一」取第一行。
- 若筛选已限定 **单一店铺**，则在该店铺内按 `msku` 唯一处理即可。
- 泛欧、库存、预测等模块若已单独约定「主店铺 / 承载 MSKU」，在其专项规范中优先，但不得与「明细行 = msku + 店铺」矛盾。

---

## 5. 品线 / 产品线

| 项 | 规则 |
|----|------|
| **字段** | 表字段名多为 **品线**；4 位数字编码（如 `6014`、`6811`）。 |
| **含义** | **亚马逊渠道侧品线定义**，系统中沿用；**产品线 = 品线**（同义，勿再拆第三概念）。 |
| **筛选** | 《产品信息筛选区》§2.3 多选 Tag；与场景、品类、model、SKU 为 **AND** 关系。 |
| **费用规划** | 营销预算按品线拆分时，指同一 4 位品线维度。 |

---

## 6. 研发状态与产品定位

两套 **独立状态字段**，不合并为单一枚举：

| 字段 | 用途（摘要） |
|------|----------------|
| **研发状态** | 产品生命周期：未上市、已上市、准备 EOM、EOM、EOL 等。 |
| **产品定位** | 经营定位：P0/P1/P2 新品/稳定、EOL、退件品、返修品、配件等。 |

**返修 / 退件**：

- **退件品** 与 **返修品** 为 **同一业务**；主数据可同时存在两种文案。
- **`-T` 后缀** 表示返修品 Listing，但 **不保证** 与 `产品定位` 中「退件品/返修品」100% 对应；**历史脏数据允许存在**，展示与规则引擎宜兼容。

## 7. 场景与品类

- **层级**：**场景是品类的上一层**；品类须归属某场景。树形主数据以 **`场景品类基础数据_v1.json`** 为准。
- **筛选**：选品类时建议带场景，或 UI 上先场景后品类，避免跨场景同名品类歧义（如「传感器&盒子」在居家与户外均有）。
- **与 Excel / 销售表**：`销售基础信息_v1.json` 中场景、品类名称须与上述 JSON **名称级**一致；新增品类先改基础数据再扩销售表。

---

## 8. 渠道与店铺

- **层级**：**先渠道，后店铺**（《产品信息筛选区》§2.5）。
- **数据源**：`渠道店铺基础数据_v1.json`；禁止页面硬编码与基础数据不一致的选项。
- **命名**：GoveeLife 渠道下店铺统一为 **`Goveelife_XX`**（**life 小写**），如 `Goveelife_US`。
- **示例对照**：

| 店铺名称 | 渠道（channel_name） | 说明 |
|----------|----------------------|------|
| `Govee_US` | Govee | 亚马逊 · 美国 |
| `独立站-US` | 独立站 | Shopify · 美国 |
| `APP商城-US` | APP商城 | App 商城 · 美国 |

- **区域 / 国家**：与 MSKU 后缀、店铺站点配合时，使用 `区域国家基础数据_v1.json` 联动（§2.4 UI 规范）。

---

## 9. 术语与文档写法

| 推荐写法 | 避免 |
|----------|------|
| **8 位 SKU**、**生产 SKU** | 「8 位 MSKU」 |
| **MSKU**（渠道可售编码） | 与 SKU 混称 |
| **model / SPU**（同义，前 5 位） | 再定义一套无关的 model |
| **品线 / 产品线**（同义，4 位） | 与 model、品类混淆 |
| **MSKU** | 会议纪要中的 **MSQ**（视为笔误，统一改为 MSKU） |

## 10. 基础数据文件清单

| 文件 | 说明 |
|------|------|
| `基础数据/销售基础信息_v1.json` | MSKU×店铺明细宽表（来源：销售基础信息导出，店铺名已规范为 Goveelife_*） |
| `基础数据/销售主数据索引_v1.json` | 去重后的 model、SKU 列表（便于下拉/检索） |
| `基础数据/场景品类基础数据_v1.json` | 场景 → 品类树 |
| `基础数据/渠道店铺基础数据_v1.json` | 渠道 → 店铺树（v1.1 起 Goveelife 命名统一） |
| `基础数据/区域国家基础数据_v1.json` | 区域 → 国家树 |

**更新流程**：业务导出表变更 → 更新 `销售基础信息_v1.json` 与索引 → 若新增店铺则同步 `渠道店铺基础数据_v1.json` → 修订本文档版本号。

## 11. 已知数据质量（不阻塞规范）

以下允许在主数据中存在，实现时勿写死过严校验：

1. 极少数 **model** 下 SKU 跨场景/品类（如编码系列复用）。
2. 极少数 **SKU** 对应多个 **品线**（如客服配件）。
3. **无后缀 MSKU**、**-T** 与 **产品定位** 不完全一致。
4. 同一 **MSKU 字符串** 多店铺（泛欧等）。
