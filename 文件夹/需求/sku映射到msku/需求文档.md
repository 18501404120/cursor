# 需求文档（改动点说明）

**需求名称**：场景品类与计划负责人自动维护（品类计划负责人模版与导入）  
**文档版本**：v1.1（重新生成）  
**关联评估**：见同目录下 `需求评估.md`

**说明**：文件夹名为「sku映射到msku」，与正文需求主题可能不一致；以 `需求` 原文及 `需求评估.md` 中待澄清项为准。

---

## 一、需求概述

- **一句话**：依据「场景 + 品类」与计划负责人的对应关系，通过品类计划负责人模版导入，批量更新该品类下全部 SKU 的计划负责人；后续在同一品类下新增的 SKU 自动带上该计划负责人；调整负责人时对该品类重新导入模版即可。
- **涉及 ERP 模块**：商品与 BOM 管理（SKU、品类、场景等主数据）；若计划负责人在其他模块复用，需口径一致（待与研发确认）。
- **使用角色/场景**：计划/商品运营或主数据维护人员维护规则与导入；下游按 SKU 上「计划负责人」做协同或筛选（若现有流程已用该字段）。

## 二、改动范围总览

| 类型 | 说明 |
|------|------|
| 新增 | 品类计划负责人模版（下载/导入）、导入结果反馈；可选：场景+品类→负责人规则列表（展示当前生效规则，视一期范围而定）。 |
| 修改 | SKU「计划负责人」的写入方式：在手工维护基础上，增加按规则批量刷新与新增 SKU 自动继承（具体是否已有字段、是否增加「来源」类字段，待研发确认）。 |
| 删除/下线 | 无（除非与旧流程冲突后决定下线某入口，待确认）。 |

## 三、具体改动点

### 3.1 页面 / 功能入口

- **位置**：待确认最终菜单路径；建议归属 **商品/SKU 主数据** 或 **主数据配置** 下，与现有「计划负责人」编辑入口的关系需产品定稿。
- **改动**：
  - 提供 **模版下载**、**模版导入**（可合并为同一功能区的两步操作）。
  - 导入完成后展示 **成功/失败统计** 及 **失败行明细**（如品类不存在、负责人无效、场景+品类重复等）。
  - 可选：规则列表页，便于与钉钉维护表对照核对（钉钉参考：https://alidocs.dingtalk.com/uni-preview?spaceId=25718099642&extension=xlsx&bizType=document&fileSize=14425&dentryUuid=PwkYGxZV3ZMOAbReIE6qyM4zWAgozOKL&cloudSpaceDentryId=185117016314&previewAtta=2&cloudSpaceSpaceId=25718099642&version=2&fileId=185117016314&scene=universalSpace&mainsiteOrigin=mainsite）。

### 3.2 字段 / 数据项

- **新增字段**（实现层待定）：
  - 规则存储：`场景`、`品类`、`计划负责人`（用户/工号等系统可解析标识，待确认）；可选 `批次/更新时间/操作人`。
  - SKU：若需区分规则写入与手工修改，可增加 **`计划负责人来源`** 等（待与评估结论 4 对齐后决定是否做）。
- **修改字段**：SKU 上 **`计划负责人`**（字段名以系统为准）— 由导入与「新增 SKU」逻辑按品类（及场景，若规则键为组合）赋值或覆盖。

### 3.3 筛选 / 查询条件

- **新增筛选**：若一期做规则列表：按场景、品类、负责人、导入批次等筛选（待确认）。
- **修改筛选**：SKU 列表既有「计划负责人」筛选保持不变，用于验收导入结果。

### 3.4 业务逻辑与规则

- **计算逻辑**：
  - 规则键：**场景 + 品类** → **计划负责人**（示例：观影场景 + 灯柱品类 → 林超辉）；同一键在系统中应唯一，重复行导入策略待确认（报错拒绝 / 后者覆盖等）。
  - **导入后**：按模版中的品类（及场景）解析规则，将该范围内 **全部已有 SKU** 的 `计划负责人` 更新为指定人员。
  - **新增 SKU**：当 SKU 归属满足某条规则时，在约定 **触发时机**（保存、审核通过、定时对齐等，待确认）自动写入 `计划负责人`。
  - **调整**：对同一品类（及场景）重新导入新负责人行，再次批量刷新范围内 SKU；是否与「手工修改锁定」冲突待评估表第 4 条结论。
- **权限与可见性**：谁可下载模版、谁可导入、是否审批，待评估表第 7 条对齐；与现有 SKU 数据权限模型一致（待确认）。

### 3.5 数据来源与依赖

- **依赖数据**：SKU 与 **品类**、**场景** 的绑定必须准确；**人员/用户主数据** 可校验负责人有效。
- **接口或表**：规则表、导入任务、SKU 更新事务与异步边界 — 待与研发/数据确认。
- **刷新频率 / 时效**：导入即时或异步（大批量建议异步 + 通知）；新增 SKU 继承与触发时机一致。

### 3.6 异常与边界

- **无数据时**：无匹配规则的 SKU，`计划负责人` 维持空或原值（待确认）；品类下 0 个 SKU 时可提示无更新条数。
- **多仓/多平台/多 SKU**：以 **SKU 主数据** 为粒度；不按仓/站点区分（若业务需要按 MSKU/站点区分负责人，为 **新需求/待确认**，当前原始需求未描述）。
- **冲突**：多规则匹配、SKU 多品类/多场景归属时的优先级或禁止策略 — 待评估表第 2 条对齐。

## 四、验收要点（可与提需方对齐后补充）

- [ ] 模版列、必填校验、错误提示符合约定；无效数据不污染已正确数据。
- [ ] 导入后，指定场景+品类下所有已有 SKU 的 `计划负责人` 与模版一致（抽样 + 必要时全量校验）。
- [ ] 该品类下 **新建 SKU** 在约定触发点后自动带出正确负责人。
- [ ] 同一品类重新导入新负责人后，范围内 SKU 全部更新（除非已定义「不覆盖手工」策略）。
- [ ] 权限：未授权不可导入；授权用户可完成全流程。
- [ ] 大批量导入性能或可接受的异步反馈（量级与指标待业务提供）。

## 五、与现有能力的关系

- **依赖的现有能力**：SKU 主数据、品类/场景属性、人员或账号体系；若有通用导入中心，优先复用任务与失败导出。
- **不影响的功能**：不默认改动采购、库存、履约核心逻辑；若其他模块读取 `计划负责人`，仅需联动回归（待确认依赖面）。
