# 需求评估文档

**评估时间**：2026-03-31  
**需求来源**：`文件夹/需求/coupon促销跟随`（原始材料文件：`需求`、`会议文件`）  
**原始需求摘要**：本次讨论 Amazon 平台同步的标准 `Coupon` 与**无门槛购买折扣**跟随。`Shopify（官网）` 对应形式为：创建 `discount` 类型活动，设置与 Amazon 相同原价/划线价 + 等额/等效优惠，确保到手价与亚马逊一致；`APP商城` 对应形式为：将从 Amazon 后台同步下来的 `Coupon` 或无门槛购买折扣信息转化成直降形式的促销活动（划线价），提升 APP 渠道转化率。  
**方案调整建议**：当前方案应明确为“只做 Amazon `Coupon` / 无门槛购买折扣跟随 + 按渠道分流设计”。建议定义为：`Amazon 标准 Coupon / 无门槛购买折扣 -> 生成卫星站跟随活动 -> 按渠道分流处理`。其中 Shopify（官网）采用 `discount` 类型承接，并保持 `相同原价/划线价 + 等额/等效优惠`；若同时间段已有划线价活动，仍可叠加成功；APP商城采用 `源优惠活动 -> 直降活动（划线价）` 转化，若同时间段已存在划线价类型促销，则会产生同类型冲突，不能跟随成功。

---

## 一、合理性评估

### 1.1 业务价值

- **结论**：合理
- **说明**：该需求直接服务于自营渠道与 Amazon 促销同步。`Shopify（官网）` 通过创建 `discount` 类型活动，并保持“相同原价/划线价 + 等额/等效优惠”来保证到手价一致，减少人工建活动；`APP商城` 通过把 Amazon `Coupon` 或无门槛购买折扣转成直降/划线价活动，改善 APP 渠道的促销展示和转化率。属于**销售与订单履约**链路中的促销协同能力，业务价值明确。

### 1.2 与现有能力契合度

- **结论**：部分契合
- **说明**：系统当前已有促销同步和活动跟随基础，因此 Amazon 优惠活动跟随方向与现有能力契合；但两个渠道的承接方式不同，不能共用一套规则。`Shopify（官网）` 更接近现有 `discount`/优惠能力延展，`APP商城` 则要承接到既有直降/划线价活动模型，需单独设计。

### 1.3 可行性

- **结论**：有条件可行
- **说明**：  
  - **数据侧**：跟随应基于 Amazon 后台同步下来的实时 `Coupon` 与购买折扣信息，而不是促销规划；同时要能识别购买折扣是否带门槛条件，避免把不支持的活动误纳入。  
  - **Shopify（官网）路径可行**：若本期处理 Amazon 标准 `Coupon` 与无门槛购买折扣，则可以按“相同原价/划线价 + 等额/等效优惠 + 同时间段”生成官网跟随记录，并在 Shopify 侧创建 `discount` 类型活动；若同时间段已有划线价活动，跟随 `discount` 仍可叠加生效，路径清晰。  
  - **APP商城路径有条件可行**：APP商城 不是同类 `Coupon`/购买折扣承接，而是将源优惠活动转成直降形式的促销活动（划线价）。若当前时间段不存在同类型活动冲突，则可落地；若该时间段已有划线价类型促销活动，由于跟随生成的也是划线价类型直降活动，会产生同类型冲突，因此不能跟随成功。  
  - **通知侧需按渠道拆分**：当前通知逻辑可复用状态框架，但消息内容必须区分渠道，否则业务无法判断当前是“推官网 `discount`”还是“推 APP 直降活动”。  
  - **验收需覆盖双渠道**：验收样例不能只测官网，必须分别准备 Shopify（官网） 和 APP商城 的核心样例。

### 1.4 范围与优先级

- **结论**：范围应按渠道拆分，先聚焦 Amazon 优惠活动跟随本身
- **说明**：  
  - **Shopify（官网）范围**：Amazon 标准 `Coupon`、无门槛购买折扣、相同原价/划线价、等额/等效优惠、创建 `discount` 类型活动、同时间段、人工点击推送、状态通知；若同时间段已有划线价活动，允许跟随 `discount` 叠加成功。  
  - **APP商城范围**：Amazon 标准 `Coupon`、无门槛购买折扣转直降活动（划线价）；无同类型冲突场景可支持，若同时间段已有划线价类型促销，则不能跟随成功。  
  - **明确不在本期范围**：有门槛购买折扣、社媒促销、有门槛活动、店铺满减联动。  
  - 若当前项目已在测试，则该需求仍建议作为独立迭代处理，避免把新渠道逻辑混入既有项目。

### 1.5 冲突与风险

- **结论**：有，见下列
- **说明**：  
  - **风险 1：渠道不区分会直接导致方案错误**。Shopify（官网） 和 APP商城 的目标展示形式不同，一个是 `discount`，一个是直降活动。  
  - **风险 2：APP商城 冲突规则复杂**。APP商城 若已有同类型、同 SKU、时间重叠的划线价活动，源优惠活动跟随转直降后会直接冲突；若后续业务希望自动化处理，必须额外设计拆分或重建方案。  
  - **风险 3：源字段完整性不足**。若 Amazon 同步数据缺少原价、优惠值、时间等关键字段，会直接影响官网 `discount` 活动和 APP 直降活动生成。  
  - **风险 4：购买折扣门槛识别错误**。若系统不能准确区分“无门槛购买折扣”和“有门槛购买折扣”，会导致不支持场景被误创建。  
  - **风险 5：SKU 映射与样例数据问题**。SKU/MSKU/编码映射异常会直接影响跟随准确性。  
  - **风险 6：通知语义存在歧义**。当前 `待跟随` 实际含义是“内部活动已生成，待人工推送到平台”，且两个渠道的推送目标不同，通知模板必须明确区分。  
  - **风险 7：当前项目已在测试**。若把这次优惠活动跟随需求混入当前一期，会扩大测试与发布风险。
