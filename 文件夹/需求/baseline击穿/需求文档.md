# 需求文档（Baseline 击穿）

**需求名称**：Baseline 击穿监控（成交价档位匹配与低价天数校验）  
**文档版本**：v1.1  
**依据**：同目录 `会议`（全渠道促销系统建设会议记录）及本期确认的 Baseline 规则口径；与「全渠道价格一致性」项目在预警展示（日期、价格、原因易懂）上对齐。

---

## 一、需求概述

- **一句话**：按**自然日**取 SKU 成交价，在**自然月**内与 Baseline **多档价格**匹配，分别累计各档「低价执行天数」；若**低于大促价**或任一档**超允许天数**，则**立即**推送预警。校验窗口为**未来 2 个自然月**，粒度为 **SKU + 国家/站点 + 月份**。
- **涉及模块**：Baseline 监控 / 价格合规预警；依赖 Baseline 配置、成交价取数、SKU 与站点主数据。
- **与会议的关系**：会议侧强调预警需标清**日期、价格、原因**、多档独立累计、重点 SKU 双源对比等；**本期文档以 Baseline 击穿规则与界面收敛为准**；规划周期（60 天锁定 + 30 天滚动）、渠道差异化取数等仍可作为全渠道促销主项目的关联依赖，在「关联背景」中保留摘要。

---

## 二、核心逻辑（Baseline 击穿）

**主链路**：按天计算成交价 → 按月匹配 Baseline 档位 → 校验低价天数是否超限 → 触发预警。

- **成交价**：以业务确认的「当日实际成交/展示口径」为准（与取数链路一致）。
- **档位**：与大促价、Deal 价、日销价、RRP 等配置对应；**无 Baseline 配置的不参与校验、不触发预警**。

---

## 三、档位匹配与校验顺序

**价格优先级（从低到高）**：大促价 ＜ Deal 价 ＜ 日销价 ＜ RRP。

校验时**按下列顺序**判断当日落在哪一档的「低价区间」，并计入**当月**对应类型的累计天数（各档天数**分别统计**）。

### 3.1 大促价档位

1. 若配置了「大促价最大天数」且该值 **大于 0**，且 **当日成交价 ＜ Baseline 大促价** → **直接**触发 **「超低价预警」**（不再依赖天数上限）。
2. 若 **Deal 价 ＞ 当日成交价 ≥ 大促价** → 记为 **「大促低价日」**，**当月**累计大促低价天数。
3. 若 **当月累计大促低价天数 ＞ 大促价最大天数** → 触发 **「大促低价超期预警」**。

### 3.2 Deal 价档位

1. 若 **日销价 ＞ 当日成交价 ≥ Deal 价** → 记为 **「Deal 低价日」**，**当月**累计 Deal 低价天数。
2. 若 **当月累计 Deal 低价天数 ＞ Deal 价最大天数** → 触发 **「Deal 低价超期预警」**。

### 3.3 日销价档位

1. 若 **RRP ＞ 当日成交价 ≥ 日销价** → 记为 **「日销低价日」**，**当月**累计日销低价天数。
2. 若 **当月累计日销低价天数 ＞ 日销价最大天数** → 触发 **「日销低价超期预警」**。

### 3.4 与区间边界相关的说明

- 当日成交价 **≥ RRP** 或落在未配置区间时，不计入上述「低价日」。
- 「**大于 0**」的天数配置：用于区分「该档不设天数上限」与「设了上限」；与「超低价」分支配合时，以产品最终配置表为准（若某档未配置最大天数，需明确默认行为：**不统计 / 不预警** 或 **等价于无上限**，由研发与业务书面确认后固化）。

---

## 四、执行范围

| 项 | 说明 |
|----|------|
| **校验周期** | **未来 2 个自然月**（按日滚动推进，每月重新累计各档天数）。 |
| **统计维度** | **SKU + 国家/站点 + 自然月**。 |
| **预警时机** | 满足**任一**档位的**超低价**或**低价超期**条件时 **立即**推送预警（无需合并多条再延迟）。 |

---

## 五、边界说明

1. **价格优先级**：大促价 ＜ Deal 价 ＜ 日销价 ＜ RRP；档位判断时与第三节顺序一致。
2. **跨月促销**：按**自然日**归属到对应**自然月**，**分别**统计各月低价天数（不跨月合并）。
3. **无 Baseline 配置**：该 SKU+站点组合**不触发** Baseline 击穿类预警。
4. **成交价缺失**：是否视为违规、是否阻塞累计，由取数与风控策略**单独约定**（建议与研发/数据对齐后写入配置说明）。

---

## 六、界面与交互改动（本期）

### 6.1 原界面收敛

- **移除**：**价格监控**、**天数监控** 入口按钮（不再在 Baseline 相关主流程提供独立按钮跳转或开关）。
- **移除**：**批量操作** 按钮（原批量导入/批量处理等统一从本界面下线；若购物车丢失清单等能力迁至其他菜单，以产品最终信息架构为准）。

### 6.2 Baseline 监控看板

- **列表/总览**：**仅展示详情入口或详情所需摘要**，**不再展示「击穿的具体信息」长文案或展开块**（如逐条复述击穿规则、多段解释性文案等）。
- **标红规则**：**仅对「触发击穿的日期」所对应的「价格」**做红色高亮（或等价强调样式）；其余列默认不借「击穿」语义整行标红，避免与详情重复、干扰扫读。
- **与会议一致**：详情或下钻中仍应能让人看懂 **日期、价格、预警类型/原因**（会议：易懂）。

## 七、字段与数据依赖（摘要）

| 概念 | 说明 |
|------|------|
| 成交价（日） | 按 SKU+站点+自然日 取数 |
| Baseline 档位价 | 大促价、Deal、日销、RRP 等配置 |
| 各档最大天数 | 按月对比累计天数 |
| 预警类型 | 超低价、大促低价超期、Deal 低价超期、日销低价超期（枚举以系统为准） |

**依赖**：Baseline 规则表、成交价明细或日汇总、SKU/站点主数据。

---

## 八、验收要点

- [ ] **档位判断**：同一日成交价仅落入一档低价统计，且与价格优先级、第三节顺序一致。
- [ ] **跨月**：促销跨自然月时，各月天数独立累计正确。
- [ ] **超低价**：成交价低于大促价时立即预警（在大促价最大天数＞0 的前提下与配置一致）。
- [ ] **超期**：各档累计天数超过最大天数时触发对应超期预警。
- [ ] **无配置**：无 Baseline 时不误报。
- [ ] **范围**：仅对未来 2 个自然月内日期校验（边界日含否以产品为准并写清）。
- [ ] **界面**：价格监控/天数监控/批量操作按钮已移除；看板不展示击穿具体信息长文案；**仅触发日对应价格**标红。

---

## 九、关联背景（会议摘录，非本节规则正文）

- **预警可读性**：超天数、破底价、日历与执行不一致等场景，展示需含**日期、价格、原因**（会议）。
- **规划周期**：全渠道促销侧 **60 天锁定 + 30 天滚动**（会议）；与 Baseline「未来 2 月」校验窗口并存时，各自职责需在信息架构或 PRD 总册中区分。
- **渠道与数据源**：购物车丢失清单 SKU、商超导入、官网跟随、导入 vs 抓取对比等（会议）——若影响**成交价来源**，需在取数映射表中体现，**不改变**第三节数学规则本身。
- **里程碑参考**：4 月底启用、试跑与缺陷修复节奏等以项目排期为准（见 `会议` 全文）。
