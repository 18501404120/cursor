# 清库存需求预警 — 系统方案（配置化）

| 项 | 内容 |
| --- | --- |
| 版本 | v0.1 |
| 日期 | 2026-08-27 |
| 状态 | 方案稿，供评审 |
| 依据 | 钉钉《库存管理机制——终版》；评审后收敛为「风险与手段分离」 |
| 目标系统 | 销售 / Forecast / 库存计划（预警工作台 + 规则配置） |

---

## 1. 一句话

系统每天按 **店铺 + SKU** 计算未来各周覆盖天数（DOS）和库龄，用**可配置规则**点灯（断货 / 积压 / 采购逾期 / 季节），再用**可配置动作阶梯**给出此刻该做的事。运营改阈值、档级、空运闸，**不改代码**。

业务原文是一棵按周复制的决策树。本方案不把树写进代码，只保留它的判断顺序：

> 用预测覆盖天数判断风险，用商品档级决定能忍断还是能忍积压，用物流时效决定此刻允许花多贵的钱。

---

## 2. 设计原则

| 原则 | 落地 |
| --- | --- |
| 风险与手段分离 | 同一 SKU 的灯不随「第几周」变来变去；变的只是该周允许的动作 |
| 全部阈值进配置 | 档级、DOS 分档、库龄、物流时效、动作条件、空运闸、季节日历、关闭规则均可配 |
| 闭区间、无空洞 | 端点必须有归属；库存用 `≤0` 视为无货 |
| 多灯并行 | 断货、积压、采购逾期、季节互不互斥，可同时亮 |
| 下周恢复只降级 | 下周 DOS 回到安全线下限以上，最多降一档，不能撤灯 |
| 规则版本化 | 每次发布生成规则包版本；历史预警绑定当时版本，可复盘 |
| 先建议后执行 | 一期只出预警 + 建议动作 + 跳转在途表；空运/调拨/调价不自动下单 |

---

## 3. 系统边界

### 3.1 做

- 按配置计算未来 N 周 DOS、库龄结构、采购交期偏差
- 生成 / 更新 / 关闭预警单
- 给出推荐动作、缺口件数、覆盖天数、费用估算（有数据则算）
- 规则配置、试算、发布、回滚
- 通知责任人（企微 / 钉钉 / 站内，按配置）

### 3.2 不做（一期）

- 不替代物流计算器、智能补货、定价系统
- 不自动创建空运单、调拨单、采购单（二期再对接工单）
- 不改 Forecast 审核流；DOS 只用已审核预测（预测源可配）

## 4. 核心对象

```text
规则包 RulePack（版本号、生效时间、范围：站点/店铺/品线）
 ├── 档级策略 TierPolicy          P0/P1/P2 的 A/B 与断货分档
 ├── 积压策略 StagnationPolicy     库龄带 + DOS 过高
 ├── 物流手段 LogisticsMethod      空运/卡航/普船时效
 ├── 动作阶梯 ActionLadder         提拉→调拨→控价→空运→…
 ├── 空运闸 AirGate
 ├── 采购异常 PoPolicy
 ├── 季节日历 SeasonalCalendar
 └── 生命周期 AlertLifecycle

预警单元 AlertUnit = 店铺 + SKU（可扩展仓节点）
周快照 WeekSnapshot = 该单元在 WK0…WKN 的库存、预测、DOS、可达物流
预警单 Alert = 信号类型 + 最高等级 + 最早危急周 + 推荐动作 + 规则版本
```

粒度默认 **店铺 + SKU**。同一 SKU 多店铺分开算（FBA 库存不混）。若后续要「站点汇总」（如泛欧），用配置 `aggregation: shop | marketplace | region`，不改引擎。

## 5. 计算口径（引擎写死公式，阈值全部可配）

### 5.1 DOS

```text
DOS(N) = 第 N 周可售库存 / 第 N 周日均预测销量
第 N 周可售库存 = 当前可售
                 + 预计在第 N 周开始前到达的在途（含已提拉）
                 − 从今天到第 N 周开始前的预测消耗
日均预测销量 = 第 N 周预测销量 / 7
```

- 预测销量 = 0：DOS 视为「不可计算」，打数据质量灯，不断货也不积压。
- 可售库存 `≤0`：DOS = 0，走断货最高档（若该档级配置了断货带）。
- 「一周 7 天」只是日历长度，**不是安全线**。安全线是档级上的 A / B。

### 5.2 库存桶（用于动作条件）

| 桶 | 口径（一期建议） |
| --- | --- |
| 海外在库 | 目标店铺 FBA 可售（可配是否含预留/不可售） |
| APP 海外 | 同区域其他店铺 / APP 仓可调拨库存，按现有调拨规则可调部分 |
| 国内在库 | 国内成品可调拨（扣已被 shipment 占用部分，避免重复发运） |
| 国内其他渠道 | 国内其他店铺/渠道可借部分 |
| 在途 | 头程在途 + 采购在途，按 ETA 落入对应周 |

具体表与字段与现有 Forecast / 海外在途 / 库龄看板对齐，上线前与数据确认一张取数清单。

### 5.3 库龄

按 FIFO 批次：给出「库龄 ≥ X 天的件数」。比较「超龄件数」与「海外在库件数」：

- 超龄件数 ≥ 海外在库 → 海外 + 国内都有积压嫌疑（灯上打标 `scope=overseas_and_domestic`）
- 超龄件数 < 海外在库 → 仅海外（`scope=overseas`）

## 6. 引擎流程

每天（可配时点，默认 07:00）对范围内每个预警单元：

```text
1. 取规则包（按店铺/站点命中最新已发布版本）
2. 投影未来 horizon_weeks 周库存与 DOS
3. 对每一周独立打灯：
     断货灯 = 用 DOS(N) 匹配档级分档
     若 DOS(N+1) > A：断货灯降一档（配置 recovery.downgrade_levels，默认 1）
     积压灯 = DOS(N) > B 与库龄带独立计算后取更严者（可配是否要求 DOS>B 才看库龄；默认否，库龄单独亮）
     物流窗口 = (该周起始日 − 今天) 落入哪条 LogisticsMethod.lead_time
4. 单元级断货灯 = 未来 focus_weeks（默认 8）内最严重的一周
   危急周 = 同等最高等级里最早的一周
5. 按动作阶梯从便宜到贵，找第一条同时满足：
     - 该动作允许的最低风险 ≤ 危急周断货灯
     - 该动作要求的物流手段在危急周可达（或动作不依赖物流）
     - 库存/利润/审批谓词为真
6. 采购逾期、季节日历另算，生成独立信号（可挂在同一预警单的子信号上）
7. 有灯则 upsert 预警单；连续 close_stable_runs 次全灭则自动关闭
```

空运用「危急周是否落在空运可达窗口」判断，**禁止**把欧洲 WK4–8 写死在代码里。物流计算器有值用计算器，没有用规则包里的 fallback 天数。

## 7. 配置模型（产品可配、研发只解释）

配置按 **规则包** 发布。界面分组与下列对象 1:1。完整默认值见同目录 `规则配置示例.json`。

### 7.1 档级策略 `tiers[]`

每个档级一张闭区间表。代码禁止再用 `A-7 / A-14 / A-21` 推导（原文 P1/P2 会算出负 DOS）。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| code | string | P0 / P1 / P2 |
| match | object | 如何命中：产品定位字段 / 手工标签 / SKU 名单 |
| healthy_min_days | number | 安全带下限（含），即 A+ε 的闭区间写法：P0=22 表示 DOS≥22 才算健康 |
| healthy_max_days | number | 安全带上限（含），即 B |
| stockout_bands | array | `{level, min_days, max_days}`，level = high/mid/low，区间左闭右闭，互相不重叠、拼满 `(0, healthy_min-1]` |
| prefer_stockout_over_stagnation | bool | P2 为 true：积压带更紧，断货允许更早发生 |
| recovery | object | `{compare: "next_week_dos_gt_healthy_min-1", downgrade_levels: 1}` |

**P0 默认（对应原文 21 / 35，改为闭区间）：**

| DOS（天） | 灯 |
| ---: | --- |
| 0～7 | 高断货 |
| 8～14 | 中断货 |
| 15～21 | 低断货 |
| 22～35 | 健康 |
| ≥36 | DOS 过高（积压候选） |

**P1 默认：** 高 0～7，中 8～14，健康 15～28，过高 ≥29。无「低断货」档（A=14，低于 A 只分高/中）。

**P2 默认：** 高 0～7，健康 8～21，过高 ≥22。无中/低断货（宁愿断货不可呆滞）。

SKU 未命中任何档级：走 `default_tier`（默认 P1），并记数据质量提示。

### 7.2 积压策略 `stagnation`

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| age_bands | 见下 | 与 DOS 过高独立 |
| require_dos_over_healthy | false | false=老货即使 DOS 低也亮积压灯 |
| deadline_days | 180 | 处理死线 |

| 库龄（天） | 灯 | 建议动作代码 |
| ---: | --- | --- |
| 0～119 | 销速异常（仅当 DOS 过高时） | REVIEW_REPLENISH |
| 120～149 | 中呆滞 | PROMOTE_HIGH_MARGIN |
| 150～179 | 高呆滞 | CLEARANCE |
| ≥180 | 已超期 | FORCE_CLEARANCE |

### 7.3 物流手段 `logistics.methods[]`

| 字段 | 说明 |
| --- | --- |
| code | PULL / AIR / RAIL / SEA |
| name | 提拉在途 / 空运 / 卡航 / 普船 |
| lead_time_source | `calculator` 或 `fallback_days` |
| fallback_min_days / fallback_max_days | 计算器无值时的窗口 |
| pull_max_days | 提拉上限（原文 7 与 14 打架，默认取计算器；fallback=7） |

匹配：`week_offset_days` 落在 `[min, max]` 则该手段「可达」。一周可命中多个手段时，动作阶梯自己选最便宜的。

欧洲示例如下，**仅作规则包默认值，按站点复制改**：

| 手段 | fallback 窗口（距今天） |
| --- | --- |
| 仅现货/调拨/控价 | 0～27 天（空运不可达） |
| 空运 | 28～56 天 |
| 卡航 | 57～70 天 |
| 普船 | ≥71 天 |

### 7.4 动作阶梯 `actions[]`（核心可配）

按 `cost_rank` 从小到大尝试，命中第一条即推荐。每条动作是「谓词 + 产出文案」，不是硬编码 if-else。

通用谓词（配置里用表达式，引擎提供函数）：

| 谓词 | 含义 |
| --- | --- |
| `severity_in` | 断货灯属于所列等级 |
| `method_reachable` | 危急周可达该物流手段；`none` 表示不依赖头程 |
| `inv.app_overseas > 0` | APP 有可调拨 |
| `inv.domestic > 0` | 国内有可发 |
| `next_week_recovered` | DOS(N+1) ≥ 档级 A（即 healthy_min-1 的开/闭与档级配置一致，P0 为 >21 即 ≥22） |
| `air_gate_pass` | 见 7.5 |
| `not_in_campaign` | 不在秒杀/大促窗（控价用） |

**默认阶梯（对应原文手段，只写一次）：**

| rank | 代码 | 何时建议 | 产出 |
| ---: | --- | --- | --- |
| 10 | PULL_INBOUND | 任意断货灯，且有更晚在途 | 提拉件数、跳转在途跟进 |
| 20 | TRANSFER_APP | 下周未恢复，且 APP>0 | 调拨件数、调后覆盖天数；高风险时限=当天，中=7 天，低=建议 |
| 30 | PRICE_CONTROL | 下周未恢复，且 APP≤0 | 停促/调回原价；排除活动期 |
| 40 | AIR_SHIP | 高断货 + 空运可达 + air_gate | 空运件数、费用、利润 |
| 50 | RAIL_SHIP | 高断货 + 卡航可达 + 空运未过闸 | 卡航件数与差价 |
| 60 | TRANSFER_DOMESTIC | 国内≤0 但其他渠道有货 | 借货件数 + 再走空运/卡航 |
| 70 | NEW_PO | 远周缺口且国内与在途都不够 | 建议补采购量 |

时限 `sla_hours` 也可配：high=24，mid=168，low=0（仅建议）。

远周国内有货：**按缺口加发**（动作 SEA_REPLENISH），禁止「有货即无预警」。缺口 =

```text
gap_qty = max(0, (A − DOS_危急周) × 日均预测)
```

### 7.5 空运闸 `air_gate`

原文既要保海运比、又要空运救货。做成必须同时满足的配置项：

| 条件 | 默认 |
| --- | --- |
| 断货灯 | 仅 high |
| 下周未恢复 | true |
| 空运可达危急周 | true |
| 空运后边际利润 > 0 | true（算不出利润则转人工审批，不自动建议通过） |
| 审批角色 | 运营负责人（可配） |
| 海运比 | 事后监控指标，**不是**禁止空运的绝对闸；可配「本月空运件数上限」软约束 |

### 7.6 采购异常 `po_policy`

不要只看 WK12。

| 条件 | 灯 |
| --- | --- |
| 承诺交期 < today | 采购逾期 |
| 承诺交期 ≥ today，但 ETA 晚于「DOS 落到 A 之前必须到货日」 | 交期过晚（即使未逾期） |

严重度：若当时已有高断货，升级为 high，否则 mid。

### 7.7 季节日历 `seasonal`

季节品 `match` 命中后：

- 淡季：只跑日历点（配置日期列表）
- 旺季：`in_season_run_weekly_dos=true`（默认 true，修正原文「完全退出周机制」）

每个日历点：`{date, signal, compare: on_hand_plus_inbound vs remaining_fcs_to_season_end}`。

默认点（修正 11 月 31 日）：

| 日期 | 库存 > 剩余 FCS | 库存 < 剩余 FCS |
| --- | --- | --- |
| 09-01 | 销速异常 | 无 |
| 10-01 | 低呆滞 | 黑五低断货 |
| 10-12 | 中呆滞（申请黑五资源） | 黑五中断货 |
| 11-01 | 中呆滞 | 黑五中断货 |
| 11-30 | 高呆滞（圣诞清库） | 无 |
| 12-02 | 高呆滞 | 无 |
| 12-15 | 明年再卖 | 无 |

「总计库存」口径可配：默认 `海外在库 + 在途 + APP 可调`。比较对象统一为 **当天到季末的剩余已审核 FCS**。

### 7.8 生命周期 `alert_lifecycle`

| 字段 | 默认 |
| --- | --- |
| upsert_key | unit + signal_type |
| auto_close_after_stable_runs | 2 |
| close_when | 未来 `close_look_ahead_weeks`（默认 4）周断货灯全灭，且积压灯 < mid |
| reopen_policy | 关闭后再次点灯则新开单（保留历史单） |
| bind_rule_pack_version | true |

## 8. 功能模块与页面

### 8.1 预警工作台（主页面）

筛选：站点、店铺、档级、信号类型、等级、品线、负责人、是否有推荐动作。

列表字段：SKU、店铺、档级、断货灯、积压灯、采购灯、季节灯、危急周、DOS(危急周)、下周 DOS、APP/国内/在途、推荐动作、SLA、规则版本、状态。

操作：认领、处理反馈（已提拉/已调拨/已控价/已空运/忽略）、跳转在途跟进表、导出。

多灯在同一行用标签展示，点进去看时间轴。

### 8.2 预警详情

- 未来 16 周 DOS 折线 + 安全带（A/B 两条参考线）
- 各周可达物流手段
- 库存桶与库龄分布
- 推荐动作推导过程（命中了哪条配置、为什么跳过更便宜的动作）——便于运营信规则
- 处理记录

### 8.3 规则配置中心（配置化的产品形态）

Tab：档级、积压、物流、动作阶梯、空运闸、采购、季节、生命周期、发布。

要求：

- 保存为草稿 → 试算 → 发布（生成版本号）
- 发布前校验：断货带无重叠、无空洞；P2 不允许负区间；动作 rank 唯一
- 支持按站点复制规则包（欧洲默认 → 北美改时效）
- 权限：运营改草稿，负责人发布

### 8.4 规则试算

选店铺+SKU+规则草稿，跑一遍引擎，对比「现行已发布版本 vs 草稿」的灯和动作差异。没有试算不允许发布。

## 11. 分期

## 12. 与原文的对应关系（给业务对表用）

| 原文 | 本方案 |
| --- | --- |
| WK0–3 / 4–8 / 9–10 三棵复制树 | 一套动作阶梯 + 物流窗口谓词 |
| `14天<WKN<21天` | `stockout_bands` 的 DOS 闭区间，WKN 只表示周序号 |
| 下周 DOS>21 当没事 | `downgrade_levels=1` |
| 断货与呆滞 if-else | 两盏独立灯 |
| 空运写在高风险缩进里 | `AIR_SHIP` + `air_gate` |
| WK11+ 国内有货无预警 | `SEA_REPLENISH` 按缺口加发 |
| A-7 公式 | 每档级独立 `stockout_bands` |
| 季节退出周机制 | 淡季日历 + 旺季仍跑周 DOS |
| 11 月 31 日 | 11-30 |
| 提拉 7 天 vs 14 天 | `pull_max_days` 单字段，优先计算器 |
