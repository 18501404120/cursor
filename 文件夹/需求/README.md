# 需求管理说明

本目录用于存放**待评估或已评估的需求**。产品经理可将接到的需求（文档、一句话、截图等）放入此处，并借助 Cursor 生成**需求评估文档**，便于快速识别不合理项与不明确点，与提需方对齐。

## 使用方式

### 1. 新建一个需求文件夹

在 `需求/` 下新建子文件夹，建议命名：`需求-简短描述-日期` 或 `需求-来源方-日期`，例如：

- `需求-库存预警规则优化-20260317`
- `需求-采购部-补货看板-20260317`

### 2. 放入需求内容

将收到的需求放入该文件夹，形式任选其一或组合：

- **文档**：.md、.txt、.docx 等
- **一句话**：新建 `需求说明.txt` 或 `需求说明.md` 写清内容
- **截图**：放入图片文件，评估时可结合图片描述进行分析

### 3. 在 Cursor 中发起评估

在 Cursor 对话中说明需求路径并请求评估，例如：

- 「请评估 `文件夹/需求/需求-xxx` 下的需求，并生成评估文档」
- 「@文件夹/需求/需求-库存预警规则优化-20260317 帮我评估这个需求，把评估结果保存到同目录」

### 4. 获得评估文档与需求文档

评估完成后，在同一需求文件夹下会生成两个文件：

- **`需求评估.md`**：合理性评估、不明确点清单（含建议追问）、建议下一步；用于与提需方快速对齐。
- **`需求文档.md`**：**需求需要改动的点**的说明文档，包含：
  - 需求概述与涉及模块
  - 改动范围总览（新增/修改/删除）
  - 具体改动点：页面与入口、字段与数据项、筛选条件、业务逻辑与规则、数据来源与依赖、异常与边界
  - 验收要点、与现有能力的关系

可直接将「不明确点」用于沟通；将「需求文档」用于开发排期与 PRD 细化。

## HTML 原型在线预览（个人 GitHub）

1. 将本仓库 **`main`** 推送到个人 GitHub（远程示例：`https://github.com/18501404120/cursor.git`）。
2. 推送后 **GitHub Actions** 会将站点发布到 **`gh-pages`** 分支（工作流：`.github/workflows/pages.yml`）。
3. 仓库 **Settings → Pages**：发布源选 **Deploy from a branch**，分支 **`gh-pages`**，目录 **`/(root)`**。
4. 在浏览器打开：
   - **需求总入口**：[文件夹/需求/index.html](index.html)（在线：<https://18501404120.github.io/cursor/%E6%96%87%E4%BB%B6%E5%A4%B9/%E9%9C%80%E6%B1%82/index.html>）
   - **商超 3P · WFS 方案说明**：[商超3p需求/原型/WFS共享库存与自动借货-方案说明.html](商超3p需求/原型/WFS共享库存与自动借货-方案说明.html)

**本地预览**：在仓库根（含 `.git` 的 `方案设计` 目录）执行 `python3 -m http.server 8765`，访问 `http://localhost:8765/文件夹/需求/index.html`。勿用 `file://` 打开含脚本的页面。
