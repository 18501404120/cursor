# 泛欧业务 — 会议总结与需求背景

> 文档来源：`需求-会议内容`（会议逐字记录整理）  
> 说明：本文档归纳会议共识、问题与诉求，供后续 PRD / 排期引用；部分技术方案仍在迭代中，以最终评审结论为准。

---

## 一、会议内容摘要

本次会议围绕 **亚马逊泛欧（Pan-EU）业务** 下，**新店铺（尤其西班牙 ES 站点）无欧盟税号、只能依托泛欧售卖** 所引发的 **ERP / 计划 / 销售预测 / 库存展示与下推** 等一系列数据与流程问题展开讨论。业务方强调该模式自 2024 年起已常态化，并非短期试点；研发与计划侧则关注 **MSKU 唯一性假设被打破** 后，**库存重复展示、预测达成率失真、周转与备货口径、PSI 新流程衔接** 等改造范围与分期落地。

会议末段归纳了 **两类需求**：  
1）**预测与主店铺维度下的展示与下推**（含虚拟 SKU / 主店铺汇总等思路，第一版约 1～2 周量级需进一步设计确认）；  
2）**库存按站点（店铺+SKU）区分展示**，海外可按国家展示，国内与采购订单挂钩需分期；短期可通过 **SKU 库存归属（主店铺）** 配置、新店铺默认策略等缓解。

在系统能力未完全到位前，**计划侧需人工将德国与 ES 等站点的 forecast 加总备货**，业务方承诺补充 **需加总的 SKU 清单**；发运与新流程若未就绪，建议暂缓复杂泛欧场景下的欧洲发货自动化，避免 SKU 量大时失控。

---

## 二、需求背景（详细）

### 2.1 业务起因：新店铺与税号约束

- 公司存在 **多个新店铺**，其中 **西班牙（ES）代理店铺当前仅有本土税号，尚无欧盟税号**。取得欧盟税号周期较长（会议中提及约半年量级），**短期内无法按常规路径单独发货**。
- 在该约束下，ES 若要正常售卖，**只能以泛欧方式运作**：备货与实际发运仍主要依托 **德国等已有泛欧枢纽站点**（会议中多次以「德国 / 第一（D1）」为主店铺表述），订单可在 ES 成交，但物流与库存逻辑与「单国单仓单MSKU」不一致。

### 2.2 业务模式变化：从分国发货到泛欧常态化

- 业务方说明：**以往德、法、意、西多分开发货**；自 **2024 年起** 已大规模启用 **泛欧**，以降低尾程费用与多国管理成本。
- **ES 新店铺并非少量 SKU 试点**：只要在 ES 店能售卖的链接，**均可能以泛欧方式跑**，量级可达 **百级 SKU**，且 **持续周期至少约半年**，对计划备货、库存认知、系统展示的一致性要求显著提高。
- 未来部分店铺恢复税号后可能 **部分恢复分国备货**，但 **泛欧作为长期存在业务模式** 不会消失；部分 SKU 仍会以德国为主，也可能 **以法国等为「附体 / 主发运国」**（泛欧可从多国之一入仓再泛到其他国），故 **主店铺不能写死为德国**，需可配置。

### 2.3 核心矛盾：共享库存与「MSKU 唯一」假设冲突

当产品开启泛欧后，**多个站点可能共用同一套库存逻辑（会议中称为共用 MSKU / 共享库存）**，导致当前系统出现典型问题：

1. **库存展示重复**  
   同一实物库存被 **多个站点下的 MSKU 同时展示相同数量**（例如调拨成功后德、法、意、西均显示同一数值），计划侧难以判断 **真实可用库存是一份还是多份**，存在 **超备或少备** 风险。

2. **预测（forecast）与达成率**  
   若仅按德国站点预测与考核，**未计入 ES 等站点的销量与预测**，会导致 **预测达成率偏低**；业务需要 **分站点看预测与准确率**，但备货与发运又希望 **收敛到主店铺（如德国 MSKU）** 执行。

3. **周转天数与 PSI / 计划下推**  
   国内库存若无法按站点拆分，则 **分站点周转** 难以精确计算；若库存全部挂在德国，**单看德国站** 可能出现 **周转「虚高」或展示异常**，需考虑 **汇总口径**（总量）与 **分站点 forecast** 的并存方式。会议中提到 **PSI（及前置的销售市场预测 forecast）** 会受影响，需与新流程、配置表（主店铺关联多 MSKU）等衔接。

4. **财务与报表维度**  
   讨论中提到：**财报有站点维度**，亚马逊侧 MSKU 可相同，但 **核算与报告仍按店铺/站点**；销售报告与财务报告取值口径需区分，**部分结论为「店铺级报告可不改」**，但业务仍关注 **订单出货、成本归集** 与站点一致性。

### 2.4 业务侧诉求（问题陈述，非最终方案）

1. **泛欧 SKU 在德国（或配置的主店铺）MSKU 上主展示**，支持 **展开查看各子站点 MSKU 的 forecast**；**不强调分站点展示大仓库存准确度**（因大仓库存反馈有时不准），但需 **分站点预测达成率** 等，以支撑备货与运营判断。

2. **库存展示逻辑**：希望 **按「店铺 + MSKU」区分**，避免「MSKU 全局唯一」带来的误导；入库与展示尽量 **以主店铺 MSKU 为锚**，其他站点可为 **展示用镜像或默认不记库存**（与现有「SKU 库存归属 / 主店铺」能力衔接）。

3. **计划与备货**：  
   - 预测仍希望 **分站点维护**（德、法、意、西、ES 等各是多少），下推到计划层时 **汇总到主店铺 MSKU** 做 **采购 / 备货建议**，避免计划在同一库存上重复决策。  
   - **ES 新店铺** 场景下，采购订单需 **下在德国（或对应主店铺）MSKU** 上（会议明确：西班牙新店铺采购要落在德国 MSKU）。  
   - 在系统未自动加总前，**请计划人工将德国与 ES 的 forecast 加总** 再备货；业务方将 **书面列出需加总规则与 SKU 范围**。

4. **发运与流程**：泛欧下 **实际发货可能仍从德国走**，但订单店铺为 ES；需与 **新发货流程、35 天生产周期** 等现实约束对齐。在 **虚拟 SKU / 汇总逻辑** 未上线前，**不建议贸然启动复杂的欧洲发货自动化**，以免 SKU 数量大时无法运维。

### 2.5 产品与技术侧回应要点（会议共识方向）

1. **已有能力**：销售系统中存在 **SKU 库存归属（主店铺）** 配置；相同 MSKU 多店铺时可指定 **库存归集到的主店铺**。新店铺若未配置，需 **运营/行政补配置**；可讨论 **新店铺默认策略**（如默认仅主店铺记库存、其余不记库存）。

2. **分期思路**  
   - **第一版**：允许在 ES 等站点 **建 forecast**，下推逻辑可先 **仍按主店铺（如德国）推计划**；**forecast 准确率页面** 可按站点展示预测准确情况；**不动大库存拆分底层**。  
   - **第二版**：评估 **虚拟 SKU** 或 **中间汇总层**（类似商超/零售商客户汇总下推思路），将多站点 forecast **汇总到主 MSKU** 供备货，实际填单仍在各店铺，**展示层汇总、执行层仍落主 SKU**。

3. **库存分站点**  
   - **海外库存**：可按 **国家/站点** 展示。  
   - **国内库存**：难以自动拆到各站点，**可按采购订单归属** 打到子 SKU（第二版方向）；第一版可先 **全部展示在主 SKU**。

4. **周转展示**：若预测分站点、库存集中在主站，**单站点周转可能异常**；可讨论 **按配置汇总销量 + 总库存** 算「汇总周转」或提示异常区间，尤其 **未来半年** 内 ES 大批量场景。

5. **工期与并行**：开发评估 **虚拟/汇总方案** 开发约 **1～2 周** 量级，但需先 **梳理数据点**；业务 **备货节点（如月中）** 紧迫，**短期内以人工加总与配置补全为主**。

### 2.6 风险、依赖与待办（背景中的约束）

| 类型 | 说明 |
|------|------|
| 数据准确性 | 库存重复展示直接导致多备/少备；需主店铺配置、默认规则与 possibly 数据清洗（错误库存标 0 / 备注）。 |
| 流程依赖 | 新 PSI / 销售 forecast 前置链条与现网 forecast 并行，需明确 **哪些 MSKU 走新流程**（会议提及分阶段、首批约 30 个产品等说法，以业务最终清单为准）。 |
| 权限 | 业务方反馈 **无编辑 SKU 归属权限**，需 IT/销售系统侧开通或代配置。 |
| 书面输出 | 业务方承诺输出 **需加总 forecast 的 SKU 规则与清单**（尤其 **带 ES 的与德国加总**，其他法意西按是否泛欧再定）。 |
| 范围扩大 | 不仅 ES，**法意西大量 SKU 已泛欧**，后续改造需按 **长期架构** 规划，避免只打补丁。 |

### 2.7 会议中涉及的两类需求（便于立项引用）

1. **需求一（预测 / 主店铺 / 准确率 / 下推）**  
   在泛欧与多站点 MSKU 并存前提下，支持 **分站点 forecast 与达成率可见**，计划侧 **汇总备货**（系统自动化分期实现），并与 **PSI、主店铺配置表** 协调；含 **虚拟 SKU 或汇总展示** 的第二版设想。

2. **需求二（库存展示 / 店铺+SKU）**  
   **库存区分站点与主从展示**，避免重复；海外按国家；国内分期按采购订单归属；短期 **统一展示在主 MSKU** 并依赖 **SKU 库存归属** 与新店默认策略。

## 三、术语与口误说明（便于读原文对照）

记录为语音识别或口语习惯，整理时采用业务常用写法：

- 「泛欧」「范围」多指 **Pan-European FBA / 泛欧库存共享**。  
- 「第一」「D1」「b」等多指 **德国站点 / 主店铺**。  
- 「复体」「附体」指 **主展示 / 主承载的 MSKU 或主店铺**。  
- 「focus / forecast」均指 **预测**。  
- 「库帕斯」疑为 **备货** 或相关计划术语。  
- 「MSQ / MIQ」结合上下文多指 **MSKU** 或 listing 维度标识。  
- 「十三」「194」「H1310」「S1310」等为会议举例 SKU，**以业务最终清单为准**。
