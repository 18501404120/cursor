# 需求评估文档

**评估时间**：2026-03-17  
**需求来源**：成品库龄看板增加未来预计呆滞字段  
**原始需求摘要**：在 ERP 成品库龄看板中增加「未来某日预计呆滞」相关计算与展示：基于当前呆滞、预计转呆滞、forecast 消耗推导未来剩余呆滞及占比（D/G）；需支持按「未来日期」筛选、按「已审核/待审核 forecast」切换、按「负责人」筛选。

---

## 一、合理性评估

### 1.1 业务价值

- **结论**：合理
- **说明**：直接支撑**库存健康度与呆滞料分析**场景。提前看到「未来某日预计呆滞」便于计划/供应链做调仓、促销、清仓决策，减少资金占用与呆滞恶化，与 ERP「库存中心 + 数据中心」中「呆滞料分析、库存预警」主线一致，符合产品经理定位中「库存周转、呆滞料、库存健康度」等提升方向。

### 1.2 与现有能力契合度

- **结论**：契合
- **说明**：归属 **库存与仓储管理**、**数据与大屏** 模块；在现有「成品库龄看板」上做字段与筛选扩展，不新增独立系统。需与现有库存维度（多仓、多 SKU、批次/效期）及 forecast 数据源对齐；若看板已支持多仓/负责人，本需求为同界面增强，兼容多仓、多平台发货场景即可。

### 1.3 可行性

- **结论**：有条件可行
- **说明**：  
  - **数据依赖**：依赖「当前呆滞 A、当前库存 E、预计可消耗 C（forecast）、预计可入库/在途 F」等；需明确 forecast 来源（哪个系统、已审核/待审核的取数逻辑）、刷新频率与时效。  
  - **计算逻辑**：公式已给出（D=A+B-C，G=E+F-C，预计呆滞=D/G），实现难度取决于 B「预计未来某日会转呆滞」的数据是否已有或需额外规则/模型。  
  - **性能**：按「未来某日」+ 多维度筛选可能涉及大表聚合，需约定数据量级与刷新策略（T+1 或准实时）。

### 1.4 范围与优先级

- **结论**：范围基本清晰，建议拆期以控制风险
- **说明**：  
  - **范围**：成品库龄看板新增字段与筛选（未来日期、forecast 类型、负责人）；公式中 B 若暂无现成数据，需与业务约定是首期用简化逻辑（如 B=0）还是同步做「转呆滞预测」规则。  
  - **优先级**：与「呆滞料分析、库存健康度」强相关，可归入数据/库存类迭代；若 forecast 与负责人数据就绪，可优先做 MVP（单 forecast 来源 + 已审核 + 负责人筛选），再扩展待审核、多 forecast 版本。

### 1.5 冲突与风险

- **结论**：无显性冲突，需注意数据口径与性能
- **说明**：  
  - 与现有「库存预警、呆滞分析」为互补关系，不替代既有库龄/呆滞报表。  
  - **风险**：forecast 与库存/在途数据口径不一致会导致 D、G 失真；「负责人」需与组织架构/库存责任人主数据统一，避免与权限、组织树冲突。  
  - 若 forecast 来自外部或未审核版本变动频繁，需约定展示说明（如「待审核 forecast 仅供参考」），避免误读为承诺。

## 二、不明确点清单（需与提需方对齐）

| # | 不明确点 | 建议追问 / 对齐方式 |
|---|----------|----------------------|
| 1 | **提出方与验收人** | 该需求由哪个部门/角色提出？验收人是谁？计划、供应链、财务是否需一起评审？ |
| 2 | **「负责人」口径** | 负责人指库存责任人、计划员、还是 SKU/品类负责人？与组织架构中的「负责人」字段是否一致？筛选维度是「按人」还是「按部门/小组」？ |
| 3 | **Forecast 数据来源与版本** | 已审核/待审核 forecast 分别从哪个系统、哪张表或接口获取？刷新频率（日/周）？多版本 forecast 时如何选版（如仅取最新已审核）？ |
| 4 | **「未来某日」范围** | 筛选日期是否限制范围（如仅支持未来 7 天/30 天/90 天）？默认展示「当前日+多少天」？ |
| 5 | **B「预计未来某日会转呆滞」** | B 当前是否有数据来源？若没有，首期是否接受 B=0 或用简单规则（如超 N 天未动销即计为转呆滞）？若需单独开发转呆滞预测，是否纳入本期范围？ |
| 6 | **成品维度与仓库范围** | 看板是否按「成品 SKU + 仓」粒度展示？是否覆盖全部成品仓（深圳/海外/FBA 等）还是先部分仓？ |
| 7 | **验收标准与示例** | 能否给 1～2 个「正确示例」：某 SKU 某未来日期的 D、G、预计呆滞占比的期望值或计算过程，便于开发与 UAT 对齐？ |
| 8 | **性能与刷新** | 数据是否允许 T+1 产出？若需近实时，当前 forecast/库存/在途的延迟要求是多少？ |
| 9 | **权限与可见范围** | 是否需按负责人做数据权限（只看本人负责的）？与现有成品库龄看板权限是否一致？ |
