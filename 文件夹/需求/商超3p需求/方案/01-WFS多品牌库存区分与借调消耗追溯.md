# 需求 01：WFS 多品牌库存区分与借调消耗追溯

> **来源**：`原始需求/会议1`（WFS库存管理、产品上架及促销规划讨论）  
> **会议主题**：WFS库存管理、产品上架及促销规划相关问题讨论

---

## 一、原始需求（用户表述提炼）

### 1.1 背景

- 成本测算后 **WFS 头程尾程最便宜**，备货策略转向 **尽量全部备到 WFS**。
- WFS **不能像 FBA 那样按店铺区分库存**，实物与账面均挂在 **沃尔玛店铺** 下。
- 当前 **三个品牌（及未来更多商超 3P 平台）共用同一 WFS 库存池**；各平台消耗尚少，靠 **人工找同事借调** 应对小 case，但规模扩大后 **超卖与监控难度** 会显著上升。

### 1.2 需求要点

| 编号 | 原始诉求 | 会议原话要点 |
|------|----------|--------------|
| R1-1 | **按品牌区分可用库存**，避免多品牌共用 WFS 时超卖 | 「三个品牌都共用 WFS 库存，怎么样去区分各品牌可能库存，避免超卖？」 |
| R1-2 | **借调与消耗可核算**：借调数量、对应消耗能拉出，用于头程/成本等算账 | 「需要把借调面板……借调的数以及对应的消耗数可以拉出来」 |
| R1-3 | **订单侧可追溯**：能识别某单 SKU 消耗的是「借调来的 WFS 库存」 | 「在订单中标识这一单的 SKU 消耗的是借调 WFS 库存的货」 |
| R1-4 | **履约维度可区分 WFS** | 若订单为 **WFS 履约**，履约方状态应能区分 WFS 仓发货（与会中「WS 履约」表述一致） |

### 1.3 提出方关注点

- **运营**：各品牌/平台卖多少、借多少心里有数，少靠口头和人工表格。
- **财务/成本**：WFS 账都在沃尔玛店铺下，需把 **借调消耗** 与 **实际销售消耗** 分开，否则头程与渠道成本算不清。

### 1.4 范围边界（会议隐含）

- 不指望 WFS 后台像 FBA 一样拆店铺库存（平台限制）。
- 区分与追溯希望在 **ERP（或订单链路）** 侧解决，而非改 WFS 物理库存结构。

---

## 二、问题与痛点

1. **账面集中、业务分散**：库存实体在 WFS，销售发生在沃尔玛、Best Buy、Lowes 等多店铺，缺少品牌维度的「逻辑库存」。
2. **借调无系统留痕**：现靠人工借调，借出、消耗、归还无法系统化对账。
3. **成本分摊困难**：无法回答「这一单用的是本品牌配额还是借调库存」。

---

## 三、解决方案

### 3.1 业务方案

1. **逻辑库存池（按品牌/店铺维度）**  
   - 在 ERP 建立 **WFS 共享池总量**（接口实时查 WFS 后台为准）+ **各品牌/子店铺逻辑配额**（可配置上限或比例，如 BBY 30%、Lowes 20%、预留沃尔玛 50%）。  
   - 销售、借调、调拨均扣减 **对应逻辑池**，总量不超过 WFS 实物可用（与需求 02、03 联动）。

2. **借调台账**  
   - 提供 **借调申请/审批/生效** 记录：借出方（逻辑池）、借入方、SKU、数量、时间、操作人。  
   - **消耗归集**：订单出库或 WFS 履约确认后，将消耗记入借入方或按规则冲销借调余额。

3. **订单标识**  
   - 订单行增加 **库存来源类型**：`本池` / `借调-{品牌}` / `WFS履约` 等（字段名以实现为准）。  
   - 与 **履约方=WFS** 的平台状态对齐，便于报表筛选。

4. **报表**  
   - **借调明细表**：借出、归还、在途。  
   - **借调消耗表**：按 SKU、品牌、期间汇总消耗，支持导出给成本分析。

### 3.2 系统方案（ERP）

| 模块 | 说明 |
|------|------|
| 主数据 | WFS 仓、共享池、品牌/店铺与逻辑池映射 |
| 借调单 | 创建、审批（可选）、与逻辑库存联动 |
| 订单扩展 | 履约类型、库存来源、关联借调单号 |
| 接口 | 定时/实时拉 WFS 库存作总量校验；订单仍走现有 Mirakl 等同步 |
| 报表 | 借调面板 + 消耗明细，支持按 SKU/品牌/月 |

### 3.3 与关联需求的关系

- **需求 02**：共享库存与超卖防控（平台可售数、预测砍量）。  
- **需求 03**：借调自助与实时校验（提高借调效率）。  
- 本需求侧重 **区分、台账、订单追溯**，不替代共享库存算法。

### 3.4 待澄清项

1. 「品牌」与「Mirakl 店铺 / 平台」映射表是否已固定？  
2. 借调是否需审批流，还是仅额度内自助？  
3. 消耗记账时点：推单、发货、还是 WFS 扣减回传？  
4. 历史人工借调是否需期初导入？

### 3.5 验收要点（建议）

1. 同一 WFS SKU 可查看 **各品牌逻辑可用量** 及 **共享池总量**。  
2. 完成一笔借调后，报表可查到 **借调记录**；对应订单可筛出 **借调消耗**。  
3. WFS 履约订单可按履约方/库存来源筛选，与平台状态一致（抽样核对）。

---

## 四、风险与依赖

- **WFS 接口能力**：仅能查总量时，逻辑池需内部强校验，与实物定期对账。  
- **多平台订单延迟**（约 10 分钟拉单）：逻辑池扣减时点需与需求 02 一致，避免重复扣或漏扣。  
- **依赖业务规则**：品牌配额、借调上限需运营书面规则（可与需求 07 沃尔玛规则文档一并整理）。
