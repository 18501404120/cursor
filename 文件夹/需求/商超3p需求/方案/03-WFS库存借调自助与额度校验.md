# 需求 03：WFS 库存借调自助与额度校验

> **来源**：`原始需求/会议1`

---

## 一、原始需求（用户表述提炼）

### 1.1 背景

- 多品牌/多平台共用 WFS 后，日常需 **从 WFS 池「借」库存** 给某店铺卖，目前 **找专人（如魏超）手动处理**，case 小尚可，规模化后 **效率低**。
- ERP 既有 **店铺间借调**（补仓库存扣减、加到目标店）逻辑，但 **WFS 仓无法像普通仓一样校验**，沃尔玛侧 **库存动不了**，名义上存在超卖风险仍要借。

### 1.2 需求要点

| 编号 | 原始诉求 | 会议原话要点 |
|------|----------|--------------|
| R3-1 | **商超 3P 专用借调功能**，减少找人手工借 | 「专门为三批做……日常手动借调，不用一直找后台」 |
| R3-2 | **借调前尽量系统校验**：实时查 WFS 库存，减去已借未还 | 「实时查 WFS 仓库存……减掉其他的已借……还能借多少」 |
| R3-3 | **规则化额度**：如 WFS 库存 30% 内可自助借 | 「小于 WFS 库存的 30%」 |
| R3-4 | **承认无法完全杜绝超卖**，先解决效率 | 「没办法解决实际超卖……只是方便平常借调」 |

### 1.3 与需求 01 的区别

- **需求 01**：借调 **台账 + 订单消耗追溯 + 品牌逻辑池**。  
- **本需求**：借调 **操作流程 + 额度校验 + 自助**，降低对人依赖。

---

## 二、解决方案

### 3.1 业务方案

1. **借调申请（自助）**  
   - 选择：借出逻辑池（默认 WFS 共享池）、借入店铺/品牌、SKU、数量。  
   - 系统展示：**WFS 实查可用**、**已借未消耗**、**本单建议可借上限**（min(规则比例, 实查−已借)）。

2. **校验规则（可配置）**  
   - 单次借调 ≤ WFS 可用 × 30%（会议示例，可改）。  
   - 借入方逻辑池 + 本次 ≤ 借入方上限。  
   - 可选：需审批超过阈值部分。

3. **执行与同步**  
   - 通过后：更新 **逻辑库存**（需求 01）；若仍需人工在 Mirakl 改可售，生成 **待办清单** 或 API 自动改（依赖接口）。  
   - **不承诺** 替代 WFS 物理移库（平台无仓调拨 API 时仅逻辑层）。

4. **与存量借调功能关系**  
   - 复用 ERP **店铺借调** 框架，扩展 **货源类型=WFS**、校验源改为 WFS API。

### 3.2 系统方案

| 功能 | 说明 |
|------|------|
| 借调单 | 类型=商超3P-WFS；状态：草稿/已生效/已消耗/已关闭 |
| 库存查询 | 调用 WFS 库存接口（与会中「实时查后台」一致） |
| 额度引擎 | 比例上限 + 已借汇总 + 可选审批 |
| 权限 | 品牌运营自助；超额审批角色 |

### 3.3 待澄清项

1. 借调生效后 **Mirakl 可售数** 是否必须自动加，还是仅 ERP 逻辑层。  
2. 已借数量 **消耗冲销** 规则（与需求 01 订单标识联动）。  
3. 是否保留「完全人工、系统只登记」模式兼容历史。

### 3.4 验收要点（建议）

1. 运营可在 ERP 发起借调，**无需找后台同事改数**（在 API 支持范围内）。  
2. 借调数量 **超过可借上限时阻断** 并提示原因。  
3. 借调记录可在 **借调面板** 查询，与需求 01 报表一致。

---

## 四、风险与依赖

- **WFS API 只读**：仅能校验总量，无法阻止沃尔玛侧继续售卖。  
- **与需求 02 冲突**：借调增加子店可售会加剧超卖风险，需联动共享库存规则。  
- **人工借调无校验的历史数据**：期初需盘点或一次性锁定。
