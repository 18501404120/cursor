# 需求 08：促销分段维护提醒与 Mirakl 促销 API 调研

> **来源**：`原始需求/会议1`

---

## 一、原始需求（用户表述提炼）

### 1.1 子需求 A：促销分段维护提醒（Notes / BVI 等）

| 编号 | 原始诉求 | 会议原话要点 |
|------|----------|--------------|
| R8-A1 | 同价促销 **不能预设两段**，只能第一段结束后 **再设第二段** | 「两个阶段价格一样的，就没法设置两个阶段」 |
| R8-A2 | **促销结束提醒**，便于及时维护下一段 | 「促销结束了告诉你一下」「结束那天通知……今天可以开始维护下一个时间计划」 |
| R8-A3 | 提醒时点：**活动结束日** 且须考虑 **结束后次日才能改价**（平台限制） | 「结束当天给你发信息没用……结束了以后立马提醒」 |
| R8-A4 | 也可考虑 **新促销开始前一日** 提醒（与结束提醒二选一或并存） | 「抓每一段促销第一天……或前一天」 |

**背景**：运营需 **每天盯日期**，否则漏设下一段价格；沃尔玛虽可 **一月多段预设**，但亚马逊侧仍有 **分段维护** 痛点，Notes/BVI 店铺尤甚。

### 1.2 子需求 B：Mirakl / 沃尔玛促销与价格 API

| 编号 | 原始诉求 | 会议原话要点 |
|------|----------|--------------|
| R8-B1 | 调研 **Mirakl 是否支持 API 改价/创建 Promotion** | 「改价格……通过 API」「研究一下有没有更省事的方法」 |
| R8-B2 | 沃尔玛侧存在 **update promotional price / create promotion** 类接口，期望 **批量设置 batch** | 「可以自动帮我们设置 promotion……不用一个个改」 |
| R8-B3 | 区分 **改价** vs **做活动**；Lowes 等可能 **无促销 API**，仅价格维护 | 「不是改价，是做活动、做 promotion」 |
| R8-B4 | 100+ SKU **手工维护恐怖**，若 API 可行可显著降本 | 「每一个维护……好恐怖」 |

**约束**：沃尔玛平台 **自动同步亚马逊价** 不可靠，业务 **坚持自维护**；API 价值在 **执行已排好的计划**，非替代排期逻辑（排期见需求 06、07）。

---

## 二、解决方案

### 2.1 子需求 A：促销结束/开始提醒

**业务方案**

1. 数据源：ERP **营销日历/价格计划** 中已维护的 **分段促销**（按 SKU、店铺、起止日、类型）。  
2. 提醒规则（可配置）：  
   - **T0**：促销 **结束日次日**（美国时区）早班提醒 — 「昨日促销已结束，可维护下一段」；  
   - **T1（可选）**：下一段 **开始前 1 天** 提醒 — 「明日开始新促销，请确认后台已配置」。  
3. 渠道：站内消息 / 钉钉 / 邮件（与 ERP 通知体系一致）。  
4. 对象：按 **店铺（Notes、BVI）** 或运营组订阅。

**系统方案**

| 项 | 说明 |
|----|------|
| 定时任务 | 每日扫描即将结束/已结束分段 |
| 去重 | 同一 SKU 同一结束日只提醒一次 |
| 跳转 | 链接到营销日历或 Mirakl 商品页（若可深链） |

**验收**：结束日次日 指定时间前收到提醒；配置关闭后不发送。

---

### 2.2 子需求 B：API 调研与自动化（分阶段）

**阶段 0：调研交付物（必须先做）**

| 调研项 | 输出 |
|--------|------|
| Mirakl API 清单 | 创建/更新 offer 价格、创建 promotion、上传促销价、图片 |
| 沃尔玛 3P 接口 | `create promotion` / `update promotional price for single item` 等是否可用、字段、限流 |
| 能力矩阵 | 平台 × 操作（划线/Coupon/Flash）× API/仅后台 |
| 试点 | 1 SKU × 1 促销类型 端到端成功日志 |

**阶段 1：若 API 可用 — 批量执行（可选立项）**

- 从需求 07 **试算结果** 或运营确认表读取：**SKU、开始、结束、促销类型、价格**。  
- 调用 Mirakl/沃尔玛 API **批量创建或更新**；失败行回滚日志。  
- **不**自动根据亚马逊实时变价（除非业务单独开关）。

**阶段 2：若 API 不可用**

- 维持 **需求 07 面板 + 需求 06 导出**；后台人工执行。  
- 评估 **RPA** 仅作最后手段，需安全评审。

---

## 三、待澄清项

1. Notes/BVI 与沃尔玛 **分段规则差异** 是否同一套提醒。  
2. 提醒 **时区**（美国太平洋/东部）与运营班次。  
3. API 试点 **店铺与 SKU** 白名单。  
4. Promotion 创建 vs **仅改促销价** 的财务口径是否一致。

---

## 四、风险与依赖

- **API 可能仅改价不能建活动**，与业务「做 promotion」预期可能不符。  
- **结束当日不能改下一段** 是平台硬约束，提醒文案需写清。  
- 自动写价错误影响面大，需 **审批或 dry-run** 模式。  
- 依赖需求 07 规则与营销日历数据质量。

---

## 五、验收要点（建议）

**提醒**

1. 配置测试分段，结束次日收到 **一次** 准确提醒。  
2. 未结束分段 **不提前误报**。

**API（阶段 0）**

1. 提交《Mirakl/沃尔玛促销 API 能力矩阵》文档。  
2. 至少 1 条 **成功或明确失败原因** 的接口调用记录。

**API（阶段 1，若做）**

1. 批量任务对 ≥10 SKU 设置指定促销段，后台可见且价格正确。
