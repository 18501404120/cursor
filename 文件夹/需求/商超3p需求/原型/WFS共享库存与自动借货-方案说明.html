2 是否触发自动配平？
  • 该 8 位 SKU 已启用 WFS 共享配置？
    • 否 → 结束（不走本流程）
    • 是 → WFS 接口是否成功？
      • 否 → 结束 + 接口异常告警（不配平）
      • 是 → 是否存在 参与店满足 当前逻辑可售 < 安全库存？
        • 是（任一店） → 发送群告警 → 执行一次配平 → 同步三店可售
        • 否 → 不配平（可选刷新展示）

当前逻辑可售 = 该店该 SKU 在 ERP 中的可售（含已虚拟借入）；与平台已同步值同源。 补货目标 = 应有 − 当前（配平后 当前 := 应有）。

5 WFS 仓共享 vs 谷仓共享 · 二选一

硬性规则 同一 8 位 SKU 只能启用一种共享：WFS 仓共享（本方案）或 谷仓共享（ERP 既有能力），不可同时配置。

WFS 仓共享（本方案）

  • 总量 = WFS 接口实查
  • 参与店：WM / BBY / Lowes 3P-US
  • 自动配平、待推预占、超卖扫描

谷仓共享（既有模块）

  • 总量 = 谷仓库存
  • 沿用「谷仓共享库存设置」
  • 与 WFS 共享 互斥
操作系统行为
保存 WFS 共享，但该 SKU 已启用谷仓共享 拒绝 提示：请先停用谷仓共享
保存谷仓共享，但该 SKU 已启用 WFS 共享 拒绝 提示：请先停用 WFS 仓共享
切换模式 先删除/停用当前模式全部配置 → 再启用另一模式（记 MODE_SWITCH 日志）

与订单履约区分：订单在 WFS 库存不足时改推谷仓发货属于履约兜底，不等于同时开启「谷仓共享配置」。共享模式仍二选一。 详见 MD §5.5。

6 计算公式（已定口径）
// ① 总量：禁止用三店库存相加
可分配池 P = max(0, Q_wfs − S_wm − S_bby − S_lowes)

// ② 各店配平目标（整数舍入规则见 MD §9.3）
应有_i = round(P × 比例_i) + 安全库存_i

// ③ 触发
∃店：当前_i < 安全库存_i → 告警 + 整 SKU 一次配平

// ④ 缺料 / 富余
缺料_i = max(0, 应有_i − 当前_i)　富余_i = max(0, 当前_i − 应有_i)

// ⑤ 配平后
当前_i := 应有_i ；平台可售 := 应有_i（<1 → 停售）
7 三店交互演算（默认 = 标准示例）

三店共享比例合计须为 100%

店铺当前安全触发 应有缺料富余配平后平台同步

8 一次配平：虚拟借货顺序（缺料从大到小）
  1. 缺料店按 缺料量降序 排队（例：WM 50 → BBY 30）。
  2. 富余店按 富余量降序 供给（例：Lowes 富余 80）。
  3. 依次 transfer = min(缺料剩余, 富余剩余)，写借货日志，不产生仓间调拨单。
  4. 配平结束：三店 当前 = 应有；已借货 = 借入店增加的可售。
9 10 分钟推 WFS 窗口 · 超卖风险与防控

风险来源 BBY、Lowes 订单约 每 10 分钟 批量推 WFS 仓 → 进 ERP 后逻辑可售不会立刻随 WFS 实扣下降； 窗口内 WM 仍可快速卖货，三店平台可售之和可能 > WFS 实查 → 超卖。 详见 MD §23。
