# 目标助手：二期与长期规划

> 依据：《项目背景》《基于规则的销量预测设计说明》《目标助手项目方案》（文件：`销量预测项目方案.md`）  
> 定位：在一期「规则打底、可解释、可配置」基础上，逐步引入 ML 调优、闭环联动与智能化迭代，实现「预测 → 补货 → 调仓」全链路价值。

---

## 一、与一期的衔接

### 1.1 一期交付物回顾（规划前提）

| 交付物 | 说明 |
|--------|------|
| **规则引擎** | 7 大因子（流量、价格、生命周期、转化率、广告、排名、广告花费）规则表 + 基准销量 × 连乘修正，支持渠道/品类/生命周期分层配置 |
| **可解释输出** | 预测值 + 因子贡献 breakdown（JSON/报表），便于业务校验与复盘 |
| **配置与日历** | 大促日历、活动倍率、新品爬坡表、清仓衰减等可配置，运营/计划可改系数 |
| **数据管道** | 历史销量、流量、价格等与 ERP/OMS 同源，核心 SKU 周/日粒度、滚动 8～13 周 |
| **准确率基线** | 分品类 WAPE/MAPE 基线、大促周对比人工基线，作为二期优化锚点 |

### 1.2 一期未覆盖、留给二期及长期的能力

- **算法**：深度模型、残差学习、多模型融合（当前为规则 + 轻量统计/可选 ML）。
- **范围**：长尾 SKU 自动化扩容、更长周期战略备货（如 26 周）。
- **闭环**：与补货引擎/安全库存/调拨建议的**全自动联动**，以及与 APS/MRP 的深度集成。
- **智能化**：准确率低于阈值时**自动触发**参数重估或模型迭代；A/B 与复盘机制固化。

---

## 二、二期规划

### 2.1 二期目标

- **精度提升**：在规则 baseline 上引入「残差学习」或分品类 ML 模型，目标将核心品类预测准确率（如 WAPE）较一期基线提升 **10%～15%**，大促周偏差显著收窄。
- **范围扩展**：从「核心 SKU + 主渠道」扩展到**长尾 SKU 自动纳入**、多站点/多仓统一视图，支撑更多计划场景。
- **闭环落地**：预测结果**稳定写入**补货引擎/数仓，驱动安全库存与补货点计算，并输出「采用系统建议」的采用率与效果指标。
- **可运维**：准确率监控、异常 SKU 告警、季度复盘流程产品化，为「自动迭代」打基础。

### 2.2 二期关键能力

| 能力模块 | 内容 |
|----------|------|
| **ML 残差/增强层** | 规则预测作为 baseline；ML 学习「实际 − 规则预测」残差，输出校准值；规则仍保留为约束与解释层（与《基于规则的销量预测设计说明》第六节一致）。分品类/分渠道可选启用。 |
| **多模型与融合** | 时序模型（如 Prophet/轻量 LSTM）+ 规则 baseline + 残差模型；融合策略可配置（加权/取中位数/置信区间）。 |
| **长尾 SKU 策略** | 历史数据不足或低销 SKU：自动降级为「规则 + 品类/渠道均值」模板，并打标签「低置信度」，避免强上复杂模型。 |
| **补货与库存联动** | 预测结果通过 API/数仓表驱动「安全库存、补货点、补货量建议」；与库存预警、呆滞分析共用同一预测快照；支持「采用率」与「缺货/呆滞改善」报表。 |
| **监控与复盘产品化** | 准确率看板（分品类/分渠道/大促周）；异常检测（销量突变、预测持续偏高/偏低）告警；季度复盘模板（哪类因子规则误差大、是否触发重标定）。 |

### 2.3 二期里程碑（建议）

| 阶段 | 周期（参考） | 目标 | 关键交付 |
|------|----------------|------|----------|
| **2.1 残差模型试点** | 6～8 周 | 1～2 个核心品类上线「规则 + 残差 ML」 | 残差模型 pipeline、回测报告、可解释输出兼容一期 |
| **2.2 规模扩展** | 4～6 周 | 长尾 SKU 纳入、多站点/多仓预测汇总 | 自动分层策略、覆盖率与准确率报表 |
| **2.3 补货闭环** | 6～8 周 | 预测驱动补货建议流稳定运行 | 接口/任务 SLA、采用率与缺货/呆滞联动看板 |
| **2.4 监控与复盘** | 4 周 | 准确率看板、告警与季度复盘流程上线 | 监控大屏、告警规则、复盘模板与文档 |

二期整体约 **20～26 周**，可与一期 M2「规模与闭环」衔接，并在首个大促季完成 2.1～2.2，次年完成 2.3～2.4。

## 三、长期规划

### 3.1 战略方向

- **全链路闭环**：从「预测 → 补货 → 调仓」延伸至与 **APS/MRP、生产计划、采购计划** 的深度集成，形成「需求预测驱动供给计划」的一体化能力。
- **多场景策略库**：大促、清仓、新品上市、渠道拓展等**场景化预测策略**（不同因子权重、不同融合方式），通过配置切换而非重复开发。
- **持续学习与自动迭代**：当准确率低于阈值或某品类系统性偏差时，**自动触发**参数重估或模型重训；结合 A/B 与灰度，形成「预测 — 监控 — 迭代」闭环。
- **数据外延**：在合规前提下引入**竞品/类目大盘、宏观指标、天气/节假日**等外部信号，提升拐点与异常期的鲁棒性。

### 3.2 能力演进路线（长期）

| 方向 | 短期（二期） | 中期 | 长期 |
|------|----------------|------|------|
| **算法** | 规则 + 残差 ML、分品类可选 | 多模型融合、大促/清仓专用子模型 | 自动特征与模型选择、在线学习（视数据与场景） |
| **范围** | 核心 + 长尾 SKU，8～13 周 | 26 周战略备货、多仓多平台汇总 | 全 SKU/全渠道统一预测视图，支持战略与战术分层 |
| **闭环** | 预测 → 补货建议、采用率度量 | 预测 → 安全库存/补货点/调拨建议自动更新 | 预测与 APS/MRP/生产排程联动，可配置「自动执行」策略 |
| **可解释与配置** | 保留规则与因子 breakdown | 规则 + 模型贡献分解，业务可调权重 | 策略库 + 场景模板，运营自助选择与微调 |
| **运维** | 准确率看板、告警、季度复盘 | 阈值触发重训、灰度发布 | 自动迭代策略、根因分析与建议（如「建议调整某因子档位」） |

### 3.3 长期成功愿景

- **业务侧**：计划/采购岗位将「系统预测 + 因子解释」作为主决策依据，人工仅做例外与策略校准；缺货率、呆滞率、周转等指标持续改善并可归因到预测质量。
- **产品侧**：**目标助手**成为智岩 ERP「库存与供应链」中台的核心能力之一（预测 + 目标管理），与库存中心、采购、履约、数据看板深度协同，支撑多仓、多平台、多品类统一运营。
- **技术侧**：形成「规则打底 + 机器学习调优」的可持续架构，兼顾可解释性、冷启动与精度，并在大促、新品、清仓等场景上建立差异化优势。

## 四、成功指标与验收（二期及长期）

| 层级 | 指标类型 | 示例 |
|------|----------|------|
| **预测质量** | 准确率 | 核心品类 WAPE/MAPE 较一期基线提升 10%～15%；大促周偏差控制在约定区间 |
| **覆盖与时效** | 系统能力 | 长尾 SKU 覆盖率、预测刷新 T+1、多站点/多仓维度可解释输出 |
| **业务采纳** | 闭环效果 | 补货/调拨流程中「采用系统建议」的 SKU 占比；缺货率、呆滞率、周转天数改善趋势 |
| **智能化** | 运维 | 准确率低于阈值时自动触发迭代；季度复盘结论可落地为配置或模型变更 |

验收时以**业务价值**为主：降本（仓储、资金、呆滞）、增收（缺货减少、大促抓住）、提效（人工预测工作量下降）是否达到或接近《项目背景》中的量化方向，并可持续度量。

## 五、风险与依赖

| 风险/依赖 | 应对 |
|-----------|------|
| 数据质量与时效 | 二期前巩固数据治理（SKU 主数据、渠道映射、时间对齐）；先做数据质量与延迟监控 |
| 业务对 ML 的信任 | 保持可解释输出与人工覆盖通道；残差/融合结果需可追溯因子与规则贡献 |
| 与现有补货/APS 流程冲突 | 继续「建议仅供参考」→ 灰度 SKU → 全量；与供应链产品、计划团队共同定义接口与责任边界 |
| 大促与极端波动 | 活动日历 + 场景化策略 + 事后快速复盘；长期可建大促专用子模型或倍率库 |
| 自动迭代误触或过度 | 阈值与触发条件需与业务共定；先人工确认再自动执行，逐步放宽 |
