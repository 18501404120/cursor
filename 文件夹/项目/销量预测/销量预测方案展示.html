一、背景

含义

在多渠道（亚马逊、独立站、沃尔玛、TikTok 等）、多仓（深圳仓、海外仓、FBA）、多 SKU 与多生命周期阶段下，销售与供应链需要可解释、可配置的销量预测，并需要目标与预测、实际对齐管理；目标助手承载上述能力，驱动补货、调拨与库存健康，并与 ERP 库存、采购、履约、数据看板深度协同。

要解决的问题

  • 人工 Excel/经验填报工作量大，且难以与补货、安全库存统一口径
  • 大促（黑五、Prime Day、网一等）波动大，缺少活动日历与规则/模型叠加能力
  • 新品、清仓、多版本 SKU 需分策略，冷启动与长尾 SKU 难以覆盖
  • 预测与补货/调仓脱节，无法形成「预测驱动供给」的闭环

解决方案

规则打底 + 机器学习调优的混合架构：规则引擎提供可解释 baseline，ML 学习残差或分品类增强；配置与日历层支持大促、活动、生命周期分层；数据管道与 ERP/OMS 同源，核心 SKU 周/日粒度、滚动 8～13 周。

业务价值

统一预测入口与口径，为降本（仓储、资金、呆滞）、增收（缺货率下降、大促备货更准）、提效（人工预测工作量下降）建立可度量的基线，并与补货、库存、经营大屏联动。

二、价值

降本

仓储与资金占用优化；呆滞识别与清库建议有据可依；过量备货与断货成本双降。

可度量 baseline + 改善趋势，与库存周转、呆滞率挂钩。

增收

缺货率下降、大促备货更准；与亚马逊/FBA 断货、独立站预售等场景直接挂钩。

系统建议采用率、缺货/呆滞改善趋势可追踪。

提效

替代大量人工填报；采购/计划岗位工作量可度量下降；规则与因子可配置，减少发版依赖。

预测刷新 T+1、可解释输出支撑复盘与信任。

成功指标示例： 补货/调拨「采用系统建议」SKU 占比；缺货率与呆滞率改善；预测与 BP 目标、实际在同一视图可对齐（产品侧不承载 MAPE/达成率类考核，算法效果由数据团队线下评估）。

三、规则设计

含义

将销量拆解为「基准销量」经多因子连乘修正，规则可解释、可配置，冷启动与新品友好；大促、调价、排名变化时运营/计划可改系数而不等模型发版。

要解决的问题

  • 黑盒模型难以被业务信任与纠偏
  • 大促、清仓、新品等场景需要快速调参与分层策略
  • 因子间重复计数（如流量×广告花费）需在配置层解耦

解决方案

公式骨架： 预测销量 = 基准销量 × f流量 × f价格 × f生命周期 × f转化率 × f广告 × f排名 × f广告花费

基准销量：近 N 周同 SKU 同渠道平滑销量或「去年同期×年成长系数」。各因子按档位表（同比/环比、阈值、大促覆盖）配置乘数；支持上下限与取整，避免异常值。

业务价值

业务能看懂「为什么这周预测是 1000 而不是 800」；可解释 JSON/报表输出便于校验与复盘；规则集按渠道+品类+生命周期绑定，支持灰度与版本管理。

四、验证

含义

通过回测、异常检测与可解释输出校验预测可用性，确保规则与模型输出可信、可追溯；质量度量以数据/算法团队线下评估为主，产品内不做 MAPE/达成率看板为默认范围。

要解决的问题

  • 无法量化「预测好不好」、与人工基线无对比
  • 大促周、新品、清仓等特殊周期偏差无专项评估
  • 异常 SKU（销量突变、预测持续偏高/偏低）缺少告警

解决方案

  • 数据与回测： 用历史周数据「假装不知道当周销量」跑规则/模型，支撑线下偏差分析；Forecast 审核可与年度目标匹配度、变动率等流程校验配合（非产品准确率 KPI）
  • 异常与告警： 销量突变、预测持续偏高/偏低等异常 SKU 告警；可解释输出（预测值 + 因子贡献）便于人工复核
  • 迭代机制： 参数重估与模型版本迭代由数据团队节奏驱动，不以「产品内准确率阈值」为唯一触发条件

业务价值

异常与偏差可追溯为因子或规则问题，支撑参数重估与模型迭代；为「采用系统建议」的采用率与缺货/呆滞改善提供可信基础（与主产品「不做 MAPE/达成率考核」策略一致）。

五、优化

含义

在规则 baseline 上引入残差学习或分品类 ML、多模型融合；结合 A/B 与灰度与数据团队复盘节奏，形成「预测 — 监控 — 迭代」闭环（迭代触发条件以线下评估与运维策略为准）。

要解决的问题

  • 纯规则在复杂周期与长尾 SKU 上精度天花板明显
  • 人工调参滞后，无法系统性利用历史偏差反馈
  • 大促、清仓、新品等场景需要专用策略而非一刀切

解决方案

  • 二期： 规则预测作 baseline，ML 学「实际 − 规则预测」残差；分品类/渠道可选启用；长尾 SKU 降级为「规则 + 品类/渠道均值」并打低置信度标签
  • 长期： 多模型融合（时序 + 规则 + 残差）、场景化策略库（大促/清仓/新品）；模型重训与版本发布按数据团队规范执行；可选引入竞品/类目大盘、宏观、天气等外部信号

业务价值

计划/采购将「系统预测 + 因子解释」作为主决策依据，人工仅做例外与策略校准；精度提升目标由数据团队线下衡量，不作为产品内考核指标。

六、实施

含义

从数据管道与规则 MVP 到 ML 增强、规模扩展、补货闭环与监控复盘，分阶段交付；预测结果稳定写入补货引擎/数仓，驱动安全库存与补货点；与透明计划、库存看板、经营大屏联动。

要解决的问题

  • 一次性全量上线风险高，业务与系统需逐步适配
  • 与现有补货/APS 流程的接口与责任边界需明确
  • 大促前需至少具备规则+人工校准保底，避免首年全依赖新模型

解决方案

阶段化实施：M0 基线（数据管道 + 规则 MVP）→ M1 混合上线（1～2 品类 ML 增强）→ M2 规模与闭环（扩 SKU、接补货建议流）→ M3 智能化（自动迭代、多场景策略库）。接口与任务 SLA、采用率与缺货/呆滞联动看板产品化；「建议仅供参考」→ 灰度 SKU → 全量，与供应链产品、计划团队共定边界。

业务价值

可验收的里程碑与关键交付；补货/调拨采用率、缺货率、呆滞率、周转天数等可持续度量；目标助手成为智岩 ERP「库存与供应链」中台核心能力之一（预测与目标管理），与库存中心、采购、履约、数据看板深度协同。

七、路线图（一期 → 二期 → 长期）

一期交付物（规划前提）

规则引擎（7 大因子 + 基准×连乘修正）、可解释输出、配置与日历、数据管道；核心 SKU 周/日粒度、滚动 8～13 周。

二期 · 残差模型试点 约 6～8 周

1～2 个核心品类上线「规则 + 残差 ML」；残差 pipeline、回测报告、可解释输出兼容一期。

二期 · 规模扩展 约 4～6 周

长尾 SKU 纳入、多站点/多仓预测汇总；自动分层策略、覆盖率与线下质量报表。

二期 · 补货闭环 约 6～8 周

预测驱动补货建议流稳定运行；接口/任务 SLA、采用率与缺货/呆滞联动看板。

二期 · 监控与复盘 约 4 周

异常告警与季度复盘流程上线；监控大屏、告警规则、复盘模板（默认不含 MAPE/达成率经营看板）。

长期 战略

全链路闭环（预测→补货→调仓→APS/MRP/生产计划）；多场景策略库；持续学习与自动迭代；数据外延（竞品/类目大盘、宏观、天气等）。

层级指标类型示例
预测可用性线下评估数据团队对规则/模型效果持续评估；大促周专项复盘
覆盖与时效系统能力长尾 SKU 覆盖率、预测刷新 T+1、多站点/多仓可解释输出
业务采纳闭环效果「采用系统建议」SKU 占比；缺货率、呆滞率、周转改善趋势
智能化运维模型与参数迭代按数据团队流程；季度复盘结论落地为配置或模型变更
