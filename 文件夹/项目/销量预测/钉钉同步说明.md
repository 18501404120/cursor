# 销量预测 · 同步到钉钉「项目 / cursor」文件夹

## 本仓库脚本做什么

脚本路径：`scripts/sync_sales_forecast_to_dingtalk_kb.py`  

将本地目录一次性上传为钉钉**知识库里的文件**（与手动在知识库「上传文件」等价）：

- `需求文档/` 下全部 `.md`
- `原型/` 下 `.md`、`.html`、`.js`、`.css` 等（见脚本内扩展名列表）

钉钉内显示的文件名带前缀 **`需求文档/…`**、**`原型/…`**，便于在同一父文件夹下区分来源。

## 与「钉钉在线文档」的区别

| 形态 | 本脚本是否支持 | 说明 |
|------|----------------|------|
| 知识库 **文件**（md/html 等） | ✅ | 三步上传接口；钉内预览能力随客户端版本变化。 |
| **在线协作文档**（空白文档 + 块编辑器） | ❌ | 需开放平台「创建知识库文档」等**另一套**接口，或钉内新建后手工粘贴。 |

若产品口头说的「Markdown 换成钉钉文档格式」指的是**可排版、可协同的钉文档**，请钉内对上传文件使用 **「转为钉文档」/ 新建文档后导入**；或使用 `--docx`（需本机安装 [pandoc](https://pandoc.org/)）先把 Markdown 转成 Word 再上传，钉内按 Office 文档预览，仍属「文件」而非钉文档 API 直写。

## 环境变量与执行

与 `文件夹/项目/GTM角色和职责/竞品调研/scripts/sync_merged_to_dingtalk_kb.py` 相同：

1. 钉钉开放平台创建企业内部应用，开通**知识库 / 企业存储 · 上传文件**相关权限。  
2. 在钉钉网页打开目标知识库下的 **`项目` → `cursor`**（或你的实际路径），从网络请求或列举接口取得该文件夹的 **`dentryUuid`**，写入 `DINGTALK_PARENT_DENTRY_UUID`。

```bash
export DINGTALK_APP_KEY="..."
export DINGTALK_APP_SECRET="..."
export DINGTALK_UNION_ID="..."
export DINGTALK_PARENT_DENTRY_UUID="目标文件夹的 dentryUuid"

# 仅列出将要上传的文件
python3 文件夹/项目/销量预测/scripts/sync_sales_forecast_to_dingtalk_kb.py --dry-run

# 实际上传
python3 文件夹/项目/销量预测/scripts/sync_sales_forecast_to_dingtalk_kb.py

# 将每个 .md 先转为 .docx 再上传（需 pandoc）
python3 文件夹/项目/销量预测/scripts/sync_sales_forecast_to_dingtalk_kb.py --docx
```

可选：`DINGTALK_CONFLICT_STRATEGY`（默认 `OVERWRITE`，同名覆盖）。

## 获取 `dentryUuid` 的提示

与竞品调研 README 相同：在钉钉文档/知识库网页中进入目标文件夹，用浏览器开发者工具查看接口响应中的 `dentryUuid`，或调用开放平台「列举子文件」类接口。

## 依赖

- Python 3.10+（推荐）  
- 本机可访问 `https://api.dingtalk.com`  
- 可选：`pandoc`（仅在使用 `--docx` 时）

## 通过钉钉 MCP（Cursor）— 配置说明与能力边界

### 本仓库当前状态

根目录 `.cursor/mcp.json` **未**接入钉钉 MCP（仅有 Excalidraw、墨刀等）。因此：**在未由你本地完成 MCP 配置并重启 Cursor 之前，助手无法代你调用「钉钉 MCP」执行同步。**

### 在 Cursor 里接入官方钉钉 MCP Server（概要）

钉钉开放平台说明：[安装并使用钉钉 MCP](https://developers.dingtalk.com/document/ai-dev/second-level-node-1)、[钉钉 OpenAPI MCP 概述](https://developers.dingtalk.com/document/aipass/dingtalk-server-api-mcp-overview-1)。

在 **Cursor → Settings → MCP**（或项目/用户级 MCP 配置）中增加类似配置（**勿把真实 Client Secret 提交到 Git**；可用用户级 MCP 或本地未跟踪文件）：

```json
{
  "mcpServers": {
    "dingtalk-mcp": {
      "command": "npx",
      "args": ["-y", "dingtalk-mcp@latest"],
      "env": {
        "DINGTALK_Client_ID": "你的企业内部应用 AppKey",
        "DINGTALK_Client_Secret": "你的 AppSecret",
        "ACTIVE_PROFILES": "按需填写，勿盲目 ALL"
      }
    }
  }
}
```

保存后**完全退出并重启 Cursor**，在 Agent 模式下用自然语言验证（例如让 AI 调用通讯录类能力），确认 MCP 已连通。

### 「MD → 钉钉文档格式」与 MCP 的关系（重要）

| 目标 | 钉钉侧常见形态 | 钉钉 MCP 是否一定能做 |
|------|----------------|------------------------|
| 把 Markdown **作为文件**放进知识库某文件夹（如「项目 / cursor」） | 知识库 **文件** | 取决于你启用的 MCP **Profile** 是否封装了「企业存储 / 知识库上传」等接口；官方 `dingtalk-mcp` 常见示例多为通讯录、日程、机器人等，**不一定包含**「按 dentryUuid 上传文件」工具，需在 [MCP 广场](https://developers.dingtalk.com/document/aipass/mcp-square-introduction) 或应用权限中核对。 |
| 把 Markdown **变成钉文档在线块编辑器文档**（alidocs 协作文档） | **在线文档** | 通常对应**另一套**开放平台能力（创建知识库文档 / 文档块写入等），未必已封装进通用 `dingtalk-mcp`；**不能**假设「接了 MCP 就自动把 md 变成钉文档」。 |

**推荐落地组合（与产品预期对齐）：**

1. **文件进「项目 / cursor」文件夹**：继续用本目录脚本 `scripts/sync_sales_forecast_to_dingtalk_kb.py`（知识库上传文件三步接口），稳定、可审计。  
2. **钉文档体体验**：在钉钉内对上传的 `.md`/`.docx` 使用 **「转为钉文档」** 或 **新建钉文档 → 导入**，由运营完成一次性格式化；若必须全自动，再在开放平台单独对接「创建文档 + 写入块」API（可封装为自建 MCP，本仓库未内置）。

### 若你已配置好「带知识库上传能力」的钉钉 MCP

在 Cursor 中对助手说明即可，例如：

- 目标父目录：**知识库「项目 / cursor」**对应的 `dentryUuid`（或 MCP 工具要求的父节点 ID）。  
- 同步范围：`文件夹/项目/销量预测/需求文档`、`文件夹/项目/销量预测/原型`。  
- 期望：上传为文件 / 或创建钉文档（二选一写清楚）。

助手将**仅在你本机 MCP 已连接且工具列表里确实存在相应 tool** 时才能代为执行；否则会退回上述 Python 脚本或钉内手工流程。
