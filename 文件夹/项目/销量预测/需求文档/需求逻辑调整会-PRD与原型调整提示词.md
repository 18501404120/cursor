# 需求逻辑调整会：PRD 与原型调整提示词

> **来源会议**：`文件夹/项目/销量预测/会议/需求逻辑调整会`  
> **用途**：提炼当前销量预测 / 目标助手方向需**对齐会议结论**的改动点，并给出**可直接复制**的提示词，用于指导修订 PRD 与 HTML 原型。  
> **说明**：会议中项目曾提及「阶段性暂停、优先渠道规划」；本文档仅沉淀**业务逻辑与文档/原型应对**，排期以组织决策为准。

---

## 一、会议结论摘要（与现行方案的核心差异）

### 1. 三条数值线必须分清

| 线 | 含义（会议口径） | 是否受销售目标影响 |
|----|------------------|---------------------|
| **客观下限 / 客观中值 / 客观上限** | 由流量、价格、促销天数等**客观因子**在「差情景 / 均值情景 / 打满情景」下算出的销量（或销售额）区间与中值；规则与 ML 应对齐，差异大则调参而非混进目标 | **否**：上下限与中值所代表的客观带**不因目标改写** |
| **目标** | 业务下达的销售额/销量目标（可高于或低于客观带） | 业务输入 |
| **系统推荐值** | 在客观三值 + 汇总后，与目标比较，按**分支规则**得到的最终推荐给专员的数；再按**比例分摊到各 SKU** | **是**：仅推荐值随「与目标的关系」调整 |

会议明确否定：在「客观最大仍低于目标」时，用 **目标 ×1.05** 之类把推荐做得**高于客观最大**——认为「不客观」「陪着一起疯」；客观最大即推荐的**硬顶**（除非用户自行改数）。

### 2. 推荐值 vs 目标：分支逻辑（会议口述，产品需落成可验收规则）

以下用**汇总层**（专员负责的全部 SKU 的销售额或统一口径的量）描述，便于与「多 SKU」一致；落到单 SKU 时再乘比例。

- **目标 > 客观最大**：推荐总额 = **客观最大**（系统告知「够不着目标」）；**不得**再乘 1.05 或强行抬过客观顶。
- **目标介于客观中值与客观最大之间**：推荐总额 = **目标**；分摊到 SKU：`各 SKU 推荐 = 各 SKU 客观中值 × (目标总额 ÷ 客观中值总额)`（会议举例 8500/8000）。
- **目标 < 客观中值**（会议倾向）：若目标低于客观中值甚至低于客观最小，**较稳妥口径**为：推荐仍以**客观侧**为锚（如「比最小还小则以最小为参考」等），需产品把边界写死，避免推荐反常识；**不可**简单用「目标×系数」替代客观上限逻辑。
- **上下限**：仅反映客观因子极值/情景，**不**因目标、α、BP 融合而改数（与会确认：「上下限是客观的，不会改」）。

### 3. 颗粒度与角色

- **销售专员**：面向**多 SKU / 多 SPU**，每条有客观三值 + 目标 + 系统推荐；需支持**汇总行**（目标总额、客观中值总额、客观最大总额等）再算比例分摊。
- **销售主管**：下属专员结果**合并**；关注目标与客观推荐的偏差、辅导分配；可后置迭代，但 PRD 可预留「汇总/对比」表述。

### 4. 单位与财务口径

- 目标常以**销售额**表达；预测若按**量**需与价、批次等统一或可换算，否则「加总比例」无法与财务对齐。PRD 需明确**主口径**（额 vs 量）及换算规则。

### 5. 与当前仓库 PRD 的冲突点（必须处理）

| 主题 | 现行《预测销量上下限规则》等文档常见写法 | 会议后应调整为 |
|------|-------------------------------------------|----------------|
| 点预测 P 与 BP | `M≤T` 时 `P=T×1.05` 等融合公式 | **废弃或限定场景**：推荐值不得突破**客观最大**；与目标关系按上节分支，**禁止**为「不低于目标」而硬抬过客观顶 |
| 上下限与 BP/α | 上下限在同构公式中与 P、T、α 强绑定 | **解耦**：客观三值独立；**仅推荐值**做目标对齐与分摊 |
| 单 SKU 叙事 | 详情、公式多以单 MSKU 展开 | 默认**专员多 SKU + 汇总分摊**主路径，单 SKU 为下钻 |

## 三、可复制提示词（用于 Cursor / 自审）

将下方整段复制到对话中，并把 `@文件` 换成你本机或仓库中的实际路径。

```text
你是熟悉智岩 ERP / 目标助手业务的产品文档编辑。请根据《需求逻辑调整会》结论，修订销量预测相关 PRD 与 HTML 原型，严格满足下列约束。

## 业务约束（必须遵守）

1. **三条线分离**
   - 「客观下限、客观中值、客观上限」仅由流量、价格、促销安排等客观因子及规则/ML 情景得出，**不受销售目标、BP、α 修改**。
   - 「目标」为业务输入，可与客观三值任意高低组合。
   - 「系统推荐值」= 在**汇总层**（专员负责的全部 SKU）比较目标与客观中值、客观最大值等之后，按分支规则得到总额，再**按比例分摊**到各 SKU 客观中值上；单 SKU 展示该分摊结果。

2. **禁止**
   - 当客观最大仍低于目标时，**禁止**用「目标×1.05」或任意系数把推荐值抬到**高于客观最大**。
   - 禁止让「上下限」随目标或 BP 融合权重变化。

3. **分支规则（请写成可验收的 if-else 表，并与财务确认单位）**
   - 目标 > 客观最大 → 推荐总额 = 客观最大（并提示无法完成目标）；各 SKU 推荐是否仍按比例取自客观中值或取各自客观最大，需给一个明确规则。
   - 客观中值 < 目标 ≤ 客观最大 → 推荐总额 = 目标；分摊系数 = 目标总额 / 客观中值总额。
   - 目标 < 客观中值（及低于客观最小）→ 给出明确规则（会议倾向「偏小则以客观为锚」），禁止与「1.05」旧逻辑混用。

4. **角色与范围**
   - 默认主场景：**销售专员 + 多 SKU**，必须有汇总行与下钻。
   - **销售主管**：合并、对比、辅导分配为二期或独立小节，可占位但勿与专员公式矛盾。

5. **单位**
   - 明确目标是「额」还是「量」；若混合，写清换算与汇总口径，否则比例分摊无效。

## 交付物

- 更新 `预测销量上下限规则-PRD.md`：名词表、计算顺序图、与旧版（M/T/α、1.05）差异及**废止说明**。
- 更新 `销量预测管理-PRD.md`：列表列、图表系列、详情字段、与配置中心的分工。
- 更新 `销量预测管理-原型说明.html`（及依赖的 prototype-anno-data JS）：界面与示例数据与上表一致；删除误导性的 1.05 演示。

## 输出要求

- 用中文；表格 + 分支伪代码；每条需求带「验收要点」。
- 修改处标注「会议依据：需求逻辑调整会」。
- 不扩大范围到 PSI、全渠道排期；仅写清本逻辑与文档原型。
```

## 四、给产品自己的 10 条检查题（改完 PRD/原型后自答）

1. 页面上能否一眼区分「客观三值」「目标」「推荐」？  
2. 目标高于客观最大时，推荐是否**绝不会**大于客观最大？  
3. 上下限的计算说明里是否**零处**写「随 BP/α 变化」？  
4. 是否已删除或废止 **T×1.05** 与「为托底而突破客观顶」的叙述？  
5. 多 SKU 汇总行是否给出**目标总额 / 客观中值总额 / 推荐总额**及分摊系数示例？  
6. 规则与 ML 双轨时，是否说明「客观三值应对齐，分歧走调参」而非用目标抹平？  
7. 销售主管视图是「暂不实现」还是「占位」？与专员数据是否同源？  
8. 金额 vs 数量是否全文口径一致？  
9. 详情弹窗是否按「先客观三值 → 再目标对比 → 再推荐」顺序展示？  
10. 变更记录是否写明**废止旧分支**、避免实施按旧 PRD 开发？
