销量预测项目 · 汇报材料
背景 价值 方案 落地 路线 风险

以可解释的销量预测，打通「预测 → 补货 → 调仓」闭环

在行业从流量红利走向精细化运营的背景下，本项目以规则打底 + 算法增强的混合架构，支撑库存降本、缺货增收与计划提效； 与智岩 ERP、订单与库存数据同源，面向管理层提供可度量、可复盘、可迭代的预测能力基座。

多渠道 · 多仓 · 大促日历 R1～R3 提前期与版本锁定 可解释因子 + 人工纠偏

一、为什么要做

业务与行业层面的三条主线：预测质量、落地成本、组织协同。

1精细化运营依赖预测

库存优化与补货决策的前提是销量预测；跨境电商需在多站点、多仓、大促波动下保持口径一致，传统经验或简单统计难以稳定支撑。

2纯算法或纯规则均有短板

单一 ML 模型可解释性弱、冷启动与中小样本场景成本高；纯规则又易僵化。需要混合模式平衡可落地性与精度。

3必须与 ERP 闭环协同

预测结果需进入补货、安全库存与经营看板，与采购、计划、数据团队共用同一套数据与快照，避免「预测一套数、执行另一套数」。

二、带来什么价值

与《项目背景》对齐的经济与运营目标（以下为方向性表述，首期以 baseline 与改善趋势验收）。

📉

降本

优化库存结构，降低仓储与资金占用；减少呆滞与过量备货，支撑周转与成本可视。

📈

增收

压低缺货率、提升大促与核心 SKU 备货准确度，减少断货损失并抓住活动峰值。

⚙️

提效

替代大量人工 Excel 填报；计划与运营在统一界面完成筛选、下钻、备注与复盘。

战略侧：「规则 + ML 调优」混合架构降低单一方案风险；准确率低于阈值时可触发参数重估或模型迭代，形成持续优化闭环。

三、总体方案怎么建

分层架构 + 业务闭环 + 五类因子，与《销量预测项目方案》一致。

业务闭环（示意）

技术分层（规则 + 算法 + 融合输出）

配置与日历
大促、活动、调价、生命周期标签、渠道权重 — 业务可维护，减少发版依赖。
规则引擎
新品/清仓/季节性/平台政策等可解释规则，输出 baseline 与上下界约束。
算法层
时序基线 + 轻量 ML（分品类/分渠道可选），学习残差或增强波动段。
融合层
规则约束 + 模型校准，统一为可上线预测值与区间。
输出层
预测销量、置信区间、因子贡献（可解释），供管理端、补货与数仓消费。

五类核心因子（与数据管道对齐）

流量 · 大盘与活动周 价格 · 促销与变价 生命周期 · 新品/主推/清仓 历史销量 · 多渠道一致口径 供给约束 · 在途、MOQ、交期

数据治理要求：SKU 主数据、渠道映射、时间对齐与订单中心一致，避免预测与补货「各算各的」。

四、产品如何落地

与当前原型与 PRD 对齐的管理侧能力（首期范围可裁剪）。

销量预测管理

  • 全局筛选 → KPI（R1～R3）→ 趋势图 → SKU 明细表
  • 单元格下钻：基量、系数、因子与最终预测一致可追溯
  • 异常备注、批量备注与「是否参与计算」协同计划流

配置中心

  • 超参数因子、规则参数与权限模拟（原型已覆盖）
  • 与滚动预测窗口、渠道/组织权限一致

对接下游

  • 预测结果写入补货引擎或数仓，驱动安全库存与补货点
  • 经营看板扩展准确率、缺货风险等指标

五、实施节奏（阶段化）

先跑通数据与规则 MVP，再混合模型与闭环规模化。

M0 基线 · 约 4～6 周

数据管道 + 规则预测 MVP

核心 SKU、口径文档、首版准确率 baseline、简单看板。

M1 混合 · 约 6～10 周

1～2 个品类 ML 增强 + 渠道维度

可解释报告、采购侧试用与反馈闭环。

M2 规模与闭环 · 持续

扩 SKU、接补货建议流

任务调度稳定、采用率与呆滞/缺货联动报表。

M3 智能化 · 视效果

自动迭代与多场景策略库

阈值触发重训、A/B 与季度复盘机制。

大促前建议至少完成 M0 + 部分 M1，以「规则 + 人工校准」保底，避免首年大促全依赖新模型。

六、主要风险与应对

便于管理层快速了解可控点与并行策略。

风险 应对思路
数据质量不足拖垮模型 首期以规则为主、ML 为辅；先做数据质量看板与口径对齐。
业务不信任「黑盒」 强制可解释输出 + 人工覆盖与备注链路 + 复盘会。
大促极端波动 活动日历 + 规则倍率 + 事后快速调参与复盘。
与现有补货流程冲突 并行期「建议仅供参考」→ 灰度 SKU → 全量推广。
