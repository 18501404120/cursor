# 目标助手项目方案（智岩科技 / Govee）

> **产品名称**：**目标助手**（原内部立项名「销量预测」；仓库目录名可沿用历史路径）。  
> 依据：公司业务介绍、ERP 产品经理定位、项目背景与价值  
> 定位：集**销量预测、目标管理（BP）与经营查看**于一体，支撑「预测 → 补货 → 调仓」闭环，与 ERP 库存、采购、履约、数据看板深度协同。**产品侧不承载** MAPE/达成率/R 版本达成考核。

---

## 一、项目定位与边界

### 1.1 在公司业务中的位置

| 维度 | 与智岩业务的契合点 |
|------|-------------------|
| **渠道** | 亚马逊为主 + 独立站 + 沃尔玛/TikTok 等，需**分渠道/分站点**预测与汇总视图 |
| **库存形态** | 深圳仓、海外仓、FBA、中转仓 —— 预测需可下钻到**仓/渠道可售库存**与补货节奏 |
| **SKU 特征** | 多版本、多套装、灯带/小家电生命周期差异大 —— 需**品类/生命周期分层**策略 |
| **大促** | 黑五、Prime Day、网一等 —— 必须支持**活动日历 + 规则/模型叠加** |
| **增长节奏** | 营收高速增长、新品迭代快 —— 冷启动 SKU 与成熟 SKU **分策略** |

### 1.2 在 ERP 产品中的位置（产品经理职责对齐）

- **上游输入**：历史销量、订单、促销、价格、渠道库存、在途、采购/生产计划（与采购、生产、订单模块数据同源）。
- **下游消费**：补货建议、安全库存、调拨建议、呆滞预警（与「库存中心 / WMS / 采购管理」联动）。
- **管理侧**：经营大屏可增加「缺货风险、库存健康度」等与履约相关的指标，与现有库存周转、缺货分析并列（**不以「预测准确率」为产品主指标**）。

### 1.3 项目边界（建议）

| 纳入首期 | 可二期扩展 |
|----------|------------|
| 核心 SKU（如 Best Seller、高周转品类） | 长尾 SKU 自动化扩容 |
| 周/日粒度预测 + 滚动 8～13 周 | 更长周期战略备货 |
| 规则 + 统计/轻量 ML 混合 | 深度模型、多模型融合 |
| 预测结果写入 ERP 或数仓供补货使用 | 与 APS/MRP 全自动闭环 |

## 二、建设目标与成功指标

### 2.1 业务目标（与项目背景对齐）

- **降本**：仓储与资金占用优化方向与背景文档量化目标一致（作为**验收参照**，首期以「可度量 baseline + 改善趋势」为主）。
- **增收**：缺货率下降、大促备货更准（与**亚马逊/FBA 断货、独立站预售**场景挂钩）。
- **提效**：替代大量人工 Excel/经验填报，**采购/计划岗位**工作量可度量下降。

### 2.2 产品目标（可验收）

| 指标类型 | 示例指标 |
|----------|----------|
| **目标对齐** | 业务侧销量目标（BP）与预测目标、实际在同一视图可对比（不做强制「达成率」考核） |
| **系统能力** | 核心 SKU 覆盖率、预测刷新频率（T+1）、渠道/仓维度可解释输出 |
| **业务采用** | 补货/调拨流程中「采用系统建议」的 SKU 占比 |
| **稳定性** | 大促期间任务成功率、延迟 SLA |

## 三、总体架构：规则打底 + 机器学习调优

与项目背景中「混合模式」一致，落地为**分层架构**：

```
┌─────────────────────────────────────────────────────────┐
│  配置与日历层：大促、活动、调价、生命周期标签、渠道权重   │
├─────────────────────────────────────────────────────────┤
│  规则引擎层：新品/清仓/季节性/平台政策等可解释规则       │
├─────────────────────────────────────────────────────────┤
│  算法层：时序基线 + 轻量 ML（分品类/分渠道可选）         │
├─────────────────────────────────────────────────────────┤
│  融合层：规则约束输出上下界 + 模型输出校准               │
├─────────────────────────────────────────────────────────┤
│  输出层：预测销量、区间、置信度、因子贡献（可解释）       │
└─────────────────────────────────────────────────────────┘
```

- **持续迭代**：由数据/算法团队按业务节奏做**参数重估或模型版本迭代**（**不**以产品内「准确率阈值」为唯一触发条件）。

## 四、核心数据与因子（5 类因子落地）

| 因子类别 | 智岩侧数据来源（示意） | 产品要求 |
|----------|------------------------|----------|
| **大盘/流量** | 平台报表、广告/站外投放、独立站流量 | 活动周可标注，支持同比/环比特征 |
| **价格** | 各渠道售价、促销价、优惠券 | 变价事件进特征或规则 |
| **生命周期** | 上架时间、品类标签、是否主推/清仓 | SKU 分层路由到不同策略模板 |
| **历史销量** | OMS/ERP 订单、FBA/海外仓出库 | 清洗退货、多渠道合并口径一致 |
| **供给与约束** | 在途、MOQ、交期、产能 | 预测输出可与「可补货量」联动，不单点拍脑袋 |

数据治理需 ERP PM 推动：**SKU 主数据、渠道映射、时间对齐**与订单中心一致，避免「预测用一套数、补货用另一套数」。

## 五、功能模块规划（产品视角）

### 5.1 预测与目标管理

- SKU/渠道/仓维度预测任务配置；滚动预测窗口；手动覆盖与备注（大促人工纠偏）。
- **目标与预测**：**业务侧销量目标（BP）**、**预测目标**（当前规则/模型输出）、实际销量在同一口径下展示；**不**做 R1～R3 锁定快照与达成率考核。

### 5.2 规则配置（中台化，与 PM「规则配置」一致）

- 大促倍率、季节系数、新品爬坡曲线、清仓衰减等**可配置**，减少发版。
- 权限：计划/运营可改规则参数，核心算法参数由数据团队或管理员控制。

### 5.3 结果展示与解释

- 预测曲线 vs 实际；**一格展示「预测值 + 区间 + 关键因子」**，满足业务信任（**不**默认展示「偏差分解」为考核用途）。
- 导出：供采购计划会、供应链周会使用。

### 5.4 与补货/库存联动（ERP 集成）

- 输出接口：每日/每周推送至补货引擎或数仓，驱动**安全库存、补货点、调拨建议**。
- 与「库存预警、呆滞分析」共用同一套预测快照，便于对账。

### 5.5 监控与告警

- 异常 SKU（销量突变、数据异常）告警；大促专项监控大屏（**不含** MAPE/达成率类看板为默认范围）。

## 六、实施路线图（阶段化）

| 阶段 | 周期（建议） | 目标 | 关键交付 |
|------|----------------|------|----------|
| **M0 基线** | 4～6 周 | 跑通数据管道 + 规则预测 | 核心 SKU 列表、历史数据口径文档、规则版 MVP、首版**可运行**预测与 BP 目标数据对齐 |
| **M1 混合上线** | 6～10 周 | 1～2 个品类 ML 增强 + 渠道维度 | 混合模型、可解释报告、采购侧试用反馈闭环 |
| **M2 规模与闭环** | 持续 | 扩 SKU、接补货建议流 | API/任务调度稳定、采用率指标、呆滞/缺货联动报表 |
| **M3 智能化** | 视效果 | 自动迭代、多场景策略库 | 阈值触发重训、A/B 与复盘机制 |

大促（Prime Day 等）前至少完成 **M0 + 部分 M1**，以规则+人工校准保底，避免「大促首年全依赖新模型」。

## 七、组织与协作（RACI 示意）

| 角色 | 职责 |
|------|------|
| **ERP/供应链产品经理** | 需求范围、流程与 ERP 集成、PRD、UAT、业务推广 |
| **供应链计划 / 采购** | 规则输入、业务验收、大促日历维护 |
| **数据/算法** | 模型与特征、监控、迭代 |
| **研发** | 管道、服务、权限、与订单/库存系统对接 |
| **财务/经营分析** | 指标口径对齐（可选，涉及库存成本展示时） |

## 八、风险与应对

| 风险 | 应对 |
|------|------|
| 数据质量差导致模型不可用 | 首期规则为主，ML 仅作辅助；先做数据质量看板 |
| 业务不信任黑盒 | 强制可解释输出 + 人工覆盖链路 + 复盘会 |
| 大促极端波动 | 活动日历 + 规则倍率 + 事后快速复盘调参 |
| 与现有补货流程冲突 | 并行期「建议仅供参考」→ 灰度 SKU → 全量 |

## 九、下一步行动清单（可直接排期）

1. **立项**：明确首期 SKU 范围、渠道（建议先亚马逊 US + 核心品类）。  
2. **数据盘点**：订单/库存/促销字段可用性与延迟（T+几）。  
3. **PRD 骨架**：预测对象、刷新频率、页面原型、接口清单。  
4. **M0 开发**：规则引擎 MVP + 预测结果表 + 简单看板。  
5. **第一次大促复盘**：对比人工 vs 系统预测，迭代规则与特征。
