GTM · EOM 流程 2.0 · 竞品分析

阶段模型、金蝶停售停服、状态卡单：A / B / C 对标报告

对标对象不是「另一套零售 EOM 工单」，而是三类可拆开的能力：华为 IPD/EOX 的分阶段里程碑、金蝶软件生命周期终止政策（EOM1/EOM3）及星空侧禁用/允许采购/ECN 用完旧料、SAP 停产件 + 物料状态的卡单与替代。学能力，不抄界面；卡单落在金蝶/供应链，GTM 出状态。

输出日期：2026-09-10 口径：A+B+C 全做 用途：EOM 2.0 方案取舍，不替代需求正文 截图：公开官网 / 官方帮助 / 技术博客演示环境
1

分析范围与映射原则

我司对象是 GTM 成品 8 位 SKU 退市工单，不是元器件 PCN，也不是用友「停销」台账。

A 华为 IPD / EOX

公开生命周期策略：GA → EOM（停售）→ LODSP（备件最后买）→ EOS（停服），关键节点至少提前 6 个月公告。

  • 学：停售、最后采购、停服、清库闭环不是同一天
  • 不搬：ToB 长服务周期、官网对客合同义务

B 金蝶停售停服 + 星空执行

两层能力分开看：官网「EOM」是金蝶卖软件的停售停服；星空物料禁用 / 允许采购 / 工程变更「用完旧料」才是卡单与旧料消耗的产品能力。

  • 学：停售拆 EOM1（停新购）与 EOM3（停销售）；公告列表 + 版本替代；禁用后仍可清库存
  • 不搬：软件 5 年停服、加模 EOM2、官网对客公告；不在 GTM 做 ECN/替代方案台

C SAP 停产件 + 物料状态

MRP4 停产标识 + 生效日 + 替代料；BOM 停产组/替代组；MD04 按库存耗尽切换需求；OMS4 状态可禁 PO、允许出库。

  • 学：状态真正卡住交易，替代有生效时点
  • 不搬：在 GTM 重做一套 MRP / 采购
映射原则：竞品字段落到我司「工单语义 / 方案字段 / 下游接口」，不落到「再做一个华为官网、金蝶 plc 公告站或 SAP GUI」。2.0 已有主动/被动发起、SKU 购物车范围、核料、方案、Last Buy 跟踪、反 EOM、库存=0 闭环；缺口主要在阶段日历、状态卡交易、主数据替代关系。金蝶公开资料没有「覆盖到停服日的建议采购量」引擎，本期不从竞品搬测算公式。

A

华为：产品生命周期是日历，不是一次审批

公开信与数字能源终止政策把 EOM 定义成「停止接受订单」，EOS 才是「停止服务」。

GA可大批量交付
→
EOM停新建/扩容订单
→
LODSP备件最后购买日
→
EOS停止服务与支持

可借鉴

  • 把「正式 EOM」只解释为停售，不要同时当成流程完结。
  • Last Buy / 备件窗口是 EOM 之后的独立阶段，对应我司 Last Buy 跟踪。
  • 关键日期至少提前一个固定窗口对内对齐（华为对客是 6 个月；零售可缩短，但要有窗口）。
  • 生命周期公告列表：按产品检索 EOM / EOS，便于销售和计划查「哪天不能再卖」。

不宜照搬

  • 运营商/政企设备 EOM 后仍服务数年，和零售成品清库不是同一约束。
  • 官网对客公告、合同级停止销售承诺，不是 GTM 工单范围。
  • 软件版本还有 EOFS（停新补丁），我司 8 位 SKU 无对等节点。
  • Info-Finder 生命周期查询器需华为账号，不能当我司交互范本。
落到 2.0：工单与台账上显式区分「正式停售日 / Last Buy 窗口截止 / 库存=0 闭环日」。不新建对外公告站。软件 EOFS、备件服务合同不纳入本期。
B

金蝶：官网「EOM」是停售停服政策；星空禁用 / 用完旧料才是卡单

公开资料里金蝶没有零售成品 EOM 工单，也没有 Last Buy 建议量引擎。能对标的是两层：金蝶作为软件厂商的生命周期终止政策，以及金蝶云·星空里物料禁用、允许采购、工程变更「用完旧料」。

不要把金蝶 ERP 说成 GTM 同类系统。官网 plc 页的 EOM1/EOM2/EOM3 管的是「金蝶卖给客户的软件还接不接订单」；我司 8 位 SKU 退市后的采购/出库拦截，应对齐星空物料控制与 ECN，而不是把软件停服年限抄进零售清库。
GA可大批量交付
→
EOM1停止新购
→
EOM3停止销售
→
EOS1停止标服
→
EOS2停止服务

政策里还有 EOM2（停加模）、EOPR（停需求补丁）、EOSM（停维护）、EOO（公有云关环境）。订阅产品时间轴不含「停标服」节点，买断产品有。基准年限：订阅 GA–EOS2、买断 GA–EOS1 约 5 年（星空旗舰/星辰等无版本产品除外）。

能力金蝶公开口径对我司的翻译
EOM1 停止新购 该日之后不再允许新购订单 接近「不再接普通新订单」，但仍可能加站/续费；比「正式 EOM」更早一档
EOM3 停止销售 零点起不再接受销售订单；订阅含新购/加站/加模/续费及标准/高级成功服务，不含金选/专项 对齐我司「正式停售」：普通采购/接单停掉。已批 Last Buy、合同例外单独白名单，类似金蝶「不含金选服务」
EOS1 / EOS2 停标服、停全部服务（含金选）；与停售日分开，往往晚 1–5 年 零售成品用「库存=0 闭环」，不要对齐软件停服。售后截止若以后要做，才对标这一层
提前通知 有版本停售提前 3–6 个月，无版本 12 个月；停服产品至少 12 个月、版本 6–12 个月；官网 plc 发布 学「固定提前窗口 + 可检索公告列表」。GTM 做对内台账即可，不做对客 plc
版本替代 停售停服公告写明退出版本 → 迭代版本（如星空 V7.6/V7.7 → V9.1） 对应工单「迭代新品 SKU」，让销售能查「停了卖什么」
物料禁用 / 允许采购、允许销售 禁后列表默认过滤、单据红字；不勾选允许采购则不能录采购价目表 正式 EOM 回写金蝶：禁普通采购、仍允许出库清货；Last Buy 走白名单，而不是整料物理删除
工程变更「用完旧料」 变更类型：立即变更 / 按日期变更 / 用完旧料。用完旧料下推后新料作主料、旧料作替代料并产生替代关系；按日期则旧料失效日=设定日 「先耗尽老库存再切新品」与 SAP Eff-out 同构。BOM/替代关系在金蝶，GTM 只出停售日与建议替代 SKU

可借鉴

  • 停售可以拆档：先停新购（EOM1），再停全部销售（EOM3），服务另算。
  • 公告列表按产品线检索，单条公告同时给停售日、停标服日、停服日和替代版本。
  • 卡单用物料「允许采购」和禁用，而不是只在计划系统写备注。
  • 用完旧料：禁止再买旧料，但允许旧库存继续消耗，避免双料齐备造成呆滞。

不宜照搬

  • 软件订阅/买断 5 年停服、加模 EOM2、公有云 EOO 关环境。
  • 官网对客生命周期公告与伙伴告知义务。
  • 在 GTM 重做工程变更单、物料替代方案、研发生命周期模板。
  • 把金蝶 AI PLM / 呆滞料智能体整段搬进成品 EOM 工单（那是研发变更冻旧采，不是 8 位 SKU 退市）。
落到 2.0：阶段语义学 EOM1/EOM3 分档；卡单与金蝶约定「禁普通 PO、允许出库、Last Buy 白名单」。Last Buy 买多少仍由方案页人工确认，不从金蝶公开能力搬测算引擎。ECN 用完旧料与新品 SKU 打通放后期。
C

SAP：停产是主数据事件，库存没耗尽就不切替代

能力分两块：停产件（MRP 把需求转给 Follow-up）与物料状态（OMS4 决定 PO/SO/出库是否报错）。

停产件（MM02 MRP4 + BOM）

  • Discontin.ind = 1：简单一对一替代。
  • Eff-out：计划「原件库存应耗尽」的日期；无库存则次日用替代料。
  • Follow-up material：替代料号。
  • BOM 上停产组与替代组必须同号，否则 MRP 不切。
  • MD04：有库存时，生效日后需求仍挂在原件；耗尽后才出现在替代料。

物料状态（OMS4，公开配置口径）

  • 采购 = B（错误）：不能再下普通 PO。
  • MRP = A（警告）：计划时提醒已停产。
  • 库存管理 = 空：允许继续出库清货。
  • 这正是「停售仍可卖库存、禁止新采购」的主数据实现。
  • 应做在金蝶物料/SKU 状态，由 GTM 正式 EOM 回写，而不是 GTM 拦单。
不要在 GTM 复制 MM02/CS02/MD04。2.0 只需约定：正式 EOM 后下游禁普通采购/接单；已批 Last Buy 白名单放行；迭代新品 SKU 作为「建议替代」展示，BOM 级强制替代留给供应链主数据。
