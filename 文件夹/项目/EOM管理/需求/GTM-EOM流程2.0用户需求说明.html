GTM · EOM 2.0 · 用户需求

从“核料测算 + 附件审批”
升级为退市全过程在线管理

EOM 已从阶段性停产确认，变成常态化退市运营。系统不能只停在计划确认， 而要以 EOM 工单 为载体、8 位 SKU 为最小单元， 把新品替代、预测、核料、Last Buy、清库、异常、S&OP 和 EOL 串成一条可见链路。

适用：LBU / ABU 载体：EOM 工单 粒度：8 位 SKU 用途：需求对齐 / 立项沟通
1

需求背景

业务要管的不再是“能不能停产”，而是一个产品为什么退、谁在处理、清到哪、还剩多少、有何风险、何时 EOL。

4

当前六大问题

不是缺一个页面，而是流程、类型、台账、协同、方案和异常六条能力同时断裂。

流程结束过早

计划确认后即标“完结”，业务才刚进入正式 EOM。

确认方案 → Last Buy 清库 EOL

主被动未区分

无法按退市类型生成节点，也记不住新品 CR / 上市时间和退市原因。

主动：新老品切换 被动：7 项规则

台账靠线下拼

产品、预测、库存、Last Buy、物料分散在多系统和 Excel，口径不一、无快照。

ERP Forecast Excel 钉钉

跨角色无责任链

系统只服务发起人与计划确认。销售、PMC、采购任务在群聊里催。

无时限 无升级 无留痕

方案不可检索

清库方式、Last Buy 数量、费用归属锁在附件里，版本一变就用错。

Excel 方案 → 结构化方案

异常无机制

新品延期、老品积压、BOM 禁用后追加 Last Buy、反 EOM 仍走线下 OA。

断货 积压 反 EOM

主动退市 / 被动退市要分开走

触发条件、发起节奏和是否维护新品切换不同；后半段清库到 EOL 共用。

主动退市 · 实时触发

产品 GTM 主导 · 替代新品已立项 / GR1

1
新老品切换计划记录迭代新品、预计 CR、上市时间
2
发起 EOM明确退市时间、预测覆盖、新品节奏
3

4
反 EOMBOM 已禁用仍需追加 Last Buy 时受控重启

项目价值

少损失、少催办、少断档；让决策、执行和复盘用同一套口径。

业务价值

  • 降损失：断货、积压、呆滞、专用料风险提前看见
  • 提效率：发起到 EOL 全程可视，缩短等待
  • 稳切换：新品里程碑与老品库存联动
  • 准计划：预测、库存、核料口径统一
  • 控异常：反 EOM、追加 LB、报废正式留痕

用户价值

  • 产品 GTM：发起完整，执行结果可回看
  • 需求计划：从拼表催办转向风险推动
  • 执行角色：待办写清何时、何品、做什么
  • 管理层：进度、风险、金额直接看
  • 交接人员：工单即完整上下文

管理价值

  • 统一流程、职责、口径和闭环标准
  • 线下协同变成可监控节点与 SLA
  • 报废、改制、转卖、Last Buy 进审计链
  • 按组织 / 品类 / 区域 / 原因复盘
  • 为组合与库存策略留下数据基础
