# 工作网具体方案（输入/输出绑定 × 状态图）· 试点 MVP

> 依据：`项目知识库.md`（试点 MVP）+ `03方案框架` + `协作流程-2.0设计` + 对象模型 MVP 对齐（2026-08）  
> 定位：在知识库之上，用「工作 ↔ 知识原子」绑定表达 **谁能开始、谁已完成、改版影响谁**。  
> 试点：KO→CR 全链模板；依赖边 **模板固定**（不自动推导）；视图 **只做 2 个**。

---

## 一句话结论

工作能不能开始、算不算完成，只看知识库里原子的 **定稿 / 冻结点**，不看上传 Word，也不看 PM 催没催。试点图上 **依赖边写在模板里**；上游改版只打角标，不把已完成打回灰色。

---

## 0. 试点范围（已对齐）

| 项 | 试点做法 |
|---|---|
| **阶段** | KO→CR 全链；约 **25～35 个工作节点**（解耦组×阶段产出包） |
| **依赖边** | **模板固定**（JSON/Excel）；跑稳后再从绑定自动推导 |
| **视图** | **项目条件图** + **我的待办**；解耦组 = 项目图加本组筛选 |
| **与知识库** | 只绑定 **知识原子**（试点组装页不作为工作输入/输出） |
| **派生** | 不做；接口争议走协同单 |

## 0.1 已拍板规则（试点执行以本表为准）

| # | 规则 |
|---|---|
| W1 | 工作绑定：① **需要** 哪些原子（输入）；② **产出** 哪些原子（输出，新版本）。 |
| W2 | **试点**：工作间依赖边写在 **全链模板** 里，维护 `上游工作 ID → 下游工作 ID`。完整方案目标仍为绑定推导，第二期启用。 |
| W3 | 输入须带 **必要/可选** + **最低要求**（`已定稿` 或 `冻结点=ES/TL/DR…`）。只绑「有这个对象」会亮太早。 |
| W4 | **未就绪（灰）**：必要输入未达最低要求。可看上游草稿，不能标完成。展示缺口（如 4/5）。 |
| W5 | **可开始（琥珀）**：必要输入均已满足，尚未开工。可开始 ≠ 必须马上干。 |
| W6 | **进行中（蓝）**：责任人已开工。 |
| W7 | **已完成（绿）**：必要输出均已 **定稿**（达该工作要求的冻结点）+ 责任人确认。不是上传文件。 |
| W8 | 可开始 **不用红灯**。待办汇总可用红作角标，不与「可开始」底色混用。 |
| W9 | **改版角标**叠在底色上，不退回灰、不盖绿。 |
| W10 | 上游新定稿/冻结：打「源已更新」。三选一：不升级 / 只升级钉扎 / 改输出。 |
| W11 | 仅「改输出」才给下游已完成工作打「需评估」角标。 |
| W12 | 已完成轮次保留；改输出是新版本，不抹历史。 |
| W13 | 开工时钉死满足条件的输入版本；之后源更新走 W10，不自动换钉扎。 |
| W14 | 粒度 = **解耦组在某阶段一次可独自验收的产出包**，不是每日任务。 |
| W15 | 同一原子可被多份工作先后产出（KO PRD v1、ES PRD v2）；绑定产出新版本，不独占。 |
| W16 | 裁剪项标 **不做**，不永久灰挡汇入。 |
| W17 | **试点两视图**：① 项目条件图；② 我的待办。JP 共识日仅参考竖线。 |
| W18 | 汇入可当特殊工作：输入 = 该 JP 的 **A 档原子** 均达冻结；输出 = `JP结论` 等。 |

## 1. 要解决什么

| 1.0 | 2.0 试点 |
|---|---|
| PM 催「今天交不交」 | 输入达冻结点 → 工作亮「可开始」 |
| 交文档就算过 | 输出在知识库定稿才算绿 |
| 上游改靠群 | 已完成仍绿 + 改版角标 |
| 手画任务依赖墙 | **模板固定边** + 绑定算状态 |

---

## 2. 与知识库的关系

```text
知识原子（定稿 / 冻结 / 钉扎）
        ▲ 产出定稿
        │
      工作
        │
        ▼ 需要（钉某一已定稿/冻结版本）
知识原子
```

工作完成写入原子；原子状态点亮下游工作。改版差异复用知识库钉扎与摘要，不另建版本体系。

---

## 3. 工作对象

名称、解耦组、责任人、对齐阶段/JP、输入/输出绑定、开工钉扎、状态、改版角标、计划时间（可选，责任人自填）。

---

## 4. 输入 / 输出绑定

### 4.1 输入

对象（原子）、必要/可选、最低要求（已定稿或某冻结点）、当前钉扎（开工后）。

**可开始** = 所有 **必要** 输入均有满足最低要求的已定稿版本。

### 4.2 输出

对象（原子）、必要/可选、完成要求（通常定稿；对齐 JP 时可要求打冻结点）。

**已完成** = 必要输出达标 + 责任人确认。

### 4.3 依赖边（试点：模板固定）

```text
全链模板列：工作 ID、名称、解耦组、阶段、输入绑定、输出绑定、上游工作 IDs
→ 渲染项目图时画边；改绑定不自动改边，需同步改模板（或第二期启用推导）
```

同一对象多生产者：边连到 **产出该冻结点的那份工作**（如 ID 外观 ES 冻结），不连到后续 DR 版工作。

---

## 5. 状态与颜色

| 状态 | 颜色 | 含义 |
|---|---|---|
| 未就绪 | 灰 | 必要输入未齐 |
| 可开始 | 琥珀 | 输入齐，未开工 |
| 进行中 | 蓝 | 已开工 |
| 已完成 | 绿 | 输出已定稿且已确认 |
| 不做 | 浅灰描边 | 已裁剪 |

**角标**：源已更新 N / 已评估·不升级 / 改版进行中（叠加，不改底色）。

---

## 6. 状态流转

创建/模板实例化 → 灰 →（输入齐）琥珀 →（开工+钉扎）蓝 →（输出定稿）绿。  
已完成遇源更新：仍绿 + 角标；不升级 / 只改钉扎 / 改输出三选一。不能从已完成退回灰。

## 8. 视图（试点：两个）

### 8.1 项目条件图

- 横轴：CD → KO → ES → TL → DR → BT → CR（JP 当列）
- 纵轴：解耦组泳道
- 节点：工作（底色 + 角标）
- 边：**读模板**，不实时推导

应能回答：谁可开始未开工、谁灰且缺哪条原子与上游责任人、谁绿带改版角标、某 JP 列 A 档输出是否齐。

**解耦组视角** = 同图加「本组」筛选，不单独第三套 UI。

### 8.2 我的待办

| 列 | 内容 |
|---|---|
| 待我处理 | 可开始未开工、进行中、需评估、改版进行中 |
| 等待中 | 灰 + 缺口 + 对方责任人 |
| 已完成 | 绿（有角标仍进待处理） |

时间条：自填计划 + 实际就绪/开工/定稿；JP 日仅参考竖线。

## 9. 粒度、模板、汇入点

**粒度**：独自验收产出包。例：「ID 外观 ES 冻结」「结构 ES 手板」「制冷 ES 调试结论」。

**模板**：家电全链预置「解耦组 × 阶段」默认绑定 + **固定依赖边**；KO 实例化并裁剪（W16）。全量清单按 H8120 协作表抽，单独维护模板表。

**汇入点工作**：输入 = 该 JP 的 A 档原子均达冻结；输出 = `JP-ES结论` 等。过/不过、回退走协作流程。

---

## 10. 权限

| 动作 | 谁 |
|---|---|
| 认领、开工、确认完成 | 工作责任人 |
| 改输入钉扎、升不升级 | 工作责任人 |
| 定稿输出原子 | 原子责任人（通常同一人） |
| 打阶段冻结点 | 汇入验收确认 |
| 裁剪工作、改模板 | PM/PD + 组主导，KO 时 |
| 看项目图 | 项目成员；无权限原子可脱敏显示「某输入未就绪」 |

---

## 11. 明确不做（试点）

| 不做 | 原因 |
|---|---|
| 上传文件 = 完成 | 退回网盘 |
| 红灯 = 可开始 | 语义冲突 |
| **试点期**绑定自动推导边 | 模板先跑稳 |
| 上游改版整链变灰 | 历史须可复现 |
| PM 在工作图排日计划 | 与 2.0 角色冲突 |
| 每日个人任务 | 粒度不对 |
| 第三种独立解耦组图 UI | 用筛选代替 |

## 附录 B · H8120 走查（结构 ES 手板）

1. 工作「结构 ES 手板」：输入 `外观主视觉@ES冻结`、`板框@已定稿`；输出 `ES样机状态` 等 B 档原子定稿。  
2. 外观未 ES 冻结：灰，缺口写明；结构可看 ID 草稿，不能绿。  
3. ID 定稿并 ES 冻结：琥珀。结构自选开工日；开工钉死外观 v1 与板框定稿。  
4. 输出定稿 → 绿；下游必要输入齐则各自琥珀。  
5. 外观 v2 打 TL：本工作仍绿 + 角标；不升级则下游不动；改输出才级联下游角标。  
6. 项目图 ES 列：看条件与 JP-ES 特殊工作，不是「结构怎么还不交」。
