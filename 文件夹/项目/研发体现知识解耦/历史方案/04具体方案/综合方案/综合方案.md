# 研发知识解耦 · 综合方案

> 依据：2026-09-10《研发解耦项目思路沟通》  
> 合成：`03方案框架/方案框架.html` + `03方案框架/中台化`  
> 口径：解耦组负责人

---

## 1. 现状 → 目标

**现在**

人跟着项目走，能力走不出项目。产品经理出一版文档，结构 / 电子 / 光学 / 制冷 / 嵌入式串行进场，PJM 催整包材料。做完一款，结论留在文档和群聊，下一款 SKU 再从头想。

**以后**

1. 打开历史 SKU，看到当时的模块组合。
2. 删减、新增，标出复用 / 二次开发 / 新做。
3. 已验证模块不进开发清单，人力放在新增。
4. 增量进协作区：Skill 出文档，按阶段节点汇入。
5. 未定稿（灰）变定稿（绿），回写模块货架和产品方案。

---

## 2. 分层架构（从下往上看）

按 ERP 能力建设的视角，项目层在上，模块方案在下。

```text
项目层（用户层）
  模块组合 · 按节点协作 · 推动更新 · 沉淀回写
        ↑
决策层
  复用 / 二次开发 / 新做
        ↑
产品方案
  SKU 绑定 · 模块组合 · 决策记录 · 未定稿 / 定稿
        ↑
模块方案（底层能力，解耦重点）
  结构 · 电子 · 光学 · 制冷 · 嵌入式
```

项目要做的事收成三句：**组合模块、推动更新、再沉淀。**

模块专业必须包含 **制冷**，与结构、电子、光学、嵌入式并列。

---

## 3. 工作闭环：项目怎么跑，日常方案怎么厚

增量协作做完必须回到项目沉淀：新方案先灰后绿，下一款才能接着用。五个框用箭头首尾相连。

```text
        1 项目沉淀
       ↗            ↘
5 增量协作          2 入库中台
       ↖            ↙
  4 识别焦点  ←  3 下一款选型
```

---

## 4. 协作区：如何协作（项目 + 日常方案）

中台决定用什么能力。选定之后，项目里和日常方案里怎么协作，用同一套方法。这就是环上第 5 步，也是回到第 1 步的入口。

| 块 | 做什么 |
|---|---|
| 结构化文档 | PRD 和专业输出按模块 / 字段生成。Skill 根据已选模块和补充需求出文档，归档后回写产品方案。文档结构化是产出，不是解耦目的。 |
| 条件工作 | 每个解耦单元看必要输入是否就绪。输入是钉扎过的模块方案或知识版本。能单验的先单验。 |
| 到点汇入 | 汇入点对齐 CD / KO / ES / TL / DR / BT / CR。带什么、过不过、谁回退写清。 |

### 四条规则

| 规则 | 项目里 | 日常方案 | 例子 |
|---|---|---|---|
| **启动** | KO 后各增量块认领目标、接口、自己策划资源。输入未定稿不能开工 | 补方案或改接口时同样认领输入版本，不必拉整机项目 | 制冷不等 ES 整机，接口字段就绪就排手板 |
| **调整** | 需求大变按 P0 / P1 / P2 分级 | 货架方案改档、改适用产品也要定级；影响已引用 SKU 的至少按 P1 通知 | PRD 改外观导致结构改模 |
| **协同** | A 块向 B 块提接口诉求，走协同单。达不成再升级 | 日常改开孔、改板框版本同样发协同单，禁止私聊定论 | 电子要结构改开孔 |
| **汇合** | 到 JP 带清单验收。不过时写清谁回退、别人能不能继续 | 日常方案定稿也是一次小汇合，然后变绿 | DR 试产制冷不达标 → 制冷 + 结构回退 |

P0：影响全项目目标或多个 JP。P1：影响 2 个以上解耦组接口。P2：组内微调，自决但留痕。判断无法按共识 JP 日汇合时，3 个工作日内发起调整或协同。

### 条件工作网

| 颜色 | 含义 |
|---|---|
| 灰 | 必要输入还是未定稿，或版本未钉扎，不能开工 |
| 琥珀 | 输入已定稿，对应角色才能开工并钉扎版本 |
| 蓝 | 在钉扎版本上产出；能单验的先单验；跨组缺口发协同单 |
| 绿 | 输出已定稿，下游或 JP 可引用；增量结果先灰回写，阶段冻结后再变绿 |

PJM 看哪条工作被输入卡住、哪个 JP 有风险，不细排每人每日任务。

### 跨组协同单

组间不再传「等结构发我包」，而是传明确字段（如板框版本 ≥ v2.1）。字段未达标，协同单可见，而不是项目经理私下协调。

```text
需求方发起
  → 写清字段 / 时点 / 影响
    → 响应方确认或拒绝
      → 达不成升级 P1 / P0
        → 结果写入上下文
```

### 到点汇入

碰头日看证据，不催整包材料。汇入点时间可以提醒，不是压缩内部排期的鞭子。

| 节点 | 项目里带什么 | 和货架的关系 |
|---|---|---|
| CD / KO | 模块组合已拍板，增量清单、接口和汇入点确认 | 复用项钉扎货架上的绿色方案版本 |
| ES | 各专业单验结论先齐套，再汇合整机是否可行 | 增量方案可以未定稿回写，先灰着进货架 |
| TL | 开模前冻结必须锁定的字段 | 被钉扎的模块方案不能悄悄换版 |
| DR / BT / CR | 试产轮次、用户测试结论、能否释放 | 阶段冻结或上市后灰变绿，成为下一款选型起点 |

衔接：

```text
中台选出模块方案
  → 增量进入解耦单元
    → Skill 生成结构化文档
      → 条件工作网推进
        → 协同单处理跨组
          → JP 汇入快照
            → 回写沉淀（灰 → 绿）→ 回到项目沉淀
```

## 5. 例子：H6199 从 H6076 起步

硬件产品经理打开已定稿的 H6076，而不是空白 PRD。

| 模块 | 怎么处理 | 决策 |
|---|---|---|
| 灯珠 | 方案一指标仍满足，已在 H6091 / H6076 验证 | 复用 |
| 电源 | 方案 B 只到 10% 调光，H6199 要 1% 深调 | 二次开发 |
| 灯体 | 仍是落地杆体，可继续用 | 复用 |
| 固件 | 墙板色温通道够用 | 复用 |
| 感应 | 货架没有，先作为 PRD 模块概念 | 新做 |

5 个模块里 3 个已验证复用。项目只接电源二次开发 + 感应新做。新方案先挂灰色未定稿，上市后变绿，H6199 写成产品方案。

家电同样走这条路径。例如从 H8120 制冰机开下一款，制冷模块若已定稿且指标满足，就复用。

## 6. 方案要求

| 编号 | 要求 | 验收口径 |
|---|---|---|
| C1 | 对外只讲一条路径 | 听完能回答：下一款从哪开始、项目里做什么、做完沉到哪 |
| C2 | 分层从下往上，制冷在模块层 | 图上项目在上、模块方案在下 |
| C3 | 未定稿灰 / 定稿绿 | 未定稿不能当正式复用基线 |
| C4 | 从历史 SKU 模块组合起步 | 能标出复用 / 改 / 新做，并给出人力焦点 |
| C5 | 决策权在解耦组负责人，项目只接增量 | 复用项不进开发清单 |
| C6 | 协作区承接增量 | 搭完中台后仍能说明项目里怎么干活 |
| C7 | 上市或阶段冻结后必须回写 | 下一款能引用上一款沉淀 |
