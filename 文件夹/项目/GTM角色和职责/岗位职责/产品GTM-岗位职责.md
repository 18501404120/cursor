# 产品 GTM 岗位职责

> 依据：《会议-GTM全流程》全渠道流出会议纪要整理。会议中对应「产品」侧 GTM（如产品规划、单品上市到退市、与 IPD/项目里程碑协同）。

## 1. 定位与范围

- 在 **4P** 框架下主责 **产品（Product）** 及与单品生命周期强相关的 **规划—上市—运营—退市** 全链路 GTM 统筹。
- 时间维度上覆盖：**从立项/规划到上市后约三个月的深度运营**，直至 **EOL**；与公司年度 BP 中的产品 Roadmap、上新节奏一致。

## 2. 核心职责

### 2.1 产品规划与市场输入衔接

- 承接 **商业洞察** 等输出的市场扫描、预测与机会判断，参与 **明年上什么、上多少节奏** 的产品规划输入。
- 维护产品与 **竞争、定价、渠道** 的联动假设，使 Roadmap 可落到 **价格、渠道、营销资源** 的后续拆解。

### 2.2 项目管理与跨部门节奏（IPD / 里程碑）

- 以 **项目管理** 为主线，推动 **开发与市场节点对齐**：掌握研发侧 **里程碑、变更、参数表/CD/CHD 模型** 等进度，避免「后端变更前端不知情」。
- 理想状态下要求 **研发项目里程碑与评审结论** 接入 GTM 项目视图；变更需触发 **市场等相关方评估** 后再执行（会议对标行业 IPD + 决策点逻辑）。
- 维护 **PCT/跨职能成员** 在各阶段的 **交付物、责任人、截止时间**：含营销 GTM、亚马逊、官网、服务、售后、交付等，保障 **加一/加二/加三/加四** 等节奏下物料与动作到位。

### 2.3 上市前流水线（一级～三级流程）

- 组织 **从样品到上市物料** 的流水线：**产品图 → KV → 营销材料 → POS/打样 → 发出**，明确各节点 **「谁、何时交付」**，避免上市时无样机、无素材。
- 将 **上市时间点（如加三之后）** 与营销三级流程锁死，系统或模板化 **到期提醒与串行依赖**，减少人肉催办。

### 2.4 产品信息与生命周期

- 建设并治理 **产品信息库**：场景、类目、渠道统一口径；字段含 **生命周期状态（含 UM 等）、在售/退市计划、各渠道即时/成交价与 RP** 等（与价格系统、渠道协同）。
- 主责 **产品状态** 在全渠道的一致性；**上市/launch** 等节点应能通过系统与研发/项目平台 **自动或规则化更新状态**。
- **退市管理**：EOL 节奏与库存、价格策略（如清仓调价）协同。

### 2.5 数据与系统需求

- **自有产出**：全渠道统一的产品主数据与状态、项目计划与交付验收。
- **依赖接入**：**SOP/BOM/EOM** 等供应与产品数据；**外部系统状态变更**（如加三/加四/Launch）自动同步；**产品信息库** 与产品经理侧数据源对齐合理性。

## 3. 产出物（示例）

- 单品/系列 GTM 项目计划、里程碑与 RACI、变更影响记录。
- 产品信息库维护规范与状态变更记录；上市检查清单与物料齐套确认。
- 与 Roadmap、退市计划一致的产品节奏说明。

## 4. 边界说明（会议共识）

- **年度产品规划体系化与深度产品洞察** 会议中部分归 **产品管理/产品线（如林佳伟侧）** 主责；产品 GTM 侧重 **可执行 GTM 项目化落地** 与 **跨部门节奏**，并 **强依赖** 上游规划与系统打通。
- **价格平台 Owner** 会议归 **区域 GTM**；产品 GTM 提供 **产品侧定价输入、生命周期与规格变更**，并消费统一价格口径。
