# 销售计划岗位职责

> 依据：《会议-GTM全流程》全渠道流出会议纪要整理。会议中对应 **「需求计划」、PSI（销售预测 + 要货）** 及与 **供应/工艺计划、库存** 的衔接；部分发言提到 **肖金存** 侧为 PSI 核心 Owner。

## 1. 定位与范围

- 作为公司 **需求与供应之间的枢纽**：把 **市场与销售意图** 转化为 **可执行的预测与要货**，并与 **工艺计划、发运、生产、库存** 对齐，形成 **共识计划** 再驱动执行（备料、生产、出库、销售）。
- 在 GTM 全链路中承接 **前置模块**（商业洞察、产品 Roadmap、定价、渠道策略、营销节奏）汇总后的 **销量假设**，落地为 **PSI 内可运算、可跟踪** 的数据。

## 2. 核心职责

### 2.1 销售预测（Forecast in PSI）

- 建立并维护 **全渠道销售预测** 逻辑与数据：与 **ROS/工艺计划、发运计划** 等后端计划对接。
- 推动 **预测模型** 上线与迭代：会议明确预测系数来自 **市场洞察、产品、营销、定价** 等前置信息，形成 **从大到小闭环**。
- 管理预测 **版本、调整记录与假设**，减少「销售提需求未测算就直接执行、事后不知盈亏」的情况（长期目标与经营测算衔接，会议建议分阶段）。

### 2.2 要货与 PSI 数据中枢

- 维护 **PSI** 作为 **公司级核心数据中转**：服务 **市场前端** 与 **后端工艺/供应**，包含 **Sales 预测 + 要货** 等模块。
- **导入/整合关键数据**：如 **客户 SO**（会议强调商超等需接入）、各渠道消耗；与 **生产、供应、库存** 数据联动，支撑可承诺与缺口识别。

### 2.3 需求计划 vs 供应计划

- 识别 **需求计划与工艺/供应计划** 之间的 **差异、缺料、产能约束**，输出 **可沟通结论**（会议提及理想状态：基于调整做 **情景模拟**——多卖多少 vs 额外成本，辅助决策；可分期实现）。
- 与 **区域 GTM** 在数据需求上 **高度重叠**（会议：销售计划除区域 GTM 所需外，更强调 **生产、供应、库存**）；在职责上更偏 **供应可行性与资源平衡**。

### 2.4 库存、周转与 DOS

- 与 **库存、流速、备货** 结合，支撑 **DOS** 等指标的分析与管理边界划分（会议：DOS 依赖库存数据，需与 SO、备货策略 **结合看**）。
- 将 **三号仓（会议提及在 PSI 内）** 等与 **后端备货** 打通时，与 **广告/消耗** 等前端数据协同，避免计划与执行脱节。

## 3. 产出物（示例）

- 滚动 **销售预测**、**要货计划** 与与供应对齐的 **共识计划**。
- PSI 内 **分渠道、分 SKU、分时间粒度** 的预测与实际消耗对比报表。
- 重大预测变更的 **影响说明**（产能、库存、发运、缺口）。

## 4. 数据与系统

- **自有/主建**：PSI 及与 ERP、生产、仓储的接口规范。
- **强依赖接入**：ROS 工艺计划、发运、生产实绩、库存；客户与渠道 SO；必要时与 **全渠道看板、财务管报** 对齐销量与经营口径。

## 5. 边界说明（会议共识）

- 会议曾讨论 **PSI Owner** 是否应为「计划」而非「需求」——无论组织名称如何，职责核心是 **预测 + 要货 + 与供应闭环**。
- **复杂经营测算**（如空运 vs 报废的精细模型）会议建议 **分阶段**；短期优先把 **PSI 内销售预测逻辑** 做扎实。
- **销售指标达成展示** 可与区域 GTM 共用 PSI Sell Out 等数据源，避免重复造数；**供应与库存** 侧指标由销售计划与供应链主牵。
