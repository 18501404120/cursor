GTM 系统架构

这份架构不是从技术组件出发，而是从 GTM 业务主线出发。 目标是把“市场洞察、产品 GTM、区域 GTM、销售计划、渠道执行、营销投放、供应履约、售后回流、经营分析”放进一个可落地的系统框架里， 明确系统分层、模块边界、协同机制和建设优先级。

这套架构解决什么问题

统一主线 让 GTM 从“岗位职责集合”变成“跨部门运营系统”。
统一口径 统一产品、价格、渠道、库存、经营数据，避免各看各表。
统一节奏 通过 PCT、项目里程碑和审批流，把上市与交付节奏对齐。
统一中枢 以 `PSI + 价格 + 产品信息 + 经营管报` 形成运营中枢。
双向协同 不是 PD 单向输出，而是 `PD ↔ GTM` 双向传递目标与约束。
分步建设 先做最小闭环，再补流程数字化，最后增强智能分析。
7 层架构 从触点层到技术平台层，完整覆盖业务和技术承载。
10 个业务域 洞察、产品、区域、PSI、渠道、营销、供应、售后、经营等模块分域建设。
3 阶段建设 `P0 / P1 / P2` 分阶段落地，避免一次性做成大而全系统。

一、架构分层

L7 触点层

亚马逊、自营、商超、官网、服务渠道等真实业务触点，是订单、反馈、评价、SO、售后问题的产生端。

L6 业务应用层

承载 GTM 核心业务模块，包括洞察、产品 GTM、区域 GTM、PSI、营销、售后和经营分析。

L5 流程编排层

固化 BP、PCT、里程碑、审批、预警等跨部门协同机制，解决“有系统但没有统一节奏”的问题。

L4 数据资产层

统一产品、渠道、客户、价格、库存、售后、经营等主数据和指标口径，避免多口径冲突。

L3 分析智能层

提供需求预测、价格测算、经营归因、异常诊断和策略建议能力。

L2 集成与接口层

连接 ERP、PLM/PD、WMS、TMS、广告平台、CRM、财务系统和渠道平台，降低重复录入。

L1 技术平台层

提供权限、API、消息、调度、日志审计和运行稳定性，是所有业务能力的底座。

架构的核心不是层数，而是把“触点、流程、数据、分析、系统接口”放进一个统一框架里。

二、核心业务数据流

GTM 系统的主价值，在于把跨部门动作变成可传递的数据流，而不是停留在线下沟通。

市场与渠道信号 洞察、渠道销售、广告、售后回流需求、竞品和用户信号。
产品与策略定义 产品 GTM、区域 GTM 把信号转成产品路线、4P 策略、价格和区域目标。
计划与履约闭环 销售计划通过 PSI 形成预测、要货、库存、发运和供需平衡。
经营与复盘 经营看板、管报、售后和渠道反馈回流，驱动下一轮 BP 与策略迭代。

三、功能模块地图

以下模块按业务域拆分，便于做需求归属、系统边界和实施规划。

战略与规划域
  • `BP 目标管理`：年度/季度目标分解、版本冻结。
  • `新品商业判定`：商业判定模板、评审与归档。
  • `Baseline 管控`：月度基线定义、偏差和滚动调整。
商业洞察域
  • `市场扫描`：行业、竞争、用户、渠道信息采集。
  • `趋势预测`：市场体量、需求变化、机会判断。
  • `SWOT 与机会池`：战略议题、机会清单、风险池。
  • `洞察输出中心`：结构化输出给产品、区域、销售计划。
产品 GTM 域
  • `路标与产品规划承接`：路标、上市窗口、优先级。
  • `GTM 项目管理`：里程碑、责任人、交付件、预警。
  • `产品信息库`：SKU、类目、场景、状态、卖点。
  • `上市准备中心`：样机、KV、素材、POS、渠道资料齐套。
  • `生命周期管理`：上市、稳定售卖、退市状态管理。
区域 GTM 域
  • `区域策略管理`：国家/区域/城市/渠道策略。
  • `渠道政策中心`：授权、返利、促销、特商规则。
  • `价格管理平台`：定价、FOB、RRP、调价、点位测算。
  • `区域达成管理`：目标拆解、执行跟踪、策略调整。
销售计划与 PSI 域
  • `需求预测`：分渠道、分 SKU、分周期预测。
  • `要货计划`：首批备货、补货策略、滚动计划。
  • `PSI 中枢`：Sell In、Sell Out、库存、在途、发运一体化。
  • `供需平衡`：缺口识别、情景模拟、预警。
渠道销售协同域
  • `亚马逊经营台`：Listing、活动、转化、评价反馈。
  • `自营渠道经营台`：页面、活动、订单、客服协同。
  • `商超/KA 经营台`：客户 SO、铺货进店、门店动销。
  • `渠道反馈回流`：问题回传 GTM / 产品 / 售后。
营销与广告域
  • `营销战役管理`：传播节奏、活动、素材排期。
  • `广告投放管理`：预算、投放、效果追踪。
  • `投放与库存联动`：投放前库存校验和预算节奏调控。
供应与履约协同域
  • `计划员工作台`：物料计划、补货、库存策略。
  • `PMC 排产协同`：产能、排程、插单、异常处理。
  • `NPI 导入协同`：试产到量产闭环。
  • `仓配履约协同`：仓储、物流、发运状态和异常追踪。
售后与质量闭环域
  • `售后工单与退换修`：故障分类、处理时效、退换修。
  • `质量问题回流`：批次问题预警、产品与研发回流。
  • `服务知识库`：FAQ、服务策略、渠道口径一致化。
经营分析与管报域
  • `经营看板`：销售、费用、利润、周转。
  • `管理报表（管报）`：区域/渠道/SKU/时间维度汇总。
  • `诊断与归因`：价格、渠道、供给、投放、产品归因。

四、流程编排重点

PCT 机制 建立 `PCT（Product Commercial Team）` 作战单元，通过例会做信息同步和共同决策，固化“`四快一慢`”节奏。
PD ↔ GTM 双向接口 `PD → GTM` 输出产品规格、样机、BOM、节点状态；`GTM → PD` 输出市场目标、价格带、渠道需求和供应窗口。
审批与预警流 覆盖定价/调价/特商、上市齐套、供需异常、经营偏差等关键流程，避免线下拍板。

五、数据资产重点

主数据 产品、SKU、区域、渠道、客户、价格规则、活动等统一主数据。
交易与执行数据 订单、发货、库存、SO、Sell Out、广告投放、售后工单。
流程与指标数据 里程碑、审批、变更、例会结论，以及销售/营销/经营/项目指标。
统一口径层 通过统一维度映射和指标口径，解决 ERP、财务、渠道系统之间的数据断层。

六、角色与模块映射

角色 核心模块 主要系统责任
商业洞察 市场扫描、趋势预测、机会池 生成策略输入与预测参数
产品 GTM 路标承接、项目管理、产品信息库、上市准备 管控上市节奏与生命周期
区域 GTM 区域策略、渠道政策、价格管理、达成管理 负责渠道与价格落地
销售计划 预测、要货、PSI、供需平衡 连接需求与供应
渠道销售 渠道经营台、SO 回流 真实销售执行与反馈
计划员 / PMC / NPI 物料、排产、导入协同 保障交付可达成性
仓库 / 物流 仓配履约、发运状态 订单履约与异常闭环
品牌 / 广告 战役管理、投放管理 流量与转化协同
售后 工单、质量回流 问题闭环和产品改进输入
财务 / 经营 管报、经营分析 经营指标权威输出

七、建设优先级

建议按最小闭环优先。先把业务跑通，再补强流程数字化，最后做预测和经营智能。

P0：最小闭环
  • `PSI 中枢`：预测、要货、Sell Out、库存。
  • `价格管理平台`：定价、调价、特商、点位。
  • `产品信息库`：SKU、生命周期、上市状态。
  • `经营看板与管报基础版`。
P1：流程联动
  • `PCT 例会与交付件数字化`。
  • `项目管理与上市齐套流`。
  • `PD ↔ GTM 双向接口事件化`。
  • `渠道 SO 自动接入`。
P2：智能增强
  • 预测模型优化。
  • 价格弹性与利润模拟。
  • 经营归因分析与策略推荐。
  • 售后问题自动回流产品迭代。

结论

GTM 系统不应做成单一“GTM 工具”，而应是一个以 `PSI + 价格 + 产品信息 + 经营管报` 为核心中枢， 向上支撑策略与流程，向下连接渠道与供应，向外联动 PD、财务、广告和售后的跨部门运营系统。

一句话定义：`GTM 系统 = 以商业成功为目标的跨部门运营系统，而不是某一个岗位的管理系统。`
