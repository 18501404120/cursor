# 全渠道系统模块梳理与按模块竞品分析框架

> **存放路径**：`文件夹/项目/GTM角色和职责/竞品调研/`  
> **文档性质**：调研提纲与模块蓝图；**本文档不包含**具体厂商功能对比、报价、截图与数据指标。  
> **适用场景**：全渠道（Omnichannel）能力建设规划、立项前模块边界对齐、后续分模块竞品深研的任务拆分。  
> **版本**：v0.1  
> **日期**：2026-04-16

---

## 1. 目的与使用方式

| 项 | 说明 |
|----|------|
| **目的** | 先统一「全渠道系统应包含哪些能力域」，再按模块判断是否值得做独立竞品对标，避免调研发散。 |
| **本文完成范围** | 模块清单 + 各模块典型子能力 + **竞品对标可行性判断（方向性）** + 后续深研待办项。 |
| **本文刻意不做** | 具体产品名单、功能矩阵打分、价格与商务条款、客户案例检索。 |

**建议后续动作**：以本文「模块」为一级目录，在 `竞品调研/` 下按模块拆分子文档（如 `订单与履约-竞品分析.md`），再开展证据型调研。

## 2. 「全渠道」边界说明（便于模块归类）

下文「全渠道」指：**多销售触点（自营电商、平台店铺、线下门店、B2B、社交电商等）在客户、商品、价格、库存、订单、营销与数据上可协同运营**的一类系统能力组合。  
实际产品中常表现为：**订单/库存中台 + 渠道连接器 + 营销/定价策略 + 主数据与报表** 的叠加；不同厂商打包粒度不同，竞品可能跨模块一体化出现，拆模块分析时需注明「对标的是子集还是全家桶」。

---

## 3. 全渠道系统建议模块总览

> 列「竞品对标」= 市场上**是否普遍**存在可单独或成组对标的产品方向（非结论「一定有某一家」）。

| 序号 | 模块 | 一句话定位 | 竞品对标（方向性） |
|------|------|--------------|---------------------|
| M1 | 订单与履约管理 | 全渠道订单归集、路由、拆合单、状态与异常处理，对接仓储配送 | **强**，OMS/电商 ERP 常见独立品类 |
| M2 | 库存与分货 | 一盘货、渠道库存策略、预留、调拨、安全库存与可售计算 | **强**，常随 OMS/ERP 或 WMS 组合出现 |
| M3 | 商品与主数据（PIM/类目） | 多渠道商品档案、规格、类目映射、上下架与生命周期 | **强**，PIM 与电商 ERP 均有 |
| M4 | 渠道与店铺运营 | 多店铺授权、平台政策适配、刊登/同步、运营工作台 | **强**，平台官方工具 + 第三方 ERP/运营中台 |
| M5 | 营销管理 | 活动、券、会员触达、内容分发、CDP/MA（可部分重叠） | **中–强**，垂直营销云与套件内营销模块并存 |
| M6 | 定价与促销管理 | 多渠道价盘、促销规则、防击穿、区域/渠道差异化定价 | **中–强**，独立 CPQ/促销引擎与 ERP 内模块并存 |
| M7 | 会员与客户运营（CRM） | 统一会员身份、积分等级、私域与客服协同 | **强**，CRM/SCRM 成熟品类 |
| M8 | 内容与数字资产（DAM） | 素材、详情页组件、合规与多语言 | **中**，独立 DAM 或套件弱模块 |
| M9 | 客服与售后 | 工单、退换货、质检、渠道客服路由 | **强**，客服 SaaS 与 OMS 售后衔接 |
| M10 | 财务结算与对账 | 平台账单、佣金、多主体对账、收入确认辅助 | **中–强**，业财一体与电商对账工具并存 |
| M11 | 数据与管报/BI | 跨渠道经营视图、归因、预警与专题分析 | **强**，BI 与行业管报方案 |
| M12 | 集成与连接（iPaaS/API） | 平台 API、Webhook、映射、监控与版本治理 | **强**，集成中台与厂商连接器生态 |
| M13 | B2B / 经销与渠道政策（可选） | 订货会、价目表、信用、返利与渠道合规 | **中**（视行业），分销/B2B 套件或 ERP 模块 |

## 4. 分模块说明（能力要点 + 竞品分析切分方式）

### M1 订单与履约管理

- **典型子能力**：抓单/拉单、审单、拆合单、预售与分批发货、发货与物流单号回传、取消拦截、异常单（缺货、地址、风控）、多仓路由规则。
- **竞品为何可对**：OMS 品类定义清晰，与平台、WMS、承运商集成是主要差异点。
- **后续深研建议**：按「日单量区间 × 平台覆盖 × 仓配模式」选对标对象；单列集成清单与 SLA。

### M2 库存与分货

- **典型子能力**：中央库存、渠道库存隔离/共享、预留与超卖策略、调拨在途、安全库存、补货建议与分货优先级。
- **竞品为何可对**：常与 M1 绑定，也有偏 WMS/供应链的独立方案。
- **后续深研建议**：区分「逻辑库存层」与「物理仓层」分别对标；关注大促与全渠道预售场景。

### M3 商品与主数据（PIM/类目）

- **典型子能力**：SPU/SKU 模型、多平台类目映射、属性模板、图片与合规字段、变体与套装、生命周期与区域可见性。
- **竞品为何可对**：PIM 与「带强商品能力的电商 ERP」均可作为对标来源。
- **后续深研建议**：主数据治理（谁主责、变更流）与「刊登效率」两条线拆表。

### M4 渠道与店铺运营

- **典型子能力**：多店多账号、权限与组织、刊登/同步策略、平台活动报名、绩效与健康度看板、违规与预警。
- **竞品为何可对**：运营中台、ERP、部分官方免费能力会重叠，需定义对标边界。
- **后续深研建议**：明确「只做连接器」还是「含运营方法论」两类竞品分开展示。

### M5 营销管理

- **典型子能力**：活动排期、券与满减、人群包、自动化旅程（与 MA 边界）、短信/邮件/企微触达、效果看板。
- **竞品为何可对**：营销云、CRM 营销模块、套件内营销与 CDP 组合均常见。
- **后续深研建议**：与 M6、M7 的边界写清（券与定价、会员积分重复问题），避免调研重复计数。

### M6 定价与促销管理

- **典型子能力**：价盘与版本、渠道/区域/客户组定价、促销叠加规则、限价与防击穿、试算与仿真、与平台活动对齐。
- **竞品为何可对**：独立促销/定价引擎与 ERP 内模块均有；复杂度因行业差异大。
- **后续深研建议**：区分 B2C 与 B2B 定价逻辑；关注「规则可审计」与「仿真」能力。

### M7 会员与客户运营（CRM）

- **典型子能力**：One ID、等级积分、权益、客服 360、标签与分群（与 CDP 可重叠）。
- **竞品为何可对**：CRM/SCRM 成熟；全渠道统一会员常需与中台项目联动。
- **后续深研建议**：线下门店与平台会员通兑场景单独列访谈提纲。

### M8 内容与数字资产（DAM）

- **典型子能力**：素材库、权限与版本、多渠道尺寸与合规、详情页组件化（与 PIM 衔接）。
- **竞品为何可对**：独立 DAM 存在；中小客户常弱化或用网盘替代。
- **后续深研建议**：若无独立预算，可标注为「套件弱对标」或「非必须模块」。

### M9 客服与售后

- **典型子能力**：工单、退换货 RMA、质检、与 OMS/财务状态联动、质检与责任判定。
- **竞品为何可对**：客服 SaaS 成熟；与订单/库存链路需看集成深度。
- **后续深研建议**：售后 SLA 与跨境场景单独成表。

### M10 财务结算与对账

- **典型子能力**：平台账单解析、费用项建模、多店铺对账、差异处理、收入辅助核算。
- **竞品为何可对**：业财产品、电商对账插件、实施型方案混杂。
- **后续深研建议**：按平台（亚马逊、天猫、抖音等）拆对账模板成熟度。

### M11 数据与管报/BI

- **典型子能力**：跨渠道指标字典、管报口径、权限、调度与自助分析、预警订阅。
- **竞品为何可对**：BI 与垂直「电商经营分析」产品均多。
- **后续深研建议**：与内部数仓/指标中台关系写清，避免与「数据中台」重复调研。

### M12 集成与连接（iPaaS/API）

- **典型子能力**：连接器市场、字段映射、重试与监控、API 生命周期、沙箱与版本。
- **竞品为何可对**：iPaaS 与头部 OMS/ERP 自带连接器生态均可对标。
- **后续深研建议**：列出必连系统清单再缩小竞品范围。

### M13 B2B / 经销与渠道政策（可选）

- **典型子能力**：订货、价目与合同、信用额度、返利与费用、渠道合规与审计。
- **竞品为何可对**：分销/B2B 套件、部分 ERP 强项；与纯 B2C 全渠道重叠度需评估。
- **后续深研建议**：若当前阶段以 DTC 为主，可标为二期或「弱优先级模块」。

## 5. 按模块做竞品分析时的统一输出模板（占位）

后续每个模块子文档建议固定包含以下小节（仍不强制填满具体厂商）：

1. **业务目标与范围**：本模块解决什么、不解决什么。  
2. **关键用户与场景**：3～5 条典型用户旅程。  
3. **能力清单**：必备 / 期望 / 可选。  
4. **竞品池（待填）**：产品类型 + 入选理由 + 排除理由。  
5. **对比维度**：功能、集成、性能、国际化、实施周期、TCO、生态。  
6. **差距与机会**：自有系统可切入的差异化。  
7. **风险与依赖**：数据主责、组织协同、合规。
