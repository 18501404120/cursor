## 全渠道需求预测

> **关联框架**：与 **库存与分货**、**定价与促销管理**、**营销管理** 强相关；向 **数据与管报** 输出偏差与准确率；与 **业务经营目标** 衔接目标达成风险。  
> **版本**：V3.0 · 2026-04-21  

---

### 1. 业务目标与范围

| 维度 | 说明 |
|------|------|
| **要解决** | 在促销、新品、季节、渠道差异下，输出 **SKU×地点×时间桶** 的需求分布；驱动补货、分货、安全库存、采购与产能预案。 |
| **边界** | 预测输出应为 **可解释** 的区间或情景，须绑定促销日历、事件变量。 |
| **与相邻模块** | 强依赖库存与分货、定价与促销、营销管理；向数据与管报提供偏差监控；与业务经营目标衔接。 |

### 2. 关键用户与场景

1. **需求计划**：基线预测、促销 uplift、人工覆盖与审计。  
2. **供应链**：安全库存、分货、补货与产能预案。  
3. **电商运营**：大促事件字典、复盘。  
4. **经管**：预测 vs 目标 vs 实绩三方对账。

### 3. 能力清单

| 层级 | 能力项 |
|------|--------|
| **必备** | 历史销量清洗、促销与节假日特征、基线预测、人工覆盖与审计。 |
| **期望** | 全渠道需求拆分、概率预测、与分货优化联动。 |
| **可选** | 深度学习、外部数据（天气、舆情）——需评估 ROI。 |

### 4. 竞品解决方案详解（每域≤3家 · 文档优先）

#### 4.1 o9 Solutions（集成业务规划 / 需求与情景）

| 类型 | 入口 |
|------|------|
| **产品说明** | [Retail demand planning（方案页）](https://o9solutions.com/solutions/retail-demand-planning/) |
| **界面与流程** | 以厂商 Demo / 实施蓝图为主；公开页偏价值叙事，**详细界面需 POC** |
| **价值说明** | 将需求、库存、财务约束与情景分析收敛到**同一数字孪生画布**，适合「SKU×渠道×区域×时间」高密度决策；强项是可解释的事件/促销 uplift 与多情景对比，减少计划会与 Excel 影子流程。对多事业部、多品牌共用主数据与指标字典时，能显著降低口径争议与版本分裂成本。 |
| **功能描述** | 典型路径：主数据与层级（产品/地点/渠道）建模 → 需求信号与历史清洗 → 在画布上叠加促销事件、约束与假设 → 输出多情景需求与供应响应，并与 S&OP 会议节奏对齐。底层多为内存计算与面向分析的模型层，通过集成连接器对接 ERP/数据湖；具体对象命名、权限粒度与批处理频率需 POC 对齐贵司数据粒度与组织职责。 |

#### 4.2 SAP Integrated Business Planning（IBP）

| 类型 | 入口 |
|------|------|
| **官方文档** | [SAP Help · SAP IBP](https://help.sap.com/docs/SAP_IBP) |
| **界面与流程** | Help 内按应用组件检索「Demand」「Response」等；Fiori 界面以租户为准 |
| **价值说明** | 与 **SAP S/4HANA、ECC、Ariba、TM** 等同栈集成时，可获得「主数据—交易—计划」一致语义，适合以 SAP 为核心的事实源企业；统计预测、约束传播与补货响应可在统一时间序列与供应网络模型上闭环，降低跨系统对账与接口漂移风险。对非 SAP 渠道占比高的企业，价值更多体现在「计划能力专业化」而非「开箱全渠道一体」。 |
| **功能描述** | 按 Help 组件划分：需求侧常见为统计预测、生命周期与促销 uplift、协同预测工作流；供应侧覆盖库存优化、补货、生产响应等，依赖 IBP 后端计算服务与 Fiori 应用。实施上需配置 planning area、master data（Location/Product/Resource）、time profile 与 key figure；与外部渠道/OMS 通常经 CPI/BTP 或中间件同步净需求与约束。全渠道「平台级日粒度×多店铺」常需额外数据层聚合与性能调优。 |

## 业务经营目标管理与目标规划

> **关联框架**：见附录性说明；**口径**：本章指业务经营数值目标（销量、销售额、毛利、核心费用、库存周转等），不含纯 HR 绩效口号层。  
> **版本**：V3.0 · 2026-04-21  

---

### 1. 业务目标与范围

| 维度 | 说明 |
|------|------|
| **要解决** | 经营目标在区域、渠道、品类、SKU、店铺、团队等维度 **可分解、可跟踪、可纠偏**；与预算版本、滚动预测、大促预案对齐。 |
| **边界** | 不替代法定合并；费用目标须与费控/营销等科目预先对齐。 |
| **与相邻模块** | 输出给数据与管报、定价与促销、库存与分货；输入来自管报关账与需求预测偏差。 |

### 2. 关键用户与场景

1. **经管 / 财务 BP**：下达与调整目标；监控费用率与毛利。  
2. **电商 / 渠道运营**：店铺级销量与推广费目标；大促闭环。  
3. **供应链计划**：在目标约束下配置库存与分货。  
4. **管理层**：同一套目标事实进入经营会材料。

### 3. 能力清单

| 层级 | 能力项 |
|------|--------|
| **必备** | 目标版本、分解矩阵、滚动修订、权限与审计、与实际对账。 |
| **期望** | 情景规划、资源约束可行性校验、与 S&OP 节奏绑定。 |
| **可选** | 与 EPM 直连、AI 辅助目标建议。 |

### 4. 竞品解决方案详解（≤3家）

#### 4.1 o9 Solutions（IBP 画布）

| 类型 | 入口 |
|------|------|
| **产品说明** | [o9 中国](https://www.o9solutions.com.cn/) · [Retail demand planning](https://o9solutions.com/solutions/retail-demand-planning/) |
| **界面与流程** | Demo / 顾问交付材料为主 |
| **价值说明** | 把经营目标、资源约束与供应能力放在同一画布上滚动推演，适合「目标—计划—执行」强耦合的 IBP 节奏；对多 BU、多币种、多情景版本并存的集团，可减少目标下达与计划反馈之间的往返邮件与离线表。 |
| **功能描述** | 实施上通常先固化指标字典与组织/产品层级，再配置情景维度与版本策略；目标分解、资源可行性与需求/供应响应在画布上联动，输出可审计的变更记录。与 ERP/EPM 的对接多通过标准连接器与批处理任务；主数据治理（谁维护 SKU 属性、谁定义渠道口径）是上线前必须拍板的架构点。 |

## 业务管理报表（管报口径 · 经营闭环）

> **关联框架**：与「数据与管报/BI」工具链互补：本章侧重 **管报关账、合并与指标口径**。  
> **版本**：V3.0 · 2026-04-21  

---

### 1. 业务目标与范围

| 维度 | 说明 |
|------|------|
| **要解决** | 法定与管理双口径下看清业务；GMV、净收入、毛利、费用、库存资金、应收与现金周期 **月结闭环**；异常可下钻订单/客户/SKU。 |
| **边界** | 管报侧重口径与关账；BI 侧重自助分析——可同平台或分层（指标中台 + BI）。 |
| **与相邻模块** | 强依赖数据与管报与财务/ERP；订单与库存估值须与管报事实一致。 |

### 2. 关键用户与场景

1. **经管 / 财务**：关账、合并抵消、事业部损益。  
2. **业务财务 BP**：渠道贡献、费用分摊解释。  
3. **IT / 数据**：指标字典、血缘、调度与权限。  
4. **管理层**：移动端订阅与预警。

### 3. 能力清单

| 层级 | 能力项 |
|------|--------|
| **必备** | 指标字典、维度一致性、关账日历、版本对比、权限。 |
| **期望** | 管报与预算/预测偏差、董事会模板、移动端订阅。 |
| **可选** | NL 问数（口径冻结前提下）。 |

### 4. 竞品解决方案详解（≤3家）

#### 4.1 Microsoft Power BI + 指标语义层

| 类型 | 入口 |
|------|------|
| **产品文档** | [Microsoft Learn · Power BI](https://learn.microsoft.com/en-us/power-bi/) |
| **界面与流程** | Learn 中「报表」「数据模型」「行级安全性」等分步说明 |
| **价值说明** | 连接器覆盖 **ERP、云仓、广告、Excel** 等广泛来源，适合「先统一可视、再逐步治理」的管报演进；语义模型（Dataset）+ 行级安全性可实现事业部隔离与同一套指标复用。对强合并、强关账流程，常需叠加 **Fabric 指标/数据仓库** 或外挂 EPM 承担「硬口径」角色。 |
| **功能描述** | 典型链路：Power Query 清洗与维度建模 → DAX 定义指标（含时间智能）→ 报表/仪表板发布到 Premium 容量或 Embedded → 通过 Gateway 定时刷新 on‑prem 数据源。管报场景需单独设计：指标血缘文档、刷新 SLA、RLS 角色表与「单一事实版本」发布流程；与钉钉/企微集成可走订阅与链接嵌入。 |
