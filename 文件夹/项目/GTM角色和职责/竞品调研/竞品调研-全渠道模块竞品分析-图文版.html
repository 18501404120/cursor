M1 订单与履约管理（OMS）

统一接入、编排、仓配路由与状态回写；与库存、渠道、集成强耦合。

业务目标多触点订单归一、审单拆合、寻源发货、异常与补偿可审计。
关键场景大促洪峰、预售分批发、跨仓路由、平台取消与拦截、3PL 轨迹回传。

Fluent Commerce

  • 云原生 DOM：订单捕获 → 编排 → 多履约单元 → 事件回写。
  • 强调 AI 连接器与履约可靠叙事（以官网为准）。

IBM Sterling OMS

  • 大型企业网络寻源、B2B/B2C 混合、复杂规则与高可配置。
  • 与 IBM 供应链套件组合交付常见。

聚水潭（国内 ERP）

  • 抓单、审单、打单发货与国内平台深度绑定，闭环快。
  • 复杂 DOM/全球多法人需评估上限或外挂中台。
对比要点 / 风险（展开）
对比Fluent/IBM 偏编排与中台化；微软 IOM 偏微软栈；聚水潭偏国内电商一体化。
风险幂等/重试缺失会导致重复发货；主数据（仓、地址）不一致拖垮 SLA。

M2 库存与分货

中央库存、渠道策略、预留/ATP、调拨在途；逻辑层与 WMS 物理层分层。

业务目标一盘货语义下给出可售与承诺，支撑 OMS 寻源与大促水位。
竞品方案Manhattan Active Inventory / ATP；NetSuite 多地点库存；SAP 库存与扩展仓；国内 ERP 同步平台可售。

Manhattan

  • 全局可视 + ATP，与门店/电商事件驱动同步。

NetSuite

  • 库存账本与财务同库；Saved Search 支撑分析。

国内 ERP

  • 多店库存推送实用；复杂 ATP 常需外挂或二期。

M3 商品与主数据（PIM）

单一事实来源、渠道映射、完成度与审批；输出给交易与营销。

竞品方案Akeneo（Family/Channel/Completeness）；inriver（PXM）；Salsify（快消数字货架）；ERP 内嵌商品档案。

Akeneo

  • 渠道子集 + 完成度门槛 + API 批量同步。

inriver / Salsify

  • 强分发与零售协同；快消 GDSN 等场景。
