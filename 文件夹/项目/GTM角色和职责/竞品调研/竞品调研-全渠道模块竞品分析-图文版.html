M1 订单与履约管理（OMS）

多触点订单归一、状态机、寻源与仓配编排、异常补偿；与库存预留、渠道 API、售后逆向强耦合。

模块能力与边界

必备接入与订单模型（头行税运/优惠拆行）、状态机、拆合单、取消拦截、发货回传、异常队列。
期望DOM、全局寻源/路由、预售分批发、部分发运、承运轨迹聚合、可版本化编排与灰度。
边界不替代 WMS 库内作业；不替代平台对交易的终裁规则；侧重企业侧编排与消息一致性。

竞品深度分析

Fluent Commerce

核心功能

  • 订单捕获与 canonical 模型；可版本编排（审单→寻源→预留→下发→确认）。
  • DOM：一单多履约单元（按仓/承运 SLA/批次），对客户侧可仍呈现一单。
  • 异常与补偿队列；与库存/承诺服务事件驱动协同。

如何实现

典型为微服务 + API 优先：渠道与 ERP/WMS 通过连接器或自建集成写入订单事件；编排引擎订阅事件并驱动状态迁移；库存侧通过 ATP/预留服务在承诺点前加锁。水平扩展依赖无状态服务与消息总线，规则与流程外置配置以支持多品牌。

关键分析

适合中台化、多区域；集成治理与可观测性成本进入 TCO，需配套主数据、幂等与死信规范。

IBM Sterling OMS

核心功能

  • 订单中心承载 B2B/B2C 混合、复杂合同价与多节点网络。
  • 履约优化：成本/服务等级/拓扑驱动的寻源；店发、仓发、直发组合。

如何实现

以高可配置规则引擎 + 适配器为主路径：与库存可视、ATP、门店及 EDI/ASN 生态对接；常与企业现有 IBM 供应链组件同栈实施。规则变更依赖受控发布与回归，多通过实施伙伴行业包加速。

关键分析

纵深与全球化强；实施周期与运维编制高，适合订单网络复杂、已接受套件化治理的大型客户。

Microsoft Dynamics 365 IOM

核心功能

  • 订单事件进入 Dataverse；与 Supply Chain / Commerce 模块协同。
  • 可结合 Power Automate 做低代码分支与人工审批。

如何实现

编排逻辑挂在微软云与 Power Platform：身份、审计、监控走 Azure AD / Monitor；与 D365 库存、主计划共享数据模型，减少异构复制。复杂 DOM 能力依赖模块版本与许可组合，需架构师划界避免与 ERP 库存重复实现。

关键分析

微软栈一致性最佳；跨 SKU 的非微软渠道仍靠集成项目补齐。

聚水潭等国内电商 ERP

核心功能

  • 平台拉单、审单、打单发货、电子面单、售后单与库存同屏。

如何实现

套件一体化 + 平台深度适配：订单与仓储、快递公司在同一产品内闭环，状态在库内联表推进而非独立 DOM 微服务。扩展通过开放 API 与脚本，大促容量依赖厂商云与店铺配额策略。

关键分析

国内上线快、平台贴合好；全球多法人 DOM、与 CPQ 合同深度耦合通常非主路径，需评估二期中台。

M2 库存与分货

中央库存、渠道可售策略、预留与 ATP、调拨在途；逻辑层与 WMS 物理库存分层。

模块能力与边界

必备多仓数量、渠道/店铺可售、预留释放、超卖防护、调拨在途。
期望ATP、全局可视、分货规则、预售分阶段释放、套装 BOM 扣减。
边界库内拣选/库位优化属 WMS；本域输出可承诺量与占用语义供 OMS 消费。

竞品深度分析

Manhattan Active Inventory

核心功能

  • 全局库存视图；ATP；渠道分配与服务等级。

如何实现

以实时库存服务为中心：各仓/店/在途通过事件增量更新；ATP 计算读取安全库存、已分配、在途入库承诺；对 OMS/ POS 提供订阅或查询 API。大促常配合缓存分区与预计算策略（视部署）。

关键分析

与全渠道订单同厂集成摩擦小；对数据延迟与一致性 SLA要求高。

Oracle NetSuite 库存

核心功能

  • 多地点库存账本；转移单；与 SO/PO 联动。

如何实现

同一数据模型承载财务成本与数量：地点维度库存事务写入总账接口；对电商渠道常通过集成中间层把「平台可售」映射为库存调整或渠道子账。ATP 能力偏 ERP 节奏，超高并发场景可能需前置缓存或 OMS 侧二次承诺。

关键分析

业财一致性强；纯实时秒杀型 ATP需架构补强。

SAP 库存 / IBP 等组合

如何实现

物料凭证驱动；ATP 在 SD/MM 链路中检查；全渠道扩展通过 CPI/ API 与 Commerce 或外部 OMS 同步。实施以流程模板+主数据清洗为主轴。

关键分析

规范与审计强；迭代成本需单独立项。

国内 ERP 库存同步

如何实现

定时/准实时任务将 ERP 可售推送到各平台库存字段；规则以运营可配置为主，ATP 数学模型相对简化，依赖平台侧限购与店铺级缓冲。

关键分析

落地快；复杂全网 ATP需评估外挂中台。

M3 商品与主数据（PIM）

单一事实来源、属性与变体、渠道映射、完成度与审批；向交易与营销输出结构化商品事实。

竞品深度分析

Akeneo

核心功能

  • Family/Attribute；Locales；Channels 子集；Completeness；Workflow。

如何实现

以产品实体 + 渠道视图建模：同一 SKU 在不同 Channel 上挂载不同属性集与完成度规则；通过 REST/API 与批量 job 同步到 Amazon、Shopify 等；变更通过消息或轮询触发下游增量。与 ERP 物料号通常做主从同步或双向 reconcile。

关键分析

模型清晰；谁主数据（PIM vs ERP）必须在项目初期写死。

inriver

如何实现

强调 PXM：弹性数据模型承载营销叙事与零售商 syndication；常与 DAM、电商前端一起做体验项目。技术路径为「核心 PIM API + syndication hub」。

Salsify

如何实现

偏快消 GDSN / 零售商模板校验：内容包按零售商 schema 输出；与「可售卖 Offer」分离，重在货架合规与速度。

电商 ERP 内嵌商品

如何实现

从平台回拉商品再编辑回写，主数据生命周期跟随运营节奏；弱于全球多语言合规与 PLM 工程 BOM 对齐。

M03 Markdown

M4 渠道与店铺运营

多店组织、刊登与库存/价格同步、平台政策与绩效；本质是「商业操作系统 + API」与运营治理。

竞品深度分析

Shopify Plus

核心功能

  • Organizations、Markets、Checkout 扩展；Hydrogen/Storefront API Headless。

如何实现

平台内核 + App 扩展：核心交易与店铺治理在 Shopify；OMS、ERP、搜索等通过 OAuth App 与 Webhook 接入。Shopify Functions 在结账链路注入业务规则（库存、折扣等，以平台能力为准）。

关键分析

迭代极快；强平台锁定与定制上限需架构接受。

BigCommerce

如何实现

REST/GraphQL API 一等公民；Multi-Storefront 在后台配置多店面目录与呈现；B2B 能力持续迭代。集成模式与 Shopify 类似但生态体量不同。

有赞 / 微盟

如何实现

门店+小程序+私域同一用户体系：订单、会员、导购任务在 SaaS 内闭环；对外通过开放 API 与 ERP/OMS 对接。平台深度强于国际 SaaS 的国内平台细节。

M04 Markdown

M5 营销管理

活动、旅程、触达、归因；与 CDP、CRM、定价券规则易重叠，需划界。

竞品深度分析

Salesforce Marketing Cloud

如何实现

Journey Builder 以事件/数据扩展表为入口；内容块调用 AMPscript/GTL；与 Data Cloud 做身份解析与细分同步。发送通道通过连接器对接短信、邮件、广告自定义受众等。

关键分析

企业级纵深强；许可组合与技能栈复杂。

HubSpot

如何实现

CRM 对象原生一体：工作流基于 CRM 属性与表单事件；营销自动化与管道阶段绑定，适合从获客到成交闭环。

Adobe Marketo

如何实现

面向 B2B 的线索评分与项目（Program）模型；与 Salesforce 等 CRM 双向同步 MQL/SQL；活动类型与渠道以营销操作为主数据。

M05 Markdown

M6 定价与促销管理

价盘版本、合同价、促销叠加、试算审计；B2B CPQ 与 B2C 平台活动分层。

竞品深度分析

Oracle CPQ + Subscription

如何实现

配置 BOM + 约束求解器生成可售配置；价格来自价目表、折扣矩阵与合同条款；结果写入报价单与订单行。订阅模块管理周期与用量，向收入分录规则输出事件。

PROS

如何实现

以数据科学 + 规则混合：历史成交、弹性、竞争信号进入优化模型；销售端 guided selling 约束折扣；与 ERP 通过 API 同步价目与审批状态。

平台内置（Shopify 等）

如何实现

脚本/Functions + 定时改价在交易路径执行；审计依赖平台日志与第三方 app。适合敏捷；集团级多法人价盘与法规试算常外挂 M6。

横向对比CPQ 系：B2B 合同与审计强，B2C 秒级大促需与前台协同。平台内置：执行敏捷，全局规则治理弱。

M06 Markdown

M7 会员与客户运营（CRM）

360、商机服务流程、会员权益；One ID 是全渠道前提。

竞品深度分析

Salesforce

如何实现

元数据驱动对象模型（Account/Contact/Case/Opportunity）；流程用 Flow/Process Builder；Customer Data Platform 侧做 ID 解析与细分回灌营销云。Loyalty Management 单独提供积分规则引擎。

Microsoft Dynamics 365

如何实现

Customer Insights 做 profile 合并；与 Azure AD、Teams、Outlook 深度集成；自动化用 Power Automate。适合已微软化的企业。

国内零售 SaaS 会员

如何实现

会员与门店导购、小程序订单绑定；积分储值在生态内闭环；对外用开放 API 与 ERP 对账。

M8 内容与数字资产（DAM）

素材版本、权限、合规、衍生尺寸；与 PIM 媒体字段协同。

竞品深度分析

Adobe AEM Assets

如何实现

资产以 JCR/CRX 或云资产服务存储，元数据 schema 可扩展；Dynamic Media 做图像模板与视频多码率；通过 Brand Portal 对外分发；与 Creative Cloud 工作流衔接。

Bynder

如何实现

云原生 SaaS：上传—审批—发布—CDN 分发；API 与 PIM/电商连接器同步 SKU 与 asset 关联键；权限到集合与角色粒度。

M08 Markdown

M9 客服与售后

工单、全渠道收件箱、RMA；与 OMS 库存释放、财务贷项联动。

竞品深度分析

Zendesk Suite

如何实现

Ticket 为核心对象：渠道（邮/聊/社媒/电话）统一路由；宏与触发器自动化；通过 Marketplace App 拉取 OMS 订单与发起 RMA；Explore 做 SLA 报表。

Salesforce Service Cloud

如何实现

Case + Omni-Channel 路由座席；与 Order Management 同栈时可单屏看订单履约状态；Field Service 处理上门；Einstein 做分类/建议回复（许可依赖）。

国内 ERP 售后

如何实现

退换货单与平台售后单号、仓库入库绑定；状态回写驱动库存与应收调整，流程在同一套件内短链路完成。

M09 Markdown

M10 财务结算与对账

平台账单解析、费用项映射、差异处理、总账接口；常介于业务中台与 ERP 之间。

竞品深度分析

NetSuite

如何实现

收入与应收模块承接SO 行；平台结算文件经脚本/集成导入为自定义交易或日记账；SuiteAnalytics 做店铺维度 P&L。三单匹配逻辑常需实施定义。

BlackLine

如何实现

专注匹配引擎 + 工作流：银行/平台流水与总账子目自动对账；例外项进入关账任务清单；与 ERP 通过认证连接器同步余额。

Stripe / Zuora

如何实现

支付与订阅：Balance transaction / Invoice 事件 API 拉取费用与退款；Zuora 管订阅周期与用量计费，收入确认规则可外挂。

M10 Markdown

M11 数据与管报 / BI

指标字典、语义层、自助分析、嵌入；依赖仓层建模与治理。

竞品深度分析

Power BI

如何实现

语义模型（Import/DirectQuery/Composite）；DAX 定义指标；Gateway 拉取内网 ERP；工作区权限 + RLS 行级安全；可嵌入 Power Apps/SharePoint。

Looker

如何实现

LookML Git 管理语义层；与 BigQuery 深度绑定；Looker Embed 将探索与仪表板嵌入产品；变更走 code review 流程。

Tableau

如何实现

可视分析 + Prep 清洗；Server/Cloud 发布；与 Salesforce CRM 数据衔接紧密；语义层相对灵活但需治理规范。

M11 Markdown

M12 集成与连接（iPaaS）

连接器、映射、API 管理、可观测性；全渠道胶水层。

竞品深度分析

MuleSoft Anypoint

如何实现

API-led：System/Process/Experience API 分层；Design Center 契约先行；Exchange 管理版本；Runtime 在 CloudHub/Fabric；策略（限流、OAuth、缓存）在 API Manager 统一。

Boomi

如何实现

Atom 运行时部署云或本地；图形化映射与连接器目录；Master Data Hub 可选；适合快速集成与中端企业。

Workato / Zapier

如何实现

Recipe/ Zap 事件触发短流程；适合非核心或运营自动化；核心交易链需评估事务性、幂等与顺序。

M13 B2B / 经销与渠道政策

订货、价目、信用、返利；主锚点选 ERP、Commerce 或 CPQ 需立项明确。

竞品深度分析

Salesforce B2B Commerce

如何实现

基于 Lightning：Buyer Group / Account 控制目录与价；购物车提交生成与 CPQ/ERP 对齐的订单；权限与审批用 Salesforce 平台能力。

NetSuite SuiteCommerce B2B

如何实现

电商前端与 同一 NetSuite 订单与 AR 交互：登录后可见合同价；信用额度占用 AR；减少中间件。

Shopify Plus B2B

如何实现

公司、价目、付款条款等原生能力扩展批发；复杂合同与返利仍常靠 App 或外挂 ERP。
