## 1. 两套数，不要混

| 名称 | 是什么 | 从哪出 | 谁提供 |
|------|--------|--------|--------|
| **被验数** | 管报按目标口径算出来的金额 | 一期无前端。研发导出 **`MSKU店铺费用明细`**：月份 + 渠道 + 店铺 + MSKU + 费用项 + 金额USD | 研发 / 产品 |
| **对照组** | 取值来源系统里、业务能打开的数 | 见第 3 节、见地图「对照组页面」 | 各包签字人 |

财务系统里的「亚马逊/自营/商超/分销利润报表」**不是默认对照组**。那是旧口径报表，用来看「管报 vs 现状差多少」可以，用来判「管报算没算对」会把口径差当成系统错。

只有主取值模式 = **财务系统同口径取数** 的行，才把财务利润报表 / 财务台账当对照组。

## 3. 对照组从哪出（按 8 种模式）

业务按包去取数，不要对着口径表猜。

| 包 | 主取值模式 | 对照组去哪 | 如何接到 MSKU |
|----|------------|------------|----------------|
| A | 平台报告取数 | **销售系统 → 工具 → 亚马逊报表导出 / 亚马逊财务报告下载**（Transaction）。抽查可开 Seller Central | 报告本身有 MSKU/订单。先按店铺+MSKU 汇总，再和被验数对 |
| B | 业务系统单据取数 | 按下表拆页面。其中 **出货/退货授权成本整项由 GTM 验证** | 单据有物料/MSKU 的直接对；没有的先对总额，再看管报卷积 |
| C | 项目预算取数 | **项目平台 → 项目 → 预算**（已通过立项） | 自主/联合营销下各末级逻辑相同，**只验一行通用项**：抽一个已通过项目，先对项目×归属月总额；管报若已拆到 MSKU，加总须等于项目预算 |
| D | 费用导入分摊 | **费用填报**已生效批次（含 **KOL**、**电商站外投放未关账**）。仓储/尾程账单不走本包 | 先对批次总额；电商站外投放关账后还要对财务覆盖数 |
| E | 计提/扣款规则计算 | 商超：**退款管理 / 扣款管理**；分销：**扣款单**、分销订单 | 商超先对客户×月，MSKU 加总等于客户金额 |
| F | 比例/参数计算 | **线下商超仓储租金**继续走海外仓仓租费率管理；**支付通道**按费用填报费率 × 当月营收 | 先验 费率 × 数量或营收 = 店铺合计，再卷积 |
| G | 财务系统同口径取数 | 利润报表 SKU；头程台账；**仓储租金/其他、尾程（Shopify/APP/3P）**对财务海外仓账单与 WFS；**亚马逊平台服务只对净额**；Shopify/APP **销售退款**对自营利润报表对应 MSKU | 渠道运营对照量级，财务确认账单/利润报表 |
| H | 汇总公式计算 | 不取源 | 产品勾稽：父级 = 规定末级之和 |

## 4. MSKU 怎么验、怎么往上卷

底表永远是 **月份 × 渠道 × 店铺 × MSKU × 末级费用项**。

卷积只加、不改口径：

```
MSKU  →  店铺  →  渠道  →  公司
```

源系统颗粒度不够时，**先在源系统能到的粒度对齐，再用管报往上卷证明没有漏、没有多**：

| 源颗粒度 | 先对哪一层 | MSKU 怎么用 |
|----------|------------|-------------|
| 店铺+MSKU | MSKU 逐行（可抽 Top + 随机） | 加总到店铺、渠道必须与汇总表一致 |
| 仅店铺 | 店铺合计 | MSKU 是分摊结果，抽 5 个看方向，不要求业务手算分摊 |
| 国家+客户 | 客户 × 月 | 该客户下全部 MSKU 加总 = 客户金额 |
| 场景、不分渠道 | 项目 / 场景总额 | 全渠道 MSKU 加总 = 项目预算（本期品牌营销暂不分摊则不应出现渠道拆分差） |

父级费用项（出货授权成本、品牌营销、平台佣金汇总等）**禁止当对照组去源系统找**。只验：父级被验数 = 指定末级被验数之和。

通过标准（差异评审会上确认即可）：

| 层级 | 建议 |
|------|------|
| MSKU 抽查 | 抽该渠道金额前 20 个 + 随机 10 个；对不上必须能解释（映射、空 MSKU 承接、四舍五入） |
| 店铺 / 客户卷积 | 差异率 ≤ 2%，或差异能逐笔说明 |
| 渠道合计（大额费用，占该渠道费用前 80%） | 差异率 ≤ 5%，且无未解释重记、漏记 |
| 公司合计盈亏方向 | 与财报不能相反 |

## 5. 谁签哪一包

| 包 | 签字人 | 不要签 |
|----|--------|--------|
| A 亚马逊平台报告 | 亚马逊运营 | 金蝶科目、财务覆盖公式 |
| B 金蝶等业务单据 | 对应渠道运营 | 分摊公式 |
| B1 授权成本 | **GTM** | 不要拆给渠道运营；不要验父级汇总 |
| B3 样品推广订单 | **渠道运营** | KOL 不在本包；不要对样品单以外的导入 |
| C 项目预算 | 品牌营销 | SKU 分摊是否精确 |
| D 费用填报（含 KOL） | **渠道运营** | 自动取数项；KOL 不要对样品推广订单；仓储/尾程不要对导入 |
| E 退款/扣款 | 商超运营 / 分销商务 | 滚动率推导 |
| F 费率参数 | 物流（商超仓租）/ 自营运营（支付通道） | 商超仓租不要改成财务账单；支付通道不要对导入批次金额 |
| G 财务同口径 | **渠道运营/财务** | 不要用管报业务预估数顶替财务定稿；仓储/尾程账单不要对费用填报 |
| H 汇总勾稽 | 产品 | — |

收入、退款没签字，费用验证不算数。顺序：销量/退货数量 → 零售销售额/销售退款 → 采购成本/关税/预留毛利 → 其余费用（按渠道金额 Top）。

## 7. 业务不要做的事

1. 不要用「收入里已扣退款」的净额去对管报零售销售额。
2. 不要用财务利润报表判管报对错（G 包除外）。
3. 不要在客户×月的源里找 MSKU。
4. 不要要求计提类与当月发票一致；看有没有重记、漏记。
5. 不要验父级汇总项。
6. 不要用费用填报去对 **仓储租金 / 仓储其他 / 尾程**（Shopify、APP、商超3P 已改为财务账单）。
7. 亚马逊 **平台服务** 不要拆三套来源分别对，只对财务或报告净额。
8. **支付通道手续费** 不要对导入批次金额，按填报费率 × 营收。
9. Shopify/APP **销售退款** 不要拆收单账单、退货、金蝶三套，直接对自营利润报表对应 MSKU。
