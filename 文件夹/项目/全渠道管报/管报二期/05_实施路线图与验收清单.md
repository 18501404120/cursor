# 实施路线图与验收清单

## 1. 总体实施策略

二期建议按“数据追溯底座优先，页面分析逐步增强”的方式实施。

优先级顺序：

1. 补齐费用明细的来源字段。
2. 建立来源单据、来源行、规则运行、导入批次、项目预算行的统一追溯关系。
3. 做费用项总览和明细下钻。
4. 做计算过程和来源单据详情。
5. 做分析图表、异常提示和财报差异。

## 2. 阶段拆分

### 阶段 0：二期口径冻结

交付物：

- 费用项清单冻结版。
- 费用部门映射冻结版。
- 主取值模式和来源类型枚举。
- 二期页面字段清单。
- 追溯字段标准。

验收：

- 每个末级费用项都有主取值模式。
- 每个费用项都有来源类型或汇总公式。
- 每个需要分摊的费用项都有分摊规则。
- 每个进入贡献利润的费用部门有明确标记。

### 阶段 1：来源追溯数据底座

交付物：

- 来源登记表。
- 来源单据表。
- 来源单据行表。
- 无明细来源标记。
- 费用事实表。
- 分摊明细表。
- 规则运行记录表。
- 数据批次和定稿状态字段。

验收：

- 费用明细可关联到来源单据、来源汇总记录或规则运行；财务同口径取数、无稳定行号单据允许标记为无明细来源。
- 导入批次、项目预算、退款、扣款、平台报告、业务单据均有统一来源编号。
- 分摊前金额和分摊后金额可校验。
- 已关账月数据可冻结。

### 阶段 2：费用项总览与明细下钻

交付物：

- 管报费用项总览页面。
- 费用明细页面。
- 筛选、排序、导出。
- 汇总金额到明细的跳转。

验收：

- 总览金额等于当前筛选下费用明细合计。
- 费用项父级金额等于下级费用项合计。
- 筛选条件在总览和明细之间正确传递。
- 数据批次和定稿状态显示正确。

### 阶段 3：来源单据详情与计算过程

交付物：

- 来源单据详情页面。
- 导入分摊计算过程。
- 项目预算进入管报过程。
- 扣款计提计算过程。
- 退款滚动计算过程。
- 规则版本和运行日志展示。

验收：

- 每条费用明细可打开来源详情。
- 导入分摊明细可解释分摊基数、比例和结果。
- 扣款管理可解释期初、实际扣款、计提扣款、期末余额。
- 退款管理可解释滚动率、目标窗口、实际退款、当月计提。
- 规则修改后能区分不同版本和生效月。

### 阶段 4：数据分析与财报对照

交付物：

- 费用趋势分析。
- 费用结构分析。
- 来源类型分析。
- 异常提示。
- 财报对照差异页面。

验收：

- 趋势图与明细汇总一致。
- 结构拆分与筛选条件一致。
- 财报差异金额等于管报金额减财务金额。
- 差异可跳转到管报明细和财务来源。
- 财务定稿覆盖有来源、金额和原因。

## 3. 接口建议

### 3.1 总览接口

`GET /api/mgmt-report/expense-summary`

入参：

- period_start、period_end
- channel、store、country
- msku、sku
- fee_dept_id
- fee_item_code
- primary_value_mode
- final_status
- data_batch

出参：

- fee_item_code、fee_item_name、fee_path、level、parent_code
- amount、amount_usd
- net_income_ratio
- mom_change、yoy_change
- source_count
- final_status
- has_finance_diff

### 3.2 明细接口

`GET /api/mgmt-report/expense-details`

出参应覆盖：

- 模板中的 `MSKU店铺费用明细` 字段。
- 来源追溯字段：source_type、source_doc_id、source_line_id、source_doc_no、rule_run_id、import_batch_no、project_budget_line_id。

### 3.3 来源详情接口

`GET /api/mgmt-report/source-detail/{source_type}/{source_doc_id}`

出参：

- 来源基础信息。
- 来源明细行。
- 管报落点。
- 操作日志。

### 3.4 计算过程接口

`GET /api/mgmt-report/calculation-trace`

入参：

- expense_fact_id 或 rule_run_id 或 allocation_id。

出参：

- 规则版本。
- 输入参数。
- 参与明细。
- 公式说明。
- 计算结果。

### 3.5 财报差异接口

`GET /api/mgmt-report/finance-reconciliation`

出参：

- 管报费用项。
- 管报金额。
- 财务字段组、财务字段。
- 财务金额。
- 差异金额、差异率。
- 对照公式/说明。
- 差异处理。

## 4. 数据校验清单

### 4.1 汇总校验

- 父级费用项金额 = 子级费用项金额合计。
- 总览金额 = 明细金额合计。
- 原币金额折算 USD 后与汇总 USD 一致。
- 正负方向按费用项配置处理。

### 4.2 来源校验

- 每条费用明细有来源类型。
- 非汇总公式类明细必须有来源编号；财务同口径取数、无稳定行号单据可只有来源汇总编号并标记为无明细来源。
- 导入类费用必须有导入批次号。
- 规则计算类费用必须有规则运行编号。
- 项目预算类费用必须有项目预算行号。

### 4.3 分摊校验

- 同一来源行分摊后金额合计 = 分摊前金额。
- 分摊比例合计应接近 100%。
- 分摊基数为空时应有异常标记。
- 已关账月分摊结果冻结。

### 4.4 定稿校验

- 已锁定月不能被普通重算覆盖。
- 财务定稿覆盖必须有覆盖来源。
- 历史过渡口径必须标记。

### 4.5 对账校验

- 差异金额 = 管报金额 - 财务金额。
- 差异率 = 差异金额 / 财务金额，财务金额为 0 时需特殊处理。
- 可对账验平费用项应能追溯到财务字段。

## 5. 测试场景

### 场景 1：费用导入分摊

1. 新增或导入一笔费用。
2. 预览分摊。
3. 生效后进入管报。
4. 在总览看到金额。
5. 下钻到明细。
6. 查看导入批次。
7. 查看分摊计算过程。

### 场景 2：项目预算进入管报

1. 项目立项预算行通过。
2. 预算金额按收益日期和分摊规则进入管报。
3. 在费用项分析看到趋势。
4. 明细可追溯到预算行。

### 场景 3：扣款计提

1. 维护客户计提规则。
2. 扣款管理生成计提扣款。
3. 录入实际扣款。
4. 期初、期末顺延重算。
5. 管报明细可查看扣款计算过程。

### 场景 4：退款滚动计提

1. 根据计提用收入和实际退款计算滚动率。
2. 生成当月计提退款。
3. 明细可查看目标窗口和滚动率计算。
4. 后续月份期初余额顺延。

### 场景 5：财报差异

1. 管报金额与财务金额产生差异。
2. 差异页展示差异金额和差异率。
3. 从差异跳转管报明细。
4. 从差异查看财务来源。
5. 财务定稿覆盖后展示覆盖标记。

## 6. 里程碑建议

| 里程碑 | 周期建议 | 交付重点 |
| --- | --- | --- |
| M1 口径冻结 | 1-2 周 | 费用项、部门、来源类型、追溯字段 |
| M2 数据底座 | 2-3 周 | 来源表、费用事实、分摊明细、批次/定稿 |
| M3 总览明细 | 2-3 周 | 总览、明细、筛选、导出、下钻 |
| M4 来源计算 | 2-3 周 | 来源详情、计算过程、规则版本 |
| M5 分析对账 | 2-3 周 | 趋势、结构、异常、财报差异 |

## 7. 上线准入

上线前必须满足：

1. P0 费用项均可展示总览金额。
2. P0 费用项明细均可追溯来源。
3. 导入、项目预算、退款、扣款、业务单据类来源至少各完成一个闭环样例。
4. 已关账月展示冻结数据。
5. 总览、明细、来源、计算过程、差异之间跳转正常。
6. 核心金额通过对账脚本或报表校验。
