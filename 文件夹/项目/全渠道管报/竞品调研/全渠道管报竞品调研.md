# 全渠道管报竞品调研

## 一、先说结论

这次调研重新收窄了范围，不再泛泛分析“谁做了数据中台/BI”，而是只回答你现在关心的落地问题：

1. 不同平台、不同渠道的费用，如何统一归到同一套管理维度。
2. 哪些费用属于营收之上，哪些属于营收之下。
3. 哪些费用可以直接归属到订单 / SKU / ASIN，哪些必须做渠道分摊或全渠道分摊。
4. 典型企业是如何通过系统把这些费用落进利润报表和管理报表里的。

### 1. 本次严格筛选结果

按照“必须有公开落地细节，否则不分析”的标准，真正能保留下来的样本其实很少。

本次**保留深度分析**的样本只有两类：

1. **使用领星利润/结算/多平台利润体系的跨境 3C 企业样本**
   包括：`OMOTON（宏泰祺）`、`GOX`、`COSCOD`、`ORICO`
   这类样本的价值在于：企业公开披露了它们确实在使用利润报表、结算报表、库存报表、广告报表等模块，而领星公开帮助文档又进一步披露了这些报表背后的具体费用归集与分摊规则，所以可以还原到“费用怎么落表”的层面。

2. **安克创新的费用治理样本**
   安克公开资料里没有完整披露最终利润报表公式，但明确披露了：
   - 多维度预算管控和费用归集
   - 预算滚动预测与调整追溯
   - 业务申请、报销、付款、预算与费用分析拉通
   - 业务与费用精细化分析

   因此安克可以作为“**平台外费用如何先进入系统**”的辅助样本，但**不足以单独还原完整 SKU / 渠道利润分摊公式**。

### 2. 本次剔除的企业

以下企业本次不做深度分析，不是因为它们不优秀，而是因为公开资料没有细到你要的层面：

1. `小米`：公开到销售数仓、集团看板、指标治理，但没有公开到跨渠道费用归集和分摊公式。
2. `绿联 UGREEN`：公开到经营规模、平台结构、智能仓储方向，但没有公开到利润口径和费用分摊层。
3. `Baseus 倍思`：公开到 VOC、客户体验和产品创新闭环，但没有公开到全渠道利润归集逻辑。
4. `Aqara 绿米`、`Govee`：公开到全球渠道和经营模式，但没有公开到具体管理报表和费用核算方法。
5. `韶音 Shokz`：公开到“业财结算中台项目启动”，但没有披露足够细的费用映射和分摊规则。

## 二、竞品落地的共同结论

从可公开验证的样本看，跨境 3C 企业在落地全渠道管报时，并不是先讨论页面长什么样，而是先把这四件事做清楚：

1. **统一利润维度**
   先统一“平台 / 店铺 / 站点 / ASIN / MSKU / SKU / 订单 / 负责人”之间的映射关系。

2. **统一利润结构**
   先定义哪些属于收入主项、哪些属于营收调整项、哪些属于平台直接费用、哪些属于履约成本、哪些属于共享费用。

3. **统一分摊基数**
   对无法直接归属到商品的费用，统一采用销售额、销量、花费占比、自然日均摊等规则，不允许每个部门自己定义。

4. **统一数据入口**
   平台能直接拉取的费用走 API / 账单；平台外或线下费用走导入/报销/预算系统，再按统一口径进入利润报表。

换句话说，竞品真正落地时，核心不是“做一张大报表”，而是先构建一张**统一利润地图**。

## 三、从竞品还原出来的统一利润地图

这一部分是整个调研最关键的内容。它不是单一企业自己发明的一套逻辑，而是从 `OMOTON / GOX / COSCOD / ORICO` 等使用同类利润体系的样本中，还原出来的**高可信落地模板**。

## 3.1 统一分析维度

竞品在利润报表落地时，通常会把维度统一成下面这条链路：

1. `平台`：亚马逊 / Walmart / eBay / 速卖通 / 线下商超 / 独立站
2. `店铺 / 站点 / 渠道主体`
3. `父ASIN / ASIN`
4. `MSKU / SKU`
5. `订单`
6. `负责人 / 店长 / 类目运营`

其中最关键的是：

1. **MSKU 是利润计算最稳定的基础颗粒度**
   很多费用最终都是先落到 MSKU，再向上汇总到 ASIN、店铺、渠道。

2. **店铺维度不是最终利润维度，而是费用容器**
   很多平台级、渠道级、店铺级费用，先落到店铺，再往商品维度分摊。

3. **ASIN / SKU / 店铺三者必须能映射**
   如果 ASIN 对应多个 MSKU，费用就不能直接落，而要继续按销售额占比拆分。

## 3.2 营收之上 / 营收之下的竞品做法

为了回答“哪些费用在营收之上，哪些在营收之下”，先把竞品的利润结构拆开。

### A. 营收主项

这一层属于“收入本体”，通常直接来自平台交易或订单系统：

1. 销售额
2. 买家运费
3. 包装收入
4. 其他收入

### B. 营收调整项

这一层本质上是**对收入的冲减或校正**，虽然在很多系统里会单独展示，但管理上通常放在“营收之上”或“净收入形成过程”里看：

1. 退款量
2. 收入退款额
3. 费用退款额
4. 促销折扣
5. 平台代收销售税 / 市场税
6. 放款差异

### C. 营收之下的第一层：平台直接费用

这类费用和平台成交强相关，一般直接放在营收之下：

1. 平台佣金
2. 平台物流费
3. 平台仓储费
4. 广告费
5. 信用卡费用
6. VINE 费用
7. 平台其他费
8. 清算相关费用

### D. 营收之下的第二层：商品与履约成本

这类费用与商品或履约链路直接相关，通常单独列在成本侧：

1. 采购成本
2. 头程成本
3. 尾程成本
4. 包装耗材
5. 海外仓履约成本
6. 退货处理成本

### E. 营收之下的第三层：渠道/共享费用

这类费用通常不能直接从平台订单中拿到，而是通过导入、费控或预算系统进入利润报表：

1. 店铺费用
2. MSKU 费用
3. 渠道推广费
4. 线下商超推广费
5. 品牌广告 / PR / 内容传播费
6. 样机 / 测试 / 展示费用
7. 软件工具费
8. 团队 / 组织共享费用

## 3.3 哪些费用直接归属，哪些费用必须分摊

### 1. 可直接归属的费用

这类费用通常不做二次分摊，直接落到订单、商品或 MSKU：

1. SP / SD 等直接有商品归属的亚马逊广告费
2. 订单级平台佣金
3. 订单级平台物流费
4. 订单级促销折扣
5. 订单级退款
6. 采购成本
7. 尾程成本
8. 有明确商品归属的特殊调整费

### 2. 需要店铺 / 渠道内分摊的费用

这类费用没有天然的订单归属，但能明确属于某个店铺或渠道：

1. 店铺订阅费
2. 平台月度仓储费
3. 店铺级广告费差异
4. 渠道 SEM 投放
5. 店铺其他费
6. 线下商超渠道推广费
7. 渠道陈列费 / 入场费 / 店庆活动费

### 3. 需要全渠道分摊的费用

这类费用通常不属于单个平台，也不属于单一渠道，而是品牌或组织共享费用：

1. 品牌广告
2. PR 传播
3. 公共内容团队费用
4. 样机类公共费用
5. 总部共享团队费用
6. 公共系统费用

竞品公开资料里，能完全公开到“全渠道共享费用公式”的企业非常少，但从安克的费控实践和领星的预估费用机制可以确认：**这类费用通常不会留在 Excel 里，而是会先进入预算/费控/预估费用模块，再按统一规则分摊。**

## 3.4 竞品公开可确认的分摊逻辑

这一部分最贴近你关心的“分摊逻辑是怎样的”。

### 1. 亚马逊广告费怎么分

根据领星公开的结算利润帮助文档，亚马逊广告费的落地方式是：

1. `SP`：原始广告报告中已能对应到 MSKU，直接归属到商品维度。
2. `SD`：原始广告报告中已能对应到 MSKU，直接归属到商品维度。
3. `SB / SBV`：先找到广告活动关联的 ASIN，再把 ASIN 映射到对应 MSKU；如果一个 ASIN 对应多个 MSKU，则按这些 MSKU 的销售额占比分摊。
4. 如果当天广告对应的商品没有任何销售数据：
   - 若当天完全没有 MSKU 产生数据，则保留一条空 MSKU 的费用记录；
   - 若当天有多个 MSKU 但都没有销售额，则平摊到每个 MSKU。
5. 如果广告发票和广告业务报告之间存在差异金额，则差异部分按销售额占比分摊到每一天、每一个 MSKU。
6. 广告发票中的税费、调整费，会先按广告花费占比分摊到具体广告，再随广告一起进入商品利润。

### 2. 月仓储费怎么分

根据公开帮助文档，月仓储费的落地规则是：

1. 先取平台月度仓储费总额。
2. 再把月仓储费平摊到当月每一个自然日。
3. 每一天的仓储费，再按当天各 MSKU 销售额占比分摊到每一个 MSKU。
4. 如果当天有 MSKU 但都没有销售额，则在当天参与商品间平摊。
5. 如果当天没有任何 MSKU 产生数据，则保留一条空 MSKU 的仓储费记录。

这个逻辑的意义是：**因为报表支持按天看利润，而仓储费通常按月结算，所以必须先做“按日均摊”，再做“按商品分摊”。**

### 3. 店铺费用怎么分

根据多平台利润报表帮助文档：

1. 店铺费用支持单独导入。
2. 导入后，系统会自动把该费用按指定月份分摊到该店铺下的 MSKU / SKU 维度。
3. 导入支持覆盖和累加两种方式。

这意味着，像下面这些费用都可以按“店铺 / 渠道费用”落表：

1. 线下商超渠道推广费
2. 商超陈列费
3. 门店活动支持费
4. 渠道返利
5. 店铺订阅费
6. 线下门店联合营销费

### 4. MSKU 费用怎么分

如果某些费用天然就是商品级费用，就不应再按店铺泛分摊，而是直接导入为 MSKU 费用：

1. 特定 SKU 样机费
2. 特定 SKU 测试费
3. 特定 SKU 特殊推广费
4. 特定 SKU 的品牌联名费用

导入后，系统会直接归到“对应店铺 + 对应 MSKU”。

### 5. Walmart 广告费怎么分

多平台利润报表对 Walmart 披露了更细的逻辑：

1. `Walmart Product Advertising`  
   如果无法明确归属于某一个商品，则按该月份内、该店铺下所有商品销售额占比分摊。

2. `SEM Marketing`  
   默认按照 MSKU 销售额占比分摊。

这个逻辑非常关键，因为它说明竞品并不是要求所有广告都必须直接归属到商品，而是允许：

1. 能直归就直归
2. 不能直归就先落店铺 / 渠道，再按销售额占比拆下去

### 6. eBay 广告费和店铺订阅费怎么分

公开帮助文档显示：

1. 有归属订单商品的广告费，直接匹配到订单商品。
2. 没有归属订单商品的广告费，按销售额占比分摊。
3. 店铺订阅费、研究订阅费等，按店铺维度费用处理，再按销售额占比分摊到商品。
4. 一般性的调整费，也走店铺维度费用分摊逻辑。

### 7. 头程成本怎么分

多平台利润报表公开逻辑显示：

1. 如果用 `成本中心` 取值，头程成本取自销售出库单物流运费或成本中心记录。
2. 如果用 `固定值` 取值，则头程成本取自产品管理中维护的国家默认头程。
3. 支持做“国家映射”，比如意大利订单可以映射到英国头程模板。

这说明竞品落地时，头程成本至少有两套做法：

1. **精确模式**：从成本中心或出库单取真实成本
2. **估算模式**：按国家 / 站点默认头程模板取值

### 8. 平台外 / 线下费用怎么进利润表

这部分正是你最关心的。

从安克的费控案例和领星的预估费用 / 店铺费用 / MSKU 费用机制看，公开可确认的落地思路是：

1. 平台直接提供的费用，走平台账单/API。
2. 平台外费用，走费控系统或利润报表导入。
3. 能明确归到商品的，导入为 MSKU 费用。
4. 能明确归到渠道 / 店铺的，导入为店铺费用。
5. 品牌级、总部级、全渠道共享费用，导入为预估费用或预算费用，再按统一规则分摊。

也就是说，**线下商超推广费**在成熟落地里，通常不会单独游离在 Excel 外，而是：

1. 如果对应某个商超渠道或门店，归为 `渠道 / 店铺费用`
2. 如果对应某个指定 SKU 活动，归为 `MSKU 费用`
3. 如果是全国品牌联合推广，归为 `全渠道共享营销费用`

## 四、样本企业深度拆解

## 4.1 OMOTON（宏泰祺）

### 4.1.1 为什么保留这个样本

这是本次最有价值的公开样本之一，原因是它公开到了：

1. 通过 API 打通亚马逊后台和自研系统
2. 使用利润报表、库存报表、结算报表、回款报表
3. 财务可以看到每一个 ASIN 的盈亏情况
4. 可以通过成本项对比分析，定位“广告投入过高”“采购成本占比过高”等亏损原因

这已经非常接近你要的“真实落地样子”。

### 4.1.2 公开可确认的落地方式

1. `数据入口`
   - 亚马逊后台数据通过 API 拉取
   - 自研系统数据同步接入
   - 财务可一键导出平台报表

2. `核心报表`
   - 利润报表
   - 库存报表
   - 结算报表
   - 回款报表

3. `使用方式`
   - 运营每天看产品利润和广告效果
   - 财务每月基于利润报表、回款报表、结算报表出经营统计
   - 财务能看到每一个 ASIN 的盈亏情况

4. `利润问题定位`
   - 可按成本项对比发现亏损原因
   - 公开案例明确举例：广告投入过高、采购成本占比过高

### 4.1.3 费用如何落地

结合 OMOTON 使用的利润体系公开文档，可还原其典型做法：

1. 亚马逊销售额、买家运费、退款、平台费、广告费直接来自平台账单和广告数据。
2. 采购成本、头程成本、库存成本由 ERP / 成本中心侧补齐。
3. 店铺级费用与商品级费用通过导入机制补齐。
4. 所有费用先落到 MSKU，再汇总到 ASIN、店铺、负责人。

### 4.1.4 对你这个项目最有价值的点

1. 这类企业不是先按渠道出总利润，而是先把利润算到 `ASIN / MSKU`。
2. 费用不是混算，而是必须能拆出“广告太高”还是“采购太高”。
3. 报表不是财务月末才看，而是运营日常就看。

### 4.1.5 适合借鉴的落地动作

1. 先做 `SKU + 渠道` 的利润底表
2. 再把广告、采购、头程、仓储、退款、平台费拆成独立字段
3. 再补 `店铺费用 / 渠道费用 / 共享费用` 的导入和分摊机制

### 4.1.6 参考资料

1. [亚马逊百强品牌OMOTON如何以财务数据驱动业务决策，实现业务高效运作？](https://www.52by.com/article/138960)
2. [结算利润-领星ERP帮助文档](https://www.lingxing.com/help/article/MonthlyProfitReportnew)

## 4.2 GOX

### 4.2.1 为什么保留这个样本

GOX 的价值在于，它公开披露了一个 3C 配件企业如何把销售、评论、广告、库存、物流、成本这些经营要素放进同一套系统里，支撑产品和财务共同决策。

### 4.2.2 公开可确认的落地方式

1. 拉取 ASIN、MSKU 等维度销售数据。
2. 自动生成产品表现报告。
3. 自动统计 Review 和 Feedback。
4. 广告投放和广告分析在同一系统内完成，且数据维度比平台后台更多。
5. 自动统计并核算利润、库存、成本的精细数据。
6. 店铺、负责人维度目标可持续跟进。

### 4.2.3 能确认到的费用口径范围

GOX 公开资料里能确认的是：

1. 销售
2. 退货
3. 库存周转
4. 广告转化率与广告出单
5. 物流
6. 成本
7. 利润

虽然它没有像帮助文档那样公开到公式级别，但可以确认它已经把这些数据放进同一套管理口径，不再是部门各算各的。

### 4.2.4 对本项目的借鉴点

1. 对 3C 配件类企业，产品评价、退货率和广告转化不能放在经营分析体系之外。
2. 如果运营每天都在看广告和产品表现，那利润报表也必须日更或准实时。
3. 管报不能只做财务看板，还要兼容运营用数场景。

## 4.3 COSCOD

### 4.3.1 为什么保留这个样本

COSCOD 的价值在于，它公开披露了一个消费电子卖家如何把采购、仓储、物流、销售、广告、成本、利润放进同一套数据分析体系，用来支撑精细化运营。

### 4.3.2 公开可确认的落地方式

1. 每小时自动获取各站点、各产品维度广告数据。
2. 自动整合采购、仓储、物流、销售、广告、成本、利润等多维数据。
3. 自动拉取本地仓、FBA 仓、海外仓数据，形成库存报表。
4. 利润报表、产品表现、店铺表现等报表更新速度快于平台原生数据。
5. 异常如利润降低、成本超支可以尽早发现并纠偏。

### 4.3.3 从公开资料能还原的利润思路

COSCOD 实际上已经把经营报表分成三层：

1. `经营输入层`：采购、仓储、物流、广告
2. `经营结果层`：销售、产品表现、店铺表现
3. `经营判断层`：利润报表、库存健康、异常识别、补货和头程方案

这和你们现在要做的全渠道管报非常接近。

### 4.3.4 对本项目的借鉴点

1. 采购、仓储、物流、广告不应该是并列系统，而应该在利润视角下统一起来。
2. 头程方案和补货量，本质上也应该由经营分析结果反推，而不是独立拍脑袋决定。
3. 管报需要把“异常发现”当成功能目标，而不是只做静态展示。

## 4.4 ORICO

### 4.4.1 为什么保留这个样本

ORICO 的公开信息没有 OMOTON 那么细，但它至少明确披露了三件事：

1. 数据智能分析
2. 采购供应链优化
3. 广告 ROI 优化

并且给出了结果指标：

1. 订单响应时间从 72 小时压缩到 8 小时
2. 库存周转率提升 60%
3. 单月可支撑百万级订单处理

### 4.4.2 能确认到的落地重点

ORICO 这个样本更偏“经营效率”而不是“财务公式”，但仍然说明了一点：

对于大体量 3C 企业，利润报表的真正价值不是做完账，而是反过来推动：

1. 采购
2. 供应链
3. 广告 ROI
4. 库存周转
5. 订单响应

### 4.4.3 对本项目的借鉴点

1. 管报一旦落到大企业，不会只看财务结论，而会直连供应链和广告决策。
2. 如果利润看板不能反推采购和补货动作，它的价值就只停留在“记账”层。

## 五、针对你这个项目最重要的落地模板

这一部分不是额外发挥，而是把上面竞品能公开确认的做法，直接转成你们项目可以使用的费用模板。

## 5.1 统一费用一级维度建议

建议把所有费用先统一到这六个一级维度：

1. **收入主项**
   销售额、买家运费、包装收入、其他收入

2. **营收调整项**
   退款、收入退款额、费用退款额、促销折扣、税金调整、放款差异

3. **平台直接费用**
   平台佣金、平台物流费、平台仓储费、平台广告费、平台其他费

4. **商品与履约成本**
   采购成本、头程、尾程、包装、退货处理

5. **渠道营销费用**
   亚马逊广告费、Walmart Product Advertising、SEM Marketing、线下商超推广费、陈列费、导购费、返利

6. **共享管理费用**
   品牌广告、PR、内容传播、样机、工具费、总部团队费、公共系统费

## 5.2 你关心的“亚马逊广告费”和“线下商超推广费”怎么统一

建议统一到同一个一级维度：`渠道营销费用`

但在二级维度上分开：

1. `站内广告费`
   - 亚马逊 SP / SB / SD
   - Walmart Product Advertising
   - eBay Promoted Listings

2. `站外渠道推广费`
   - SEM
   - 社媒投放
   - 联盟营销

3. `线下渠道推广费`
   - 商超陈列费
   - 导购费
   - 联合促销费
   - 进场活动费
   - 渠道返利

这样做的好处是：

1. 在管理层总览里，这些都能汇总成“渠道营销费用”
2. 在渠道分析页里，又能继续拆出“亚马逊广告费”和“线下商超推广费”

## 5.3 分摊规则建议

### 1. 直接归属规则

能直接匹配到订单 / SKU / ASIN 的费用，不分摊，直接归属。

适用：

1. SP / SD 广告
2. 订单级平台费
3. 订单级促销折扣
4. 订单级退款
5. 采购成本
6. 尾程物流

### 2. 渠道内分摊规则

只能明确归到某个店铺 / 渠道，但不能直接归到 SKU 的费用，先归店铺/渠道，再按销售额占比分摊到 SKU。

适用：

1. 店铺订阅费
2. 平台月仓储费
3. Walmart Product Advertising
4. eBay 店铺订阅费
5. 线下商超推广费
6. 门店活动支持费

### 3. 全渠道分摊规则

品牌级共享费用，不归某一个店铺，按统一口径在全渠道分摊。

适用：

1. 品牌广告
2. PR
3. 公共内容团队费用
4. 样机公共费用
5. 总部共享费用

建议分摊基数优先级：

1. 明确受益对象时，按受益渠道销售额 / 毛利额 / 预算额分摊
2. 不明确时，按渠道销售额占比分摊
3. 对品牌建设型费用，可按品牌销售额或目标收入占比分摊

## 六、最终结论

如果把这次调研压缩成一句话，结论就是：

**竞品真正落地全渠道管报时，核心不是“先做一张报表”，而是先把费用归集和分摊机制做成系统规则。**

对你们项目最值得直接借鉴的不是某一家公司的 UI，而是以下四条落地原则：

1. 平台费用优先直连平台账单和广告账单，不走人工汇总。
2. 平台外费用必须进入费控/预算/导入机制，不能留在线下。
3. 所有费用都要先确定归属层级：订单、SKU、ASIN、店铺、渠道、全公司。
4. 对不能直归的费用，统一采用销售额占比、花费占比、自然日均摊等明确规则，不允许各部门自行解释。

从竞品公开案例看，真正成熟的做法不是“财务月底算利润”，而是：

1. 运营每天看利润
2. 财务按 ASIN / SKU 看盈亏
3. 供应链根据利润和库存联动补货
4. 管理层根据统一口径看渠道、SKU 和费用结构

这也正是你们全渠道管报项目最应该对齐的方向。
