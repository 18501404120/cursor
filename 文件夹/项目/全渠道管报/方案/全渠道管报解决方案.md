# 全渠道管报解决方案

## 1. 方案背景

### 1.1 业务背景

结合现有材料，智岩科技当前业务具有以下典型特征：

1. 公司以 `Govee` 品牌为核心，主营智能氛围照明、智能家居延伸产品，面向海外 C 端市场。
2. 渠道结构已形成 `平台电商 + 独立站 + 社媒电商 + 线下零售` 的全渠道格局。
3. 亚马逊仍是核心营收来源，同时还覆盖独立站、TikTok、eBay、Etsy、Target 等线上渠道，并逐步进入沃尔玛、家得宝等线下零售体系。
4. 业务模式不是单纯卖货，而是 `硬件 + 软件 + 内容` 的复合经营模式，内容营销、红人投放、样机、PR、社媒种草等投入对经营结果影响显著。
5. 随着渠道增多、SKU 增多、营销动作增多，管理层已经不满足于只看销量、营收、毛利，而需要进一步看清渠道利润、SKU 利润、费用结构和预算执行情况。

### 1.2 项目问题本质

当前全渠道管报面临的问题，不是“缺少一张报表”，而是“缺少一套统一的经营分析体系”：

1. 不同渠道、不同系统、不同部门对销量、营收、费用、分摊口径理解不一致。
2. 现有报表颗粒度不足，无法稳定支撑 `SKU + 渠道` 的真实损益分析。
3. 广告、PR、内容、样机等营销费用大量游离在系统外，导致利润分析不完整。
4. BP 与实际经营未同源，预算无法形成动态闭环。

### 1.3 建设定位

本方案的定位不是建设单一报表，而是建设一套服务经营决策的全渠道管理分析底座，最终支撑三类核心场景：

1. 管理层看全渠道经营质量，回答“为什么赚、为什么亏、哪里值得投”。
2. 业务团队看渠道和 SKU 表现，回答“哪个渠道值得继续放量、哪个 SKU 需要调整”。
3. 财务团队看费用归集与预算偏差，回答“费用是否归对、摊对、算对”。

### 1.4 与《财务各渠道逻辑》的衔接（口径输入物）

业务侧整理的 **`财务各渠道逻辑.xlsx`**（建议与管报需求材料一并存放于 `文件夹/项目/全渠道管报/需求/`）是全渠道销售报表与财务费用口径的**结构化输入**，方案中凡涉及「管报费用字段、取值来源、改造方向」的落地，**应以该表为单一事实来源（SSOT）的初稿**，经财务与业务双签后冻结进指标字典与开发需求。

该表约定俗成的结构如下（与线下表格一致即可，不要求改模板）：

1. **Sheet1（全渠道销售报表 / 财务侧）**  
   罗列**财务系统**中与管报相关的各类**费用项字段**，并写清每一字段的**取值逻辑**。  
2. **后续 Sheet（业务维度）**  
   按**业务视角**拆分各费用项：同样包含字段说明与取值信息；与 Sheet1 形成「财务科目 / 报表列 ↔ 业务费用项」对照。  
3. **单元格书写约定**  
   - **上半部分**：**当前系统**实际采用的取值逻辑（现状）。  
   - **下半部分（「取值」之后）**：**希望**管报 / 中台 / 接入层采用的取值逻辑（目标）。  

实施时，应将每一个「现状 → 目标」差异转化为：**数据源改造、ETL 规则、分摊规则或主数据映射** 条目，并进入测试用例与财务勾稽验收。**当前仓库若尚未纳入该 xlsx，需先入库后再将附录模板中的占位行替换为表中真实字段与原文。**

## 2. 建设目标

围绕项目背景书和项目规划思想，建议将全渠道管报建设目标明确为四个统一、两类闭环、五类输出。

### 2.1 四个统一

1. **统一口径**：统一销量、营收、退款、费用、利润、预算等核心定义。
2. **统一颗粒度**：统一以 `SKU + 渠道` 为核心分析颗粒度，必要时可上卷至品牌、品类、平台、国家、店铺。
3. **统一费用逻辑**：将广告、内容、PR、样机、物流、仓储、平台费、返利等费用纳入统一归集与分摊机制。
4. **统一预算联动**：让 BP 与管报使用同一套维度、同一套费用结构、同一套利润口径。

### 2.2 两类闭环

1. **经营闭环**：预算制定 -> 执行跟踪 -> 偏差分析 -> 经营复盘 -> 策略调整。
2. **数据闭环**：源数据接入 -> 口径加工 -> 费用归集 -> 分摊计算 -> 报表输出 -> 结果校验。

### 2.3 五类输出

1. 公司级管理驾驶舱
2. 渠道经营分析
3. SKU + 渠道损益分析
4. 费用结构与投入产出分析
5. BP 与实际偏差分析

## 3. 建设范围与业务边界

### 3.1 一期建议纳入范围

#### 渠道范围

1. 亚马逊各主要站点
2. 独立站
3. TikTok 等社媒电商
4. eBay、Etsy、Target 等平台渠道
5. 线下零售渠道，如沃尔玛、家得宝等
6. 新兴市场分销渠道

#### 产品范围

1. 智能灯带
2. 室内氛围灯
3. 户外智能灯
4. GoveeLife 小家电

#### 费用范围

1. 平台直接费用
2. 物流与仓储成本
3. 广告投放费用
4. 内容、PR、样机等营销费用
5. 渠道推广费、返利、陈列费等线下渠道费用
6. BP 中已有和计划纳入的关键预算费用

### 3.2 一期建议先不深挖的范围

为保证项目可落地，建议一期聚焦销售经营分析，不把范围扩得过大。以下内容可在二期、三期逐步深化：

1. 研发费用按产品线精细分摊
2. 总部行政费用按组织深度分摊
3. 复杂生产制造成本的全过程精算
4. 海外税务、合规费用的专项管理报表

原则上，一期先解决“看得见经营结果背后的主要投入结构”，而不是一次性解决全部财务管理问题。

## 4. 整体解决方案架构

建议方案采用 `一个底座、两套引擎、五类应用` 的总体架构。

### 4.1 一个底座：统一经营分析底座

统一经营分析底座负责完成以下工作：

1. 打通平台、订单、广告、仓储、物流、费控、预算等数据来源。
2. 建立统一主数据体系，包括品牌、品类、SPU、SKU、渠道、店铺、国家、组织、负责人等。
3. 建立统一经营分析模型，沉淀标准指标和标准利润结构。

### 4.2 两套引擎

#### 引擎一：费用归集与分摊引擎

负责解决以下问题：

1. 平台费用怎么自动接入
2. 平台外费用怎么进入系统
3. 费用应该落到订单、SKU、渠道还是公司共享层
4. 不能直接归属的费用按什么规则分摊

#### 引擎二：BP 联动与偏差分析引擎

负责解决以下问题：

1. 预算和实际是否使用同一套维度和费用结构
2. 渠道、品类、SKU 层面预算执行偏差如何查看
3. 偏差原因如何归因到销量、价格、费用、物流、广告等关键项

### 4.3 五类应用

1. 管理层驾驶舱
2. 渠道损益分析
3. SKU + 渠道经营分析
4. 费用结构与投入产出分析
5. 预算执行与滚动预测分析

## 5. 数据与主数据设计

全渠道管报能否成立，关键不在报表前端，而在主数据是否统一。

### 5.1 核心分析维度

建议统一以下维度：

1. **时间维度**：年、季度、月、周、日
2. **产品维度**：品牌、产品线、品类、系列、SPU、SKU
3. **渠道维度**：渠道类型、平台、站点、店铺、线下客户、分销商
4. **市场维度**：国家、区域、市场
5. **组织维度**：事业部、团队、负责人
6. **履约维度**：仓库、发货模式、物流模式
7. **预算维度**：预算版本、预算科目、预算归属对象

### 5.2 关键映射关系

以下映射关系必须在底层打通，否则后续利润和费用都算不稳：

1. `SKU <-> SPU <-> 产品线`
2. `SKU <-> 渠道商品编码 <-> 平台商品标识`
3. `订单 <-> 店铺 <-> 站点 <-> 渠道`
4. `广告活动 <-> 渠道 <-> 商品 / SKU`
5. `费用单据 <-> 预算科目 <-> 管报费用科目`
6. `预算对象 <-> 实际对象`

### 5.3 统一口径字典

项目启动后，建议优先产出一套正式的 `口径字典`，至少覆盖以下内容：

1. 销量定义
2. 营收定义
3. 净销售额定义
4. 毛利定义
5. 渠道贡献利润定义
6. 经营利润定义
7. 各类费用分类定义（与 **§7.3 全量费用项清单**一致，含别名与财务科目映射）
8. 各类分摊基数定义（与 §7.3、§7.5 一致）
9. BP 与实际对齐逻辑

### 5.4 全渠道销售报表：财务字段与业务费用「双轨 + 现状/目标」维护

在《财务各渠道逻辑.xlsx》的基础上，建议在指标字典与数据需求中固定下列维护方式，避免财务与业务各写一套：

1. **财务轨（Sheet1）**  
   - 字段名与财务系统 / 总账或结算接口中的命名对齐（或显式给出别名映射）。  
   - 每个字段必须可追溯：**来源系统、报表/单据类型、汇总粒度（订单/店铺/渠道/公司）、更新频率**。  
   - **现状逻辑**：与当前生产环境或结账规则一致，用于解释「现在数从哪来」。  
   - **目标逻辑（取值）**：与管报目标态一致，用于排期与改造；若与现状相同，也应显式写「与现状一致」，避免歧义。

2. **业务轨（后续 Sheet）**  
   - 按渠道、活动类型或费用池组织均可，但需**每条业务费用项**能指回财务轨中的字段或组合（多对一、一对多需在映射表注明）。  
   - 同样采用**现状 / 取值（目标）**双段描述，便于业务确认「希望管报怎么算、与财务结账差异如何解释」。

3. **差异治理**  
   - 凡「现状 ≠ 目标」的字段，必须登记：**责任系统（ERP / 费控 / 广告中台等）、依赖主数据、预计上线阶段、与关账勾稽关系**。  
   - 与会议共识一致：**财务报表中的品牌分摊等逻辑须与管报对齐**，该对齐要求在双轨表中应有对应行或可推导关系。

4. **落地载体**  
   - 评审通过后，将 xlsx 内容同步为正式 **`口径字典` 附录**（可为 Markdown / 在线表 / 需求管理系统中的结构化表），版本号与 xlsx 修订日期挂钩。

## 6. 管报利润结构设计

建议将全渠道管报统一为一套标准利润结构，从上到下看清“收入、调整、直接费用、履约成本、渠道营销、共享费用、利润结果”。

### 6.1 标准利润结构

| 层级 | 内容 | 管理意义 |
| --- | --- | --- |
| 收入主项 | 销售额、买家运费、其他收入 | 看业务规模 |
| 营收调整项 | 退款、折扣、税金调整、放款差异 | 看净收入形成过程 |
| 平台直接费用 | 平台佣金、支付手续费、平台广告、平台物流、平台仓储、平台其他费 | 看平台经营成本 |
| 商品与履约成本 | 采购成本、头程、尾程、包装、退货处理 | 看商品交付成本 |
| 渠道营销费用 | 内容、PR、样机、达人、线下推广、返利、陈列费 | 看渠道投入结构 |
| 共享管理费用 | 品牌共投、总部共享费用、公共工具费 | 看组织级经营负担 |
| 利润结果 | 毛利、渠道贡献利润、经营利润 | 看最终经营质量 |

### 6.2 营收之上与营收之下的口径建议

#### 营收之上

这一层用于形成可比净收入，建议包含：

1. 销售额
2. 买家运费
3. 其他收入
4. 收入退款额
5. 促销折扣
6. 税金调整
7. 放款差异

**明细项的归属对象、取值逻辑与是否含税**以 **§7.3.1** 为准。

#### 营收之下

这一层用于呈现真实投入结构，建议包含：

1. 平台直接费用
2. 商品与履约成本
3. 渠道营销费用
4. 共享管理费用

各层级下的**全量费用项、数据源与分摊规则**以 **§7.3.2～§7.3.5** 为准。

### 6.3 利润层级建议

建议至少形成三层利润结果：

1. **毛利**  
   净销售额 - 商品与履约成本

2. **渠道贡献利润**  
   毛利 - 平台直接费用 - 渠道营销费用

3. **经营利润**  
   渠道贡献利润 - 共享管理费用

这样设计的好处是，管理层可以分别看清：

1. 商品本身赚不赚钱
2. 渠道动作值不值得做
3. 整体经营结果是否健康

## 7. 费用归集与分摊方案

这是全渠道管报项目的核心，也是当前痛点最集中的部分。

### 7.1 总体原则

建议所有费用处理遵循四条原则：

1. **能直接归属就不分摊**
2. **先落业务对象，再落管理对象**
3. **先分渠道内费用，再分公司共享费用**
4. **同一类费用全公司只允许一种主规则**

### 7.2 费用归属层级

建议将费用归属层级固定为五层：

1. 订单级
2. SKU 级
3. 渠道 / 店铺级
4. 品类 / 品牌级
5. 公司共享级

所有费用必须先确定归属层级，再确定是否需要分摊。

### 7.3 费用项全量清单（归属、取值逻辑与分摊）

本节给出全渠道管报口径下的**标准费用项全集**及每一项的**归属方式**与**取值逻辑**（数据从哪来、按什么粒度汇总、是否需分摊）。下列命名若与公司财务科目或《财务各渠道逻辑.xlsx》不一致，**以双签后的指标字典与 xlsx 映射为准**；可在不改动归属逻辑的前提下做别名对照。

**表列统一含义**

| 列名 | 含义 |
| --- | --- |
| 利润层级 | 对应 §6.1 标准利润结构中的位置 |
| 归属层级 | §7.2 五层之一；复合场景取「先落点」层级 |
| 归属对象 | 费用最终服务分析的最小管理对象（订单 / SKU / 店铺 / 渠道 / 客户 / 品牌 / 公司） |
| 取值逻辑 | 金额如何得到：数据源、期间、币种、匹配键、是否含税等 |
| 归集方式 | 系统接入形态：直连 / 台账 / 分摊引擎 / 手工调整 |
| 分摊规则 | 不能直接归属时的默认规则；**直接归属**填「—」 |

**与 §6.1 对齐说明**：**亚马逊站内广告（SP / SD / SB / SBV 等）**列入 **平台直接费用**（与 §6.1「平台广告」一致）；**站外投流、达人、内容制作**等列入 **渠道营销费用**，避免与平台账单内广告重复计量。

#### 7.3.1 净销售额相关项（收入与调整）

> 本节为**收入侧与冲减项**，严格说不属「费用」，但全渠道销售报表与财务勾稽必须统一取值，故一并定义归属与取值逻辑。

| 费用项 | 利润层级 | 归属层级 | 归属对象 | 取值逻辑 | 归集方式 | 分摊规则 |
| --- | --- | --- | --- | --- | --- | --- |
| 商品销售额（GMV） | 收入主项 | 订单级 | 订单 → SKU → 店铺/渠道 | 平台订单报表：行项目销售金额之和；**按订单时间或结算时间**由口径字典锁定一种；币种按店铺本币，管报统一折算为管理币种 | 平台订单 / 结算 API | — |
| 买家运费收入 | 收入主项 | 订单级 | 订单 → SKU | 订单行「运费」字段汇总；退款时按平台规则冲减 | 订单接口 | — |
| 礼品包装费等其它收入 | 收入主项 | 订单级 | 订单 → SKU | 订单行其它正向收入项 | 订单接口 | — |

### 7.4 三类分摊池设计

为保证规则清晰，建议在系统中明确建立三类分摊池：

#### 直接归属池

适用费用：

1. 订单级平台费
2. 订单级物流费
3. 可直接映射商品的广告费
4. 可直接映射 SKU 的样机费

处理方式：直接落单，不参与二次分摊。

#### 渠道费用池

适用费用：

1. 渠道推广费
2. 线下商超活动费
3. 店铺订阅费
4. 渠道内无法直归 SKU 的广告费
5. 渠道返利和陈列费

处理方式：先归到渠道 / 店铺 / 客户，再在渠道内部按统一基数分摊到 SKU。

#### 公司共享池

适用费用：

1. 品牌共投费用
2. 公共 PR
3. 总部共享团队费用
4. 公共系统费用

处理方式：按公司统一规则在全渠道分摊，不允许各业务线自行处理。

### 7.5 分摊基数建议

建议固定以下优先级，避免不同部门各算各的：

1. **第一优先**：实际归属对象
2. **第二优先**：活动对象或合同归属对象
3. **第三优先**：渠道内销售额
4. **第四优先**：渠道内出货额或销量
5. **第五优先**：全渠道销售额或毛利额

其中：

1. 广告、推广、样机类费用优先按受益对象和销售额分摊。
2. 仓储类费用优先按时间和销售额结合分摊。
3. 总部共享费用优先按销售额或预算占比分摊。

### 7.6 与《财务各渠道逻辑》一致的改造与验收

第 **7.3 节全量费用项清单**为管报侧**标准全集**；财务科目命名、结账期间与 **「现状 / 取值（目标）」** 的字段级差异以《财务各渠道逻辑.xlsx》及双签指标字典为准，二者通过映射表一一对应，避免重复或遗漏。建议按以下节奏落地：

1. **盘点**  
   以 Sheet1 全量费用字段为清单，对照当前数仓 / ERP 是否已具备取值条件；标记缺口数据源。

2. **对齐**  
   对每个字段，将单元格内 **现状** 与 **取值（目标）** 转为开发故事：接口字段、计算 SQL、分摊引擎规则或人工补录点。

3. **勾稽**  
   目标态管报在渠道汇总、公司汇总层与财务试算表或结账报表做**期间总额与关键科目**勾稽；允许已知差异项单列「解释科目」。

4. **验收**  
   UAT 按 xlsx 行号或字段编码抽查：**同一字段现状版与目标版输出对比**、**业务 Sheet 与财务 Sheet 交叉验证**。

## 8. BP 联动方案

全渠道管报如果不与 BP 打通，只能形成“事后解释”，不能形成“事前规划 + 事中纠偏 + 事后复盘”。

### 8.1 BP 与管报同源原则

建议 BP 与管报做到四个同源：

1. 同维度
2. 同费用科目
3. 同利润结构
4. 同分析颗粒度

### 8.2 BP 管理对象

建议 BP 至少覆盖以下对象：

1. 渠道
2. 品类 / 产品线
3. 核心 SKU
4. 关键费用项
5. 组织 / 负责人

### 8.3 BP 联动分析场景

建议支持以下分析：

1. 渠道预算 vs 实际
2. SKU 销售预算 vs 实际
3. 广告预算 vs 实际
4. 物流和仓储预算 vs 实际
5. PR / 内容 / 样机预算 vs 实际
6. 利润预算 vs 实际

### 8.4 偏差归因建议

预算偏差建议分为五类原因：

1. 销量偏差
2. 价格偏差
3. 费用偏差
4. 履约成本偏差
5. 渠道结构偏差

这样管理层可以明确看到：是卖少了、卖贵了、投多了、物流贵了，还是渠道结构变了。

## 9. 报表与产品模块设计

结合项目规划思想，建议最终产品化时形成以下模块。

### 9.1 管理层驾驶舱

核心看什么：

1. 总营收、净销售额、毛利、经营利润
2. 各渠道销售与利润贡献
3. 费用结构占比
4. 预算执行偏差
5. 关键异常预警

### 9.2 渠道经营分析

核心看什么：

1. 各渠道营收、利润、费用结构
2. 渠道投产比
3. 渠道增长质量
4. 渠道预算执行情况

### 9.3 SKU + 渠道损益分析

核心看什么：

1. SKU 在不同渠道的收入表现
2. SKU 在不同渠道的费用负担
3. SKU 单品利润
4. SKU 渠道适配性

### 9.4 费用专项分析

核心看什么：

1. 广告费用结构
2. 内容、PR、样机费用结构
3. 线下推广费和返利结构
4. 平台费、物流费、仓储费变化
5. 费用归集和分摊结果

### 9.5 BP 与滚动预测分析

核心看什么：

1. 月度预算执行进度
2. 偏差原因
3. 滚动预测结果
4. 资源调整建议

## 10. 数据校验与治理机制

如果没有治理机制，管报上线后很快又会回到“报表很多，但没人完全信”的状态。

### 10.1 指标治理

1. 建立统一指标字典
2. 指标变更必须走评审流程
3. 关键指标指定唯一口径负责人

### 10.2 数据校验

建议建立三类校验：

1. 平台数据与订单数据校验
2. 经营数据与财务数据校验
3. 预算数据与实际数据校验
4. **《财务各渠道逻辑》字段级校验**：每个费用字段的目标取值是否与指标字典一致；现状与目标差异是否均有登记与审批

### 10.3 结账节奏

建议形成统一结账节奏：

1. 日级预估经营利润
2. 月级正式结账利润
3. 月度预算偏差复盘

### 10.4 权限治理

1. 管理层看汇总口径
2. 财务看完整成本与分摊细节
3. 业务看负责范围内的经营结果
4. 敏感字段按角色控制

## 11. 实施路径建议

建议按照“先底座、后专项、再闭环”的思路分阶段推进。

### 11.1 第一阶段：统一口径与基础损益

目标：

1. 完成核心主数据统一
2. 完成收入、退款、平台费、采购、物流等基础损益模型
3. 先跑通渠道级和 SKU 级基础利润

产出：

1. 口径字典（含自《财务各渠道逻辑.xlsx》导入的**财务轨 + 业务轨**字段清单，及现状/目标说明）
2. 基础利润模型
3. 初版渠道与 SKU 损益报表

### 11.2 第二阶段：费用归集与分摊深化

目标：

1. 将广告、内容、PR、样机、线下渠道费用纳入系统
2. 建立三类分摊池
3. 形成标准分摊规则和可回溯逻辑

产出：

1. 费用分类体系
2. 分摊规则表
3. 费用专项分析报表

### 11.3 第三阶段：BP 联动与经营闭环

目标：

1. 打通预算和实际
2. 建立偏差归因和滚动预测能力
3. 将管报从“结果分析工具”升级为“经营管理工具”

产出：

1. BP 对比分析
2. 偏差归因模块
3. 滚动预测机制

## 12. 验证标准

为保证方案不是概念化表达，建议在实施过程中设置以下验证标准。

### 12.1 口径验证

1. 同一指标在不同报表结果一致
2. 财务与业务对关键指标无重复争议

### 12.2 损益验证

1. 核心渠道可稳定输出渠道利润
2. 核心 SKU 可稳定输出 SKU + 渠道损益

### 12.3 费用验证

1. 广告、物流、仓储、样机、PR、线下推广等关键费用可纳入统一体系
2. 每类费用都能回溯其归集和分摊路径
3. 《财务各渠道逻辑》中标记为「目标取值」的字段，在管报中的结果与字典定义一致，且与财务勾稽无未解释偏差

### 12.4 预算验证

1. BP 与实际可做同口径比较
2. 偏差可归因到核心业务因素

## 13. 预期价值

### 13.1 对管理层

1. 从“看结果”升级为“看原因、看结构、看投入产出”
2. 更科学地进行渠道资源配置和预算决策

### 13.2 对业务团队

1. 看清不同渠道的真实经营质量
2. 看清 SKU 在不同渠道的盈利能力
3. 让营销动作和经营结果真正挂钩

### 13.3 对财务团队

1. 费用归集更规范
2. 分摊规则更透明
3. 与业务沟通成本显著下降

### 13.4 对公司整体

1. 形成统一经营语言
2. 建立全渠道规模化运营的数据基础设施
3. 为后续滚动预测、经营模拟、资源优化提供基础

## 14. 结论

全渠道管报项目的核心，不是增加更多报表页面，而是建立一套能够真正解释经营结果、支撑经营决策的分析体系。

对智岩科技而言，最关键的不是单独算清某一个平台，而是把 `亚马逊、独立站、TikTok、线下零售、分销渠道` 放进同一套经营语言里，把 `广告、内容、PR、样机、物流、仓储、返利、推广费` 放进同一套费用结构里，再把 `预算、执行、复盘` 放进同一套闭环里。

当这三件事同时成立时，全渠道管报才不是“报表项目”，而是公司经营管理升级的基础设施。
