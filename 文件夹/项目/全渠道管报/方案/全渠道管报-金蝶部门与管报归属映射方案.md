# 全渠道管报 · 费用归属规则方案

- 文档日期：2026-07-20
- 状态：精简版，用于确认费用归属逻辑
- 适用范围：全渠道管报费用导入、自动取数、月度计提运行

---

## 1. 目标

本方案只解决一个问题：**费用最终归属到哪个管报部门，并带出对应的金蝶组织和金蝶部门。**

不再区分渠道经营部门、公司共享部门、中间层级等管理属性；费用归属以业务实际发生场景为准。

---

## 2. 费用归属优先级

### 2.1 用户指定管报部门

如果用户导入费用时已经指定了管报部门，则直接按用户指定的管报部门归属。

系统根据该管报部门带出：

- 对应金蝶组织
- 对应金蝶部门
- 对应管报部门

### 2.2 未指定管报部门，但有店铺

如果用户没有指定管报部门，但数据中有店铺名称，则按第 3 节店铺映射表自动归属。

### 2.3 未指定管报部门，也没有店铺

如果没有店铺，系统先按费用分摊规则把费用拆分到具体店铺，再按第 3 节店铺映射表归属。

分摊结果必须至少包含：

| 字段 | 说明 |
| --- | --- |
| 分摊后店铺 / 场景 | 例如 `Offline-US`、`APP商城-US` |
| 分摊金额或比例 | 用于拆分原始费用 |
| 分摊规则来源 | 方便追溯 |

如果无法分摊到具体店铺，则进入待确认。

### 2.4 借货场景

借货场景按**实际销售店铺 / 费用发生店铺**归属，不按 MSKU 来源归属。

示例：

| 场景 | 归属规则 |
| --- | --- |
| 商超借 APP 的货销售 | 即使 MSKU 属于 APP，也归属商超 |
| APP 借商超库存销售 | 即使库存来源是商超，也归属 APP |

## 4. 待确认规则

以下情况进入待确认，不自动归属：

1. 用户未指定管报部门，且没有店铺，也无法按分摊规则拆分到店铺。
2. 分摊后店铺不在第 3 节映射表中。
3. 店铺名称同时命中多个管报部门。
4. 金蝶组织和金蝶部门明显不匹配，例如 `109` 组织挂 `BM110...` 部门。
5. 德国分销样本较少，后续如新增其他德国 / 欧盟分销场景，需要继续核对是否归 `127 / BM127002`。

---

## 5. 核心结论

1. 用户指定管报部门时，以用户指定为准。
2. 用户未指定时，优先按店铺映射。
3. 没有店铺时，先按分摊规则拆到店铺，再按店铺映射。
4. 借货场景按实际销售店铺归属，不按 MSKU 来源归属。
5. 无法确定归属时进入待确认，不默认挂到任一组织或部门。
