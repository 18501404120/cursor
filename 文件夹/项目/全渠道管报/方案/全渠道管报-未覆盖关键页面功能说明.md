# 全渠道管报-未覆盖关键页面功能说明（结合华为培训会议内容修订）

- 文档日期：2026-05-08
- 适用范围：补齐当前原型在“流程治理与经营闭环”侧的缺口
- 修订依据：`需求/华为培训会议内容`
- 目标：将培训中的管理方法（战略解码、预算闭环、一报一会、任务到人、弹性资源配置）转化为页面级能力

---

## 0. 培训结论对产品设计的强约束

根据培训内容，原型补齐必须遵循以下约束：

1. **战略→预算→执行→考核闭环**：不能只做结果看板，必须有从中长期目标（3-5年）解码到年度预算、再到月度执行和考核的链路。
2. **预算三维管理**：预算至少按`产品维度 + 客户/渠道维度 + 区域维度`组织，并支持交叉分析。
3. **一报一会机制系统化**：按月固化“关账->经营分析会->任务下发->下月回看”的节奏。
4. **任务到人（可量化）**：指标必须可分解到组织、团队、责任人，支持SMART化跟踪。
5. **弹性资源配置**：预算执行中要支持对可变费用（差旅、招待、渠道费用等）进行弹性控制，不是一次性静态预算。
6. **预算严肃性与可控性并存**：支持“目标牵引但可管理”，避免目标随意上调/下调。

## 1. 月结与锁数中心（关账运营台）

### 页面目标
建立“月结时点管理 + 一报一会前置准备 + 锁数治理”的统一流程，支撑按月经营管理。

### 核心功能
1. 月度经营日历：支持“结账完成日、分析会日期、任务下发日、复盘日”配置。
2. 锁数与解锁：按月份、组织、渠道、区域执行锁数，解锁需审批。
3. 会前数据就绪检查：校验关键指标是否齐备（收入、利润、费用、回款、预测）。
4. 版本快照：保留“会前版、会后调整版、锁定版”。
5. 例会包自动生成：一键生成“本月达成、累计达成、预测偏差、任务清单”会议包。

### 关键交互
1. “发起月结”-> 系统检查缺失数据 -> 提醒责任人补齐。
2. “生成一报一会材料”-> 自动汇总核心指标与差异原因。
3. “锁数”-> 冻结该月版本并输出锁数编号。

### 输入/输出
1. 输入：月度指标、对账状态、责任人矩阵、例会规则。
2. 输出：月结状态、锁数版本、经营会材料、会后任务清单。

### 验收要点
1. 每月有明确状态流转，不再靠手工提醒。
2. 锁数后变更有审批和日志。
3. 经营会材料可自动复用，减少PPT手工整理。

## 2. BP任务中心（战略解码与预算到人）

### 页面目标
把“战略目标”可执行地解码到年度预算，并分配到组织和个人责任。

### 核心功能
1. 战略解码面板：支持3-5年目标录入与年度目标分解。
2. 三维预算模型：按产品、客户/渠道、区域三维建模并联动校验。
3. 任务分发：预算项分配到部门、团队、责任人。
4. 预算编制流程：草稿->提交->评审->冻结->发布。
5. 目标可控性检查：系统提示“偏离战略过大/过小”的异常预算版本。

### 关键交互
1. 导入战略目标 -> 自动生成预算骨架。
2. 预算填报时显示“战略目标对齐度”（如偏差率）。
3. 冻结后自动同步到执行看板与考核模块。

### 输入/输出
1. 输入：战略目标、主数据、预算模板、审批流。
2. 输出：年度预算版本、责任分解表、对齐度报告。

### 验收要点
1. 预算可追溯到战略来源。
2. 预算可落到责任人并可跟踪。
3. 预算版本具备冻结与回溯能力。

## 3. 经营执行与任务闭环中心（新增）

### 页面目标
将“一报一会”中的问题和动作变成系统任务，形成月度滚动闭环。

### 核心功能
1. 经营任务池：记录每次经营会输出的任务（目标差距、原因、行动）。
2. 任务到人到时间：每条任务必须有负责人、截止日期、量化目标。
3. 上月任务回看：下次会议自动展示上月任务完成情况。
4. 任务关联指标：任务绑定具体指标（订货、收入、利润、费用、回款等）。
5. 任务升级机制：逾期或连续未达标自动升级上报。

### 关键交互
1. 会中直接建任务 -> 指派责任人 -> 自动通知。
2. 任务进展更新 -> 自动回填到下月会议看板。
3. 未完成任务必须填写原因与补救动作。

### 输入/输出
1. 输入：经营会结论、指标偏差、责任矩阵。
2. 输出：任务台账、完成率、逾期清单、复盘报告。

### 验收要点
1. 每次会议都有闭环任务，不再口头流转。
2. 任务完成率可量化统计。
3. 关键任务可追溯“提出-执行-复盘”全链路。

## 4. 勾稽与差异中心（对账工单台）

### 页面目标
支撑经营会对“数据差异”的快速解释，减少会上扯皮。

### 核心功能
1. 自动勾稽：业务口径 vs 财务口径的月度对账。
2. 差异工单：差异自动分发到财务/业务/数据责任人。
3. 会前差异摘要：输出“本月Top差异及状态”。
4. 线下预沟通记录：支持会前沟通纪要沉淀（培训强调会前沟通）。
5. 关闭标准：差异需有结论、证据、审批人。

### 关键交互
1. 会前运行勾稽 -> 自动生成差异包。
2. 差异分派 -> 责任人补充原因与处理计划。
3. 会后复核 -> 差异关闭或延续跟踪。

### 输入/输出
1. 输入：业务/财务数据、勾稽规则、组织责任关系。
2. 输出：差异清单、处理状态、关闭证明。

### 验收要点
1. 重大差异必须会前有初步结论。
2. 差异处理进展可在会中一屏查看。
3. 差异关闭可审计。

## 5. 弹性资源配置中心（新增）

### 页面目标
把“预算执行中的动态资源调整”产品化，支持可变费用弹性控制。

### 核心功能
1. 可变费用池管理：差旅、招待、渠道费用、推广费用等。
2. 弹性阈值规则：如“预算执行低于阈值时自动触发控费建议”。
3. 调整动作管理：预算转移、冻结、追加、下调。
4. 影响评估：调整前后对利润、达成率、现金流影响模拟。
5. 控制方式分级：硬控制（系统拦截）+ 软控制（预警提醒）。

### 关键交互
1. 发起资源调整 -> 选择原因 -> 评估影响 -> 审批。
2. 规则触发后自动提示“建议调减/调增”费用项。
3. 执行后回看效果，形成策略复盘。

### 输入/输出
1. 输入：预算执行进度、费用明细、预测结果、审批规则。
2. 输出：调整单、资源流向图、效果评估报告。

### 验收要点
1. 资源调整有证据、有审批、有结果。
2. 系统能区分固定费用与可变费用。
3. 调整后对达成率影响可量化。

## 6. 口径版本中心（口径治理台）

### 页面目标
保障预算与执行的口径一致，防止“预算一套、执行一套”。

### 核心功能
1. 口径字典版本：指标、分摊、预测口径版本化。
2. 偏差解释模板：为一报一会准备标准解释模板。
3. 变更影响评估：识别影响的预算、任务、考核对象。
4. 发布与回滚：口径切换可灰度，异常可回滚。
5. 版本对比：展示新旧口径差异与生效范围。

### 验收要点
1. 会中所有指标都有口径来源。
2. 口径变更后自动提示影响对象。

---

## 7. 异常预警中心（经营监控台）

### 页面目标
围绕“时间进度 vs 完成进度”做过程预警，强化月中纠偏。

### 核心功能
1. 进度偏差预警：如5月时间进度40%，完成进度低于阈值则告警。
2. 预测落差预警：全年预测显著低于预算目标时预警。
3. 预警分级：红黄蓝分级与处理时限。
4. 问题归因模板：市场原因、渠道原因、产品原因、执行原因。
5. 处置联动：告警可直接转任务或资源调整单。

### 验收要点
1. 预警规则支持按产品/渠道/区域配置。
2. 告警能闭环到任务和资源动作。

---

## 8. 权限与审计中心（治理与合规台）

### 页面目标
支撑“管理严肃性”，确保关键动作可追责。

### 核心功能
1. 角色权限：管理层、财务、业务、数据、审计分级。
2. 审批链日志：锁数、预算冻结、资源调整、口径变更全留痕。
3. 导出审计：谁导出过哪些敏感数据。
4. 会议决议留痕：经营会关键决策与任务指派归档。

### 验收要点
1. 关键动作无审批不可生效。
2. 审计可追溯到人和时间。

---

## 9. 绩效联动中心（新增）

### 页面目标
将预算执行结果与组织/个人绩效衔接，实现“目标-执行-激励”闭环。

### 核心功能
1. 指标分解到人：支持从团队指标拆分到个人责任指标。
2. 绩效计算规则：支持利润、现金流、达成率等权重配置。
3. 考核结果看板：组织与个人完成情况、排名、偏差说明。
4. 激励模拟：按不同权重模拟奖金包变化（策略分析）。

### 验收要点
1. 绩效指标与预算指标同源。
2. 结果可解释、可复核。

## 10. 建议原型补齐顺序（修订）

### 第一批（必须先补，直接对应培训方法论）
1. 月结与锁数中心
2. BP任务中心（含战略解码）
3. 经营执行与任务闭环中心
4. 弹性资源配置中心

### 第二批（强化治理与一致性）
1. 勾稽与差异中心
2. 口径版本中心
3. 异常预警中心
4. 权限与审计中心

### 第三批（结果应用与长期能力）
1. 绩效联动中心
2. 多币种与汇率口径中心
3. 滚动预测与情景模拟中心
4. 主数据治理中心

---

## 11. 与现有原型的衔接原则（修订）

1. 保留现有页面作为“分析展示层”（看板、费用分摊、映射维护）。
2. 新增页面构成“经营管理层”（预算流程、月度会议、任务闭环、资源调整）。
3. 统一主对象：预算版本、月份、产品、渠道客户、区域、责任人。
4. 统一四类治理字段：状态、版本、责任人、日志。
5. 每个页面都要支持“会前准备-会中决策-会后跟踪”三段式使用场景。
