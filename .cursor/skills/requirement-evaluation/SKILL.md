# 需求评估 Skill

## 何时使用

- 用户说「评估这个需求」「帮我评估需求」「需求合理性分析」等
- 用户指向或提供路径：`文件夹/需求` 下某子文件夹或文件
- 用户将需求内容（文档、一句话、截图描述）放在 需求/xxx 下并请求评估

## 执行步骤

1. **确定需求来源**
   - 若用户给出路径（如 `需求/需求A`）：读取该文件夹下所有可读文件（.md、.txt、.docx 等）及图片描述，合并为「原始需求内容」。
   - 若用户直接粘贴或描述需求：以用户输入为「原始需求内容」；若同时指定了保存文件夹，则评估文档写入该文件夹，否则询问或使用 `需求/待评估-YYYYMMDD` 形式新建。

2. **评估前必读上下文**
   - 阅读 `文件夹/提示词/产品经理定位.md`，对齐智岩 ERP 的 8 大模块（商品 BOM、采购、生产、库存、订单履约、售后、成本财务、数据大屏）、多仓多平台多 SKU 大促等约束。

3. **执行两项评估**
   - **合理性评估**：业务价值、与现有系统/模块的契合度、可行性（数据/接口/排期）、范围与优先级、与现有需求或规划的冲突。
   - **不明确点识别**：列出需与提需方对齐的问题（见下方清单），每条标注「建议与谁对齐、如何问」。

4. **输出评估文档**
   - 在**需求所在文件夹**下生成 `需求评估.md`，结构按 [evaluation-template.md](evaluation-template.md)。
   - 若文件夹不存在且用户未指定名称：先建 `需求/需求-YYYYMMDD-HHmm/`，再将评估与原始需求摘要写入该文件夹。

5. **输出需求文档（改动点说明）**
   - 在同一需求文件夹下生成 **`需求文档.md`**，结构按 [requirement-doc-template.md](requirement-doc-template.md)。
   - 需求文档须**描述清楚需求需要改动的点**：涉及模块、页面/功能入口、新增/修改的字段与筛选、业务逻辑与规则、数据来源与依赖、异常与边界、验收要点；与产品经理定位中的 8 大模块对应，便于开发与测试理解改动范围。
   - 若评估中存在不明确点，需求文档中对应处可标「待与提需方确认」或引用评估中的澄清建议。

## 合理性评估维度

| 维度 | 检查要点 |
|------|----------|
| 业务价值 | 解决谁的问题、什么场景、不做的后果；是否与研发/采购/库存/履约/成本等 ERP 主线一致 |
| 与现有能力 | 是否与商品、采购、生产、库存、订单、售后、成本、数据等 8 大模块重叠或冲突；是否多仓/多平台/多币种/大促兼容 |
| 可行性 | 数据来源是否可得、是否依赖外部系统或接口、研发/资源是否可支撑 |
| 范围与优先级 | 需求边界是否清晰、是否可拆期（MVP/后续）；与当前迭代或路线图优先级是否匹配 |
| 冲突与风险 | 与现有需求、配置中台化、大促保障等是否冲突；合规与风控风险 |

## 不明确点识别清单（快速与用户对齐）

逐条检查，缺失或模糊则列入「需澄清」并给出**建议追问**：

- **提出方与干系人**：谁提的、谁验收、还有哪些角色受影响？（追问：验收人是谁？需要采购/仓库/财务一起评审吗？）
- **场景与用户**：谁在什么场景下用、频率与关键路径？（追问：主要使用角色？每天/每周用？）
- **目标与成功标准**：做完后如何算「成功」？可量化指标？（追问：上线后希望看到什么数据或行为变化？）
- **范围边界**：做哪些渠道/仓库/SKU/站点？做哪些不做哪些？（追问：先支持亚马逊还是全渠道？先哪个仓？）
- **验收标准**：功能上「完成」的定义、验收用例或示例？（追问：能否给一个「通过」的示例？）
- **时间与依赖**：期望上线时间、依赖的系统/数据/排期？（追问：是否有大促或项目硬 deadline？依赖哪边先就绪？）
- **约束与例外**：性能、权限、合规、多语言/多币种等约束；异常与边界如何处理？（追问：并发量级？权限按组织还是按人？）

## 输出文件规范

- **需求评估.md**：与本次需求内容同文件夹（即用户新建的 `需求/xxx/` 下）；须包含需求摘要、合理性评估结论、不明确点清单（含建议追问）、建议下一步。
- **需求文档.md**：同文件夹；须包含需求概述、改动范围总览（新增/修改/删除）、具体改动点（页面与入口、字段、筛选、业务逻辑、数据依赖、异常与边界）、验收要点、与现有能力的关系；**重点写清「需要改动的点」**，便于排期与开发。

## 参考模板

- 评估文档：[evaluation-template.md](evaluation-template.md)，输出时按该模板填空，不删减章节标题。
- 需求文档：[requirement-doc-template.md](requirement-doc-template.md)，按该模板描述改动点，不删减章节标题；未确定项可标「待确认」并引用需求评估中的不明确点。
