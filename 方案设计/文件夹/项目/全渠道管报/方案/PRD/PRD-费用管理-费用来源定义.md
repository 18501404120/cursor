## 1. 需求背景与目标

### 1.1 背景

全渠道管报月度费用运行前，需预先定义每个费用项在各渠道下的**取数/计提规则**。规则配置是后续自动取数、固定金额/比例计提、历史滚动占比、同期占比预估等能力的**主数据基础**。

### 1.2 建设目标

1. 提供费用来源配置的增删改查、启停管理能力；
2. 支持五种费用来源类型，覆盖自动取数与四类手工维护规则；
3. 按口径范围自动展开明细组合，支持逐行维护、批量编辑、导入导出；
4. 列表摘要按**明细维护值汇总**展示，而非仅取顶部默认值；
5. **启用**配置占用渠道、参与计提；**停用**配置保留但不占渠道、不参与新计提。

### 1.3 目标用户

| 角色 | 主要场景 |
|------|----------|
| GTM/财务运营 | 维护各费用项在各渠道下的计提规则 |
| 财务主管 | 审核规则、启停配置 |
| 管报分析 | 查看规则摘要，理解费用取数口径 |

### 1.4 上下游

| 方向 | 说明 |
|------|------|
| 上游 | 费用项主数据、渠道/国家/店铺/场景/零售商主数据、历史费用与比例基数 |
| 下游 | 月度费用运行、管报费用汇总、费用填报对账 |

## 4. 全局业务规则

### 4.1 配置对象定义

一条**费用来源配置** = 

```
一个费用项 + 一种费用来源类型 + 一组适用渠道
+（非自动取数时）口径范围 + 明细维护值
```

### 4.2 启用/停用与渠道占用

| 状态 | 参与月度计提 | 占用渠道 |
|------|--------------|----------|
| 启用 | 是 | **是**（同费用项下渠道互斥） |
| 停用 | 否 | **否** |

**关键规则（已确认）：**
- 仅**启用**配置占用渠道；
- 编辑**停用**配置保存时，**不**做渠道冲突校验；
- 列表「启用」操作前须校验渠道占用；
- 启停、规则修改后：**已运行月份与历史报表保留快照，不回溯重算**；仅未运行月份按新规则生效。

### 4.3 渠道互斥

- 粒度：**同一费用项**下，一个渠道只能被**一条启用配置**占用；
- UI：已被占用的渠道在下拉中置灰；
- 切换费用项时，自动剔除新费用项下已被占用的已选渠道。

### 4.4 筛选规则（点击查询生效）

**修改筛选项后，须点击「查询」按钮才刷新列表**；未点查询前列表保持上一次结果。导出与列表一致，按上一次查询的筛选条件取数。

| 筛选项 | 选项 |
|--------|------|
| 费用项 | 全部 + 末级费用项（树形；选项展示节点名称，可按名称/连续编码检索） |
| 费用来源 | 全部、自动取数、固定金额、固定比例、历史滚动占比、同期占比预估 |
| 渠道 | 全部、亚马逊、shopify、App商城、线下商超、商超3P、线下分销 |
| 状态 | 全部、启用、停用 |

**导出规则：** 导出**上一次查询的筛选结果**（须与列表展示一致）；仅配置摘要，不含明细维护值。

### 4.5 列表摘要生成规则（已确认：明细汇总）

保存时 `来源摘要` 按**明细维护值汇总**生成，非仅取弹窗顶部默认值。

| 来源类型 | 摘要格式 |
|----------|----------|
| 自动取数 | 列表展示「系统自动取数」 |
| 固定金额 | `¥{min}–{max} / 月（均值 ¥{avg}）· {口径} · {N} 条明细`；全部相同则只展示单值 |
| 固定比例 | `{min}%–{max}%（均值 {avg}%）× {比例基数} · {口径} · {N} 条明细` |
| 历史滚动占比 | `{历史窗口} 滚动 · {比例基数} · {口径} · {N} 条明细` |
| 同期占比预估 | `同比月占比 · {比例基数} · {口径} · {N} 条明细` |

### 4.6 同费用项多来源类型并存（已确认）

| 场景 | 是否允许 |
|------|----------|
| 同费用项 + **不同渠道** + 不同来源类型 | ✅ 允许 |
| 同费用项 + **同渠道** + 不同来源类型（均启用） | ❌ 不允许（渠道占用互斥，与来源类型无关） |
| 同费用项 + 多条停用配置 | ✅ 允许（不占渠道） |

同一费用项可按渠道拆分不同计提方式（如亚马逊用历史滚动占比、shopify 用同期占比预估），但同一渠道在启用状态下只能归属一条配置。

### 4.7 三层数据模型与关账分层（已确认）

费用来源相关数据分三层理解，历史月调整须先判断问题落在哪一层：

| 层级 | 含义 | 典型载体 | 调整入口 |
|------|------|----------|----------|
| ① 规则层 | 费用项在各渠道下的取数/计提规则 | 本页「费用来源定义」 | 编辑来源配置并保存 |
| ② 运行层 | 按规则 × 当月基数计算出的各月计提结果 | 月度费用运行（下游模块） | 规则变更后对未关账月自动重跑 |
| ③ 管报层 | 已进库/已关账的正式报表数 | 管报汇总、月度就绪确认（P4） | 不回溯；差额走费用填报调整 |

**关账分层原则（与退款/扣款、费用填报 PRD 对齐）：**

| 归属月状态 | 规则保存后 | 月度运行重跑 | 管报结果 |
|------------|------------|--------------|----------|
| **未月度运行** | 按新规则运行即可 | — | — |
| **已运行、未关账** | 生成新版本后自动触发该月及后续开放月重跑 | ✅ 系统自动重跑，保留运行日志 | 随自动重跑更新 |
| **已关账 / 已进库** | ❌ 不回溯 | ❌ 不允许重跑 | 保留快照；如需更正走差额调整 |

**最早未关账月：** 由财务/产品维护关账月清单（正式环境配置项）；所有自动重算、自动重跑均不得影响清单内已关账月份。已关账月如需更正，只能通过费用填报差额调整处理。

### 4.8 规则版本与生效月（已确认）

每次**保存**来源配置（含启停、类型切换、参数/明细变更）须生成一条**规则版本记录**，至少包含：

| 字段 | 说明 |
|------|------|
| `rule_version_id` | 版本唯一标识 |
| `source_config_id` | 来源配置 ID（如 R001） |
| `effective_from` | 生效归属月，格式 `YYYY-MM`；默认 = **保存操作所在自然月** |
| `source_type` | 费用来源类型快照 |
| `scope_params` | 口径范围、历史窗口、比例基数等参数快照 |
| `detail_snapshot` | 口径明细维护值快照（历史滚动占比为系统计算结果快照） |
| `saved_by` / `saved_at` | 操作人、时间 |

**生效规则：**

1. 查看或运行**某一归属月 M** 时，取 `effective_from ≤ M` 的**最新一条**规则版本；
2. 保存当月及之后未关账月份按新版本计提；已月度运行但未关账的月份由系统自动重跑并生成新的运行快照；
3. 切换来源类型（如固定比例 → 历史滚动占比）视为新版本；旧版本仍关联历史运行快照；
4. 查看历史月份运行明细时，须展示**当时生效的规则版本号**及类型摘要，不得用当前编辑中的规则覆盖展示。

**示例：** 5 月为固定比例且已关账；6 月保存为历史滚动占比。则 5 月运行结果仍关联 v1（固定比例），不回溯；6 月及后续未关账月份自动使用 v2（历史滚动占比）重跑。

### 4.9 历史归属月问题处理指引（已确认）

用户在当前月（如 7 月）发现历史月（5/6/7 月）数据有问题时，按**问题类型**处理，**不在本页做导入模式或自动覆盖**。

| 问题类型 | 判断依据 | 推荐处理 |
|----------|----------|----------|
| **A. 规则错了** | 类型、窗口、基数、明细维护值不应如此 | 修正本页规则 → 系统对**未关账月**自动重跑 |
| **B. 运行结果错了** | 规则无误，但某月计提金额/展开不对 | 对目标月触发系统自动重跑（仅未关账月） |
| **C. 底层历史数据错了** | 历史滚动/同期占比所依赖的历史费用或基数补录有误 | 补录上游数据 → 开放月按 §6.5/§6.6 重算；关账月不回溯 |
| **D. 已关账硬差额** | 关账月不允许重跑，但仍需调管报 | 走《费用填报管理》新增差额调整批次，不覆盖原快照 |

**类型切换特别说明（固定比例 ↔ 历史滚动占比等）：**

- 配置页切换类型会清空并重建明细（§7.2），**不删除**已月度运行的历史快照；
- 历史滚动占比明细占比为**系统计算、只读**，不可手工改比例；只能改规则参数或修正底层历史数据，由系统对未关账月自动重跑；
- 7 月回看 5 月：应展示 5 月运行时绑定的规则版本与结果，而非当前编辑中的规则。

**保存确认文案（须展示）：**

> 本次修改将生成规则新版本，自 **{effective_from}** 起影响后续月度计提。  
> 已关账月份（{关账月列表}）保留快照，不会自动回溯。  
> 未关账月份将由系统自动重跑；已关账月份如需更正，请通过费用填报新增差额调整批次。

## 6. 五种费用来源类型

### 6.1 类型枚举

| 内部值 | 展示名 | 需口径明细 |
|--------|--------|------------|
| auto | 自动取数 | 否 |
| fixedAmount | 固定金额 | 是 |
| fixedRate | 固定比例 | 是 |
| rollingRate | 历史滚动占比 | 是 |
| yoyMonthRate | 同期占比预估 | 是 |

### 6.2 自动取数

**参数：** 无额外规则参数。

**行为：**
- 显示提示：系统从既有数据源自动同步，仅需确认费用项与适用渠道；
- 隐藏口径范围与明细区；
- 保存提示：`已保存：自动取数 · 渠道「…」`

**本期不展开：** 数据源、同步频率、失败补数、对账口径。

### 6.3 固定金额

| 参数 | 必填 | 说明 |
|------|------|------|
| 默认月固定金额 | 是 | > 0，顶部默认值为批量编辑参考金额 |
| 币种（顶部） | 否 | 可选手动选择；选项含 CNY/USD/EUR 等标准三字码；**默认 USD**（不再默认 CNY）；用于批量填入金额时的参考币种，**不替代**明细行币种 |
| 适用周期 | — | 固定「每月」 |

**明细维护列：**

| 列 | 必填 | 说明 |
|----|------|------|
| 月固定金额 | 是 | > 0 |
| 币种 | 是 | 下拉可选；与金额成对维护，**每行各自独立** |

**明细币种默认带出规则（已确认）：**

1. 按明细行 **国家** → 主数据「国家当地币种」映射；
2. 若口径含 **站点/店铺**（无国家列）→ 按站点所属国家再映射当地币种；
3. 映射不到 → 币种为空，**保存前必选**；
4. **仅首次带出**；用户已手改过的币种，不因国家/站点变化被覆盖。

**适用范围：** 仅「费用来源 = 固定金额」增加明细币种列；固定比例、历史滚动占比、同期占比预估**不加**币种列。

**计算：** 按各明细行维护的金额与币种成对参与计提（金额按该行币种理解）。

### 6.4 固定比例

| 参数 | 必填 | 说明 |
|------|------|------|
| 默认比例值（%） | 是 | 0–100，步长 0.01 |
| 比例基数 | 是 | 当月实际营收 / 当月销售额；须持久化 |

**明细维护值列名：** 比例值（%）

**计算：** `本月费用 = 当月比例基数 × 明细比例值`

### 6.5 历史滚动占比

| 参数 | 必填 | 说明 |
|------|------|------|
| 历史窗口 | 是 | 近 12/6/3 个月 |
| 比例基数 | 是 | 当月实际营收 / 当月销售额 |

**计算公式：**
```
滚动占比 = AVG(历史各月费用 ÷ 历史各月基数)   // 仅对有效月求平均
本月费用 = 当月比例基数 × 滚动占比
```

**有效月判定与缺数处理（已确认）：**

| 场景 | 处理规则 |
|------|----------|
| **缺数月份**（费用或基数为空） | 不参与滚动窗口计算 |
| **有效月不足**（如窗口 12 个月但仅 2 个月有数） | 按**实际有效月数**求平均，不设最低月数门槛、不阻断启用/运行 |
| **异常月**（基数 ≤ 0） | 剔除该月，不参与均值 |
| **极端占比 / 负值月份** | 按原公式 `费用÷基数` 正常计入均值，**不告警**；财务场景允许负数，拉会整年均值不受影响 |
| **补录后** | 已关账/已出报表月份保留快照、不回溯；当前开放月及未来月用补录后数据重算 |

**明细维护值：** 滚动占比（%），**系统计算、只读**，不可手工编辑、不可批量编辑、不可导入。

### 6.6 同期占比预估

| 参数 | 必填 | 说明 |
|------|------|------|
| 比例基数 | 是 | 当月实际营收 / 当月销售额 |
| 历史参考窗口 | — | 固定近 12 个月（用于校验） |
| 缺数处理 | — | 固定取近 12 个月滚动均值 |

**计算公式：**
```
本月预估占比 = 去年同月费用 ÷ 去年同月基数
缺数时 = 过去 N 个月有效占比算术平均（N ≤ 12，仅含基数 > 0 的月份）
本月费用 = 当月比例基数 × 本月预估占比
```

**补录与重算（已确认）：**

| 数据状态 | 是否重算 |
|----------|----------|
| 已月度运行 / 已出管报 | ❌ 不回溯，保留快照 |
| 当月运行中、未关账 | ✅ 用补录后参考数据重算 |
| 未来月预估 | ✅ 随最新参考数据更新 |

**明细维护值：** 预估占比（%），可手工维护、批量编辑、导入。

## 12. 主数据管理入口

本页工具栏并列提供「费用部门管理」「费用项管理」两个主数据弹窗。二者数据本地持久化（原型为浏览器存储；正式环境入库），关闭弹窗后本页费用项下拉即时刷新。

### 12.1 费用项管理

**入口：** 列表工具栏「费用项管理」

**初始化与编码：** 见 §19.1、§19.2（与原型种子 `fee-item-master-data.json` / `DEFAULT_ITEMS` 一致）。

**树层级（已确认，共 7 级）：**

| 顺序 | 层级名称 | 说明 |
|------|----------|------|
| 1 | 管报业务总类 | 如收入、成本、毛利、费用、营业利润、销量、退货数量 |
| 2 | 大类 | 如市场投入、公共费用 |
| 3 | 子类 | 如营销投入、渠道投入、销售投入 |
| 4 | 管报场景 L1 | 如自主营销、渠道激励 |
| 5 | 管报场景 L2 | 如产品营销、平台费用 |
| 6 | 管报场景 L3 | 如海外社媒投放、平台佣金（部分路径在此层即末级） |
| 7 | 管报下级费用项 | 如发货佣金、退货佣金（有下级时才出现） |

- **「线上 / 线下 / 线上/线下」不是费用项层级**，源表中该列仅作业务属性说明，**不得作为树节点**。
- 弹窗树须展示完整初始化树（含收入/成本/费用等全部分支），不得使用旧版短编码样例（如 `CAT01`、`F001`）。

**编码规则（摘要，详见 §19.1）：**
- 格式为**连续字符串，不加 `-`**：根 `T`+两位（`T01`、`T04`），下级在父编码后直接拼两位同级序号（`T0402`、`T040301010102`）；
- 解析层级：去掉前缀 `T` 后按每 2 位切分；
- 费用项树由**初始化主数据 / 后台配置**维护；本页**不提供**新增节点、新增下级、编辑、删除。

**列表/导出展示（与本页联动）：**
- 「费用项」列主文案为**名称全称**（根到当前节点路径，` / ` 连接）；编码以次要样式另起一行展示；
- 导出拆为「费用项名称全称」「费用项编码」两列。

**弹窗能力（只读树 + 备注）：**
1. 树形**只读浏览**：支持全部展开/收拢、按名称/编码搜索（自动展开匹配路径）；
2. **不提供**「新增节点」「新增下级」「编辑」「删除」；
3. 节点展示：`名称 · 连续编码`（编码无 `-`）；
4. **仅可维护备注**：补充适用场景与口径边界，不直接改变计提逻辑；有备注时操作区显示提示；
5. 业务配置仅可选**无下级的末级节点**；有子节点的父节点不可被选为费用项。

**与本页联动：**
- 列表筛选、新增/编辑弹窗的费用项下拉与主数据同步；
- 树结构变更（若有）由初始化/后台完成，本页刷新后下拉同步。

**改名与历史快照（已确认）：**
- 费用项以**连续编码**为唯一键，名称/全称仅作展示；
- 月度运行/管报生成时落库 `fee_code + fee_name_snapshot`（建议快照存名称全称），历史报表展示快照；
- 名称变更由主数据侧完成，不触发历史重算；审计记录「原名 → 新名」。

### 12.2 费用部门管理

**入口：** 列表工具栏「费用部门管理」

**初始化数据：** 见 §19.3（与原型 `DEFAULT_NODES` 一致）。

**字段约定（已确认）：**
- **不展示、不维护「节点编码」**：新增/修改弹窗、右侧详情、导出均不出现节点编码；业务识别依赖名称 + 金蝶组织/BM。
- **不维护「属性类型」**（如渠道经营/公司共享）：初始化数据与页面均不含该字段。
- 仍展示并维护：名称、上级节点、费用可选、金蝶组织、金蝶 BM 编码/名称、备注。

**树结构与展示：**
1. 最上层为金蝶组织（如 102/109/110/127），其下按部门层级展开；
2. 费用可挂到**中间层级**（如销售中心、新渠道），也可挂到末级渠道/部门（含 OC（全渠道）等独立部门）；
3. 节点展示名称，并可对照金蝶组织、BM 编码与名称，便于与财务对账；
4. 业务页部门下拉展示格式统一为：`组织编码·组织名 / 管报部门名`（如 `102·Govee / APP商城`）。

**维护能力：**
1. 支持新增、修改、删除、导出（导出列不含节点编码/属性类型，含名称、上级名称、金蝶对照等）；
2. 有下级时须先删下级再删父节点；
3. **级联禁用：** 上级设为「禁用不可选」时，所有下级自动级联为「禁用不可选」；
4. 禁用部门在业务页面的部门下拉中**不显示**，避免误选。

**与本页关系：**
- 本页「费用来源」配置流不直接绑定部门字段；
- 作为费用管理模块统一主数据入口，供费用填报归属、分摊/不分摊部门必填、管报对账等下游使用；
- 部门主数据变更后，费用填报等页的部门树同步生效。

## 13. 状态机

```
┌─────────┐  列表停用 / 保存为停用   ┌─────────┐
│  启用   │ ──────────────────────► │  停用   │
│         │ ◄────────────────────── │         │
└─────────┘  列表启用 / 保存为启用   └─────────┘
     │ 参与计提、占用渠道                  │ 保留配置、不占渠道
     └────────────────────────────────────┘
```

**转换约束：**
- 停用 → 启用：须通过渠道占用校验；
- 规则修改或启停：仅影响未运行月份；已运行/已关账月见 §4.7–§4.9。

## 16. 验收清单

1. 设置筛选项后点击「查询」，列表按条件刷新；导出与列表筛选结果一致。
2. 列表摘要按明细汇总展示区间/均值，与明细实际值一致。
3. 启用配置占用渠道；停用配置不占渠道、编辑保存不被渠道冲突拦截。
4. 列表启用前校验渠道冲突；弹窗保存仅启用状态校验。
5. 说明字段保存后可回显。
6. 切换编辑不同记录时，不适用字段不残留上一条值。
7. 固定比例的比例基数（rateBase）保存后可回显。
8. 历史滚动占比明细只读，不可编辑/导入。
9. 查看模式：表单只读，筛选与导出仍可用。
10. 自动取数不展示口径明细，保存仅需费用项+渠道。
11. 启停后已运行月份不重算，未运行月份按新规则。
12. 费用项管理弹窗：无新增节点/新增下级/编辑/删除；仅可维护备注；树只读浏览+搜索+展开收拢（§12.1）。
13. 同费用项可在不同渠道配置不同来源类型；同渠道启用配置仍互斥。
14. 历史滚动占比：缺数/基数≤0 月剔除；有效月按实际月数均值；负值月正常计入、不告警。
15. 同期占比补录后不回溯关账月；导出含停用（筛全部时）、CSV UTF-8 BOM。
16. 切换来源类型、移除渠道、缩口径等破坏性操作须二次确认。
17. 列表「费用项」展示名称全称 + 次行连续编码（无 `-`）；导出两列分别为全称与编码。
18. 费用项管理树层级不含「线上/线下」；初始化树完整（§19.2），无旧版 `CAT*`/`F*` 短编码残留。
19. 费用部门管理/初始化不展示节点编码、不维护属性类型（§12.2、§19.3）。
20. 口径范围支持「渠道+店铺」「渠道+店铺+零售商」；店铺口径不展示国家列。
21. 店铺仅加载已选渠道对应店铺；零售商仅线下商超有值，其它渠道零售商为空。
22. 保存来源配置后生成规则版本，`effective_from` 默认为保存月；历史月查看展示当时版本。
23. 保存确认文案含生效月、关账月不回溯说明。
24. 规则变更后，未关账月由系统自动重跑；已关账月重跑拦截并提示费用填报差额调整。
25. 固定比例改历史滚动占比后，已关账月运行快照仍为旧类型，未关账月自动使用新类型重跑。
26. 固定金额：顶部币种默认 USD；明细「月固定金额」后有币种列，默认按国家/站点当地币种带出，可改选，保存前必选。

28. 固定金额导入/导出明细含币种列；其它来源类型不加币种列。

## 17. 已确认事项

1. **同费用项多来源类型**：允许在不同渠道并存；同渠道启用配置互斥（§4.6）。
2. **口径范围变更迁移**：按 key 尽量保留；缩口径取最近维护值；保存前预览确认（§7.2）。
3. **历史滚动占比缺数/异常/补录**：缺数月、基数≤0 月剔除；有效月按实际月数求均；负值/极端占比正常计入不告警；补录不回溯关账月（§6.5）。
4. **同期占比补录重算**：已关账月不回溯；开放月与未来月重算（§6.6）。
5. **费用项改名**：历史报表保留 `fee_name_snapshot`，编码不变、不触发重算（§12.1）。
6. **列表导出**：跟随查询筛选；状态「全部」含停用；CSV UTF-8 BOM；字段顺序见 §5.3。
7. **破坏性操作确认**：切换来源类型强确认；移除渠道、缩口径中确认（§14）。
8. **费用项展示与编码**：列表展示名称全称；编码为连续串不加 `-`（§5.1、§19.1）。
9. **费用项树层级**：仅总类→大类→子类→场景 L1/L2/L3→管报下级费用项；「线上/线下」不入树（§12.1）。
10. **费用部门无节点编码/属性类型**：页面与初始化表均不包含；业务以名称+金蝶组织/BM 识别（§12.2、§19.3）。
11. **费用项管理仅备注**：本页不提供新增/编辑/删除树节点，仅可维护备注；树结构由初始化主数据维护（§12.1）。
12. **店铺口径**：新增「渠道+店铺」「渠道+店铺+零售商」；店铺按已选渠道从渠道店铺基础数据加载；店铺口径不含国家列（§7.1、§7.4）。
13. **零售商仅线下商超**：所有含零售商口径统一适用；线下商超展开零售商，其它渠道零售商为空（§7.5）。
14. **规则版本与生效月**：每次保存生成版本；按归属月取最新 `effective_from`；历史运行展示当时版本（§4.8）。
15. **关账分层**：已关账/已进库月不回溯；未关账月自动重跑；硬差额走费用填报差额调整（§4.7、§4.9）。
16. **不做导入模式**：来源配置与历史修正均不采用追加/覆盖导入模式；已关账差额由费用填报处理。
17. **已关账月更正**：不重跑、不覆盖原快照，统一通过费用填报差额调整处理。
18. **固定金额币种（2026-08-12）**：顶部币种默认 USD 且可选；明细行新增币种列，按国家/站点当地币种默认带出、可改选、仅首次带出；批量编辑方案 B（金额必填+币种可空）；导入导出含币种；其它来源类型不加币种列（§6.3、§9.5–§9.7）。

## 19. 主数据初始化与编码规则

### 19.1 费用项编码规则

1. **唯一主键**：费用项以编码为唯一键，名称仅作展示；改名不改编码。
2. **树形编码格式（连续串，无分隔符）**：
   - 管报业务总类：`T` + 两位序号，如 `T01`（收入）、`T04`（费用）；
   - 下级节点：在父编码后直接拼接两位同级序号，如 `T0402`、`T04030201`（**不加 `-`**）；
   - 同级序号按初始化清单出现顺序从 `01` 递增；固定两位，可按每 2 位解析层级。
3. **层级范围（仅以下 7 级，不含线上/线下）**：管报业务总类 → 大类 → 子类 → 管报场景 L1 → 管报场景 L2 → 管报场景 L3 → 管报下级费用项。源数据中的「线上/线下」仅作业务属性说明，**不进入费用项树**。
4. **去重**：相同路径只保留一条节点。
5. **展示**：列表「费用项」展示**名称全称**（根到末级，用 ` / ` 连接）；编码另起一行或次要样式展示连续编码。
6. **可选性**：业务配置仅可选末级节点。
7. **维护边界**：费用来源页「费用项管理」**仅可改备注**，不在前端增删改树节点；树结构变更走初始化数据/后台主数据。
8. **初始化规模**：共 **135** 个节点，末级 **97** 个；种子文件 `原型/费用管理/fee-item-master-data.json`。

> **说明**：连续编码不会引入业务冲突，只要保证全局唯一且两位分段固定即可；比带 `-` 的编码更利于入库字段长度与模糊检索。解析层级时按 `T` 后每 2 位切分即可。
