# 项目知识库具体方案（知识原子 × 组装页）· 试点 MVP

> 依据：`01核心需求` 需求 D + `03方案框架` 第四件事 + 对象模型 MVP 对齐（2026-08）  
> 定位：把「数字驱动的项目上下文」落成 **可执行的试点对象模型**；全链 KO→CR 模板，对象规则收窄，避免大系统建设。  
> 工作如何被点亮、完成、改版：见同目录 `工作网.md`。  
> 本文不展开：搜索信息架构、汇入点清单 UI、派生原子、文件夹钉版本、组装页独立版本链。

---

## 一句话结论

项目知识库不是网盘。**知识原子是一等公民（源）**；**组装页是给人看的视图**（引用原子@钉扎 + 胶水）；**文件夹只是标签导航**（不钉版本）。试点采用「原子版本链 + 组装页最新视图 + JP 汇入快照」；源更新只提醒、不灌入；历史汇入靠快照复现。

## 0. 试点范围与执行节奏（已对齐）

| 项 | 试点做法 |
|---|---|
| **阶段覆盖** | KO→CR 全链工作模板与 JP 必看清单 |
| **文件夹** | 仅标签/导航（阶段、解耦组、材料类型），**不钉文件版本** |
| **组装页版本** | **最新视图** + **JP 汇入快照**；不做组装页独立 v1/v2/v3 版本链 |
| **派生原子** | **第一期不做**；不能改源 → 走协同单 |
| **权限** | **两档**：项目成员可看；原子/组装页责任人可改 |
| **原子规模** | A 档 ~35（各 JP 必看）+ B 档 ~25（组内接口/产出），合计 ~60 |

```text
Step 1（1～2 周）定清单
  H8120 抽 A/B 档原子 + 全链 JP 必看表 + 工作模板表头

  原子定稿/冻结/钉扎/落后提醒；组装页引用；文件夹标签筛

  每月复盘：原子是否过多、JP 口径是否够用
```

## 0.1 已拍板规则（试点执行以本表为准）

| # | 规则 |
|---|---|
| R1 | 知识原子可被多个组装页引用；组装页可被多个文件夹 **标签** 命中。都是引用，不是复制。 |
| R2 | **知识原子**有：版本链、状态、责任人、修改时间、修改摘要。**组装页**有：责任人、分组布局、胶水文本、对各原子的钉扎；**无独立版本链**（历史靠 JP 快照）。 |
| R3 | 对外仍说「最新 / 定版」；对内原子是 **一条版本链 + 多个命名冻结点**（ES/TL/DR/BT/CR…）。「最新」永远是工作头。 |
| R4 | **定稿** 与 **打冻结点** 是两个动作（试点 UI 可合并为一步「定稿并打 ES 定版」）。定稿 = 不可再改、可被引用；冻结点 = 阶段标签；打上后 **不回拨**。 |
| R5 | 组装页引用默认 **钉死某一已定稿版本**。每个引用位只钉一版。 |
| R6 | 新挂引用默认钉「当前场景定版」（有对应冻结点钉该点，否则钉最近一次定稿）。不是默认钉 v1。 |
| R7 | 源出新定稿 / 新冻结点 ≠ 自动改写组装页钉扎，更 ≠ 改写已固化的 JP 快照。 |
| R8 | 提醒分两种：① 责任人「你有未定稿最新版」；② 引用方「所钉版本已落后」。 |
| R9 | 打开时是 **消费提醒**；改钉扎 **仅组装页责任人**，批量处理。普通读者不强迫选版本。P0 走调整机制。 |
| R10 | 「保持当前版」后，同一冻结点不再每次追问；直到该原子出现 **更新的定稿/冻结点**。 |
| R11 | **文件夹不钉版本**；只按标签列出组装页，并汇总 A 档原子是否达 JP 冻结要求。 |
| R12 | **JP 汇入快照** = 该 JP 时刻的钉扎集合 + 胶水 + 各原子当时版本与附件；打开历史 JP 必须可复现。 |
| R13 | 组装页所钉原子若存在未定稿版本，该组装页 **不能参与 JP 快照导出**（日常仍可编辑最新视图）。 |
| R14 | 原子定稿时附件一并冻结，禁止原地覆盖。 |
| R15 | 组装页 = 原子引用 + 分组 + 胶水。长文/图纸挂在原子下；仅多处复用内容才升格为原子。 |
| R16 | 组装页内原子必须 **分组**（外观 / 规格 / 认证…）。 |
| R17 | **试点不做派生**；非责任人不能改源，走 **协同单**（见协作流程 P0/P1/P2）。 |
| R18 | **权限两档**：项目成员可看；原子责任人改原子，组装页责任人改钉扎与布局。极少数敏感原子可标「仅某组可见」。 |
| R19 | 原子可独立查看、可按名/责任人/是否未定稿筛选；完整搜索 IA 后续做。 |
| R20 | 汇入验收看 **A 档原子是否均已打对应冻结点** + JP 快照是否已固化；清单 UI 后续做，数据模型先支撑。 |

**完整方案预留、试点不做**：文件夹钉文件@定版（原 R11 同构）、组装页独立版本链、派生原子树、细粒度 ACL 分文件/分原子两套。

## 1. 要解决什么

### 1.1 两层重复，试点只做强一层引用

| 层 | 解的问题 | 2.0 试点做法 |
|---|---|---|
| **组装页层** | 同资料复制进多夹 | 一份组装页，多文件夹标签命中 |
| **知识原子层** | 同内容写进多份材料 | 一个原子，多组装页引用@钉扎 |

文件夹 **不参与** 第二层引用链，只做导航与 JP 汇总视图。

### 1.2 和「字段化」的关系

- **知识原子** = 字段化对象（单值、内容块、带附件），不是表单输入框。
- **组装页** = 按角色/阶段给人读的视图，不是 Word 堆。
- **JP 快照** = 汇入验收时刻的不可变包。

对外统一称 **知识原子**。

---

## 2. 对象模型（试点：三层 + 标签）

```text
项目
 ├── 知识原子（源 · 一等公民）
 │     ├── 版本链：最新(未定稿) → 定稿 → 冻结点 ES/TL/DR…
 │     ├── 附件（随定稿冻结）
 │     └── A 档 / B 档（是否 JP 必看）
 │
 ├── 组装页（视图 · 非源）
 │     ├── 分组 + 胶水文本
 │     └── 引用 → 知识原子@钉死已定稿版本
 │     └── 日常 =「最新视图」；JP 通过时 → 导出快照（挂 JP 记录）
 │
 ├── JP 汇入快照（不可变）
 │     └── 某 JP 时刻：各原子版本号 + 钉扎 + 胶水
 │
 └── 文件夹（标签 · 非源）
       └── 标签：阶段 / 解耦组 / 材料类型 → 筛出组装页列表
       └── 汇总：A 档原子冻结是否齐
```

| 对象 | 是否源 | 打开时看到什么 |
|---|---|---|
| 知识原子 | 是 | 内容、版本链、冻结点、被哪些组装页引用 |
| 组装页 | 否 | 分组原子列表（各钉一版）+ 胶水；可改钉扎 |
| JP 快照 | 否（历史固化） | 汇入当时那一包，不可改 |
| 文件夹 | 否 | 标签筛出的组装页 + A 档原子达标摘要 |

## 3. 知识原子

### 3.1 形态与分档

| 形态 | 例子 |
|---|---|
| 单值 | BT 结论、PRD 版本号、DR 试产轮次 |
| 内容块 | 外观主视觉、板框方案摘要 |
| 带附件 | 2D/3D、测试报告（挂在原子下） |

| 分档 | 数量（试点） | 用途 |
|---|---|---|
| **A 档** | ~35 | 各 JP 必看；汇入验收硬门槛 |
| **B 档** | ~25 | 组内产出与接口；不进 JP 硬门槛 |

**试点不做复合原子树**：外观拆成平级原子（主视觉 / 尺寸 / CMF），不嵌套父子块。

### 3.2 必备属性

标识、显示名、责任人、版本链、状态、修改摘要、内容、附件、引用清单、**分档（A/B）**。

### 3.3 谁改、改哪一版

责任人只改 **最新未定稿**；已定稿不可改；要改则复制为新最新。定稿与打冻结点逻辑分开（UI 可合并一步）。

---

## 4. 组装页（= 文件，试点无独立版本链）

打开组装页：分组展示所引用的原子（各钉一版）+ 胶水；点原子标题进本体。

| 类型 | 是否复用 | 是否进 JP 快照 |
|---|---|---|
| 引用的原子（钉死某版） | 是 | 是 |
| 分组与排序 | 仅本页 | 是 |
| 胶水文本 | 否 | 是 |

**与完整方案差别**：组装页没有自己的 v1→v2 定版链；**JP 快照挂在 JP 记录上**，不是「组装页·TL 定版」这种文件级历史。

---

## 5. 文件夹 = 标签导航（试点）

- 文件夹 = `阶段`（ES/TL/DR…）、`解耦组`、`材料类型` 等标签。
- 打开「ES 文件夹」= 所有带 ES 标签的组装页 + **A 档原子 ES 冻结是否齐**。
- **不钉版本、不复制、不提醒升级文件夹层钉扎**。

---

## 6. 版本：原子一条链 + 多个冻结点

```text
v1 定稿 ──● ES 定版
           │
v2 定稿 ──● TL 定版      ← 相对 v1 没改时，TL 可打在 v1 上
           │
v3 最新（未定稿，可编辑）
```

组装页 **不参与** 此版本链；汇入验收时把当时钉扎写入 **JP 快照**。

---

## 7. 引用与钉扎

逻辑同前（R5～R10）：每个引用位钉一版；源更新不灌入；仅组装页责任人可批量升级钉扎。

新挂引用：有场景冻结点则钉该点，否则钉最近定稿；无定稿则不可参与 JP 快照导出。

---

## 8. 提醒分档

| 档 | 谁看到 | 行为 |
|---|---|---|
| A. 未定稿 | 原子责任人 | 你有未定稿最新版 |
| B. 消费提醒 | 任何打开者 | N 个引用源已更新，不打断 |
| C. 升级决策 | 组装页责任人 | 清单：升 / 保持 / 稍后 |
| D. 强制同步 | 调整规则圈定人 | P0 不靠碰巧打开；知识库提供影响面 |

---

## 9. JP 汇入快照与附件

### 9.1 快照内容

- 各原子引用钉的版本号与附件
- 组装页分组、胶水
- JP 标识、时间、导出人/责任人

打开「JP-ES 快照」：按当时版本还原，即使原子后来已到 v5。

### 9.2 附件

原子定稿时按版本存储，禁止同槽位覆盖。图纸展示摘要 + 附件清单；不承诺 CAD 级 diff。

---

## 10. 派生 / 覆盖（完整方案 · 试点不做）

试点：**非原子责任人** 不能改源 → **协同单**。  
第二期再评估：子原子拆分或派生树。

---

## 11. 权限（试点两档）

| 动作 | 谁 |
|---|---|
| 改原子最新、定稿、申请打冻结点 | 原子责任人 |
| 改组装页钉扎、布局、胶水 | 组装页责任人 |
| 导出 JP 快照 | 组装页责任人或 JP 组织人（PM/项目经理） |
| 给原子打冻结点 | 汇入验收确认后；与定稿按钮分开 |
| 查看 | 项目成员（默认） |
| 敏感原子 | 可标「仅某组可见」（少数，不铺全量 ACL） |

改钉扎只组装页责任人；原子责任人不能替下游改钉扎。

---

## 12. 分组与原子粒度

- **分组**：组装页布局必需。
- **平级原子**：需要独立定稿、独立责任人、独立作为工作输入/输出的，拆成单独原子。
- **不嵌套复合块**：避免派生前的局部覆盖复杂度。

---

## 13. 汇入点如何消费

打开 ES 标签视图 / JP-ES，回答：

> A 档原子是否均已 **ES 冻结**？哪些组装页钉扎落后？责任人是谁？JP 快照是否已导出？

数据支撑：原子冻结状态、钉扎落后计算、引用影响面、JP 快照列表。

## 附录 B · H8120 走查（外观主视觉 · 试点版）

1. 建 A 档原子「外观主视觉」，ID 责任人。v1 定稿并打 **ES 冻结**。  
2. 组装页「ID 包」「结构说明」「包材页」引用该原子，钉 ES 定版；三页共享同一源。  
3. ID 改最新 v2（未定稿）：三页展示不变；ID 见「未定稿」提醒。  
4. v2 定稿并打 **TL 冻结**：三页出现消费提醒；**仅各组装页责任人** 决定升 TL 或保持 ES。  
5. 结构需要不同外观：结构 **发起协同单**（试点不派生）；包材仍钉主原子。  
6. **JP-TL 通过**：导出 **JP-TL 快照**（当时钉扎 + 胶水 + 各原子版本）。三个月后打开快照仍是当时那包。  
7. DR 外观 P0 变更：引用清单算影响面，走调整规则，不靠碰巧打开包材页。
