4

协作区：文档结构化接在货架后面

中台决定用什么能力。选定之后，项目里和日常方案里怎么协作，用同一套方法：输入钉扎、Skill 出文档、条件工作、跨组协同、到点汇入、回写沉淀。这就是环上第 5 步，也是回到第 1 步的入口。

结构化文档

PRD 和专业输出按模块 / 字段生成，而不是先交一整本再人工拆。Skill 根据已选模块和补充需求出文档，归档后回写产品方案。

条件工作

每个解耦单元看必要输入是否就绪。输入是钉扎过的模块方案或知识版本，不是「等上游把包发我」。能单验的先单验。

到点汇入

汇入点对齐 CD / KO / ES / TL / DR / BT / CR。带什么、过不过、谁回退写清。PJM 维护规则和风险，不细排每人每日任务。

如何协作 · 四条规则

变了、要帮忙、碰头了，不靠项目经理临时拉群

规则项目里怎么做日常方案怎么做例子
启动 KO 后各增量块认领目标、接口、自己策划资源。输入未定稿，工作保持灰色，不能开工。 补方案或改接口时同样认领输入版本。不拉整机项目，也可以启动一块日常修订。 制冷不等 ES 整机，接口字段就绪就排手板。
调整 需求大变按 P0 / P1 / P2 分级：P0 全员知，P1 相关组联合定，P2 组内自决并留痕。 货架上方案改档、改适用产品，也要定级。影响已引用 SKU 的，至少按 P1 通知相关主责人。 PRD 改外观导致结构改模 → P0 或 P1，不能私聊改完。
协同 A 块向 B 块提接口诉求，走协同单：要什么、何时要、影响什么。达不成再升级。 日常改开孔、改板框版本、改制冷接口，同样发协同单。禁止「群里说一声就算定了」。 电子要结构改开孔 → 协同单，而不是等项目经理转述。
汇合 到 JP 带清单验收。不过时写清谁回退、别人能不能继续。复用项只核对引用版本。 日常方案定稿也是一次小汇合：主责人验收、解耦组负责人确认对象和状态，然后变绿。 DR 试产制冷不达标 → 制冷 + 结构回退，包材可先不动。
条件工作网

一块工作什么时候能开始，看输入，不看催办

灰 · 未就绪

必要输入还是未定稿，或版本未钉扎。主责人能看见阻塞原因，但不能开工。

琥珀 · 可开始

输入已定稿。对应角色才能点开工，并把输入版本钉扎，避免做到一半被偷偷换版。

蓝 · 进行中

在钉扎版本上产出。能单验的先单验，不必等整机包。跨组缺口发协同单。

绿 · 已完成

输出已定稿，下游或 JP 可引用。增量结果先灰回写货架，阶段冻结后再变绿。

PJM 看的是哪条工作被输入卡住、哪个 JP 有风险，不是给每个人排每天干什么。

跨组协同单

怎么向别的专业要东西

组间不再传「等结构发我包」，而是传明确字段，例如板框版本 ≥ v2.1。字段未达标，协同单自动可见，而不是项目经理私下协调。

需求方发起→ 写清字段 / 时点 / 影响→ 响应方确认或拒绝→ 达不成升级 P1 / P0→ 结果写入上下文
  • P0：影响全项目目标或多个 JP，全员 + 业务侧知会
  • P1：影响 2 个以上解耦组接口，相关组联合决策
  • P2：组内微调，自决但字段留痕
  • 判断无法按共识 JP 日汇合时，3 个工作日内发起调整或协同
Skill 与知识原子

文档跟着增量生成

硬件产品经理或解耦组负责人用 Skill，按已选模块和增量需求生成结构化 PRD / 知识原子。文档结构化是产出，不是解耦目的。

  • 知识原子仍是最小可引用单元：责任人、适用范围、来源、正式版本
  • 方案卡片先看归纳，质疑时下钻字段和原文
  • 原子未定稿，下游条件工作保持灰色
  • 归档后回写产品方案，环才能回到沉淀
到点汇入

碰头日看证据，不催整包材料

汇入点时间是大家约好的碰头日，可以提醒，不是压缩内部排期的鞭子。每块只带本块结论：什么叫过、不过谁回退、别人能不能继续。

节点项目里带什么和货架的关系
CD / KO模块组合已拍板，增量清单、接口和汇入点确认，协作区打开。复用项钉扎货架上的绿色方案版本。
ES各专业单验结论先齐套，再汇合整机是否可行。增量方案可以未定稿回写，先灰着进货架。
TL开模前冻结 3D / 2D 和必须锁定的字段。被钉扎的模块方案不能悄悄换版。
DR / BT / CR试产轮次、用户测试结论、能否释放。每轮也是子汇合。阶段冻结或上市后，灰变绿，产品方案成为下一款选型起点。
中台选出模块方案→ 增量进入解耦单元→ Skill 生成结构化文档→ 条件工作网推进→ 协同单处理跨组→ JP 汇入快照→ 回写沉淀 · 灰→绿

H6199 落地灯 Max

灯体

复用

新品要人体感应，货架没有，先作为 PRD 模块概念立新方案。
新做

家电同样走这条路径。例如从 H8120 制冰机开下一款，制冷模块若已定稿且指标满足，就复用，不必整机重做。
