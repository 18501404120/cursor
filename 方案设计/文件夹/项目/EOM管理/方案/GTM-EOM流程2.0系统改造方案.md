## 二、改造背景

### 2.1 业务背景

业务已将 EOM 从半年度专项工作调整为常态化管理：

1. LBU 按月开展被动退市评审，主动退市满足条件后实时发起。
2. ABU 每月预排查、季度统一发起，需求计划和区域 GTM 职责由产品 GTM 承接。
3. EOM 不再只是“发起并确认停产”，而是覆盖退市触发、核料、清库方案、Last Buy、库存清理、物料清理、反 EOM、S&OP 复盘和 EOL 闭环的完整业务过程。
4. 需求计划作为统一归口，需要通过系统维护台账、推动节点并监控清尾进度。

### 2.2 当前系统现状

当前 GTM 系统已具备：

- EOM 流程列表、发起、编辑、查看、关闭、撤回、重新发起。
- 上传 Excel 版 EOM 方案。
- 选择 Model/SKU/MSKU 产品范围。
- 计划人员确认或驳回。
- 核料管理、余料测算、建议下单、物料结余、理论售完日期。
- SKU 核料看板及部分导出能力。
- SCM 侧 BOM 展开、专用料/共用料识别、在库/在途和余料消耗测算。
- EOM/EOL 产品采购下单拦截，准备 EOM 产品下单提示。

当前 EOM 流程状态为：

```text
待提交 → 待计划确认 → 完结
                    ↘ 计划驳回

待提交/待计划确认 → 已关闭
待计划确认 → 撤回
已关闭 → 重新发起
```

### 2.3 核心问题

当前系统本质是“核料测算 + EOM 附件审批”，与业务 EOM 2.0 的差距主要体现在：

1. **流程结束过早**：计划确认后系统即显示“完结”，但业务上此时才进入正式 EOM 和清库执行。
2. **缺少主动/被动退市分流**：没有触发类型、退市规则、替代新品等结构化字段。
3. **台账仍依赖线下维护**：库存、预测、Last Buy、呆滞库存、物料和清库进度未统一进入 EOM 工单。
4. **缺少执行责任链**：销售、计划、PMC、采购、需求计划、计委会没有独立节点任务。
5. **缺少异常处理**：未覆盖新品延期、库存不足、库存积压、BOM 已禁用后追加 Last Buy 等场景。
6. **缺少真实业务闭环**：没有以成品全链路库存清零作为 EOL 自动闭环条件，清尾进度也未进入在线台账。
7. **系统已有数据未充分复用**：核料、库存、日销、物料结余等数据已存在，但没有汇聚到 EOM 台账。

## 三、改造目标

### 3.1 总体目标

将当前“EOM 发起审批”改造为“EOM 全生命周期运营平台”，实现：

```text
退市触发
  → 核料准备
  → 清库方案决策
  → 正式 EOM
  → Last Buy 与库存/物料清理
  → S&OP 复盘
  → EOL 自动闭环
```

### 3.2 具体目标

1. 将业务方案中的主动退市 10 个节点、被动退市 8 个节点纳入系统管理。
2. 以 EOM 工单为载体，以 8 位 SKU 为最小退市管理单元。
3. 自动汇聚产品、渠道、销量、预测、库存、物料和采购数据。
4. 以节点任务驱动七类业务角色协同。
5. 前序节点处理完成后自动通知下一处理人；正式 EOM 后并行消息通知销售、采购和 PMC 查看台账，不发待办。
6. 对清库方案、Last Buy、报废决策、反 EOM 全程留痕。
7. 满足条件后自动将 SKU 状态切换为 EOL。
8. 最终替代线下 EOM 台账和线下清尾跟踪表。

### 3.3 非本次目标

以下能力不在首期一次性完成：

- 重建 Forecast、库存、采购、BOM 等源系统。
- 用 GTM 系统替代采购下单、MRP、报废 OA 等专业系统。
- 一次性清理全部历史主数据。
- 将所有业务动作都设计为主流程状态。
- 建设独立风险预警页、风险等级/风险类型字段。
- 建设 SLA、预警阈值和报废阈值配置中心。
- 建设超期自动升级和 S&OP 风险清单。
- 节点任务驳回；销售/采购/PMC 在 GTM 点完成清尾或留痕。

原则是：**GTM 负责流程编排与台账，专业系统负责数据和专业交易。**

## 四、总体设计原则

### 4.1 工单粒度

#### 4.1.1 主工单粒度

一个 EOM 工单可包含多个 8 位 SKU：

```text
EOM工单
  ├─ 8位SKU A
  │   ├─ MSKU/Listing/渠道明细
  │   ├─ Last Buy记录
  │   ├─ 库存快照
  │   └─ 物料清理记录
  └─ 8位SKU B
```

#### 4.1.2 为什么不以 Model 作为最小粒度

- 产品状态实际按 8 位 SKU 管理。
- BOM、核料和 Last Buy 均需落到 8 位 SKU。
- 同一 Model 下可能存在仍在售或从未上市的 SKU。
- Model 只作为批量发起和汇总查看维度。

#### 4.1.3 为什么渠道不直接存到 SKU 主记录

一个 SKU 可能对应多个 MSKU、店铺、平台和渠道。渠道字段应作为 SKU 下的可展开明细动态查询，避免在 SKU 主记录重复拼接并产生数据不一致。

### 4.2 双状态模型

系统必须将三类状态分开管理：

1. **EOM 工单阶段**：表示业务流程走到哪里。
2. **SKU 产品状态**：表示产品生命周期状态。
3. **节点任务状态**：表示具体责任人是否完成动作。

不再使用一个“状态”同时表达三种含义。

对外（工单列表、筛选、自定义列、导出、详情顶栏与概要、通知）只展示**工单阶段**，不展示现网「流程状态」（待提交 / 待计划确认 / 计划驳回 / 完结）。现网对照仅用于规则说明页和历史数据迁移，不作为业务字段露出。

### 4.3 数据分类

台账数据按四类管理：

| 数据类型 | 示例 | 管理方式 |
| --- | --- | --- |
| 主数据 | Model、SKU、品类、国家规格、上市时间 | 从源系统同步，发起时保存快照 |
| 动态指标 | 当前库存、呆滞库存、DOS、清库进度 | 定时刷新，显示数据时间 |
| 业务事件 | 发起时间、Last Buy 下单时间、确认时间 | 事件发生时固化，不随源数据变化 |
| 人工决策 | 退市原因、清库方案、报废决策、备注 | 结构化录入并保留版本 |

### 4.4 可追溯原则

所有关键数据必须记录：

- 数据来源。
- 统计口径。
- 数据时间。
- 操作人。
- 操作时间。
- 变更前值和变更后值。

## 五、目标业务流程

## 5.1 主动退市流程

### 阶段一：发起 EOM

#### 节点 A1：新老品切换计划释放

| 项目 | 设计 |
| --- | --- |
| 触发时间 | 每年 4 月 |
| 责任人 | 产品 GTM |
| 系统动作 | 建立次年新老品切换计划，关联老品 SKU、迭代新品 SKU、预计 CR 时间和新品上市时间 |
| 输出 | 新老品迭代计划清单 |
| 通知对象 | 需求计划、区域 GTM、销售、计划、PMC、采购 |

#### 节点 A2：发起主动 EOM

| 项目 | 设计 |
| --- | --- |
| 触发条件 | 替代新品已立项并达到 GR1 |
| 责任人 | 产品 GTM |
| 必填信息 | 老品 SKU、迭代新品 SKU、预计 EOL、新品预计 CR、新品上市时间、预测覆盖时间、退市原因 |
| 系统动作 | 生成 EOM 工单；产品状态更新为“准备 EOM”；自动创建核料单并开始计算；对有销售专员的 MSKU 发送钉钉提醒刷新预测；通知 PMC 打开核料页进行核料 |
| 流转方式 | 提交成功后工单进入核料中；Forecast 与核料并行，不卡流程 |

### 阶段二：清库准备

#### 节点 A3：销售刷新预测（并行，不卡流程）

- 与核料并行，不作为进入核料的条件。
- 有销售专员的 MSKU 发钉钉提醒（跳转 Forecast），不生成 GTM 销售待办。
- 销售更新预测并填写可接受 Last Buy 数量（仅供方案参考）。
- 系统自动读取当前预测、近三月销量、库存和 DOS。
- 预测刷新后自动留存版本快照，并刷新台账预测字段。
- **Forecast 审核入库不发钉钉/ERP 通知**；进工单或台账即可看到最新预测。
- 空预测标识数据异常，方案页强提示，不硬拦提交。
- Forecast 后到：未锁定且未确认的建议下单可刷新参考值；已确认 SKU 与已定版核料不自动解锁、不自动重算。

#### 节点 A4：核料

| 项目 | 设计 |
| --- | --- |
| 时间要求 | GR1 + 7 个工作日 |
| 主责 | 需求计划 |
| 执行 | 计划、PMC、采购 |
| 系统能力 | 复用现有核料模块和 SCM EOL 计算能力 |
| 输出 | 建议 LB 数量、物料结余、呆滞责任、供应商额外备料；计划确认的最终下单数量、报废金额、原因、结论、交付天数 |
| 进入条件 | EOM 工单提交成功，不等待 Forecast |

核料计算成功后，计划人员在核料信息页填写结论。数量、金额、原因、交付天数按 SKU 一份（现网合并列）；计划负责人、结论按 MSKU 各一份（现网不合并）。导入只用于快录，不自动确认。勾选单位为 8 位 SKU，该 SKU 下任一 MSKU 结论为空则提醒，不得确认该 SKU。「我负责某 SKU」= 该 SKU 下至少一条 MSKU 的计划负责人是我。无负责人的 MSKU 指定为计划部门负责人，主数据维护后自动刷新。计划部门负责人可填写、导入并确认本单全部 SKU。工单「计划确认人员」由核料行负责人自动带出。

现网工单「确认」只跳转核料页。在核料页确认所选 SKU 后锁定这些 SKU，工单仍为核料中，列表展示已确认 SKU / 本单 SKU。全部 SKU 确认后自动定版，系统通知 GTM 和参与角色确认清库及 Last Buy 方案。一次导入只允许一个工单，不得混单。工单进入核料中即通知 PMC 打开核料页核对专用料、物料结余等测算；PMC 核料不替代计划确认、不卡定版。

#### 节点 A5：确认清库及 Last Buy 方案

GTM **发起人**在清库方案页保存后，点「GTM确认整单」才记 GTM 已确认（保存本身不视为已确认）。确认前二次校验：必须已上传 GTM确认方案和 EOM方案，未传硬拦；空预测强提示、不硬拦。GTM 名单中其他人只收通知。只会签计划：普通计划负责人确认自己负责的 SKU，计划部门负责人可确认本单全部 SKU。全部 SKU 计划确认后方案生效，**不等报废 OA**。需求计划、销售、PMC、采购只收通知，可进工单查看，不在系统点确认。无方案驳回；有问题由发起人直接改当前方案（改后清空确认），或发起人关闭工单后重新发起。关闭仅发起人。本期不做撤回。

系统要求结构化填写：

- 清库方式：正常销售、降价、渠道调拨、改制、转卖、报废。
- Last Buy 计划时间、实际下单时间、完成时间、数量及执行计划。
- 成品库存处理方案。
- 专用物料处理方案。
- 责任部门及费用归属。
- 预计 EOL 时间。

涉及报废时，页头汇总成品报废合计、物料报废合计。成品合计超过 50 万元或物料合计超过 20 万元时，保存方案或点「GTM确认整单」给出**非阻断提示**：请线下发起计委会 OA。系统不创建 OA、不回写审批结果、不挡 GTM/计划确认与正式 EOM。线下 OA 不同意时，发起人改当前方案或正式 EOM 后改版；系统不自动退回。

### 阶段三：执行 EOM

#### 节点 A6：正式 EOM

清库和 Last Buy 方案确认后：

1. EOM 工单进入“EOM 执行”阶段。
2. SKU 产品状态由“准备 EOM”切换为“EOM”。
3. EOM 产品禁止继续新增普通采购下单。
4. 已确认的 Last Buy 通过专门标识放行。
5. 固化正式 EOM 基准库存、预测和物料快照。
6. 同时生成销售清库存、采购跟踪 Last Buy、PMC 清专用料三类并行跟踪任务，并以消息通知（不发待办）。销售不在 GTM 点完成、不留痕。

> 当前系统“计划确认后完结”应调整为“计划确认后进入 EOM 执行”。

#### 节点 A7：库存清理

- 销售按清库方案在销售侧执行，不在 GTM 记录清库动作。
- 系统每日刷新库存，双周形成清尾快照。
- 需求计划通过在线台账查看当前库存、呆滞库存、PSI DOS 和清库进度。
- 如需调整方案，由 GTM 新增清库方案版本，不设置独立风险等级或风险字段。

异常类型：

1. 老品库存已清零但新品延期。
2. 老品库存不足以支撑到新品上市。
3. 新品正常上市但老品库存未清完。
4. 清库进度低于计划。
5. 呆滞库存占比持续上升。

#### 节点 A8：物料清理

触发条件：

- Last Buy 订单及在途订单已全部入库。

PMC 在台账查看专用料剩余数量、金额和预计完成时间。首期不要求在 GTM 点完成或填写改制/转卖/报废人工进度。报废 OA 走线下，台账不关联审批单、不回写结果。

#### 节点 A9：反 EOM

不限制发起人、退市类型、BOM。仅正式 EOM 后（工单阶段为 EOM执行或 EOL已闭环）可发起；草稿、核料中、待方案决策尚未 EOM，取消走关闭，不出现反 EOM。已有审批中的反 EOL OA 时不可再发。

```text
工单详情填写 SKU / PSKU / 反EOL原因 / 附件 / 审批人（多选）
  → 提交后自动创建钉钉 OA「反EOL流程审批」
  → 回写 OA 单号、状态
  → 审批通过：打上「已反 EOM」，工单已关闭，本单 SKU 回提交前（已上市 / 未上市），禁止重开，本单只读
  → 驳回或撤销：不打标签，阶段和 SKU 保持发起前，允许再发
```

GTM 必填并传给 OA：SKU、PSKU（手填可多填）、反EOL原因、附件、产品经理、销售渠道 leader、研发确认、项目审核、项目助理（均多选）。抄送人非必填，对应 OA 流程抄送人。

Sourcing、审批人由 OA 模板带出，GTM 不维护。会签/或签由 OA 处理。

本期做填单、自动起 OA、回写单号与状态；通过后关单并释放 SKU。不解禁 BOM、不跟踪追加 Last Buy。已反 EOM 关单后不可再发、不可重新发起；再退市须新开工单。

反 EOM 不使用手工“关闭”或“重新发起”替代。

### 阶段四：闭环

#### 节点 A10：S&OP 复盘与 EOL 闭环

月度 S&OP：

- 二级计委会查看清库进度、未完成事项和原因。
- 超权限报废由计委会在线下 OA 决策；GTM 不发起、不回写、不挡正式 EOM。
- 线下不同意时，发起人在系统内改方案或改版，系统不自动退回。

EOL 自动闭环条件：

```text
成品全链路库存 = 0
```

专用料、Last Buy 只在台账展示，不挡闭环。已反 EOM 关单后 SKU 已释放，不再走本单 EOL。

满足后系统：

1. 自动将 SKU 状态由 EOM 切换为 EOL。
2. 记录闭环时间和触发数据快照。
3. 关闭未完成的普通监控任务。
4. 通知 GTM、销售、需求计划、计划、PMC 和采购。
5. EOM 工单全部 SKU 均闭环后，工单状态更新为“EOL 已闭环”。

---

## 5.2 被动退市流程

被动退市不包含“新老品切换计划”。反 EOM（发起 OA 反EOL）主动、被动均可发起。

### 5.2.1 触发规则

系统提供以下七项标准退市原因：

1. 生命周期进入衰退期且市场表现持续下滑。
2. 销量流速大幅下滑且 DOS 过高。
3. SPU 利润持续下降或低于预期。
4. 营销和销售费用超出且无可行补救措施。
5. 区域全渠道下单量无法满足 MOQ。
6. 法律法规不再允许销售。
7. 组件、器件或第三方软件不可获得且无替代方案。
8. 其他：必须补充说明。

### 5.2.2 发起机制

| 渠道 | 机制 |
| --- | --- |
| LBU | 月初统一评审，特殊事项可实时发起 |
| ABU | 每月预排查，季度统一正式发起 |

被动退市由区域 GTM 发起；ABU 由产品 GTM 承接区域 GTM 和需求计划职责。

### 5.2.3 流程节点

```text
被动退市触发
  → 提交即进核料（并行提醒销售刷新预测）
  → 确认清库及LB方案
  → 正式EOM
  → 库存清理
  → 物料清理
  → S&OP复盘及EOL闭环
```

## 六、状态机改造

## 6.1 EOM 工单主状态

| 状态码建议 | 状态名称 | 进入条件 | 退出条件 |
| --- | --- | --- | --- |
| 10 | 草稿 | 新建未提交 | 提交或关闭 |
| 30 | 核料中 | 提交成功（自动创建核料单并开始计算） | 全部 SKU 确认后自动定版；或发起人关闭 |
| 40 | 待方案决策 | 核料定版 | GTM 与计划完成方案确认；或发起人关闭 |
| 50 | EOM 执行 | 正式方案确认 | 工单内全部 SKU 成品全链路库存为 0；或反 EOM OA 通过关单 |
| 70 | EOL 已闭环 | 工单内全部 SKU 成品全链路库存为 0 | 终态 |
| 80 | 已关闭 | 草稿、核料中或待方案决策时发起人关闭；或反 EOM OA 通过 | 手工关闭可重开（原单回草稿，流水号不变）；已反 EOM 禁止重开 |

取消原状态码 20「启动 EOM」、60「清尾中」。成品清库、Last Buy、专用料清理在 EOM 执行期内三路并行跟踪，进度看台账，不另做执行跟踪页，不另切工单阶段。本期不做撤回。提交后不能撤回复草稿，只能关闭。关闭允许「草稿、核料中、待方案决策」，必须填写原因。正式 EOM 之后不可手工关闭；反 EOM OA 通过后关单。

手工关闭时，SKU 若已是准备 EOM，释放回提交前原产品状态。反 EOM OA 通过时，本单 SKU（含已是 EOM）同样释放回提交前。手工关闭后可重新发起（原流水号）；已反 EOM 禁止重开。核料定版后不因方案问题或 Forecast 后到解锁。

方案无驳回。GTM 直接改当前方案并清空确认。本期不做节点任务驳回、不做任务转交。空预测方案页强提示，不硬拦。

Forecast 与核料并行：提交即进核料中；钉钉提醒销售刷新预测，不卡流程。Forecast 后到只刷新台账，**不发入库通知**；未锁定未确认的建议下单可刷新参考值。

正式 EOM 后方案改版必须会签留版本，阶段不退回。反 EOM 走 OA 反EOL 审批，不走改版。通过后关单、SKU 回提交前，禁止重开。

## 6.2 异常状态

异常状态不替代主状态，通过独立异常标识管理。本期：

| 异常类型 | 说明 |
| --- | --- |
| 已反 EOM | 反 EOL OA 审批通过后打上；工单同时变为已关闭 |
| 数据异常 | 库存、物料、预测等源数据异常 |

本期不设工单异常「已驳回」。方案问题用改方案或关闭重开处理。「已暂停」本期不做。

## 6.3 SKU 产品状态

| 产品状态 | 触发条件 |
| --- | --- |
| 未上市 | 主数据尚未上市 |
| 已上市 | 正常销售 |
| 准备 EOM | EOM 工单正式提交 |
| EOM | 清库及 Last Buy 方案正式确认 |
| EOL | 成品全链路库存为 0 |

手工关闭、以及反 EOM OA 通过后的关单，均释放 SKU 回提交前（已上市 / 未上市）。方案改版不回拨产品状态。已反 EOM 关单后不再走本单 EOL。

## 6.4 节点任务状态

```text
待处理 → 处理中 → 已完成
```

正式 EOM 前从核料开始按顺序流转：当前任务完成后生成并通知下一处理人。销售预测刷新不在串行链上。方案节点无驳回。本期不做节点任务驳回、不做任务转交。计划请假由计划部门负责人直接确认该 SKU；GTM 方案只认发起人。正式 EOM 后，销售清库、采购跟踪 Last Buy、PMC 清专用料均以拉数展示并消息通知查看，不在 GTM 点完成、不留痕。

## 7.4 发起 EOM

采用分步表单：

### 第一步：选择退市类型

- 主动退市。
- 被动退市。
- LBU/ABU。
- 退市原因。

### 第二步：选择产品范围

支持：

1. 按 Model 搜索并带出全部有效 8 位 SKU。
2. 按 SKU 搜索。
3. Excel 批量导入 SKU。
4. 全选 Model 下全部 SKU。
5. 排除 SKU 时必须填写排除原因。

列表库存列对齐销售系统产品库存看板，按 8 位 SKU 汇总：

- **在库库存**：金蝶在库（国内在库仓 + 海外仓在库仓 + 配件仓），含占用和待调拨，不含不良品仓、不含物流贴标仓。
- **总计库存数量**：在库库存 + 已拣货 + FBA可售 + FBA在途 + 海外在途。不含采购在途、FBA转仓/预留、海外占用和借调。

完整性校验：

- 已 EOL 的 SKU 不允许重复发起。
- 已存在进行中 EOM 工单的 SKU 不允许重复发起。
- 选择“整 Model 退市”时，必须纳入所有有效 SKU或填写排除原因。
- 未上市且无销售记录的 SKU，可纳入主数据治理清单，不强制走完整清库流程。

### 第三步：维护退市计划

- 预计 EOL 时间。
- 是否新品迭代。
- 迭代新品 SKU。
- 新品预计 CR 时间。
- 新品上市时间。
- 预测覆盖时间。
- 附件。
- 备注。

### 第四步：确认责任人

| 字段 | 规则 |
| --- | --- |
| GTM | 默认发起人，可增加其他人；发起人不可删。方案确认、改方案、关闭 **只认发起人**；其他 GTM 只通知可查看。反 EOM 不限发起人，仅正式 EOM 后可发。本期不做撤回 |
| 计划负责人 | 按 SKU 配置去重，只读不支持修改 |
| 销售专员 | 按 MSKU 基础信息去重，只读不支持修改；未带出视为不需要 Forecast，不提示、不提醒；有专员则钉钉提醒刷新预测，不卡核料 |
| 需求计划、采购 | 用户必选，可多人，提交后仅通知可查看 |
| PMC | 用户必选，可多人；进入核料中发待办，打开核料页进行核料，不卡定版 |
| 抄送人员 | 默认现网名单，选人组件可增删 |

计划部门负责人不在此页另选，按组织角色识别，可在核料和方案确认中确认全部 SKU。

### 第五步：提交校验

提交前展示：

- SKU 范围完整性。
- 重复工单检查。
- 产品状态检查。
- 必填字段检查。
- 责任人缺失检查。
- 主数据缺失检查。

### 7.5.1 概要

- 工单基础信息。
- 当前阶段。
- 当前责任人。
- 预计/实际完成时间。
- 整体清库进度。
- 当前执行事项。

### 7.5.2 流程时间轴

展示所有业务节点：

- 节点名称。
- 责任角色。
- 计划完成时间。
- 实际完成时间。
- 处理结论。
- 附件。

### 7.5.3 SKU 台账

按 8 位 SKU 展示业务台账。展开规则与 EOM 产品台账相同：每个 MSKU 一行；左侧为 MSKU 编码、渠道、店铺、线上/线下；预计 EOL、EOM 时长带出 SKU 值；Last Buy（计划/下单/完成时间、数量、状态、LB 后基准库存）与专用料/通用料子行显示“-”；库存、销量、预测、DOS、清库进度按 MSKU。Last Buy 以本表字段为准，不另做数量进度条。EOL 是否可闭环看 SKU 主行当前库存是否为 0。

### 7.5.4 清库方案

清库方案页与核料信息详情使用同一套 Model → SKU → MSKU 全列。核料测算列只读。发起人在表内按 SKU 填写清库方式、Last Buy 数量、成品/物料报废金额、方案结论；页头汇总 Last Buy 数量与两类报废。不维护 Last Buy 金额。成品报废合计超过 50 万元或物料报废合计超过 20 万元时，页头给出非阻断提示（请线下走计委会 OA），不创建 OA、不挡保存与确认。

Last Buy 计划时间、成品/物料处理说明、费用归属、预计 EOL 写在附件中。附件每份选择类型：GTM 确认方案、EOM 方案、清库方案；保存时 EOM 方案必传；点「GTM确认整单」时 GTM确认方案与 EOM方案必传（二次校验，未传硬拦）。

主入口为工单「清库方案」Tab 直改，不使用整单弹窗。

版本示例：

```text
V1 初始方案
V2 新品延期后调整清库节奏与 Last Buy 计划（BOM 未禁用）
V3 库存积压后增加降价/调拨
```

每个版本记录：

- 变更原因。
- 各 SKU 方案结论（清库方式、Last Buy 数量、报废金额、结论文本）。
- 决策人。
- 生效时间。
- 分类附件。

正式 EOM 后改版必须按 GTM + 计划（按 SKU，部门负责人可确认全部）会签，工单阶段不退回待方案决策。待方案决策改当前版本并清空确认，无驳回。反 EOM 走 OA 反EOL，不走方案改版。

## 7.6 EOM 产品台账

台账支持：

- 工单维度查看。
- SKU 维度查看。
- Model 聚合查看。
- 展开 MSKU 行：左侧为 MSKU 编码、渠道、店铺、线上/线下，不单列平台。
- 预计 EOL、EOM 时长在 MSKU 行带出 SKU 值；Last Buy 与专用料/通用料子行显示“-”。
- 导出当前结果含 MSKU 行，与页面同口径。
- 工单详情 SKU 台账同一套展开规则。正式 EOM 后三路进度以本页及工单 SKU 台账为准，不另做执行跟踪页。
- 自定义列。
- 冻结关键列。
- 导出业务标准模板。

## 7.7 首期功能边界

首期不设置风险等级、风险类型或风险处理状态，不建设独立风险预警页。业务人员直接通过台账中的预计 EOL、PSI DOS、当前库存、呆滞库存、清库进度、Last Buy 状态及专用料库存判断是否需要跟进。

首期不建设 EOM 配置页。以下业务规则按规范固定执行：

- 核料在 GR1 后 7 个工作日内完成。
- 清尾进度每 14 个自然日更新一次。
- 成品报废合计超过 50 万元或物料报废合计超过 20 万元时，保存方案或点「GTM确认整单」给出非阻断提示：请线下发起计委会 OA。系统不创建 OA、不等待审批、不挡方案确认与正式 EOM。
- 前序任务完成后通知下一处理人；正式 EOM 后三类清尾并行消息通知，不发待办。

## 7.8 通知页

菜单位于核料管理下方：「通知」，子菜单为首项「总揽」，以及销售、GTM、需求计划、计划、PMC、采购。

**总揽**为只读对照页，不按登录人过滤。按触发情况对照销售、GTM 发起人、其他 GTM、需求计划、计划、PMC、采购的收件类型（待办 / 消息 / 视条件 / 不通知）及标题、正文。完整矩阵与原文以原型「通知 / 总揽」为准，PRD 6.13 有摘要表。

每个角色页展示该角色收到的通知列表：渠道（ERP 待办 / 钉钉待办 / 钉钉消息）、已读状态、标题、正文、工单号、SKU 范围、工单阶段、发送时间。可按全部 / 待办 / 消息筛选，点击进入对应工单；销售预测刷新跳转 Forecast；PMC 核料待办打开核料页。

角色口径：

- 销售：有专员则发起后收预测提醒（钉钉消息，跳转 Forecast，不卡核料，GTM 不生成销售待办）；正式 EOM 后收钉钉消息看台账清库，不在 GTM 点完成；方案改版与工单关闭收知情消息；方案节点只收消息、不会签。Forecast 审核入库不另发消息。
- GTM：仅发起人收方案提交/改版/关闭等待办；其他 GTM 全程只收消息。报废超金额不发 OA 通知。反 EOM 回写通知相关人员。Forecast 审核入库不通知；核料计算失败不通知发起人及其他 GTM。
- 需求计划、采购：发起时为必选通知对象，无必办待办；提交后工单已在核料中，可查看；正式 EOM 后采购收拉数查看消息，不强制在 GTM 点完成。需求计划：正式 EOM 已生效（看台账）、正式 EOM 后改版、反 EOL OA 发起与回写、EOL 闭环均通知需求计划；Forecast 审核入库、清尾进度更新、核料计算失败均不通知。
- PMC：进入核料中收核料待办（打开核料页核对专用料/物料测算，不卡定版）；核料计算失败、核料定版、正式 EOM 后收消息。
- 计划：核料确认、方案确认、改数后重新确认为待办。核料计算失败、正式 EOM 生效、EOL 闭环收消息。Forecast 审核入库不通知。

### 8.3 指标计算口径

#### 8.3.1 EOM 时长

```text
未闭环：当前日期 - 发起EOM时间
已闭环：实际EOL时间 - 发起EOM时间
```

#### 8.3.2 呆滞库存占比

```text
呆滞库存占比 = 呆滞库存数量 ÷ 当前总库存数量
```

当前总库存为 0 时显示 0%，并标记计算时间。

#### 8.3.3 DOS

EOM 不单独计算 DOS，直接复用现网 PSI DOS：

- 以当日期末 Inventory 从次日起逐日扣减未来 Sell out 预测，得到库存可覆盖天数。
- 期初海外可用库存不含在途；未来推演过程中按 PSI 规则叠加在途到货和 Sell through。
- 周、月维度取对应周期最后一天的 DOS。
- 零预测日及其他边界处理完全沿用 PSI，不在 EOM 中另设口径。
- 台账需同时展示 PSI 数据时间和预测版本。

#### 8.3.4 清库进度

有 Last Buy：

```text
清库进度 =
(Last Buy完成后的基准库存 - 当前库存)
÷ Last Buy完成后的基准库存
```

无 Last Buy：

```text
清库进度 =
(正式EOM时基准库存 - 当前库存)
÷ 正式EOM时基准库存
```

基准库存为 0 时：

- 当前库存为 0：进度 100%。
- 当前库存大于 0：标记“基准异常”，不直接计算。

#### 8.3.5 专用料关闭率

```text
专用料关闭率 =
(正式EOM时专用料基准金额 - 当前专用料金额)
÷ 正式EOM时专用料基准金额
```

数量和金额均需保留，工作台默认按金额展示。

## 10.2 固定业务时限

| 节点 | 主动退市 | 被动退市 |
| --- | --- | --- |
| 发起 EOM | GR1 | week-0 |
| 核料完成 | GR1 + 7 个工作日 | week-1 |
| 清库方案确认 | GR1 至 GR2 | week-3 |
| 清尾进度更新 | 每 14 个自然日 | 每 14 个自然日 |
| S&OP 复盘 | 月度 | 月度 |

## 10.3 通知机制

通知渠道：

- ERP 待办。
- 钉钉待办或钉钉消息。

通知事件：

- 当前任务完成后，通知下一处理人。
- 工单进入核料中，通知 PMC 进行核料（待办，进入核料页，不卡定版）；有销售专员则并行提醒刷新预测。
- 核料计算失败仅通知计划与 PMC，其它人不通知。
- 正式 EOM 后，同时以消息通知销售、采购和 PMC 查看台账（不发待办）；需求计划收知情消息「已正式 EOM，进度请看台账」。
- 正式 EOM 后改版通知销售、需求计划、计划（会签待办）、PMC、采购及其他 GTM。
- 发起人关闭工单通知销售、需求计划、计划、PMC、采购及其他 GTM。
- 反 EOL OA 已发起与回写通知销售、GTM、需求计划、计划、PMC 和采购。
- 并行清尾进度更新或任务完成，不通知需求计划；进度以台账为准。
- 报废超金额不发 OA 发起/返回通知（OA 走线下）。
- EOL 自动闭环后，通知 GTM、销售、需求计划、计划、PMC 和采购。
- **Forecast 审核入库不发通知**：系统静默刷新台账；销售只在发起时收到「请刷新预测」提醒。

```text
发起 EOM → 进入核料中，并行钉钉提醒销售刷新预测，同时通知 PMC 进行核料
核料计算失败 → 仅通知计划与 PMC 协同重算，其它人不通知
核料定版 → 通知相关角色确认方案
方案确认 → 同时消息通知销售、采购、PMC 看台账（不发待办）；需求计划知情已正式 EOM
方案改版 / 反 EOL OA / EOL 闭环 → 均消息通知需求计划知悉
工单关闭 → 消息通知销售、需求计划、计划、PMC、采购等
三类清尾进度 → 不通知需求计划，进度到台账查看
Forecast 审核入库 → 只刷新台账，不推送待办或消息
```

系统提供「通知」菜单：首项「总揽」按触发情况对照各角色收件类型与原文；其余按销售、GTM、需求计划、计划、PMC、采购分角色查看收件内容。各角色待办与仅通知的边界见 7.8。

- 替代线下台账。
- 替代人工催办。

## 15.3 P2：执行闭环与经营看板

建议周期：2—3 个迭代。

范围：

1. Last Buy 订单、生产和入库明细联动。
2. 物料改制、转卖和报废进度以库存为准（报废 OA 不进 GTM）。

业务结果：

## 十六、数据迁移方案

## 16.1 迁移范围

## 十七、验收标准

## 17.1 发起

- 能区分主动/被动退市。
- 整 Model 发起时能够完整带出全部有效 8 位 SKU。
- 重复 EOM SKU 不允许提交。
- 支持批量导入并输出逐行失败原因。
- 提交后 SKU 自动进入准备 EOM，工单进入核料中。

## 17.2 流程

- 主动退市和被动退市按固定业务规则生成对应节点。
- 每个节点均有责任人、截止时间和处理记录。
- 计划确认后进入 EOM 执行，而不是业务完结。
- 当前任务完成后自动通知下一处理人。
- 正式 EOM 后同时消息通知销售清库存、采购跟踪 Last Buy、PMC 清专用料；三路只看台账，不在 GTM 点完成。销售全程无待办。
- 方案无驳回；关闭允许至待方案决策；计划按 SKU 确认，计划部门负责人可确认全部 SKU。本期不做撤回、不做节点任务驳回、不做任务转交。提交即进核料中，Forecast 不卡流程。空预测方案页强提示、不硬拦。报废超金额仅非阻断提示，不挡正式 EOM。

## 17.3 台账

- 所有业务确认字段均能展示。
- 动态指标显示数据来源和更新时间。
- 关键事件保留不可变快照。
- 支持 SKU、Model、工单查看，并展开 MSKU（含渠道、店铺、线上/线下）。
- 导出含 MSKU 行，与页面口径一致。

## 17.4 Last Buy

- 可维护计划数量并关联实际采购订单。
- 能展示下单、生产、入库和完成状态。
- Last Buy 完成后自动保存库存快照。
- EOM/EOL 下单拦截不能阻断已审批 Last Buy。

## 17.5 EOL 闭环

- 成品全链路库存为 0 即闭环。专用料、Last Buy 不挡闭环。已反 EOM 关单后 SKU 已释放，不再走本单 EOL。
- 自动闭环失败可重试。
- 自动闭环有完整日志和人工复核入口。
- 工单内全部 SKU 闭环后，工单才显示 EOL 已闭环。

## 17.6 数据准确性

- SCM 任务失败不得显示计算成功。
- 在途库存不得重复统计。
- 专用料、共用料分类经过业务样本验算。
- DOS、清库进度、呆滞库存占比与业务台账抽样一致。

## 十九、最终建议

本次改造不应仅作为“列表加字段、增加导入导出”的普通页面需求实施。

推荐按以下路径推进：

1. **先统一业务口径**：确认台账字段、主粒度、状态和计算公式。
2. **再治理入口和数据**：确保发起 SKU 完整、源数据可信。
3. **然后上线节点任务和在线台账**：以处理完成后通知下一人为主，替代人工交接。
4. **最后补齐交易联动和异常闭环**：Last Buy、报废、反 EOM、S&OP、EOL。

系统改造的关键成功标准不是“字段全部展示”，而是：

> 任意一个 EOM SKU，都能在系统中回答：为什么退、谁在处理、处理到哪一步、还剩多少库存和专用料、Last Buy 是否完成、预计何时 EOL，以及最终如何完成闭环。
