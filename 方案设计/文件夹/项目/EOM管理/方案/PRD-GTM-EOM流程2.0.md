## 1. 需求背景与目标

### 1.1 背景

EOM 已从阶段性停产确认，调整为常态化退市运营。业务需要覆盖：退市触发、销售预测刷新、核料、清库及 Last Buy 方案确认、正式 EOM、成品清库、Last Buy 执行、专用料清理、反 EOM、S&OP 复盘和 EOL 闭环。

当前 GTM 已支持发起 EOM、选择产品、上传方案附件、计划确认、核料测算和部分导出。计划确认后系统即显示“完结”，后续清尾依赖 Excel、群聊和人工催办。系统无法完整回答：为什么退、谁在处理、处理到哪一步、还剩多少库存和专用料、Last Buy 是否完成、预计何时 EOL。

### 1.2 建设目标

将“核料测算加附件审批”改造为以 EOM 工单为载体、以 8 位 SKU 为最小管理单元的全生命周期退市管理：

1. 区分主动退市和被动退市，按类型生成对应节点。
2. 计划确认后进入 EOM 执行，不得显示业务完结。
3. 前序节点处理完成后通知下一处理人；正式 EOM 后销售、采购、PMC 三路并行清尾，只发消息看台账，不在 GTM 点完成。
4. 汇聚产品、预测、库存、Last Buy、物料和清库信息，形成在线台账。
5. 按统一条件自动判定 SKU 是否完成 EOL。
6. 逐步替代线下台账和清尾跟踪表。

### 1.3 目标用户

| 角色 | 主要场景 |
|------|----------|
| 产品 GTM | 发起主动退市，维护新品衔接，确认清库方案，必要时发起反 EOM |
| 区域 GTM | 发起被动退市，维护区域退市原因和产品范围 |
| 需求计划 | 统筹核料、方案、任务交接、台账和 EOL 复核 |
| 销售 | 刷新预测，确认可接受 Last Buy 数量；按方案执行成品清库（不在 GTM 点完成） |
| 计划 | 参与核料，确认生产与 Last Buy 可执行性 |
| 采购 | 跟踪 Last Buy 下单、生产、在途和入库 |
| PMC | 维护专用料改制、转卖、报废及关闭进度 |
| 计委会 | 通过线下 OA 决策超金额报废（GTM 不发起、不回写） |
| 管理层 | 查看进度、库存、物料和闭环结果，开展月度复盘 |

### 1.4 上下游

| 方向 | 说明 |
|------|------|
| 上游 | 产品主数据、项目里程碑、核料结果、PSI/预测、库存、SCM 物料、采购订单、反 EOL OA 审批结果 |
| 下游 | 产品状态写回、销售系统 PSI 展示与 Sell out 硬拦、采购计划 Last Buy / 禁下单、S&OP 复盘、EOL 闭环通知 |

原则：GTM 负责流程编排、任务交接、台账汇聚和闭环判定；预测、库存、采购、BOM、生产和报废审批继续在原系统执行。销售系统本期只改 PSI 管理、PSI 审核，不改 Forecast。Last Buy 在 GTM 清库方案按渠道填写，计划在采购计划自行下最后一单，两套并行、不互相校验数量。

## 2. 功能范围

### 2.1 本期覆盖

1. EOM 工作台。
2. EOM 工单列表、发起、详情、节点任务和操作日志。
3. 主动退市、被动退市分流及产品范围完整性校验。
4. 销售预测刷新、核料关联、核料页按 SKU 确认（导入仅快录）、清库及 Last Buy 方案版本管理。
5. 正式 EOM 后成品清库、Last Buy、专用料进度在台账跟踪（不另做执行跟踪页）；销售/采购/PMC 只收消息，不在 GTM 点完成。
6. EOM 产品在线台账及导出。
7. 反 EOM。
8. EOL 自动闭环及人工复核。
9. 任务完成后通知下一处理人。
10. 销售系统 PSI 管理、PSI 审核适配（产品状态 / 预计 EOL / Sell out 全链路硬拦）。
11. 采购计划：准备 EOM 可下 Last Buy（提示状态、预计 EOL、Last Buy 数量）；变为 EOM 后不可以再下任何采购单。

### 2.2 本期不做

1. 独立风险预警页，以及风险等级、风险类型、风险处理状态字段。
2. EOM 配置页；SLA、预警阈值、报废金额不做成可配置项。
3. 超期自动升级、到期前提醒、S&OP 风险清单。
4. 重建预测、库存、采购、BOM 等源系统。
5. 在 GTM 内完成报废审批；不自动创建报废 OA、不回写、不挡正式 EOM。超金额仅非阻断提示，OA 走线下。
6. 一次性治理全部历史主数据。
7. 节点任务驳回；销售/采购/PMC 在 GTM 点完成清尾或留痕。
8. Forecast、Forecast 审核页面改动。

业务人员通过预计 EOL、PSI DOS、当前库存、呆滞库存、清库进度、Last Buy 状态和专用料库存金额判断是否需要跟进。

### 2.3 已确认口径

1. DOS 完全复用现网 PSI，不另算“库存÷平均日销”。
2. Last Buy 时间拆分为计划时间、实际下单时间、完成时间。
3. EOL 只卡台账 SKU「当前库存」= 0（产品库存看板总计库存数量，不含采购在途，见 7.3.5）。专用料、Last Buy、反 EOM 在台账展示，不挡闭环；专用料金额只用于展示和管理。PSI Sell out 硬拦用的「全链路库存」（成品 + 采购在途）与 EOL 不是同一口径。
4. 成品报废合计超过 50 万元或物料报废合计超过 20 万元时，仅非阻断提示请线下走计委会 OA。系统不创建 OA、不回写、不挡方案确认与正式 EOM。
5. 前序任务完成后通知下一处理人；正式 EOM 后三类清尾并行跟踪，销售/采购/PMC 只收消息、不在 GTM 点完成。销售全程无 GTM 待办。本期不做节点任务驳回、不做任务转交。
6. 核料以页面直改和按 SKU 确认为主；最终下单按 MSKU，SKU 只展示合计；报废/原因/交付天数按 SKU；计划负责人、结论按 MSKU。工单「确认」只跳转核料页；导入只用于快录。全部 SKU 确认后自动定版，并按 MSKU 最终下单带入方案 Last Buy。改数记核料日志，页上不展示初盘。普通计划负责人只确认自己负责的 SKU；计划部门负责人可确认本单全部 SKU。
7. 清库及 Last Buy 方案无驳回。有问题由**发起人**直接改当前方案（改后清空已确认）；产品范围或核料结论等无法靠改方案解决时，关闭工单后重新发起。方案确认只会签发起人（GTM 侧）与计划；发起人须点「GTM确认整单」并过二次校验（GTM确认方案、EOM方案必传）；其他 GTM 只通知。
8. 清库方案页与核料信息页使用同一套 Model → SKU → MSKU 全列。核料测算列只读带出。清库方式、成品报废、物料报废、方案结论按 8 位 SKU 一份；**Last Buy 按渠道 / MSKU 填**，SKU 只汇总。核料定版时按 MSKU 最终下单带入 Last Buy，此后只在方案页改。页头汇总 Last Buy 数量、成品报废合计、物料报废合计。**不维护 Last Buy 金额。** Last Buy 计划时间、成品/物料处理说明、费用归属、预计 EOL 写在上传文件中。附件一个区、每份选类型（GTM 确认方案 / EOM 方案 / 清库方案）；保存时 EOM 方案至少 1 份。点「GTM确认整单」二次校验 GTM确认方案+EOM方案，未传硬拦。主入口是清库方案 Tab 直改，不用整单弹窗。
9. 不设工单阶段「清尾中」。方案确认后进入 EOM 执行，直至整单 EOL 已闭环。成品清库、Last Buy、专用料清理为执行期内并行跟踪，不另切阶段。
10. 不设工单详情「执行跟踪」Tab。三路进度以 EOM 产品台账、工单「SKU 台账」为准。Last Buy 展示计划时间、下单时间、完成时间、数量、状态，不另做「已生产/入库 vs 计划」进度条。
11. Forecast / Forecast 审核本期不改。销售侧只改 PSI 管理、PSI 审核。GTM 仍可钉钉提醒销售刷新预测（跳转现网 Forecast），不卡核料。
12. PSI Sell out：管理页弹窗「提交审核」、审核页组长 / 主管通过时，总量（各时间段日销限额 × 区间天数之和）大于全链路库存（成品 + 采购在途，含已下达 Last Buy 在途）硬拦。不做「超过百分之八异常」。不另做「准备 EOM / 已 EOM 待复核」队列，不另做第三级审批。预计 EOL 已过只提醒，不挡提交、不挡通过。
13. 采购计划下 Last Buy 不与方案数量校验；创建 / 拦截弹窗提示该 MSKU 产品状态、预计 EOL、Last Buy 数量，不写「是否与方案一致」。产品状态变为 EOM 后不可以再下任何采购单（与现网一致）。计划确认方案前弹窗列出 Last Buy 数量，确认采购单是否已下；确认后状态变 EOM，不可再下采购单。方案确认后不下推采购计划。

## 3. 总体流程

### 3.1 主动退市

```text
新品达到 GR1
  → 产品GTM发起主动EOM，SKU进入准备EOM，工单进入核料中
  → 系统自动创建核料单并开始计算；钉钉提醒销售刷新预测（不卡核料）；同时通知 PMC 打开核料页进行核料
  → 计划按 SKU 确认核料结论；PMC 核料不卡定版；需求计划/采购可查看
  → GTM 提交清库及 Last Buy 方案，计划按 SKU 确认（部门负责人可确认全部）
  → 工单进入EOM执行，SKU进入EOM
  → 同时消息通知销售清成品、采购跟踪Last Buy、PMC清专用料（进度看台账，不发待办）
  → 台账 SKU「当前库存」为 0 后 SKU 自动进入 EOL；工单全部 SKU 闭环后工单进入 EOL 已闭环
```

主动退市可维护新老品切换关系。需要反 EOL 时在工单发起反 EOM，自动生成 OA，不得用关闭或重新发起代替。

### 3.2 被动退市

```text
区域GTM按标准原因发起
  → 提交即进核料（并行钉钉提醒销售刷新预测，同时通知 PMC 进行核料）
  → 确认清库及Last Buy方案
  → 正式EOM
  → 销售、采购、PMC并行清尾
  → EOL闭环
```

被动退市不要求维护新老品切换计划。反 EOM（发起 OA 反EOL）主动、被动均可发起。

LBU：月初统一评审，特殊事项可实时发起。  
ABU：每月预排查，季度统一正式发起；产品 GTM 承接区域 GTM 和需求计划职责。

被动退市标准原因：生命周期衰退、销量流速下滑且 DOS 过高、利润持续下降、营销销售费用超出、无法满足供应链起订量、法律法规不允许继续销售、组件或软件不可获得且无法替代、其他。选择“其他”必须补充说明。

### 3.3 固定时限

按业务规范写死，不做配置页：

| 节点 | 主动退市 | 被动退市 |
|------|----------|----------|
| 发起 EOM | 新品达到 GR1 | 月度评审 week-0 |
| 核料完成 | GR1 后 7 个工作日 | week-1 |
| 清库方案确认 | GR1 至 GR2 | week-3 |
| 清尾进度更新 | 每 14 个自然日 | 每 14 个自然日 |
| S&OP 复盘 | 月度 | 月度 |

## 4. 状态与任务

### 4.1 三类状态分开管理

1. 工单阶段：表示业务流程走到哪里。
2. 产品状态：表示 SKU 生命周期。
3. 节点任务状态：表示责任人是否完成动作。

不得用一个“状态”同时表达三种含义。

### 4.2 工单阶段

| 阶段 | 建议状态码 | 进入条件 | 退出条件 |
|------|------------|----------|----------|
| 草稿 | 10 | 新建未提交 | 提交或关闭 |
| 核料中 | 30 | 提交成功（系统自动创建核料单并开始计算） | 该单全部 SKU 确认核料结论后自动定版；或发起人关闭 |
| 待方案决策 | 40 | 核料定版 | GTM 与计划均完成方案确认；或发起人关闭 |
| EOM 执行 | 50 | 方案正式确认 | 工单内全部 SKU 台账「当前库存」为 0 |
| EOL 已闭环 | 70 | 工单内全部 SKU 台账「当前库存」为 0 | 终态 |
| 已关闭 | 80 | 草稿、核料中或待方案决策时发起人关闭；或反 EOM OA 通过 | 重新发起：原单回草稿，流水号不变；已反 EOM 禁止重开 |

取消原状态码 20「启动 EOM」、60「清尾中」。成品清库、Last Buy、专用料清理是 EOM 执行期内的三路并行跟踪，进度看台账，不另做执行跟踪页，不另切工单阶段。状态码为设计建议，最终以开发设计为准。

本期不做撤回。提交后不能撤回复草稿，只能关闭。关闭允许「草稿、核料中、待方案决策」，必须填写原因并写入日志。正式 EOM 之后不可手工关闭，可改版或发起反 EOM；反 EOM OA 通过后工单变为已关闭。

关闭时，若 SKU 已是「准备 EOM」，必须释放回提交前的原产品状态（已上市/未上市），解除进行中占用。重新发起沿用原工单、原流水号，关闭原因与历史日志保留；再次提交后才重新进入准备 EOM。核料已定版后不再解锁改结论；核料结论错误须关闭后重新发起。Forecast 后到不解锁已确认 SKU 与已定版核料。

**方案没有驳回。** 待方案决策期间仅发起人直接修改当前方案；保存后清空 GTM 确认和全部 SKU 的计划确认，必须重新确认。销售、需求计划、PMC、采购及其他 GTM 不参与会签。**本期不做节点任务驳回、不做任务转交**（所有角色）。有问题由发起人改方案或关闭后重开。计划请假由计划部门负责人直接确认该 SKU；GTM 方案只认发起人。

**Forecast 与核料并行。** 提交后立即进入核料中，不等待销售刷新预测。有销售专员的 MSKU 发钉钉提醒（跳转 Forecast），并按组织架构抄送该专员的 STL、TL；不生成 GTM 销售待办、不卡工单阶段。未带出专员的 MSKU 不提醒。Forecast 后到只刷新台账预测；未锁定且未确认的建议下单可刷新参考值；已确认 SKU 与已定版核料不自动解锁、不自动重算。**Forecast 审核入库不发钉钉/ERP 通知**（GTM、需求计划及其他角色均不提醒），进工单或台账即可看到最新预测。销售填写的可接受 Last Buy 仅供方案参考。空预测或刷新失败标识数据异常，方案页强提示，不硬拦进入待方案决策、不硬拦方案提交。

正式 EOM 后的方案变更生成新版本并按同样规则会签（GTM + 计划按 SKU，部门负责人可确认全部），工单阶段不退回待方案决策，产品状态仍为 EOM。反 EOM 走 OA 反EOL 审批，不得用方案改版、关闭或重新发起代替。

方案确认后必须进入 EOM 执行，不得显示业务完结。现网「完结」仅作映射。

本期可并行存在的异常标识：已反 EOM、数据异常。已反 EOM 仅在反 EOL OA 审批通过后打上。不再使用工单异常「已驳回」。「已暂停」本期不做。异常标识不替代主阶段。

### 4.3 SKU 产品状态

| 产品状态 | 触发条件 |
|----------|----------|
| 未上市 | 主数据尚未上市 |
| 已上市 | 正常销售 |
| 准备 EOM | EOM 工单正式提交 |
| EOM | 清库及 Last Buy 方案正式确认 |
| EOL | 台账 SKU「当前库存」为 0 |

未上市且无销售记录的 SKU 提示主数据治理，不强制走完整清库。已 EOL 或已有进行中 EOM 的 SKU 不得发起。关闭后占用解除，允许再发起或原单再提交。

方案改版、关闭前改方案不回拨产品状态：待方案决策期间仍为准备 EOM，改版后仍为 EOM。手工关闭、以及反 EOM OA 通过后的关单，均释放 SKU 回提交前状态（已上市 / 未上市）。

### 4.4 节点任务

任务状态：待处理、处理中、已完成。本期不做已驳回、不做已转交。

正式 EOM 前从核料开始串行交接：当前人完成后生成并通知下一人。销售预测刷新不在串行链上，与核料并行、不卡阶段。  
正式 EOM 后并行跟踪：销售清成品、采购跟踪 Last Buy、PMC 清专用料。三类任务只读展示，不发待办、不在 GTM 点完成、不留痕。清尾进度以台账拉数为准，完成后不通知需求计划。

每个任务需包含：所属工单和 SKU 范围、任务名称、责任角色、责任人、计划完成时间、实际完成时间、处理结果、附件。处理结果对清尾三类任务仅展示台账拉数，不由销售/采购/PMC 在 GTM 填写。

方案节点无驳回。本期不做节点任务驳回、不做任务转交。计划部门负责人可在核料和方案确认中代确认本单全部 SKU，减少因请假卡住。GTM 方案只认发起人；换人改名单或关闭后重开。

### 6.3 发起 EOM

改动位置：EOM 工单 → 发起 EOM

分五步：

**第一步：退市类型**

- 业务单元：LBU / ABU。
- 退市类型：主动退市 / 被动退市。
- 发起节点：主动默认为 GR1，被动默认为月度评审 week-0；均可选择特殊事项实时发起。
- 退市原因：按类型带出标准原因；选择“其他”必须填写说明。
- 被动退市可选择多项原因。

**第二步：产品范围**

- 按场景品类、Model、SKU 搜索只刷新候选，已选清单独立保存。
- 支持跨筛选累积勾选、当前结果全选、Excel 导入（写入已选清单）。
- 已选产品范围独立展示，可查看、删除单条或清空。
- 未勾选不必填排除原因，不强制整 Model 齐套。下一步只校验已选清单至少 1 个可纳入 SKU。
- 已 EOL、已存在进行中 EOM 的 SKU 不允许提交。
- 未上市且无销售记录的 SKU 提示进入主数据治理，不强制走完整清库流程。
- 导入需逐行反馈成功或失败原因；单行失败不影响其他有效行。
- 列表原「当前库存」拆为两列，口径对齐销售系统 **产品库存看板**（`/board/inventoryMgr`），按 8 位 SKU 汇总全部店铺/listing：

| 列名 | 口径 | 计算规则 |
| --- | --- | --- |
| 在库库存 | 产品库存看板「在库数量」 | 金蝶在库：国内在库仓 + 海外仓在库仓 + 配件仓。含占用、待调拨；**不含**不良品仓、**不含**物流贴标仓（已拣货） |
| 总计库存数量 | 产品库存看板实物库存分项加总 | 在库库存 + 已拣货 + FBA可售 + FBA在途 + 海外在途。不含采购在途、FBA转仓、FBA预留、海外仓客户占用、借调（那些属于 Forecast「总计库存」） |

无数据时显示 0。两列只读，不作为提交校验项。

- 预计 EOL、是否新品迭代、迭代新品 SKU、新品预计 CR 时间、新品上市时间在本步列表按 **8 位 SKU** 维护；同一 SKU 多行 MSKU 共用一套数，改一行同步同 SKU 其它行。
- 支持勾选纳入行后「批量填写」：只覆盖弹层已填项，空项不改原行。
- 预计 EOL 发起时选填，后续可在台账补。
- 「是否新品迭代」= 否时，该 SKU 的迭代新品 SKU / 新品预计 CR / 新品上市时间清空且不可填。
- 被动退市时新品衔接 4 列仍展示但不可填，只可填预计 EOL。

**第三步：退市计划**

- 本步不再录入预计 EOL 与新品衔接（已在产品范围按 SKU 填写）。
- 支持上传附件和填写备注（工单级）。

**第四步：责任人**

本步分三块，避免只读带出与选人混用同一套输入框：

1. **系统带出**：GTM（发起人）、销售专员、计划负责人。纯文本，不进输入框；多人用顿号（如 `张三、李四`）；无人显示 `—`，行仍保留。
2. **需指定**：其他 GTM、需求计划、PMC 对接人、采购对接人、抄送人员。头像链 +「请选择」增删；已选人头像右上角叉删除。
3. **草稿通知**：整步最底部勾选「保存草稿时通知抄送人员（只读）」。

| 字段 | 来源 | 发起页 | 提交后用途 |
| --- | --- | --- | --- |
| GTM（发起人） | 当前登录人 | 纯文本只读，不可删 | **仅发起人**提交方案、改版、关闭 |
| 其他 GTM | 用户选择，可多人 | 选填；头像链 + 请选择 | **只通知、可查看**。反 EOM 不限发起人，仅正式 EOM 后可发 |
| 计划负责人 | SKU/MSKU 配置按人去重 | 纯文本只读，不支持修改 | 核料与方案确认资格；按 SKU 确认 |
| 销售专员 | MSKU 基础信息按人去重 | 纯文本只读，不支持修改 | 有专员的 MSKU 钉钉提醒 Forecast，并抄送该专员的 STL、TL；正式 EOM 后钉钉消息看台账清库，不发待办；未带出视为不需要 Forecast，不提醒。STL/TL 按组织架构自动带出，不在本页维护 |
| 需求计划 | 用户选择，可多人 | 必选；头像链 + 请选择 | **仅通知**，可进工单查看，无必办待办 |
| PMC 对接人 | 用户选择，可多人 | 必选；头像链 + 请选择 | 进入核料中发待办，打开核料页进行核料（核对专用料/物料测算）；定版仍以计划确认为准，不卡流程 |
| 采购对接人 | 用户选择，可多人 | 必选；头像链 + 请选择 | **仅通知**，可查看 Last Buy 拉数 |
| 抄送人员 | 默认现网抄送名单（落成具体人） | 头像链 + 请选择，可增删 | 仅知情 |
| 草稿通知 | 勾选 | 本步最底部 | 勾选后保存草稿通知抄送人只读；不勾选仅发起人可见 |

未带出销售专员视为该 MSKU **不需要 Forecast**：发起页不提示、不拦截提交；该 MSKU 不提醒、不等待、不卡流程。有专员的 MSKU 发钉钉提醒刷新预测，并抄送该专员的 STL、TL，同样不卡核料。本单全部未带出专员时不发预测提醒（也不抄送 STL/TL）。

**第五步：提交确认**

提交前展示：SKU 范围完整性、重复工单、产品状态、必填信息、责任人、主数据缺失。存在阻断项时不允许提交，并提示具体 SKU 和原因。

提交后：

1. 生成 EOM 工单和 SKU 台账，自动创建核料单并开始计算，工单进入核料中。
2. 相关 SKU 产品状态更新为准备 EOM。
3. 有销售专员的 MSKU 发钉钉提醒刷新预测（跳转 Forecast），并抄送该专员的 STL、TL；不生成 GTM 销售待办、不卡核料；未带出专员的不提醒。通知需求计划、采购及 GTM 名单中的其他人。**同时通知 PMC 进行核料**（ERP + 钉钉待办，进入核料页）。

支持保存草稿。草稿仅发起人可继续编辑。

### 6.4 工单详情

改动位置：EOM 工单 → 查看（列表行内仅此入口）

详情顶栏按当前阶段与身份展示：编辑、确认、GTM确认 / 计划确认、模拟 Forecast 入库、处理、关闭、反 EOM、重新发起、日志。点「确认」进入核料信息 Tab 勾选 SKU；点「处理」仅针对核料、方案等须在系统完成的节点；正式 EOM 后清尾无「处理」。点「日志」切到操作日志 Tab。

结构：概要 + 流程时间轴 + SKU 台账 + 核料信息详情 + 节点任务 + 清库方案 + 操作日志。不设「执行跟踪」Tab。

**概要**：退市类型、业务单元、发起人、发起时间、预计 EOL、工单阶段、当前责任人、Model/SKU 数、清库进度、专用料关闭率、核料单号、当前生效方案、当前执行事项。不展示风险摘要。

**流程时间轴**：展示全部节点、责任角色、计划/实际完成时间、处理结论和附件。正式 EOM 节点需标明销售、采购、PMC 并行处理。

**SKU 台账**：与 EOM 产品台账同一套列（取值见第 7 章），作为正式 EOM 后三路进度的唯一查看入口。按 8 位 SKU 展示产品状态、新品 SKU、Last Buy 计划/下单/完成时间、数量和状态、LB 后基准库存、当前库存、呆滞库存、专用料/通用料金额、近三月销量、销售总预测、EOL 前总预测、PSI DOS、清库进度。展开规则与 EOM 产品台账相同：每个 MSKU 一行，左侧为 MSKU 编码、渠道、店铺、线上/线下；预计 EOL、EOM 时长带出 SKU 值；Last Buy 与专用料/通用料子行显示“-”；当前库存、销量、预测、DOS 按 MSKU；清库进度本期带出 SKU 值（listing 无独立基准）。不展示风险列。EOL 是否可闭环看 SKU 主行「当前库存」是否为 0。

**核料信息详情**：展示本单关联核料单，口径见 6.11。

**节点任务**：正式 EOM 前按串行节点展示；正式 EOM 后展示三类并行跟踪（只读，操作仅「查看」进 SKU 台账）。核料、方案等须在系统完成的节点，处理人在对应页提交。串行节点完成后通知下一处理人；并行清尾不在 GTM 点完成，不通知需求计划。任务状态不等于清尾进度，进度以台账拉数为准。

**清库方案**：与核料信息详情同一套 Model → SKU → MSKU 全表明细。核料列只读；发起人在表内填写方案结论，并上传分类附件。结构化维护并保留版本。每个版本记录变更原因、SKU 结论、决策人、生效时间、关联附件。各角色默认执行当前生效版本。不使用整单弹窗作为主入口。

**操作日志**：记录关键操作、操作人、时间、变更前值和变更后值。

### 6.5 节点任务处理

改动位置：工单详情 / 工作台待办 → 处理当前任务（仅核料、方案等须在系统完成的节点）

核料、PMC 核料、方案确认：点「处理」进入对应页（核料 Tab / 清库方案 Tab），不走通用处理弹窗。

正式 EOM 后销售清成品、采购跟踪 Last Buy、PMC 清专用料三类任务只读。不发待办，只发钉钉消息。操作列为「查看」，进入 SKU 台账。不在 GTM 填写处理结果、不点完成、不驳回。清尾进度以台账拉数为准；EOL 只看 SKU「当前库存」是否为 0。

本期不做节点任务驳回、不做任务转交（所有角色）。有问题由发起人改方案或关闭后重开。计划请假由计划部门负责人直接确认该 SKU；GTM 方案只认发起人。

须在系统完成的节点，处理人填写处理状态、处理结果、本次更新时间和附件或关联单据。选择“已完成”后：

1. 串行节点：关闭当前任务，生成下一任务并通知下一处理人。
2. 并行清尾任务：不在 GTM 点完成，系统按台账拉数展示进度，不通知需求计划。

销售预测刷新在 Forecast 完成，与核料并行。销售确认或更新预测，并填写可接受 Last Buy 数量（仅供方案参考）。每次提交保存版本和提交时间。预测缺失或刷新失败时标识数据异常，方案页强提示，不硬拦方案提交。Forecast 后到刷新台账，不发入库通知；已确认/已定版核料不自动解锁。

核料任务可创建或关联核料单，展示建议 Last Buy 数量、成品库存、专用料、通用料、物料结余和供应商额外备料。核料结果需标识计算时间和版本。计算失败不得显示为成功。工单进入核料中即通知 PMC 打开核料页进行核料（核对专用料、物料结余等测算）。计划人员在核料页按 SKU 填写并确认结论；详情顶栏「确认」进入核料 Tab。全部 SKU 确认后自动定版，进入方案确认。PMC 核料不替代计划确认、不卡定版。详见 6.11。

### 6.6 清库及 Last Buy 方案

改动位置：工单详情 → 清库方案

页面即核料同款全表，**不用整单弹窗改方案**。待方案决策改当前版本；正式 EOM 后点「新增方案版本」填变更原因后，在同一张表上改出新版本。

#### 6.6.1 页面结构

1. **版本条**：当前版本、变更原因、确认进度（GTM / 计划已确认 SKU）、页头汇总。
2. **附件区**：一个上传区，每份文件选择类型，可多份。类型及用途：
   - **GTM确认方案**（确认必传）：发起人会签意见、决策说明
   - **EOM方案**（保存必传、确认必传）：退市方案正文，含范围、节奏、Last Buy 计划时间、费用归属、预计 EOL
   - **清库方案**（选填）：成品/物料处理说明、渠道动作
   草稿可不传。点保存时 EOM 方案至少 1 份。点「GTM确认整单」或正式 EOM 后会签通过时二次校验 GTM确认方案+EOM方案，未传硬拦。空预测强提示、不硬拦。Last Buy 计划时间等只写在这些文件里，不进表。
3. **明细表**：行粒度和列与核料信息详情一致（Model → SKU → MSKU 全列）。核料测算列、核料结论、计划负责人只读。SKU 合并列右侧增加方案结论列。
4. **版本历史**：表下展示历史版本摘要（原因、汇总数量/报废、附件、决策人、时间）。
5. **底栏**：保存草稿 / 保存 / 导入方案 / 导出方案（发起人）；确认所选 SKU（计划，口径与核料相同）。

#### 6.6.2 页面可填字段

| 字段 | 粒度 | 口径 |
|------|------|------|
| 清库方式 | SKU | 正常销售、降价、渠道调拨、改制、转卖、报废，可多选 |
| Last Buy 数量 | MSKU / 渠道 | 本渠道确认要补的**成品台数**；0 = 不补单。**核料定版时按该 MSKU 最终下单带入**，发起人可在方案页改。SKU 行只汇总。**不是整单一个总数** |
| 成品报废金额 | SKU | 现有成品报废，不是 Last Buy 货值 |
| 物料报废金额 | SKU | 现有物料报废 |
| 方案结论 | SKU | 短文本 |

MSKU 行不另填方案数。计划负责人仍按 MSKU 只读展示，用于按 SKU 确认。

页头只读汇总：

- Last Buy 汇总数量 = Σ SKU Last Buy 数量
- 成品报废合计、物料报废合计（超过 50 万 / 20 万仅非阻断提示，请线下走计委会 OA）

**不维护 Last Buy 金额**（SKU 级和汇总级都不做）。

导入导出模板一行一个 MSKU。导入弹窗提供上传模块，支持 Excel / CSV，须先上传再导入。列：8位SKU、MSKU、渠道Last Buy、清库方式（SKU维度）、成品报废金额（SKU维度）、物料报废金额（SKU维度）、方案结论（SKU维度）。Last Buy 只写该 MSKU；标了（SKU维度）的按 SKU 覆盖。兼容未标注「（SKU维度）」的旧列名。

#### 6.6.3 确认与生效

方案确认只会签 **发起人（GTM 侧）** 与 **计划**，不需要销售、需求计划、PMC、采购及其他 GTM 在系统点确认。后几类人收通知后可进工单查看。

确认规则：

1. **仅发起人**在清库方案页保存后，点「GTM确认整单」才记 GTM 已确认。保存本身不视为 GTM 已确认。确认前弹出二次校验：GTM确认方案、EOM方案未上传则硬拦；空预测、报废超金额强提示、不硬拦。GTM 名单中的其他人只收通知，不能点确认、不能改方案。之后发起人改方案会清空该确认，须再次点「GTM确认整单」。
2. 普通计划负责人只确认自己负责的 8 位 SKU（「我负责」口径与核料相同）。确认前校验该 SKU 已选清库方式、已填方案结论；未填硬拦。Last Buy 数量可为 0。
3. **计划部门负责人**可确认本单全部计划负责人名下的 SKU，一次可确认全部未确认 SKU。
4. 计划确认所选 SKU（含部门负责人确认全部）前弹窗：方案确认后产品状态将变为 EOM，将不可以再下采购单；列出各 SKU 产品状态、预计 EOL、Last Buy 数量，请确认采购单是否已经下达。取消则不确认。方案确认后不下推采购计划，由计划自行在采购计划下 Last Buy。
5. 生效条件：发起人已完成 GTM 确认，且本单全部 SKU 均已被计划侧确认。**不等报废 OA。** 进度展示为「计划已确认 SKU / 本单 SKU」。同一人兼发起人与计划时，点「GTM确认整单」只记 GTM 确认，计划 SKU 仍须再确认（部门负责人可一次确认全部）。
6. **无方案驳回。** 仅发起人直接改当前版本；保存后清空 GTM 与全部 SKU 的计划确认，必须重确认。成品报废合计 >50 万或物料报废合计 >20 万时，保存或点「GTM确认整单」给出非阻断提示（请线下走计委会 OA），不创建 OA、不挡确认。线下不同意时改当前方案，不关单、不退核料。
7. 产品范围选错、核料结论错误、整单不应继续：发起人关闭工单（须填原因）后重新发起。关闭后 SKU 释放准备 EOM，核料定版结论不带回新草稿自动生效。

方案需由发起人与计划按上列规则确认后生效，工单进入 EOM 执行，SKU 进入 EOM，并固化正式 EOM 时的库存、预测和物料基准快照。提交时若预测未刷新或为空，页面强提示当前预测版本/缺失情况，不硬拦保存。Last Buy 在核料定版时按 MSKU 最终下单带入，发起人可在方案页改。

报废金额按页头合计提示，不进流程门禁：

- 成品报废合计不超过 50 万元、物料报废合计不超过 20 万元：无额外提示。
- 成品报废合计超过 50 万元或物料报废合计超过 20 万元：非阻断提示「请线下发起计委会 OA」。系统不创建 OA、不回写、不挡方案确认与正式 EOM。

线下 OA 不同意时，发起人修改当前方案重新确认，工单不关闭、不退回核料中。系统不知道 OA 结果，没有自动退回。

方案变更必须记录变更原因、变更内容、决策人和生效时间。待方案决策改当前版本并清空确认；正式 EOM 后改版必须按 GTM + 计划（按 SKU，部门负责人可确认全部）会签，工单阶段不退回待方案决策，产品状态仍为 EOM。反 EOM 走 OA 反EOL，不得用方案改版代替。

### 6.7 正式 EOM 后执行

方案确认后通知销售、采购、PMC、需求计划。销售、采购、PMC、需求计划都只收通知（销售为钉钉消息，不发待办），进工单 **SKU 台账** 或 EOM 产品台账查看拉数，不在 GTM 点完成、不留痕。不另做「执行跟踪」页。

**成品清库**

- 每日刷新台账「当前库存」（产品库存看板总计库存数量）。
- 在台账展示 LB 后基准库存、当前库存、清库进度、呆滞库存及占比、近三月销量、销售总预测、EOL 前总预测、PSI DOS。
- 每 14 个自然日固化一次清尾快照。
- 销售按清库方案在销售侧执行；不在 GTM 记录降价、调拨及其他清库动作。

**Last Buy 跟踪**

- 以台账为准：Last Buy 计划时间、下单时间、完成时间、数量、状态。不另做「已生产/入库 vs 计划」进度条。
- 状态为未发起、待下单、生产中、入库中、已完成。
- 支持关联采购或生产记录。
- Last Buy 下单后、完成后分别保存库存快照。
- 方案确认后不自动下推采购计划；计划按会议结论自行在采购计划下 Last Buy。数量不与方案互相校验。详见 6.16。
- 准备 EOM 可以下 Last Buy；创建时提示该 MSKU 产品状态、预计 EOL、Last Buy 数量。产品状态变为 EOM 后不可以再下任何采购单（与现网一致）。拦截提示同样带出这三项。因此 Last Buy 须在正式 EOM 前下达。
- 已下达的 Last Buy 继续执行、入库，不受「EOM 后禁新建采购单」阻断。
- Last Buy 未完成不挡 EOL。

**专用料清理**

- Last Buy 及在途订单全部入库后，系统在台账展示专用料/通用料库存金额（悬停可见件数），供 PMC 查看。
- 展示专用料、通用料的数量和金额。
- 不要求 PMC 在 GTM 填写改制/转卖/报废人工进度；进度以库存拉数为准。
- 报废 OA 走线下，GTM 不关联审批单、不回写结果。
- 专用料不为 0 不挡 EOL。
- 物料分类或数据异常时提供人工复核入口。

### 6.8 反 EOM

改动位置：工单详情 → 发起反 EOM

不限制发起人、退市类型、BOM 状态。仅正式 EOM 后（EOM执行、EOL已闭环）可发起；草稿、核料中、待方案决策尚未 EOM，顶栏不出现反 EOM，取消走关闭。当前工单已有审批中的反 EOL OA 时不可再发；驳回或撤销后允许再发。

业务上仍称「反 EOM」；提交后创建的钉钉 OA 模板为「反EOL流程审批」。

**填写并传给 OA**（对齐现网钉钉 OA「反EOL流程审批」）

| 字段 | 规则 |
|------|------|
| SKU | 手填，可多填（逗号或换行），必填。不校验是否属于本单 |
| PSKU | 手填，可多填，**非必填** |
| 反EOL原因 | 手工填写，必填 |
| 附件 | 可多份，非必填 |
| 产品经理 | 选人，必填，多选 |
| 对应销售渠道leader | 选人，必填，多选 |
| 研发确认 | 选人，必填，多选 |
| 项目审核 | 选人，必填，多选 |
| 抄送人 | 选人，非必填，多选；对应 OA 流程抄送人 |

**GTM 不维护**

- Sourcing、审批人：OA 模板自动带出（现网为 1 人审批）。
- OA 表单「发送到聊天」：不接到 GTM。
- **无「项目助理」节点**（现网 OA 已去掉）。
- 同一节点多人如何批（会签/或签）：OA 能力，GTM 只把人选传给 OA。

OA 节点顺序：产品经理 → 对应销售渠道leader → Sourcing（OA 带出）→ 审批人（OA 带出）→ 研发确认 → 项目审核 → 抄送人。

**提交与回写**

1. 提交后自动创建 OA，工单记录 OA 单号和状态（审批中 / 已通过 / 已驳回 / 已撤销）。
2. **审批中**：不打标签，工单阶段不变，不可再发。
3. **已驳回 / 已撤销**：不打标签（若误打则去掉），阶段和 SKU 状态保持发起前，允许再发反 EOM。
4. **已通过**：打上「已反 EOM」，工单阶段变为已关闭，本单 SKU 释放回提交前（已上市 / 未上市）。不可再发反 EOM，不可重新发起，本单只读（可看详情和日志，不能改方案、确认、处理、关闭、编辑）。
5. 不得以手工关闭或重新发起普通 EOM 代替反 EOM OA。本期不解禁 BOM、不跟踪追加 Last Buy。

### 6.9 EOL 闭环

SKU 台账「当前库存」为 0 时，自动由 EOM 切换为 EOL。专用料、Last Buy 只在台账展示，不挡闭环。已反 EOM 关单后 SKU 已释放，不再走本单 EOL。

当前库存不为 0 则不闭环。自动闭环失败（数据刷新异常等）支持重试和人工复核。人工闭环必须填写原因并记录日志。

闭环时记录实际 EOL 时间和触发数据快照，关闭未完成的普通监控任务，并通知 GTM、销售、需求计划、计划、PMC 和采购。

工单内全部 SKU 均完成 EOL 后，工单才进入 EOL 已闭环。

### 6.10 EOM 产品台账

改动位置：GTM → 管理 → EOM 管理 → EOM 产品台账

支持按工单、SKU、Model 查看。主表一行一个 8 位 SKU，展开为该 SKU 下 MSKU 行。子行左侧展示 MSKU 编码、渠道、店铺、线上/线下，不单独展示平台。从预计 EOL 到清库进度与主表列对齐：预计 EOL、EOM 时长带出 SKU 相同值；Last Buy（计划/下单/完成时间、数量、状态、LB 后基准库存）与专用料/通用料仅 SKU 有数，子行显示“-”；当前库存、销量、预测、PSI DOS 按 MSKU；呆滞仅 SKU 有数（金蝶库龄不到 listing）；清库进度本期带出 SKU 值。SKU 主行「当前库存」= 产品库存看板「总计库存数量」（不含采购在途，见 7.3）；MSKU 行为该 listing 同口径分项加总，不以相加与主行对账。清库方案与操作仅留在 SKU 主行。导出当前结果包含 SKU 行及其下 MSKU 行，口径与页面一致。工单详情「SKU 台账」同一套规则。正式 EOM 后三路进度以本页及工单 SKU 台账为准，不另做执行跟踪页。支持自定义列、冻结关键列、导出业务标准模板。动态指标显示数据来源和更新时间。各列完整取值逻辑见第 7 章。

不展示风险列。管理字段增加：EOM 流水号、退市类型、退市原因、当前工单阶段、当前责任人、实际 EOL 时间、数据更新时间。不增加是否超期、风险等级、风险类型。

### 6.11 核料结论填写、页面确认与导入快录

改动位置：核料信息详情、工单详情顶栏「确认」、工单「计划确认人员」

吸收 CKW-002「核料完成后统一模板导入」。导入只用于快速录入，**不能替代**核料页直改和按 SKU 确认。本期只保留 **按当前工单** 导入，不另做混单导入。

#### 6.11.1 字段粒度

核料详情按 Model → SKU → MSKU 展开。交付时间、报废金额、原因按 SKU 合并；**最终下单数量、计划负责人、结论按 MSKU 行**。SKU 行最终下单只读合计。

| 字段 | 粒度 | 口径 |
|------|------|------|
| 下单后最快交付时间 | SKU | 天数（整数），不是日期 |
| 最终下单数量 | MSKU | 可为 0（不补单）；SKU 行只读合计 |
| 最终报废金额 | SKU | 可为 0 |
| 原因 | SKU | MOQ物料结余 / 销售需求变化 / 供应链需求外风险备料 / 物料报废金额小于等于2万 |
| 计划负责人 | MSKU | 只读，来自主数据；无主时计划部门负责人兜底 |
| 结论 | MSKU | lastbuy后报废 / 不补单报废；各店铺可不同 |

库存、店铺、日销、DM 结余、售完日期为 MSKU 行。

**主路径是页面直改**：最终下单按 MSKU 编；报废金额/原因/交付天数按 SKU 编一次；结论按 MSKU 各编。导入和页面编辑均不改「建议下单」「锁定建议下单」。SKU 行最终下单只展示合计、不可改。

勾选单位为 **8 位 SKU**：多 MSKU 合并成一行勾选，不得按店铺行勾选。确认前该 SKU 下全部 MSKU 结论必须已填。

#### 6.11.2 计划负责人与「我负责」

1. 「我负责某 MSKU」= 该行计划负责人 = 当前登录人。
2. 「我负责某 SKU」= 该 SKU 下至少一条 MSKU 的计划负责人是我。具备后可勾选确认该 SKU。
3. 计划负责人按 MSKU 展示。主数据可落到 MSKU；未落到 MSKU 时回退该 SKU 第一负责人。
4. 核料计算完成时，仍无负责人的 MSKU 统一指定为 **计划部门负责人**，并标记来源为 leader 兜底。
5. 主数据随后维护了该 MSKU 或 SKU 的计划负责人后，系统自动刷新为维护后的人，不再用 leader。若该 SKU 已确认锁定，刷新后解锁，改由新负责人填写并确认。
6. 工单「计划确认人员」按核料行计划负责人去重自动带出。该 SKU 下任一 MSKU 的计划负责人可勾选确认该 SKU，但须该 SKU 下全部 MSKU 结论已填。
7. **计划部门负责人**可填写、导入并确认本单全部 SKU（含他人负责的未锁定行）。普通计划负责人仍只能处理自己负责的 SKU/MSKU。

#### 6.11.3 按工单导出 / 导入

导入只写入，**不自动确认**。一次只处理 **一个 EOM 工单**。模板 **一行一个 MSKU**。导入弹窗提供上传模块，支持用户上传 Excel 或 CSV；须先上传文件再导入。可先下载模板。

模板列：EOM流水号、核料流水号、8位SKU、MSKU、计划负责人（只读）、下单后最快交付时间（天）（SKU维度）、最终下单数量、建议报废金额（SKU维度）、原因（SKU维度）、结论。

数量按 MSKU 写入；标了（SKU维度）的金额/原因/交付时间按 SKU 覆盖；结论只写该 MSKU。同一 SKU 有多个 MSKU 时必须填 MSKU。导入兼容未标注「（SKU维度）」的旧列名。
核料填写（最终下单、报废金额、原因、交付天数、结论）的初盘与改数写入核料日志，核料页不展示初盘。全部 SKU 确认定版时，按 MSKU 最终下单带入方案渠道 Last Buy，此后只在方案页改。

导出：默认只导出当前登录人负责的 MSKU。可勾选「导出本单全部」，他人行仅供对照。

导入匹配：SKU/MSKU 必须属于当前工单核料单。填写了 EOM 流水号或核料流水号时，必须与当前工单一致。禁止混单。

导入权限与结果：

1. 只覆盖当前用户有权处理的行：普通计划负责人为「该 MSKU 计划负责人 = 当前用户」且该 SKU 尚未确认；计划部门负责人可覆盖本单全部尚未确认的行。
2. 无权行跳过，在导入结果中列出，不导致整单失败。
3. 单行失败不影响其他有效行。
4. 核料已定版、计算失败、草稿、无核料单、或工单已过核料节点：禁止导入。
5. 已确认锁定的 SKU：该行失败，不得覆盖。

#### 6.11.4 确认入口与按 SKU 确认

**工单详情「确认」**：现网列表同名按钮不再放在行内。展示条件：工单阶段为核料中、核料计算成功、当前用户是该单计划确认人员之一或计划部门负责人。进入详情后点「确认」，打开该工单核料信息 Tab，**不在列表上提交确认**。

**核料信息页「确认所选 SKU」**：

1. 勾选我负责且尚未锁定的 8 位 SKU，可单条或批量。计划部门负责人可勾选本单任意未锁定 SKU。
2. 若该 SKU 的报废金额/原因/交付天数未填，或该 SKU 下任一 MSKU 的最终下单或结论为空：提醒后该 SKU 不得确认。
3. 已填齐的所选 SKU：锁定；工单阶段不变，仍为核料中。
4. 列表进度为「已确认 SKU / 本单 SKU」。确认部分 SKU ≠ 整单完结，也 ≠ 进入待方案决策。
5. 该单全部 SKU 都确认后：核料自动定版，**定版那一次**按 MSKU 最终下单带入方案渠道 Last Buy，工单进入待方案决策。此后核料锁定，改 Last Buy 只在方案页。方案确认后进入 EOM 执行。现网「完结」仅作迁移映射，2.0 页面不得显示业务完结。
6. 定版后全员只读。**不因方案问题解锁核料。** 核料结论错误时关闭工单后重新发起。

权限沿用现网：核料结论编辑 / 导入 `gtm:manage:materialInfo:deliveryTime`；确认 `gtm:manage:eomProcess:plan`。普通用户资格以核料行计划负责人为准；计划部门负责人可处理本单全部行。

### 6.14 PSI 管理（销售系统）

6. 产品状态为 EOM 后：常规要货关闭。准备 EOM 阶段仍可填 Sell out，但受全链路库存硬拦。
7. 不改实时版本 / 评审版本切换，不改弹窗时间连续、类型、增删行等现网校验。

### 7.3 完整取值逻辑

#### 7.3.0 通则与库存口径对照

1. **刷新**：动态指标（当前库存、呆滞、物料金额、近三月销量、预测、DOS、清库进度）按日定时拉数，并支持工单/台账手动刷新。页头展示数据更新时间。事件快照（发起、正式 EOM、LB 完成、EOL）写入后不再被日刷覆盖。
2. **日期**：时长、自然月、预测截取均按业务日（UTC+8）0 点切日。
3. **空值**：源系统无数据、核料未成功、基准未锁定时显示 `-`，不显示 0（库存/销量/金额无数据时显示 0；`-` 仅用于「不适用」）。
4. **SKU 与 MSKU 不对账**：主行当前库存含无法拆到 listing 的国内在库等；禁止用 Σ MSKU 校验主行。
5. **现网库存有三套口径，必须分开，不得混用：**

| 名称 | 现网出处 | 公式 | 本期用途 |
|------|----------|------|----------|
| 在库数量 | 产品库存看板 `/board/inventoryMgr`，`quantityStored` | 金蝶：国内在库仓 + 海外仓在库仓 + 配件仓。含占用、待调拨；**不含**不良品仓、**不含**物流贴标仓（已拣货） | 发起页「在库库存」；台账不单列 |
| 总计库存数量 | 同上，发起页已采用 | **在库数量 + 已拣货 + FBA 可售 + FBA 在途 + 海外在途**。不含采购在途、FBA 转仓、FBA 预留、海外仓客户占用、借调 | **台账「当前库存」SKU 主行；EOL 判定库存** |
| Forecast 成品库存 | `ForecastV2DetailVO.getQuantityTotalInStock()` | 国内在库 + 海外仓在途 + 海外仓在库 + FBA 在途 + FBA 转仓 + FBA 可售 + FBA 预留(处理中)。不含采购在途、不含已拣货 | 对照，台账不展示、不参与 EOL |
| Forecast 总计库存 | `ForecastV2DetailVO.buildQuantityTotal()` | 采购在途 + 国内在库 + 已拣货 + FBA 可售 + FBA 转仓 + FBA 在途 + 海外仓在途 + 海外仓在库 + FBA 预留(处理中) − 海外仓客户占用 | 对照；含采购在途，**不能**作 EOL 条件（否则 Last Buy 在途会挡住闭环） |
| PSI 全链路库存 | 6.14 / 6.15 | 成品库存 + 采购在途（含已下达 Last Buy 在途） | **仅** Sell out 提交/审核硬拦 |

EOL 只看台账 SKU「当前库存」是否为 0。专用料、Last Buy 未完成、采购在途均不挡闭环。

#### 7.3.1 身份、主数据、产品状态

| 字段 | 取值 |

#### 7.3.3 时间与时长

**发起 EOM 时间** = 提报时间（工单级，SKU 行重复展示）。

**预计 EOL**：当前生效方案上该 SKU 的目标日期。发起时选填，台账可补。未填显示 `-`。MSKU 行带出 SKU 值。

**在售时长**（天，整数）：

- 未 EOL：`trunc(当前业务日) − trunc(上市时间)`。
- 已 EOL：`trunc(实际 EOL 日) − trunc(上市时间)`。
- 上市时间为空或结果 < 0：显示 `-`。

**EOM 时长**（天，整数；不足 1 天记 0）：

- 未闭环：`trunc(当前业务日) − trunc(发起 EOM 时间的日期)`。
- 已闭环：`trunc(实际 EOL 日) − trunc(发起 EOM 时间的日期)`。
- MSKU 行带出 SKU 值。

现网无此字段，2.0 新建。

#### 7.3.4 Last Buy（仅 SKU 主行；子行 `-`）

方案 Last Buy 按渠道/MSKU 填写；计划在采购计划自行下单，**两套数量不互校**。台账 LB 数量以**生效方案渠道合计**为主展示，实际下单量悬停可看。

**纳入统计的采购计划**：`tag = Last Buy`（或等价来源标记）且关联本工单该 8 位 SKU，状态不含拒绝下单 / 已取消 / 已废弃（`PurchasePlanStateEnum.REFUSE_ORDER / CLOSE / DISCARD`）。

**LB 数量**

- 主数字 = 当前生效方案该 SKU 全部渠道 Last Buy 数量之和（整数台）。
- 主行副文案固定「渠道合计」（与截图一致）。
- 方案合计为 0：数字 0，状态走「无需 LB」。
- 悬停：计划数量（方案）vs 采购计划剩余/下单数量（实单，仅展示，不改主数字）。

**LB 计划时间**

- 取生效方案该 SKU 各渠道计划下单日的**最早**日期。
- 方案未填且无 LB：`-`。

**LB 下单时间**

- 纳入统计的采购计划中，首次离开「待下单集合」进入后续状态的业务日，多单取**最早**。
- 尚无此类单据：`-`。

**LB 完成时间**

- 纳入统计的全部采购计划均为「已完结」`FINISH` 的当天，多单取**最晚**完结日。
- 尚未全部完结：`-`。

**LB 状态**（五态 + 无需 LB）

现网采购计划**没有**「生产中」枚举（`PurchasePlanStateEnum`）。台账用下列映射，SKU 多单时取**最落后**状态（上优先于下）：

| 台账状态 | 判定 |
|----------|------|
| 无需 LB | 生效方案该 SKU Last Buy 合计 = 0，且无纳入统计的采购计划 |
| 未发起 | 方案合计 > 0，且无纳入统计的采购计划（或仅有拒绝/取消/废弃） |
| 待下单 | 存在单据状态 ∈ 待 TL/Leader/销售确认/PMC 复核/供应链 Leader 审核、待拆单、待 MOQ 确认、Forecast 备料明细、待下单（id：1、2、9、10、11、12、13、14、16） |
| 生产中 | 存在已离开待下单集合、尚未进入入库中集合、且未完结的单据。若实单从待下单直接到待入库，则跳过本态 |
| 入库中 | 存在单据状态 ∈ 待入库 / 待销售 PMC 审核 / 待供应链 PMC 审核（id：4、7、8，现网注释「算库存」） |
| 已完成 | 纳入统计的单据全部为已完结 `FINISH(5)`，或方案合计=0 已走无需 LB（二者互斥） |

**LB 后基准库存**（清库进度分母，锁定后不变）

- **有 Last Buy**（方案合计 > 0）：该 SKU LB 状态变为「已完成」的当天，把当天 SKU「当前库存」写入快照。锁定前本列显示 `-`，清库进度显示 `-`。
- **无 Last Buy**：正式 EOM（方案生效）当天，把当天 SKU「当前库存」写入快照。
- 锁定后日刷只更新「当前库存」，不改基准。
- 不以「当时库存 + 计划 LB」预估（避免与实单差异、也避免把采购在途算进 EOL 库存）。

#### 7.3.5 当前库存、呆滞库存、呆滞占比

**当前库存（SKU 主行）**

- 来源：销售系统产品库存看板，按 8 位 SKU 汇总全部店铺/listing。
- 公式 = **总计库存数量** = 在库数量 + 已拣货 + FBA 可售 + FBA 在途 + 海外在途。
- 在库数量 = 金蝶国内在库仓 + 海外仓在库仓 + 配件仓（含占用、待调拨；不含不良品仓、不含物流贴标仓）。
- 已拣货 = 金蝶物流贴标仓。
- **不含**采购在途（含 Last Buy 在途）、FBA 转仓、FBA 预留、海外仓客户占用、借调。
- 无数据当 0。EOL：该值 = 0 即 SKU 切 EOL。

**当前库存（MSKU 行）**

- 同一套分项加总，范围改为**该 listing**。
- 不与 SKU 主行求和校验。

**呆滞库存（数量，台）**

- 来源：销售系统**金蝶成品库龄看板**（`/ms-ai-sales/rest/kingdee-inventory-age`）。
- 公式对齐 `KingdeeInventoryAgeQueryServiceImpl.getDefaultStagnantQty`：库龄 **>270 天** 数量 = `qtyAge271365 + qtyAgeOver365`（270 当天不算呆滞）。
- 按 8 位 SKU 取值。金蝶呆滞数量优先用源 `stagnantQty`；为空或 0 时回退上述分桶之和。
- **不采用**旧成品库龄看板超 180 天、PSI 国内库龄 ≥180 天。分母与「当前库存」不是同一仓储切片时，占比仅作参考，不强行对账。
- 金蝶库龄到 SKU 不到 listing：**MSKU 行呆滞库存、呆滞占比显示 `-`**，不得按销量分摊。

**呆滞占比**

- `呆滞库存数量 ÷ 该行当前库存`，百分比，保留 1 位小数，四舍五入。
- 当前库存 = 0：显示 `0%`（不显示 `-`）。
- 呆滞 > 当前库存（口径切片不一致）：占比按计算结果封顶 100%，悬停提示口径不同。

#### 7.3.6 专用料库存、通用料库存（金额）

页面两列与截图一致，展示 **CNY 金额**（可千分位、前缀 `¥`），不是件数。数量保留在快照/悬停：在库件数、在途件数。

来源：该工单最新一次**计算成功**的核料结果，物料三维标记 `GtmEolMaterialEnum`（SCM `V2EolServiceImpl.calcMaterialAmount`）：

| 标记 | code | 台账列 |
|------|------|--------|
| EOL 专用物料 | 0 | **专用料库存** |
| EOL 共用物料 | 1 | 并入 **通用料库存** |
| 通用物料 | 2 | 并入 **通用料库存** |

单物料金额 = `含税单价 taxPrice × (在库数量 + 在途数量)`；单价或数量 ≤ 0 则该物料贡献 0。SKU 列 = 该 SKU 下符合标记的物料金额之和。

- 核料未成功、未出结果、工单尚在草稿：两列 `-`。
- 结果为 0：显示 `¥0`。
- MSKU 行：`-`（物料在 SKU/BOM，不拆店铺）。
- 现网核料页以结余测算为主、无这两列；台账为 2.0 汇聚展示。金额只用于展示和管理，**不挡 EOL**。

工作台专用料关闭率用本列「专用料库存」金额，见 7.3.11。

#### 7.3.7 近三月销量、销售总预测、EOL 前总预测

数据来自销售系统，Forecast **页面本期不改**，台账只读拉数。

**M-3 月 / M-2 月 / M-1 月**

- 实际销量（订单/平台 Sell out 月汇总），**不是** Forecast 预测。
- 自然月：以当前业务月为 M，则 M-1 为上一个完整自然月，M-2、M-3 依次再往前。例：2026-09-16 → M-1=2026-08，M-2=2026-07，M-3=2026-06。
- MSKU 行 = 该 listing 月销；SKU 行 = 该 SKU 下 listing 月销之和。
- 无销量为 0。

**销售总预测**

- 当前有效 Forecast 版本中，该 listing 的 `estimateSales`（或等价日/周预测）里 **日期 ≥ 当前业务日** 的预测销量合计。
- SKU 行 = 下属 listing 合计。无有效版本或无未来预测为 0。
- 须展示预测版本号与预测刷新时间（可放悬停）。

**EOL 前总预测**

- 同上数据源，截取 **当前业务日 ≤ 日期 ≤ 预计 EOL**（含两端）的预测合计。
- 预计 EOL 为空：本列 `-`（无法截取）。
- 预计 EOL < 当前业务日：显示 0。
- SKU / MSKU 聚合规则同销售总预测。

#### 7.3.8 PSI DOS

不在 GTM 重写公式。算法复用 `PsiCalcServiceImpl.calcDosDaySeries`：

1. 取 PSI 当日（及后续推演日）期末库存序列、未来 Sell out 序列。
2. 当日期末库存 ≤ 0 → DOS = 0。
3. 自**次日**起按日扣减 Sell out：能扣满整日记 1 天；最后不足一天记 `剩余库存 / 当日 SO`（scale=1，HALF_UP）。Sell out≤0 的日期仍计 1 天（与现网一致）。
4. 期初海外可用库存不含在途；后续日按 PSI 叠加海外在途到货与 Sell through，期末库存为负则取 0。
5. 台账展示**当前业务日**的 DOS，单位「天」，页面取整（四舍五入到整数，与截图 `28天` 一致）；悬停保留现网 1 位小数。
6. 须展示 PSI 数据时间。

**MSKU 行**：该 listing 当日 DOS。

**SKU 行**：将该 SKU 下 listing 的期末库存、未来 Sell out **分别加总后按同一算法重算**当日 DOS，禁止对 listing DOS 做算术平均或取 min/max。

无 PSI 数据：`-`。

#### 7.3.9 清库进度、清库方案

**清库进度**（百分比，1 位小数）

- 基准 = 该粒度「LB 后基准库存」。SKU 行用 SKU 基准与 SKU 当前库存；MSKU 行：基准未按 listing 锁定则显示 `-`（本期只锁 SKU 基准；MSKU 进度可用 SKU 进度带出或 `-`，**本期 MSKU 清库进度带出 SKU 值**，避免无 listing 基准）。
- 基准未锁定：`-`。
- 基准 > 0：`(基准 − 当前库存) ÷ 基准 × 100%`。结果 < 0（库存高于基准，如退货）显示 `0%`，悬停「当前库存高于基准」。结果 > 100% 显示 `100%`。
- 基准 = 0 且当前库存 = 0：`100%`。
- 基准 = 0 且当前库存 > 0：显示 `-`，标记「基准异常」。
- 进度条颜色仅展示：<40% 红，<70% 黄，否则蓝（与原型一致，非业务规则）。

**清库方案**

- 当前生效方案版本号，如 `V1`、`V2`。无结构化方案（仅附件）显示 `-`。
- 仅 SKU 主行；点击进入该工单清库方案页（只读或按权限编辑）。
- MSKU 行：空白（不显示 `-` 以外的版本号，避免误解为店铺方案）。

#### 7.3.10 操作

仅 SKU 主行。按钮是否出现跟权限走，无权限不展示（不是置灰）。

| 按钮 | 行为 |
|------|------|
| 查看 | 打开台账行只读抽屉/页：SKU 快照、库存分项、LB 计划 vs 实单、物料金额明细、数据时间 |
| 详情 | 打开该 EOM 工单详情 |
| 核料 | 打开该工单核料信息；无核料单或无权时不展示 |

#### 7.3.11 专用料关闭率（工作台，非台账列）

`(正式 EOM 时专用料基准金额 − 当前专用料库存金额) ÷ 正式 EOM 时专用料基准金额`。

- 基准金额 = 正式 EOM 当天 7.3.6 专用料库存快照。
- 基准 = 0 且当前 = 0：100%。基准 = 0 且当前 > 0：`-`（基准异常）。
- 工作台默认按金额；数量可在悬停给出。EOL 判定不看本指标。

### 7.4 数据分类

1. 主数据：发起时保存快照，不随源数据覆盖。
2. 动态指标：库存、预测、销量、PSI DOS、物料定时刷新，必须显示数据时间。
3. 业务事件：发起、正式 EOM、Last Buy 下单、Last Buy 完成、实际 EOL 保存不可变快照。
4. 人工决策：退市原因、清库方案、报废决策、备注保留版本。

## 8. 通知

通知渠道：ERP 待办，以及钉钉待办或钉钉消息。

系统菜单位于核料管理下方：「通知」。首项「总揽」按触发情况对照各角色收件类型与原文；其余按销售、GTM、需求计划、计划、PMC、采购分角色展示收件内容。角色页通知需能直接进入对应工单或任务；销售预测刷新进入 Forecast；PMC 核料待办进入核料页。发给销售的钉钉消息同时抄送该专员的 STL、TL。

通知时机：

1. 当前任务完成后，通知下一处理人。
2. 工单进入核料中，通知 PMC 进行核料（待办，进入核料页，不卡定版）；有销售专员则并行提醒刷新预测，并抄送该专员的 STL、TL。
3. 正式 EOM 后，同时以消息通知销售（含 STL、TL）、采购、PMC（不发待办）；需求计划只收一条知情消息「已正式 EOM，进度请看台账」，不要求复核任务。
4. 并行清尾进度更新或任务完成，不通知需求计划；进度以台账为准。
5. 报废超金额不发 OA 发起/返回通知（OA 走线下）。
6. 反 EOL OA 回写后，通知工单相关人员（含单号与状态；通过时一并告知已打标签）。
7. EOL 闭环后，通知 GTM、销售、需求计划、计划、PMC 和采购。

**不通知：** Forecast 审核入库只静默刷新台账（及未锁定未确认行的建议下单参考值），不向 GTM、需求计划、计划、销售或其他角色发待办或消息。销售只在发起时收到「请刷新预测」提醒；入库结果进工单或台账查看。

各角色收件规则见 6.13。总揽页用于一次性核对全部触发情况。不做到期前提醒、超期自动升级和 S&OP 风险清单。

## 10. 系统边界与数据刷新

GTM 不复制源系统交易明细，只保存关联单据、关键快照和汇总指标。

| 数据 | 来源 | 刷新方式 |
|------|------|----------|
| 产品、场景、品类、国家规格、上市时间 | 产品主数据 | 发起时快照，后续可手工核对 |
| 新品 CR、上市时间 | 项目系统 | 自动带出，允许调整并留痕 |
| 近三月销量、Sell out 预测、PSI DOS | 销售预测 / PSI | 每日或预测版本发布后刷新 |
| 成品库存、呆滞库存、在途 | 库存服务 | 每日，支持手动刷新 |
| 专用料、通用料、建议 Last Buy | 核料 / SCM | 核料定版及每日刷新 |
| Last Buy 订单及入库 | 采购计划 / 生产 | 每日或订单事件触发；PSI 只读已下达 Last Buy 数量 |

| EOL 条件检查 | GTM | 每日自动检查 |

库存、预测、BOM 或物料获取失败时，显示数据异常，不得用错误结果自动闭环，也不得把失败计算显示为成功。

## 11. 异常与边界

1. 新品项目取消后，支持暂停、调整或转为被动退市，具体规则待确认。
2. 新品延期或老品积压时，通过新增清库方案版本处理，不生成风险工单。
3. 反 EOM 仅正式 EOM 后可发；必须自动生成 OA；审批中不可再发；驳回/撤销可再发；通过后关单、打标签、SKU 回提交前，禁止重开。
4. EOM 工单关闭或暂停时必须填写原因，并处理未完成任务。
5. 历史迁移后无法还原的指标必须明确标识，不得伪造历史快照。
6. 本期产品状态变为 EOM 后不可以再下任何采购单。若后续要开特批普通下单，再单独立项。

## 12. 分期实施

### 12.1 第一期：口径与入口

1. 修正台账字段名称和粒度。
2. 增加主动/被动退市和退市原因。
3. Model / 场景搜索带出候选 SKU，勾选进入已选清单；支持当前结果全选和导入；不强制排除原因。
4. 将“计划确认后完结”改为“进入 EOM 执行”。
5. 核料在核料页按 SKU 勾选确认；计划负责人、结论按 MSKU；导入只用于快录；全部 SKU 确认后自动定版。
6. 核验核料和 SCM 计算结果，失败不得显示成功，在途不得重复统计。
7. 反 EOM：仅正式 EOM 后可发；填单对齐现网 OA（无项目助理，PSKU 非必填）；回写单号与状态；驳回/撤销可再发；通过后关单、打标签、SKU 回提交前，禁止重开。
8. 销售 PSI 管理 / 审核叠加产品状态、预计 EOL 与 Sell out 全链路硬拦；采购计划 Last Buy 提示与 EOM 后禁下单。Forecast 页面不改。

### 12.2 第二期：在线台账与任务流

1. 新工单阶段和产品状态分离。
2. 串行节点任务及完成后通知下一人。
3. 结构化清库方案和版本。
4. Last Buy 三个时间和执行状态。
5. 库存、预测、物料自动回填和双周快照。
6. 正式 EOM 后三类并行跟踪（只读，不发待办）。
7. EOL 自动闭环。
8. ABU 流程适配。

### 12.3 第三期：执行闭环

1. Last Buy 订单、生产和入库明细联动。
2. 物料改制、转卖、报废进度以库存为准（报废 OA 不回写）。
3. 反 EOM 后半段（解禁 BOM、追加 Last Buy 跟踪）。本期反 EOM 只做到填单、起 OA、回写。
4. S&OP 复盘视图。
5. 历史数据迁移和主数据治理。

独立风险预警页、风险字段、配置中心和超期自动升级不纳入以上三期。后续如仅靠台账无法有效识别异常，再单独立项。

## 13. 数据迁移

迁移范围：进行中的 EOM 流程、准备 EOM/EOM 状态 SKU、已有核料单、线下台账、清库方案附件、未完成 Last Buy。

规则：

1. 已关闭流程迁为历史记录，不生成待办。
2. 原“完结”不得一律视为 EOL：
   - 产品已 EOL：迁为闭环。
   - 产品仍为 EOM：迁为 EOM 执行。
   - 产品仍为准备 EOM：进入人工核查。
3. 缺失 SKU、Model、责任人的记录进入数据异常清单。
4. 线下台账导入前校验 SKU、日期、库存和状态。

上线建议：历史数据初始化 → 新旧台账并行两周 → 核对库存、预测、物料口径 → 停止线下新增 → GTM 作为唯一正式台账。

## 14. 验收标准

### 14.1 发起

1. 能区分主动退市和被动退市。
2. 跨 Model / 场景多次搜索勾选后，已选清单保留且可删除。
3. 未勾选不必填排除原因；下一步只认已选清单。
4. 已 EOL 或已存在进行中 EOM 的 SKU 无法提交。
5. 批量导入能反馈逐行结果。
6. 提交后 SKU 进入准备 EOM，工单进入核料中；有销售专员的 MSKU 钉钉提醒对应专员刷新预测，并抄送其 STL、TL，不卡核料。

### 14.2 流程

1. 主动、被动按固定规则生成不同节点。
2. 每个节点有责任人、截止时间和处理记录。
3. 核料中工单「确认」跳转核料页；在核料页按 SKU 勾选确认。该 SKU 下 MSKU 结论等为空则提醒。确认后工单不显示完结。全部 SKU 确认后核料定版，进入待方案决策。方案确认后进入 EOM 执行，而不是完结。
4. 核料结论以页面直改为主，可按当前工单导入快录，一行一个 MSKU；金额/原因/交付时间按 SKU（列名标注 SKU维度），结论与最终下单按 MSKU。
5. 当前任务完成后自动通知下一处理人。
6. 正式 EOM 后同时生成销售、采购、PMC 三类并行跟踪任务（只读，不发待办）。
7. 方案无驳回。仅发起人在清库方案页直改当前版本并清空确认；无法靠改方案解决时关闭（草稿至待方案决策）后重新发起。本期不做节点任务驳回、不做任务转交、不做撤回。空预测方案页强提示、不硬拦。
8. 计划只确认自己负责的 SKU；计划部门负责人可确认全部 SKU。全部 SKU 计划确认且发起人已确认后方案生效。其他 GTM 只通知。报废超金额仅非阻断提示，不挡生效。
9. 清库方案表展示核料全列；可填清库方式、Last Buy 数量、成品/物料报废、方案结论。不出现 Last Buy 金额。提交时已上传 EOM 方案。
10. Forecast 与核料并行：提交即进核料中；预测后到不解锁已确认/已定版核料。Forecast 审核入库只刷新台账，不发通知。
11. 工单列表、筛选、自定义列、导出、详情和通知只展示工单阶段，不展示现网「流程状态」，方案确认后不显示完结。
12. 反 EOM：仅正式 EOM 后可发；填单对齐现网 OA（无项目助理，PSKU 非必填）；提交后自动生成 OA；审批中不可再发；驳回/撤销保持原状可再发；通过后关单、打「已反 EOM」、SKU 回提交前，禁止重开，本单只读。
13. 成品报废合计超过 50 万元或物料报废合计超过 20 万元时，保存方案或点「GTM确认整单」给出非阻断提示；系统不创建 OA、不回写、不挡正式 EOM。

### 14.3 台账

1. 业务确认字段均可查看和导出。
2. 动态指标展示来源和更新时间。
3. 关键事件保留不可变快照。
4. 支持按 SKU、Model、工单查看，并可展开 MSKU（含渠道、店铺、线上/线下）。导出含 MSKU 行。
5. 页面与导出口径一致。
6. 不出现风险等级、风险类型字段。
7. 正式 EOM 后三路进度只看台账，不出现执行跟踪页。

### 14.4 Last Buy 与物料

1. 可分别查看计划时间、下单时间、完成时间。
2. 能从计划跟踪到入库完成。
3. 下单及完成后自动保存库存快照。
4. 准备 EOM 可下 Last Buy（提示状态、预计 EOL、Last Buy 数量）；变为 EOM 后不可以再下任何采购单。已下达 Last Buy 继续执行。
5. 专用料、Last Buy 进度在台账展示，不挡 EOL。

### 14.5 EOL

1. 台账 SKU「当前库存」为 0 即闭环。专用料、Last Buy、反 EOM 不挡闭环。
2. 库存不为 0 时不闭环；台账可见当前库存。
3. 自动闭环失败可重试，并支持人工复核。
4. 工单内全部 SKU 闭环后，工单才显示 EOL 已闭环。
5. 闭环有完整快照和日志。

### 14.6 数据准确性

1. 计算失败不得显示成功。
2. 在途库存不得重复统计。
3. 专用料、共用料分类经过业务样本验算。
4. PSI DOS、清库进度、呆滞库存占比与源系统和业务抽样一致。

### 14.7 销售 PSI 与采购计划

1. PSI 管理弹窗提交审核时，Sell out 总量超过全链路库存硬拦，不保存。
2. PSI 审核组长 / 主管通过时，同一条数量规则硬拦，保持待审。
3. 不出现「超过百分之八异常」；不出现独立的 EOM 复审队列。
4. 预计 EOL 已过只提醒，不挡提交、不挡通过。
5. Forecast / Forecast 审核页面无本期改动。
6. 采购计划创建 Last Buy / 常规量产时提示产品状态、预计 EOL、Last Buy 数量。
7. 产品状态为 EOM 后无法再创建任何采购单；拦截提示同样带出上述三项。
8. 计划确认方案前出现采购单是否已下达的确认弹窗，并列出 Last Buy 数量；取消则不确认。

## 16. 成功标准

本需求不以新增字段数量或页面数量衡量，而以业务是否形成闭环衡量。

上线后，对任意一个 EOM SKU，用户应能在系统中回答：

1. 为什么退市。
2. 由谁发起、谁正在处理。
3. 当前处于哪个业务阶段。
4. 新品何时上市，老品预计何时 EOL。
5. Last Buy 计划、下单、完成情况如何。
6. 当前还剩多少成品库存、呆滞库存和专用料。
7. 清库进度是否符合计划。
8. 清库方案发生过哪些调整。
9. 最终何时、依据什么数据完成 EOL。

## 17. 附录：技术设计

产品口径以本文第 1–16 章为准。下表与接口名为设计建议，最终以开发设计为准。

### 17.1 系统职责

| 系统/服务 | 职责 |
|------|------|
| ms-gtm | EOM 工单、状态机、节点任务、台账、方案版本 |
| 产品/物流主数据 | Model、SKU、品类、场景、国家规格、上市时间 |
| 销售系统 PSI | 产品状态展示、Sell out 全链路硬拦、只读 Last Buy；Forecast 本期不改 |
| 库存/贸易/金蝶 | 成品库存、呆滞库存、入库和在途 |
| ms-scm | BOM、物料分类、物料库存、余料测算、建议下单 |
| 采购计划 | Last Buy 自行下单；准备 EOM 可下、EOM 后禁新建任何采购单 |
| 项目系统 | 迭代新品、CR、上市里程碑 |
| 钉钉 | 待办 / 消息 |
| OA | 仅反 EOM。报废 OA 线下完成，GTM 不集成 |

集成原则：GTM 不复制源系统交易明细，只保存关联 ID、关键快照和汇总指标。动态数据展示当前值；正式 EOM、Last Buy、EOL 等关键事件必须保存快照。跨系统调用支持重试、幂等和失败补偿。自动 EOL 由后端定时任务或事件驱动，不依赖前端。

### 17.2 数据模型建议

不建议将全部台账字段塞入一张宽表。建议至少拆分：

**`eom_case`（工单）**：id、eom_no、eom_type（主动/被动）、business_unit、trigger_reason、current_stage、status、initiator、expected_eol_date、actual_eol_date、created_time、updated_time。

**`eom_case_sku`**：case_id、model、sku、product_snapshot、replacement_flag、replacement_sku、expected_cr_date、replacement_launch_date、product_gtm、region_gtm、expected_eol_date、product_status。

**`eom_task`**：case_id、sku_id（可空表示工单级）、node_code、role_code、assignee、planned_deadline、completed_time、task_status、result。

**`eom_plan_version`**：case_id、version_no、change_reason、effective_time、creator、status、last_buy_qty_sum（无金额）、scrap_fg_sum、scrap_mat_sum。

**`eom_plan_line`**：version_id、sku_id、clear_ways、last_buy_qty（SKU 汇总；渠道数量在渠道/MSKU 明细）、scrap_fg、scrap_mat、conclusion。不存 Last Buy 金额。渠道 Last Buy 按 MSKU 存，实现时可另表或 JSON。

**`eom_plan_file`**：version_id、file_type（gtm / eom / clear）、file_name、file_url。

**`eom_last_buy`**：case_sku_id、planned_order_date、actual_order_time、planned_qty、confirmed_qty、purchase_order_id、order_status、inbound_qty、completed_time。数量来自采购计划实单，不与方案数量互校。

**`eom_inventory_snapshot`**：case_sku_id、snapshot_type（发起、正式 EOM、LB 下单后、LB 完成后、双周、EOL）、snapshot_time、domestic_stock、overseas_stock、purchase_in_transit、total_stock、slow_stock、data_source。

**`eom_material_snapshot`**：case_sku_id、material_code、material_type（专用/EOM 共用/通用）、in_stock_qty、in_transit_qty、amount、currency、snapshot_time。

**`eom_reverse_record`**：case_id、sku_text、psku_text、reason、attachments、pm_users、sales_lead_users、rd_users、review_users、cc_users（无 assistant_users）、oa_process_id、oa_status、tagged_at、closed_at、sku_restored。

物料处置人工进度表、报废决策表本期可不建：专用料进度以库存拉数为准，报废 OA 走线下。

### 17.3 接口建议

本期不做撤回，不下发 `withdraw`。本期不做任务转交，不下发 `transfer`。已反 EOM 关单后 `restart` 必须拒绝。

```text
POST /v2/eom/cases                         新建/保存草稿
POST /v2/eom/cases/{id}/submit             提交
GET  /v2/eom/cases                         查询列表
GET  /v2/eom/cases/{id}                    查询详情
POST /v2/eom/cases/{id}/close              关闭
POST /v2/eom/cases/{id}/restart            重新发起（已反 EOM 关单拒绝）
GET  /v2/eom/models/{model}/skus           查询 Model 全部 SKU
POST /v2/eom/cases/{id}/skus/import        导入 SKU
POST /v2/eom/cases/{id}/skus/validate      完整性及重复校验
GET  /v2/eom/tasks/my                      我的待办（不含清尾三类跟踪）
POST /v2/eom/tasks/{id}/complete           完成节点（核料/方案等须在系统完成的节点）
POST /v2/eom/cases/{id}/plans              新增方案版本
GET  /v2/eom/cases/{id}/plans              查询方案历史
GET  /v2/eom/cases/{id}/last-buy           查询 LB 进度（关联采购计划）
GET  /v2/eom/ledger                        查询台账
POST /v2/eom/ledger/export                 异步导出
POST /v2/eom/cases/{id}/refresh            手动刷新动态数据
GET  /v2/eom/cases/{id}/snapshots          查询历史快照
POST /v2/eom/cases/{id}/reverse            发起反 EOM（创建 OA）；仅 EOM执行 / EOL已闭环
POST /v2/eom/cases/{id}/reverse/callback   OA 回写；通过时关单、打标签、释放 SKU
POST /v2/eom/cases/{id}/eol/check          手动复核 EOL 条件
POST /v2/eom/jobs/eol-close                自动闭环任务
```

销售 PSI：`POST /sell-out/save` 在现有校验后叠加全链路库存硬拦，见 6.14。

### 17.4 现网复用与治理

可直接复用：EOM 产品选择 / 列表详情 / 操作日志、抄送人员、核料模块、SCM EOL 计算（`GtmEolMaterialEnum` + `V2EolServiceImpl.calcMaterialAmount`）、SKU 核料看板部分字段、通用导出、产品状态枚举；销售产品库存看板「在库数量 / 总计库存数量」、金蝶成品库龄看板默认呆滞（`KingdeeInventoryAgeQueryServiceImpl.getDefaultStagnantQty`，>270 天）、Forecast `estimateSales` 与 `getQuantityTotalInStock` / `buildQuantityTotal`（后两者仅对照，台账当前库存不走总计库存）、PSI `PsiCalcServiceImpl.calcDosDaySeries`、采购计划 `PurchasePlanStateEnum`。采购下单：准备 EOM 可下 Last Buy，变为 EOM 后禁新建任何采购单。

必须重构：计划确认后完结的状态机；整单未分类 Excel 表达方案；仅发起人与计划两类权限；工单状态与产品状态混用；用关闭/重发模拟反 EOM。

SCM 接入正式台账前需核验或修复：

1. `GtmEolBatchServiceImpl.updateBatchStatus` 忽略传入状态并固定更新为成功。
2. 物料总库存已含在途后，剩余量计算再次叠加在途。
3. 物料耗尽判定使用「所有物料仍需采购」作为完成条件，与注释语义相反。
4. MSKU DM 结余成本硬编码乘以 0.8。
5. Forecast Client 已引入但计算链路未实际使用。
6. 批次状态枚举、实体注释和业务文档口径不一致。

本地 `ERP_backend` 不含 `ms-gtm` 源码。正式开发前须补充核查：EOM/核料表、产品状态写回、默认责任人、消息待办、下单锁定、EOL 自动闭环、事务与幂等。
