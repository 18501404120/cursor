## 1. 需求背景与目标

### 1.1 背景

EOM 已从阶段性停产确认，调整为常态化退市运营。业务需要覆盖：退市触发、销售预测刷新、核料、清库及 Last Buy 方案确认、正式 EOM、成品清库、Last Buy 执行、专用料清理、反 EOM、S&OP 复盘和 EOL 闭环。

当前 GTM 已支持发起 EOM、选择产品、上传方案附件、计划确认、核料测算和部分导出。计划确认后系统即显示“完结”，后续清尾依赖 Excel、群聊和人工催办。系统无法完整回答：为什么退、谁在处理、处理到哪一步、还剩多少库存和专用料、Last Buy 是否完成、预计何时 EOL。

### 1.2 建设目标

将“核料测算加附件审批”改造为以 EOM 工单为载体、以 8 位 SKU 为最小管理单元的全生命周期退市管理：

1. 区分主动退市和被动退市，按类型生成对应节点。
2. 计划确认后进入 EOM 执行，不得显示业务完结。
3. 前序节点处理完成后通知下一处理人；正式 EOM 后销售、采购、PMC 三路并行清尾。
4. 汇聚产品、预测、库存、Last Buy、物料和清库信息，形成在线台账。
5. 按统一条件自动判定 SKU 是否完成 EOL。
6. 逐步替代线下台账和清尾跟踪表。

### 1.3 目标用户

| 角色 | 主要场景 |
|------|----------|
| 产品 GTM | 发起主动退市，维护新品衔接，确认清库方案，必要时发起反 EOM |
| 区域 GTM | 发起被动退市，维护区域退市原因和产品范围 |
| 需求计划 | 统筹核料、方案、任务交接、台账和 EOL 复核 |
| 销售 | 刷新预测，确认可接受 Last Buy 数量，执行成品清库 |
| 计划 | 参与核料，确认生产与 Last Buy 可执行性 |
| 采购 | 跟踪 Last Buy 下单、生产、在途和入库 |
| PMC | 维护专用料改制、转卖、报废及关闭进度 |
| 计委会 | 通过 OA 决策超金额报废 |
| 管理层 | 查看进度、库存、物料和闭环结果，开展月度复盘 |

### 1.4 上下游

| 方向 | 说明 |
|------|------|
| 上游 | 产品主数据、项目里程碑、核料结果、PSI/预测、库存、SCM 物料、采购订单、OA 审批结果 |
| 下游 | 产品状态写回、采购下单拦截、S&OP 复盘、EOL 闭环通知 |

原则：GTM 负责流程编排、任务交接、台账汇聚和闭环判定；预测、库存、采购、BOM、生产和报废审批继续在原系统执行。

## 2. 功能范围

### 2.1 本期覆盖

1. EOM 工作台。
2. EOM 工单列表、发起、详情、节点任务和操作日志。
3. 主动退市、被动退市分流及产品范围完整性校验。
4. 销售预测刷新、核料关联、核料页按 SKU 确认（导入仅快录）、清库及 Last Buy 方案版本管理。
5. 正式 EOM 后的三路并行执行跟踪：成品清库、Last Buy、专用料清理。
6. EOM 产品在线台账及导出。
7. 反 EOM。
8. EOL 自动闭环及人工复核。
9. 任务完成后通知下一处理人。

### 2.2 本期不做

1. 独立风险预警页，以及风险等级、风险类型、风险处理状态字段。
2. EOM 配置页；SLA、预警阈值、报废金额不做成可配置项。
3. 超期自动升级、到期前提醒、S&OP 风险清单。
4. 重建预测、库存、采购、BOM 等源系统。
5. 在 GTM 内完成报废审批；超金额报废继续走 OA，GTM 只发起并回写结果。
6. 一次性治理全部历史主数据。

业务人员通过预计 EOL、PSI DOS、当前库存、呆滞库存、清库进度、Last Buy 状态和专用料数量判断是否需要跟进。

### 2.3 已确认口径

1. DOS 完全复用现网 PSI，不另算“库存÷平均日销”。
2. Last Buy 时间拆分为计划时间、实际下单时间、完成时间。
3. 专用料数量为 0 才允许 EOL；金额只用于展示和管理。
4. 成品报废超过 50 万元、物料报废超过 20 万元时，由 GTM 发起 OA 并同步结果。
5. 前序任务完成后通知下一处理人；正式 EOM 后三类清尾任务并行处理。
6. 核料以页面直改和按 SKU 确认为主；计划负责人、结论按 MSKU；工单「确认」只跳转核料页；导入只用于快录。全部 SKU 确认后自动定版。

## 3. 总体流程

### 3.1 主动退市

```text
新品达到 GR1
  → 产品GTM发起主动EOM，SKU进入准备EOM，通知销售
  → 销售刷新预测并填写可接受Last Buy数量，完成后通知需求计划
  → 需求计划组织核料并定版，完成后通知方案确认角色
  → 确认清库及Last Buy方案
  → 工单进入EOM执行，SKU进入EOM
  → 同时通知销售清成品、采购跟踪Last Buy、PMC清专用料
  → 三路完成后通知需求计划复核EOL条件
  → 满足条件后SKU自动进入EOL；工单全部SKU闭环后工单进入EOL已闭环
```

主动退市可维护新老品切换关系。BOM 已禁用且需追加 Last Buy 时，必须走反 EOM，不得用撤回、关闭或重新发起代替。

### 3.2 被动退市

```text
区域GTM按标准原因发起
  → 销售刷新预测
  → 核料
  → 确认清库及Last Buy方案
  → 正式EOM
  → 销售、采购、PMC并行清尾
  → EOL闭环
```

被动退市不要求维护新老品切换计划，原则上不出现反 EOM 节点；确需追加 Last Buy 时按专项异常处理。

LBU：月初统一评审，特殊事项可实时发起。  
ABU：每月预排查，季度统一正式发起；产品 GTM 承接区域 GTM 和需求计划职责。

被动退市标准原因：生命周期衰退、销量流速下滑且 DOS 过高、利润持续下降、营销销售费用超出、无法满足供应链起订量、法律法规不允许继续销售、组件或软件不可获得且无法替代、其他。选择“其他”必须补充说明。

### 3.3 固定时限

按业务规范写死，不做配置页：

| 节点 | 主动退市 | 被动退市 |
|------|----------|----------|
| 发起 EOM | 新品达到 GR1 | 月度评审 week-0 |
| 核料完成 | GR1 后 7 个工作日 | week-1 |
| 清库方案确认 | GR1 至 GR2 | week-3 |
| 清尾进度更新 | 每 14 个自然日 | 每 14 个自然日 |
| S&OP 复盘 | 月度 | 月度 |

## 4. 状态与任务

### 4.1 三类状态分开管理

1. 工单阶段：表示业务流程走到哪里。
2. 产品状态：表示 SKU 生命周期。
3. 节点任务状态：表示责任人是否完成动作。

不得用一个“状态”同时表达三种含义。

### 4.2 工单阶段

| 阶段 | 进入条件 | 退出条件 |
|------|----------|----------|
| 草稿 | 新建未提交 | 提交或关闭 |
| 启动 EOM | 提交成功 | 销售完成预测刷新并发起核料；或发起人撤回/关闭 |
| 核料中 | 核料任务已创建 | 该单全部 SKU 确认核料结论后自动定版 |
| 待方案决策 | 核料定版 | 清库及 Last Buy 方案确认；或方案驳回回核料中 |
| EOM 执行 | 方案正式确认 | 进入清尾跟踪 |
| 清尾中 | 库存或物料开始清理 | 满足 EOL 条件 |
| EOL 已闭环 | 工单内全部 SKU 满足闭环条件 | 终态 |
| 已关闭 | 草稿或启动 EOM 时发起人关闭 | 重新发起：原单回草稿，流水号不变 |

撤回仅允许从「启动 EOM」回到草稿，草稿本身没有撤回。关闭仅允许「草稿、启动 EOM」，必须填写原因并写入日志。核料中及之后不可撤回、关闭。

撤回或关闭时，若 SKU 已是「准备 EOM」，必须释放回提交前的原产品状态（已上市/未上市），解除进行中占用。重新发起沿用原工单、原流水号，关闭原因与历史日志保留；再次提交后才重新进入准备 EOM。

方案驳回仅允许发生在尚未正式 EOM 的「待方案决策」：回到核料中，挂异常「已驳回」，**整单**核料结论解锁。节点任务驳回只改任务状态，工单阶段不变，**不允许**核料中退回启动 EOM。

正式 EOM 后的方案变更必须会签并生成新版本，工单阶段不退回待方案决策，产品状态仍为 EOM。BOM 已禁用且需追加 Last Buy 必须走反 EOM，不得用方案改版、撤回、关闭或重新发起代替。

方案确认后必须进入 EOM 执行，不得显示业务完结。现网「完结」仅作映射。

本期可并行存在的异常标识：已驳回、反 EOM 中、数据异常。「已暂停」本期不做。异常标识不替代主阶段。

### 4.3 SKU 产品状态

| 产品状态 | 触发条件 |
|----------|----------|
| 未上市 | 主数据尚未上市 |
| 已上市 | 正常销售 |
| 准备 EOM | EOM 工单正式提交 |
| EOM | 清库及 Last Buy 方案正式确认 |
| EOL | 成品库存为 0、专用料数量为 0、无未完成 Last Buy 或在途、无执行中反 EOM |

未上市且无销售记录的 SKU 提示主数据治理，不强制走完整清库。已 EOL 或已有进行中 EOM 的 SKU 不得发起。撤回、关闭后占用解除，允许再发起或原单再提交。

方案驳回、方案改版、反 EOM 均不回拨产品状态：驳回后仍为准备 EOM，改版和反 EOM 后仍为 EOM。反 EOM 执行中不得进入 EOL。

### 4.4 节点任务

任务状态：待处理、处理中、已完成、已驳回、已转交。

正式 EOM 前串行交接：当前人完成后生成并通知下一人。  
正式 EOM 后并行执行：销售清成品、采购跟踪 Last Buy、PMC 清专用料；任一任务完成后通知需求计划更新整体进度。

每个任务需包含：所属工单和 SKU 范围、任务名称、责任角色、责任人、计划完成时间、实际完成时间、处理结果、附件、驳回原因、转交记录。

驳回必须填写原因。方案驳回退回核料中并整单解锁；节点任务驳回记录原因并通知上一处理人，不改变工单阶段。转交必须记录原责任人、新责任人、原因和时间。

### 4.5 现网流程状态对照

| 现网 | 2.0 工单阶段 |
|------|----------------|
| 待提交 | 草稿 |
| 待计划确认 | 启动 EOM / 核料中 / 待方案决策 |
| 计划驳回 | 核料中 + 异常「已驳回」 |
| 已关闭 | 已关闭 |
| 完结 | EOM 执行 / 清尾中 / EOL 已闭环（页面展示真实阶段，不得显示完结） |

规则说明页：GTM → 管理 → 规则 → 状态流转。

## 6. 分页面需求

### 6.1 EOM 工作台

改动位置：GTM → 管理 → EOM 管理 → EOM 工作台

展示内容：

1. 进行中工单数、待我处理数、EOM 执行中 SKU 数、清尾中 SKU 数、清库达成率、专用料关闭率、本月新增 EOM SKU 数、本月完成 EOL SKU 数。
2. 按工单阶段、责任部门、主动/被动退市分布。
3. 我的待办：当前登录人待处理任务，可进入工单或直接处理。
4. 清尾产品进度：展示当前库存、清库进度、PSI DOS、Last Buy 进度、专用料剩余数量，点击进入产品台账或工单详情。
5. 所有指标标明统计范围和数据更新时间。

点击指标或图表后，进入对应筛选结果。不展示风险等级、超期任务数、风险 SKU 数。

### 6.2 EOM 工单列表

改动位置：GTM → 管理 → EOM 管理 → EOM 工单

筛选：EOM 流水号、核料流水号、Model、SKU、退市类型、退市原因、责任人、工单阶段、产品状态、发起时间、预计 EOL、实际 EOL。

列表字段：EOM 流水号、退市类型、发起人、Model/SKU 数量、当前阶段、当前责任人、发起时间、预计 EOL、清库进度、专用料关闭率、方案版本、操作。

不展示超期状态、风险等级。

操作：发起 EOM、批量导入 SKU、导出台账、查看、编辑、确认（核料中且我是计划负责人时，跳转核料页）、撤回、关闭、重新发起、当前节点处理、发起反 EOM、查看日志。撤回仅「启动 EOM」，并释放 SKU 准备 EOM 占用；关闭仅「草稿、启动 EOM」，须填原因；重新发起为原单回草稿、流水号不变。

列表阶段必须反映真实执行进度。核料中工单上的「确认」跳转到核料信息详情，不在工单上提交确认，也不得把工单标成业务完结。方案确认后显示 EOM 执行或清尾中，不得显示完结。

「计划确认人员」列展示由核料行计划负责人自动带出的名单，以及确认进度（已确认 SKU / 本单 SKU）。

### 6.3 发起 EOM

改动位置：EOM 工单 → 发起 EOM

分五步：

**第一步：退市类型**

- 业务单元：LBU / ABU。
- 退市类型：主动退市 / 被动退市。
- 发起节点：主动默认为 GR1，被动默认为月度评审 week-0；均可选择特殊事项实时发起。
- 退市原因：按类型带出标准原因；选择“其他”必须填写说明。
- 被动退市可选择多项原因。

**第二步：产品范围**

- 按 Model 带出全部有效 8 位 SKU。
- 支持按 SKU 搜索、Excel 导入、全选。
- 排除 SKU 必须填写排除原因，未填不得进入下一步。
- 已 EOL、已存在进行中 EOM 的 SKU 不允许提交。
- 未上市且无销售记录的 SKU 提示进入主数据治理，不强制走完整清库流程。
- 导入需逐行反馈成功或失败原因；单行失败不影响其他有效行。

**第三步：退市计划**

- 预计 EOL 时间必填。
- 主动退市展示是否新品迭代、迭代新品 SKU、新品预计 CR 时间、新品上市时间、预测覆盖时间。
- 被动退市默认隐藏新品衔接字段。
- 支持上传附件和填写备注。

**第四步：责任人**

系统自动带出产品 GTM、区域 GTM、需求计划、销售负责人、计划负责人、PMC 对接人、采购对接人。允许有权限人员调整，并记录调整日志。缺失责任人不得提交。

**第五步：提交确认**

提交前展示：SKU 范围完整性、重复工单、产品状态、必填信息、责任人、主数据缺失。存在阻断项时不允许提交，并提示具体 SKU 和原因。

提交后：

1. 生成 EOM 工单和 SKU 台账。
2. 相关 SKU 产品状态更新为准备 EOM。
3. 生成销售预测刷新任务，并通知销售。

支持保存草稿。草稿仅发起人可继续编辑。

### 6.4 工单详情

改动位置：EOM 工单 → 查看 / 处理

结构：概要 + 流程时间轴 + SKU 台账 + 执行跟踪 + 节点任务 + 清库方案 + 操作日志。

**概要**：退市类型、业务单元、发起人、发起时间、预计 EOL、当前阶段、当前责任人、Model/SKU 数、清库进度、专用料关闭率、核料单号、当前生效方案、当前执行事项。不展示风险摘要。

**流程时间轴**：展示全部节点、责任角色、计划/实际完成时间、处理结论和附件。正式 EOM 节点需标明销售、采购、PMC 并行处理。

**SKU 台账**：按 8 位 SKU 展示产品状态、新品 SKU、Last Buy 数量和状态、当前库存、呆滞库存、专用料数量和金额、近三月销量、预计 EOL 前预测、PSI DOS、清库进度。支持展开渠道、库存、Last Buy、物料和预测明细。不展示风险列。

**执行跟踪**：正式 EOM 后展示三路进度：

1. 销售 · 成品清库：基准库存、当前库存、清库进度、PSI DOS。
2. 采购 · Last Buy：计划时间、下单时间、完成时间、计划数量、已生产/已入库数量。
3. PMC · 专用料清理：剩余项数、金额、处理方式、完成条件为数量为 0。

同时展示 EOL 闭环条件及当前是否满足。任一条件未满足时不得闭环，并写明未满足原因。

**节点任务**：正式 EOM 前按串行节点展示；正式 EOM 后展示三类并行任务。处理人可提交结果、说明和附件。完成后系统通知下一处理人或需求计划。

**清库方案**：结构化维护并保留版本。每个版本记录变更原因、变更内容、决策人、生效时间、关联附件。各角色默认执行当前生效版本。

**操作日志**：记录关键操作、操作人、时间、变更前值和变更后值。

### 6.5 节点任务处理

改动位置：工单详情 / 工作台待办 → 处理当前任务

处理人填写处理状态、处理结果、本次更新时间和附件或关联单据。选择“已完成”后：

1. 串行节点：关闭当前任务，生成下一任务并通知下一处理人。
2. 并行清尾任务：关闭当前任务，通知需求计划复核整体进度。
3. 驳回：必须填写原因。方案驳回仅「待方案决策」可退回核料中并整单解锁。节点任务驳回退回指定前序任务并通知上一处理人，**不改变工单阶段**，不允许核料中退回启动 EOM。
4. 转交：记录原责任人、新责任人、原因和时间，并通知新责任人。

销售预测刷新任务需展示当前有效预测、近三个月销量、当前库存和 PSI DOS；销售确认或更新预测，并填写可接受 Last Buy 数量。每次提交保存版本和提交时间。预测缺失或刷新失败时标识数据异常，不得带入方案决策。

核料任务可创建或关联核料单，展示建议 Last Buy 数量、成品库存、专用料、通用料、物料结余和供应商额外备料。核料结果需标识计算时间和版本。计算失败不得显示为成功。计划人员在核料页按 SKU 填写并确认结论；工单「确认」只跳转核料页。全部 SKU 确认后自动定版，进入方案确认。详见 6.11。

### 6.6 清库及 Last Buy 方案

改动位置：工单详情 → 清库方案 → 新增方案版本

结构化填写：

1. 清库方式：正常销售、降价、渠道调拨、改制、转卖、报废，可多选。
2. Last Buy 计划时间、数量和执行要求。
3. 成品库存处理方案、专用物料处理方案、责任部门、费用归属、预计 EOL。
4. 成品报废金额、物料报废金额。

方案需由销售、计划、PMC、采购和需求计划按职责确认。全部确认后生效，工单进入 EOM 执行，SKU 进入 EOM，并固化正式 EOM 时的库存、预测和物料基准快照。

报废金额判断按固定规则：

- 成品报废不超过 50 万元：GTM 决策。
- 成品报废超过 50 万元：发起 OA，一级计委会决策。
- 物料报废不超过 20 万元：PMC 执行。
- 物料报废超过 20 万元：发起 OA，一级计委会决策。

GTM 不完成审批，只发起 OA 并回写结果。审批未返回前，方案不得正式生效，工单停在待方案决策。不同意报废时，退回 GTM 重新制定清理方案，工单不关闭、不退回核料中。

方案变更必须生成新版本，记录变更原因、变更内容、决策人和生效时间。正式 EOM 后改版必须会签，工单阶段不退回待方案决策，产品状态仍为 EOM。BOM 已禁用且需追加 Last Buy 必须走反 EOM，不得用方案改版代替。

### 6.7 正式 EOM 后执行

方案确认后同时生成三类并行任务，并通知对应责任人。

**成品清库**

- 每日刷新全链路成品库存。
- 展示正式 EOM 或 Last Buy 完成后的基准库存、当前库存、清库进度、呆滞库存及占比、近三月销量、当前预测、预计 EOL 前总预测、PSI DOS。
- 每 14 个自然日固化一次清尾快照。
- 销售可记录降价、调拨及其他清库动作和结果。

**Last Buy 跟踪**

- 展示计划数量、确认数量、实际下单数量、实际入库数量。
- 分别展示计划时间、实际下单时间、完成时间。
- 展示未发起、待下单、生产中、入库中、已完成。
- 支持关联采购或生产记录。
- Last Buy 下单后、完成后分别保存库存快照。
- 已审批 Last Buy 不受普通 EOM 下单拦截阻断。
- 未完成的 Last Buy 不允许进入 EOL。

**专用料清理**

- Last Buy 及在途订单全部入库后，PMC 必须维护专用料处理进度。
- 展示专用料、通用料的数量和金额。
- 维护改制、转卖、报废的计划数量、实际数量、金额和进度。
- 涉及报废时关联 OA 审批单及结果。
- 专用料数量不为 0 时，不允许 SKU 完成 EOL。
- 物料分类或数据异常时提供人工复核入口。

### 6.8 反 EOM

改动位置：工单详情 → 发起反 EOM

仅 BOM 已禁用且需要追加 Last Buy 时可发起。必须关联原工单和具体 SKU，填写原因、追加数量、影响范围和预计完成时间。

流程：GTM 发起 → 计划确认 BOM 状态 → 审批追加 Last Buy 数量 → 临时解除 BOM 禁用 → 跟踪 MRP、采购、生产和入库 → 全部入库后重新禁用 BOM → 恢复原清尾流程。

反 EOM 执行中不得完成 EOL。不得以撤回、关闭或重新发起普通 EOM 代替。

### 6.9 EOL 闭环

同时满足以下条件时，SKU 自动由 EOM 切换为 EOL：

1. 成品全链路库存为 0。
2. 专用料数量为 0。
3. 不存在未完成的 Last Buy 或在途订单。
4. 不存在执行中的反 EOM。

闭环时记录实际 EOL 时间和触发数据快照，关闭未完成的普通监控任务，并通知 GTM、需求计划、销售、计划、PMC 和采购。

自动闭环失败时展示未满足条件，支持重试和人工复核。人工闭环必须填写原因并记录日志。

工单内全部 SKU 均完成 EOL 后，工单才进入 EOL 已闭环。

### 6.10 EOM 产品台账

改动位置：GTM → 管理 → EOM 管理 → EOM 产品台账

支持按工单、SKU、Model 查看，展开 MSKU、渠道、平台、线上/线下。支持自定义列、冻结关键列、导出当前筛选结果、导出业务标准模板。动态指标显示数据来源和更新时间。页面与导出口径一致。

不展示风险列。管理字段增加：EOM 流水号、退市类型、退市原因、当前工单阶段、当前责任人、实际 EOL 时间、数据更新时间。不增加是否超期、风险等级、风险类型。

### 6.11 核料结论填写、页面确认与导入快录

改动位置：核料信息详情、EOM 工单列表「确认」、工单「计划确认人员」

吸收 CKW-002「核料完成后统一模板导入」。导入只用于快速录入，**不能替代**核料页直改和按 SKU 确认。本期只保留 **按当前工单** 导入，不另做混单导入。

#### 6.11.1 字段粒度

核料详情按 Model → SKU → MSKU 展开。与现网表一致：列 1～原因按 SKU 合并；**计划负责人、结论不合并，按 MSKU 行**。

| 字段 | 粒度 | 口径 |
|------|------|------|
| 下单后最快交付时间 | SKU | 天数（整数），不是日期 |
| 最终下单数量 | SKU | 可为 0（不补单） |
| 最终报废金额 | SKU | 可为 0 |
| 原因 | SKU | MOQ物料结余 / 销售需求变化 / 供应链需求外风险备料 / 物料报废金额小于等于2万 |
| 计划负责人 | MSKU | 只读，来自主数据；无主时计划部门负责人兜底 |
| 结论 | MSKU | lastbuy后报废 / 不补单报废；各店铺可不同 |

库存、店铺、日销、DM 结余、售完日期为 MSKU 行。

**主路径是页面直改**：SKU 字段编一次；结论按 MSKU 各编。导入和页面编辑均不改「建议下单」「锁定建议下单」。

勾选单位为 **8 位 SKU**：多 MSKU 合并成一行勾选，不得按店铺行勾选。确认前该 SKU 下全部 MSKU 结论必须已填。

#### 6.11.2 计划负责人与「我负责」

1. 「我负责某 MSKU」= 该行计划负责人 = 当前登录人。
2. 「我负责某 SKU」= 该 SKU 下至少一条 MSKU 的计划负责人是我。具备后可勾选确认该 SKU。
3. 计划负责人按 MSKU 展示。主数据可落到 MSKU；未落到 MSKU 时回退该 SKU 第一负责人。
4. 核料计算完成时，仍无负责人的 MSKU 统一指定为 **计划部门负责人**，并标记来源为 leader 兜底。
5. 主数据随后维护了该 MSKU 或 SKU 的计划负责人后，系统自动刷新为维护后的人，不再用 leader。若该 SKU 已确认锁定，刷新后解锁，改由新负责人填写并确认。
6. 工单「计划确认人员」按核料行计划负责人去重自动带出。该 SKU 下任一 MSKU 的计划负责人可勾选确认该 SKU，但须该 SKU 下全部 MSKU 结论已填。

#### 6.11.3 按工单导出 / 导入

导入只写入，**不自动确认**。一次只处理 **一个 EOM 工单**。模板 **一行一个 MSKU**。

模板列：EOM流水号、核料流水号、8位SKU、MSKU、计划负责人（只读）、下单后最快交付时间（天）、最终下单数量、最终报废金额、原因、结论。

数量/金额/原因/交付时间按 SKU 覆盖；结论只写该 MSKU。同一 SKU 有多个 MSKU 时必须填 MSKU。

导出：默认只导出当前登录人负责的 MSKU。可勾选「导出本单全部」，他人行仅供对照。

导入匹配：SKU/MSKU 必须属于当前工单核料单。填写了 EOM 流水号或核料流水号时，必须与当前工单一致。禁止混单。

导入权限与结果：

1. 只覆盖「该 MSKU 计划负责人 = 当前用户」且该 SKU 尚未确认的行。
2. 他人行跳过，在导入结果中列出，不导致整单失败。
3. 单行失败不影响其他有效行。
4. 核料已定版、计算失败、草稿、无核料单、或工单已过核料节点：禁止导入。
5. 已确认锁定的 SKU：该行失败，不得覆盖。

#### 6.11.4 确认入口与按 SKU 确认

**工单列表「确认」**：现网同名按钮保留。展示条件：工单阶段为核料中、核料计算成功、当前用户是该单计划确认人员之一。点击后跳转该工单关联的核料信息详情，**不在工单上提交确认**。

**核料信息页「确认所选 SKU」**：

1. 勾选我负责且尚未锁定的 8 位 SKU，可单条或批量。
2. 若该 SKU 的数量/金额/原因/交付时间未填，或该 SKU 下任一 MSKU 结论为空：提醒后该 SKU 不得确认。
3. 已填齐的所选 SKU：锁定；工单阶段不变，仍为核料中 / 待计划确认。
4. 列表进度为「已确认 SKU / 本单 SKU」。确认部分 SKU ≠ 整单完结，也 ≠ 进入待方案决策。
5. 该单全部 SKU 都确认后：核料自动定版，工单进入待方案决策，再走清库及 Last Buy 方案确认。方案确认后进入 EOM 执行，现网状态才映射为「完结」，2.0 不得显示业务完结。
6. 定版后全员只读。仅整单被驳回后解锁，允许再次填写、导入和确认。

权限沿用现网：核料结论编辑 / 导入 `gtm:manage:materialInfo:deliveryTime`；确认 `gtm:manage:eomProcess:plan`。资格以核料行计划负责人为准。

### 6.12 状态流转规则页

改动位置：GTM → 管理 → 规则 → 状态流转

只读说明页，用静态图 + 表展示 2.0 状态机，并对照现网。不改数据、不跳转工单。本期五块：

1. 工单阶段主路径。
2. 撤回 / 关闭 / 重新发起 / 方案驳回等非主路径；核料页按 SKU 确认。
3. 方案变更与反 EOM：会签留版本、阶段不退回；BOM 已禁用追加 LB 走反 EOM。
4. 产品状态：未上市 → 已上市 → 准备 EOM → EOM → EOL；撤回/关闭释放准备 EOM。
5. 异常标识：已驳回、数据异常、反 EOM 中。不含已暂停，不含核料单四态。

### 7.3 指标口径

**EOM 时长**

- 未闭环：当前日期 − 发起 EOM 时间。
- 已闭环：实际 EOL 时间 − 发起 EOM 时间。

**呆滞库存占比**

呆滞库存数量 ÷ 当前总库存数量。当前总库存为 0 时显示 0%，并标记计算时间。

**PSI DOS**

不单独计算。直接读取现网 PSI：当日期末库存从次日起逐日扣减未来 Sell out 预测，得到可覆盖天数。期初海外可用库存不含在途；后续推演按 PSI 规则叠加在途到货和 Sell through。周、月取周期最后一天。零预测日及其他边界完全沿用 PSI。

**清库进度**

- 有 Last Buy：以 Last Buy 完成后的基准库存为起点。
- 无 Last Buy：以正式 EOM 时的基准库存为起点。
- 进度 =（基准库存 − 当前库存）÷ 基准库存。
- 基准库存为 0 且当前库存为 0：进度 100%。
- 基准库存为 0 且当前库存大于 0：标记基准异常，不直接计算。

**专用料关闭率**

（正式 EOM 时专用料基准金额 − 当前专用料金额）÷ 正式 EOM 时专用料基准金额。数量和金额均保留；工作台默认按金额展示。EOL 判定只看数量是否为 0。

### 7.4 数据分类

1. 主数据：发起时保存快照，不随源数据覆盖。
2. 动态指标：库存、预测、销量、PSI DOS、物料定时刷新，必须显示数据时间。
3. 业务事件：发起、正式 EOM、Last Buy 下单、Last Buy 完成、实际 EOL 保存不可变快照。
4. 人工决策：退市原因、清库方案、报废决策、备注保留版本。

通知时机：

1. 当前任务完成后，通知下一处理人。
2. 节点驳回后，通知上一处理人。
3. 正式 EOM 后，同时通知销售、采购、PMC。
4. 并行任务完成后，通知需求计划。
5. 超金额报废 OA 返回结果后，通知方案相关人员。
6. EOL 闭环后，通知全流程相关角色。

不做到期前提醒、超期自动升级和 S&OP 风险清单。通知需能直接进入对应工单或任务。

## 9. 权限

### 9.1 功能权限

| 能力 | 说明 |
|------|------|
| 查看工单和台账 | 有数据权限的用户可查看 |
| 发起 EOM | 产品 GTM 发起主动退市，区域 GTM 发起被动退市；ABU 由产品 GTM 承接 |
| 编辑草稿及方案 | 发起人可编辑草稿和被驳回工单；有方案权限的人可维护方案 |
| 处理本角色任务 | 仅当前责任人可处理本人任务 |
| 发起反 EOM | 仅授权 GTM |
| 人工复核 EOL | 仅需求计划及授权管理人员 |
| 导出台账 | 授权人员 |
| 查看全流程 | 需求计划和管理层 |

### 9.2 数据权限

- 产品 GTM：负责产品线范围。
- 区域 GTM：负责区域或渠道范围。
- 销售：负责渠道或店铺范围。
- 计划、PMC、采购：按 SKU 或物料责任关系。
- 需求计划：全量台账。
- 管理层：全量只读。

关键字段修改和人工闭环必须记录日志。

## 10. 系统边界与数据刷新

GTM 不复制源系统交易明细，只保存关联单据、关键快照和汇总指标。

| 数据 | 来源 | 刷新方式 |
|------|------|----------|
| 产品、场景、品类、国家规格、上市时间 | 产品主数据 | 发起时快照，后续可手工核对 |
| 新品 CR、上市时间 | 项目系统 | 自动带出，允许调整并留痕 |
| 近三月销量、Sell out 预测、PSI DOS | 销售预测 / PSI | 每日或预测版本发布后刷新 |
| 成品库存、呆滞库存、在途 | 库存服务 | 每日，支持手动刷新 |
| 专用料、通用料、建议 Last Buy | 核料 / SCM | 核料定版及每日刷新 |
| Last Buy 订单及入库 | 采购 / 生产 | 每日或订单事件触发 |
| 报废审批结果 | OA | 审批完成后回写 |
| 清库进度、专用料关闭率 | GTM 计算 | 每日计算，每 14 个自然日固化快照 |
| EOL 条件检查 | GTM | 每日自动检查 |

库存、预测、BOM 或物料获取失败时，显示数据异常，不得用错误结果自动闭环，也不得把失败计算显示为成功。

## 11. 异常与边界

1. 新品项目取消后，支持暂停、调整或转为被动退市，具体规则待确认。
2. 新品延期或老品积压时，通过新增清库方案版本处理，不生成风险工单。
3. BOM 禁用后追加 Last Buy 必须走反 EOM。
4. EOM 工单关闭或暂停时必须填写原因，并处理未完成任务。
5. 历史迁移后无法还原的指标必须明确标识，不得伪造历史快照。
6. EOM 后是否允许特批普通下单待确认；未确认前，仅放行已审批 Last Buy 和反 EOM 追加数量。

## 12. 分期实施

### 12.1 第一期：口径与入口

1. 修正台账字段名称和粒度。
2. 增加主动/被动退市和退市原因。
3. Model 带出全部有效 8 位 SKU，支持全选、排除原因和导入导出。
4. 将“计划确认后完结”改为“进入 EOM 执行”。
5. 核料在核料页按 SKU 勾选确认；计划负责人、结论按 MSKU；导入只用于快录；全部 SKU 确认后自动定版。
6. 核验核料和 SCM 计算结果，失败不得显示成功，在途不得重复统计。

### 12.2 第二期：在线台账与任务流

1. 新工单阶段和产品状态分离。
2. 串行节点任务及完成后通知下一人。
3. 结构化清库方案和版本。
4. Last Buy 三个时间和执行状态。
5. 库存、预测、物料自动回填和双周快照。
6. 正式 EOM 后三类并行任务。
7. EOL 自动闭环。
8. ABU 流程适配。

### 12.3 第三期：执行闭环

1. Last Buy 订单、生产和入库明细联动。
2. 物料改制、转卖、报废及 OA 回写。
3. 反 EOM 全过程。
4. S&OP 复盘视图。
5. 历史数据迁移和主数据治理。

独立风险预警页、风险字段、配置中心和超期自动升级不纳入以上三期。后续如仅靠台账无法有效识别异常，再单独立项。

---

## 13. 数据迁移

迁移范围：进行中的 EOM 流程、准备 EOM/EOM 状态 SKU、已有核料单、线下台账、清库方案附件、未完成 Last Buy。

规则：

1. 已关闭流程迁为历史记录，不生成待办。
2. 原“完结”不得一律视为 EOL：
   - 产品已 EOL：迁为闭环。
   - 产品仍为 EOM：迁为清尾中。
   - 产品仍为准备 EOM：进入人工核查。
3. 缺失 SKU、Model、责任人的记录进入数据异常清单。
4. 线下台账导入前校验 SKU、日期、库存和状态。

上线建议：历史数据初始化 → 新旧台账并行两周 → 核对库存、预测、物料口径 → 停止线下新增 → GTM 作为唯一正式台账。

---

## 14. 验收标准

### 14.1 发起

1. 能区分主动退市和被动退市。
2. 按 Model 发起时能带出全部有效 8 位 SKU。
3. 排除 SKU 未填原因不得进入下一步。
4. 已 EOL 或已存在进行中 EOM 的 SKU 无法提交。
5. 批量导入能反馈逐行结果。
6. 提交后 SKU 进入准备 EOM，并通知销售刷新预测。

### 14.2 流程

1. 主动、被动按固定规则生成不同节点。
2. 每个节点有责任人、截止时间和处理记录。
3. 核料中工单「确认」跳转核料页；在核料页按 SKU 勾选确认。该 SKU 下 MSKU 结论等为空则提醒。确认后工单不显示完结。全部 SKU 确认后核料定版，进入待方案决策。方案确认后进入 EOM 执行，而不是完结。
4. 核料结论以页面直改为主，可按当前工单导入快录，一行一个 MSKU；数量/金额/原因按 SKU，结论按 MSKU。
5. 当前任务完成后自动通知下一处理人。
6. 正式 EOM 后同时生成销售、采购、PMC 三类并行任务。
7. 方案驳回必须填写原因，退回核料中并整单解锁；节点任务驳回不改变工单阶段，不允许核料中退回启动 EOM。

### 14.3 台账

1. 业务确认字段均可查看和导出。
2. 动态指标展示来源和更新时间。
3. 关键事件保留不可变快照。
4. 支持按 SKU、Model、工单查看，并可展开渠道明细。
5. 页面与导出口径一致。
6. 不出现风险等级、风险类型字段。

### 14.4 Last Buy 与物料

1. 可分别查看计划时间、下单时间、完成时间。
2. 能从计划跟踪到入库完成。
3. 下单及完成后自动保存库存快照。
4. 已审批 Last Buy 不被普通下单拦截阻断。
5. 专用料数量不为 0 时不得 EOL。

### 14.5 EOL

1. 成品库存为 0、专用料数量为 0、无未完成 Last Buy 或在途、无反 EOM，四项同时满足才闭环。
2. 未满足时展示具体原因。
3. 自动闭环失败可重试，并支持人工复核。
4. 工单内全部 SKU 闭环后，工单才显示 EOL 已闭环。
5. 闭环有完整快照和日志。

### 14.6 数据准确性

1. 计算失败不得显示成功。
2. 在途库存不得重复统计。
3. 专用料、共用料分类经过业务样本验算。
4. PSI DOS、清库进度、呆滞库存占比与源系统和业务抽样一致。

## 16. 成功标准

本需求不以新增字段数量或页面数量衡量，而以业务是否形成闭环衡量。

上线后，对任意一个 EOM SKU，用户应能在系统中回答：

1. 为什么退市。
2. 由谁发起、谁正在处理。
3. 当前处于哪个业务阶段。
4. 新品何时上市，老品预计何时 EOL。
5. Last Buy 计划、下单、完成情况如何。
6. 当前还剩多少成品库存、呆滞库存和专用料。
7. 清库进度是否符合计划。
8. 清库方案发生过哪些调整。
9. 最终何时、依据什么数据完成 EOL。
