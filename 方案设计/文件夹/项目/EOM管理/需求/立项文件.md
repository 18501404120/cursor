## 一、项目背景

EOM 已由阶段性的停产确认工作，转变为**常态化的产品退市运营工作**：LBU 按月评审、实时发起，ABU 月度预排查、季度统一发起。业务需要管理的是一个完整过程——退市触发 → 核料 → 清库及 Last Buy 方案 → 正式 EOM → 库存/物料清理 → 反 EOM → S&OP 复盘 → EOL 闭环。

而当前 GTM 系统本质仍是"核料测算 + 附件审批"：**计划确认后系统即显示"完结"**，后续清库、Last Buy、物料清理和 EOL 闭环全部依赖 Excel 台账、钉钉群聊和人工催办。由此产生四类核心问题：

1. **状态失真**：系统显示"完结"时，业务才刚进入正式 EOM 执行，清库超期、物料未清等风险被隐藏。
2. **台账线下化**：产品、预测、库存、Last Buy、物料数据分散在多系统和线下表格，需求计划反复导数拼表，口径不一致、无法复盘。
3. **协同无责任链**：销售、计划、PMC、采购等角色任务在线下分配，靠人催办，无留痕、无预警。
4. **无真实闭环**：没有以"成品全链路库存清零"自动判定 EOL，关单靠人工跨系统核对。

## 二、项目价值

### 2.1 核心价值：把钱省下来

- **降低库存损失**：对新品延期、老品断货、库存积压、呆滞库存、专用料未清等风险提前预警，让 Last Buy 与清库方案可以及时调整，直接减少报废和积压金额。
- **保障新老品平稳切换**：新品里程碑、老品库存、预测联动管理，避免"老品断货丢销售"和"新品上市老品积压"两头受损。

### 2.2 效率价值：把人解放出来

- **退市全程在线化**：从发起到 EOL 全程可视，节点完成自动通知下一处理人，替代群聊催办，缩短 EOM 周期。
- **需求计划不再拼表**：在线台账自动汇聚预测、库存、Last Buy、物料数据，需求计划从"导数、拼表、核对、催办"转向风险分析和业务推动。
- **各角色任务清晰**：每个节点有明确责任人、完成时限和完成标准，"何时、为哪个产品、做什么"一目了然。

### 2.3 管理价值：让经营看得见

- **统一口径**：流程、角色职责、数据口径、闭环标准全部统一，页面、导出、复盘同一套数。
- **决策可追溯**：清库方案、Last Buy、报废决策、反 EOM 全程留痕，关键节点保存不可变快照，审计链完整。
- **复盘有依据**：管理层可直接查看进度、风险、金额和超期原因，支持按组织、品类、区域、退市原因复盘，为产品组合和库存策略优化提供数据基础。

### 2.4 可衡量的预期收益

上线后持续观测：线下台账替代率、节点按时完成率、平均 EOM 周期、清库达成率、专用料关闭率、呆滞库存金额变化、人工催办次数及台账整理工时变化、EOL 自动闭环率。基准值与目标值上线前由业务确认。

## 三、改动点

### 3.1 流程重构（核心改动）

将"计划确认即完结"改为覆盖退市全过程的工单阶段：**草稿 → 核料中 → 待方案决策 → EOM 执行 → EOL 已闭环**，计划确认后不再显示业务完结；同时结构化区分**主动退市 / 被动退市**，按类型生成对应业务节点。

### 3.2 功能改动

| 模块 | 改动内容 |
| --- | --- |
| 发起 | 主动/被动退市分流；产品范围改为搜索找货 + 已选清单；按 8 位 SKU 维护新品衔接与预计 EOL；完整性校验防重复发起 |
| 预测与核料 | Forecast 与核料并行（钉钉提醒销售刷新预测并抄送 STL、TL，不卡流程）；核料在核料页按 SKU 直改确认，全部确认后自动定版 |
| 清库方案 | 方案结构化（清库方式、Last Buy 数量、报废金额按 SKU 入表），版本化管理；发起人与计划双会签生效；报废超金额仅非阻断提示，线下走计委会 OA |
| 正式 EOM 后 | 成品清库、Last Buy、专用料三路并行，进度看台账；销售/采购/PMC 只收消息，不在 GTM 点完成 |
| 在线台账 | 以 8 位 SKU 为最小单元，汇聚产品、预测、库存、Last Buy、物料、清库进度，支持 MSKU 展开、自定义列与导出，替代线下 Excel |
| 反 EOM | 仅正式 EOM 后可发起，填单对齐现网 OA「反EOL流程审批」（无项目助理，PSKU 非必填）并回写；通过后关单、SKU 释放回提交前状态 |
| EOL 闭环 | 成品全链路库存为 0 即自动判定 EOL，保留数据快照；整单 SKU 全部闭环后工单才进入"EOL 已闭环" |
| 通知协同 | 节点完成自动通知下一处理人；发给销售的钉钉消息同时抄送该专员的 STL、TL；新增工作台、工单列表、状态流转规则说明页与分角色通知页 |

### 3.3 边界（本期不做）

- 不重建预测、库存、采购、BOM 等源系统，GTM 只做流程编排与台账汇聚。
- 不在 GTM 内做报废审批：不创建 OA、不回写、不挡正式 EOM。
- 不做独立风险预警页、SLA 配置中心、超期自动升级、节点任务驳回与任务转交。

---

## 四、成功标准

上线后，对任意一个 EOM SKU，用户能在系统中直接回答：**为什么退、谁在处理、到哪一步、还剩多少库存和专用料、Last Buy 是否完成、有什么风险、何时依据什么数据完成 EOL**——不再依赖线下表格和人工询问。
