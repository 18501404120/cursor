【销售系统】PSI 适配 EOM

范围：只改销售系统 PSI 管理、PSI 审核。Forecast、Forecast 审核本期不改。Last Buy 数量在 GTM 清库方案按渠道填写，计划在采购计划自行下最后一单，两套并行、不互相校验数量。PSI 不手填 Last Buy，也不把 Last Buy 写入 Sell out。

产品状态：EOM 工单提交后对应 SKU 为「准备 EOM」；计划确认清库方案、进入正式 EOM 后为「EOM」。变为 EOM 后不可以再下采购单（与现网一致）。

---

一、PSI管理

改动位置：销售系统 → 库存 → PSI管理（实时版本 / 评审版本共用）

本次改动：
1. SKU 信息区补产品状态：准备 EOM、EOM。正式 EOM 后打「常规要货已关闭」。预计 EOL 已过只打预警，不锁填写周期。
2. 筛选增加「产品状态」（准备 EOM、EOM）。快捷筛选「准备 EOM / 已 EOM 单独复核」，要货前把退市品拿出来看一遍。
3. Sell out 按退市节奏由销售在本页填写。保存时若该行 Sell out 大于全链路库存（成品库存 + 采购在途，含已下达的 Last Buy 在途），硬拦，不允许保存。没有「超过百分之八算异常」之类的差异阈值。
4. Last Buy 下完后不再要货：Sell through 失效，不再计算、不可再填要货。Inventory、DOS 仍展示。
5. Last Buy 只读参考，按店铺 / 渠道展示采购计划里实际单据数量。不要求等于方案 Last Buy，也不要求等于 Sell out。没有单据则空，不挡保存 Sell out。
6. 产品状态为 EOM 后：常规要货关闭。准备 EOM 阶段仍可填 Sell out，但受全链路库存硬拦。
7. 不改实时版本 / 评审版本切换，不改 Sell in、Inventory、DOS 原口径。不按天数拆审核流。

异常处理：
- Sell out 超过全链路库存：提示「不能超过全链路库存」，本次不保存。
- 预计 EOL 已过：页面预警，仍允许按总量规则保存 Sell out。

---

二、PSI审核

改动位置：销售系统 → 库存 → PSI审核（待审核 / 审核记录）

本次改动：
1. 在现有待组长审核、待主管审核之外，增加「准备 EOM / 已 EOM 待复核」筛选。只看退市品待审行，防止老品要货过激。
2. 列表补产品状态、只读 Last Buy（口径同 PSI 管理）、全链路库存。审核人对照 Sell out 是否超过全链路库存。
3. 单条或批量通过时，若 Sell out 大于全链路库存，硬拦，不允许通过。
4. 本队列不替代组长、主管两级，不另做第三级审批人，不按天数分流。

异常处理：
- 该筛选无数据：空列表，原两级审核不受影响。
- Sell out 超全链路库存：提示拦截，保持待审。

附：GTM 清库方案 / 采购计划（与 PSI 同期改，不在销售系统 Forecast）

清库方案：
1. Last Buy 按渠道 / MSKU 填，SKU 只汇总。支持导入导出方案（一行一个 MSKU）。清库方式、成品报废、物料报废、方案结论列名标注（SKU维度）。
2. 计划确认所选 SKU 或确认全部前，弹窗：方案确认后产品状态变为 EOM，将不可以再下采购单。请确认 Last Buy 采购单是否已经下达。取消则不确认。
3. 核料定版时按 MSKU 最终下单带入方案 Last Buy；之后核料锁定，只在方案页改。方案确认后不自动下推采购计划；计划按会议结论自行在采购计划下单。核料填写（最终下单、报废、原因、交付、结论）的初盘与改数只进核料日志，核料页不展示。

采购计划：
1. 准备 EOM：可以下 Last Buy。创建时提示该 MSKU 的产品状态和预计 EOL，不校验是否等于方案 Last Buy。
2. 产品状态变为 EOM 后：不可以再下任何采购单（与现网一致）。
3. 常规量产 / 额外要货在准备 EOM 仍提示，避免当普通要货下。
