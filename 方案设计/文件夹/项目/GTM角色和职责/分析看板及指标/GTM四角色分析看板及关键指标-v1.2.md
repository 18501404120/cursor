# GTM 四角色：重点分析看板与关键指标（v1.2）

> **文档版本**：v1.2  
> **相对 v1.1 的调整方向**（按业务方指令）：① **保留** PSI / 月度计划委会；② 共享底座 **2.2 改为 Baseline 管理**（对齐现行全渠道 baseline：以产品为主轴）；③ **产品信息库**统一表述为 **产品生命周期管理看板**，强调 **产品 × 国家 × 店铺**、标签、状态等全链路可视；④ **管报/经营平台**侧重 **BP 规划与达成、成本在系统中的定义与业务侧回报**，并强化 **经营与财务对比分析**；⑤ **暂不纳入**：市场扫描与机会、预测假设与系数、区域品线洞察简报三类看板；⑥ **产品侧**将原「产品与项目健康」并入生命周期看板；⑦ **首销定价**改为 **价格展示看板**；⑧ **区域侧**将原 5.1/5.2/5.3 中与 baseline、实际价对标相关内容 **合并消化** 为 **Baseline 与价格对标看板**，保留 **PSI·SO 执行跟踪** 独立一块；⑨ **5.5 区域经营复盘**暂保留；⑩ **需求计划**去掉与共享 PSI **重复的「PSI 与计委共识」独立看板**（共识与版本指标已在 **2.1**），保留预测要货质量、库存分货呆滞、产销交付健康。  

**编制依据**：`职责流程图1/GTM四角色职责全流程图-v8.1.html`、`OC工作内容.docx`、`调研会议`、`会议-GTM全流程`。  

**上一版本**：v1.1、v1.0（同目录，**不随本文件修改**）。

## 二、共享底座

### 2.1 PSI / 月度计划委会（保留）

| 项目 | 内容 |
|------|------|
| **看板名称** | PSI / 月度计划委会数据与决议视图 |
| **名称解读** | 继续作为公司级 **预测—供应—库存** 共识与 **一级/二级计划委会** 节奏的载体；**计委决议、PSI 版本、共识计划** 等关键指标**统一在本看板族呈现**，需求计划角色不再单独拆一块与 2.1 重复的「PSI 与计委共识」看板（见 v1.2 需求计划章说明）。 |
| **主责 / 共阅** | 需求计划 **主责**；区域 GTM **强共阅**；产品 GTM **共阅**。 |
| **关键指标 / 数据对象** | 滚动预测版本、要货计划版本、共识计划号；一级计委决议执行率、二级计委议题关闭率（需求评审、预测准确率复盘）；供需缺口金额与关闭周期；渠道 Sell Out、客户 SO 接入覆盖；PSI 周/月报准时率。 |

### 2.2 全渠道 Baseline 管理看板（原「价格管理平台」位置调整为 Baseline 主轴）

| 项目 | 内容 |
|------|------|
| **看板名称** | 全渠道 Baseline 管理看板 |
| **名称解读** | 与现行 **Baseline 管理** 一致：以 **产品** 为主轴，维护并监控 **各渠道/各国家/各店铺** 下的 **baseline 版本、例外审批、是否击穿** 等规则。名称含义：**把「能卖什么价、不能破什么线」从事后抽查变成事前配置 + 事中监控**，为区域执行与价格展示提供统一底线。 |
| **主责 / 共阅** | 区域 GTM **主责**执行与例外申请；产品 GTM **共阅**新品/主推 baseline 包；需求计划 **共阅**（促销与资源假设对预测的影响）。 |
| **关键指标 / 数据对象** | Baseline 版本与生效范围（按产品/渠道/区域维度）；例外审批占比与清单；击穿 baseline 事件数；与价格展示看板联动的「规则源」版本号。 |

### 2.3 产品生命周期管理看板（信息库 / 与第四章 4.2 同一主题）

| 项目 | 内容 |
|------|------|
| **看板名称** | 产品生命周期管理看板（数据落库：产品信息库，关联 SKU 技术信息） |
| **名称解读** | 强调 **每个产品** 在 **国家、店铺（渠道）** 等粒度上的 **产品标签、产品状态** 及关键属性；**任意时点** 均应在信息库中可追溯、可查询。名称含义：**生命周期 = 从规划、上市准备、在售、切换到退市的「单一事实来源」**，不仅是静态主数据，更是 **状态机 + 标签体系** 的可视化。 |
| **主责 / 共阅** | 产品 GTM **主责**维护与发布；区域 GTM、需求计划 **共阅**消费。 |
| **关键指标 / 数据对象** | 产品×国家×店铺 覆盖完整率；产品标签、状态变更及时率；与 GR 里程碑一致性；新老品/EOM 标签准确率；GTM 负责人/上市窗口/新品标签等字段完整率。（**GR、物料齐套、导入切换** 等「健康度」指标作为本看板下的 **子模块指标** 一并呈现，不再单独设「产品与项目健康看板」。） |

### 2.4 经营平台 / 管报（BP 规划与达成参考 + 经营与财务对比）

| 项目 | 内容 |
|------|------|
| **看板名称** | BP 规划与达成 · 经营-财务对比参考看板（管报/经营平台） |
| **名称解读** | 管报/经营平台作为 **参考底座**：系统中已定义的 **成本、费用、收入口径** 等，应在业务侧形成可理解的 **回报与达成** 呈现；核心用途之一是 **BP 规划管理数据 vs 实际达成** 的对照，并支持 **经营口径与财务口径的对比分析**（避免只看销量、不看费用与利润结构）。 |
| **主责 / 共阅** | 财务/经营平台 **供数**；区域与产品 GTM **主阅**达成与偏差；商业洞察 **共阅**用于复盘对照；需求计划 **共阅**费用与资源假设。 |
| **关键指标 / 数据对象** | BP 销量/收入/利润目标 vs 实际（分区域、分渠道、分产品系列）；**经营口径 vs 财务口径** 差异说明（若存在多口径）；成本与费用占收入比、预算执行率；库存资金占用与周转；下钻至周/系列/渠道（与会议-GTM全流程「可拆维度」一致，落地以系统能力为准）。 |

### 3.1 经营与财务对比分析看板

| 项目 | 内容 |
|------|------|
| **看板名称** | 经营与财务对比分析看板 |
| **名称解读** | 「对比」强调 **经营视角（业务可读）** 与 **财务视角（管报科目）** 的同屏或关联分析，支撑 **经营主脉** 式复盘：**钱从哪来、花到哪去、是否匹配 BP 假设**；与 2.4 管报底座衔接，可侧重 **洞察/复盘会议** 所需的切片与叙事。 |

## 四、产品 GTM

### 4.1 全渠道经营分析看板（与区域联合）

| 项目 | 内容 |
|------|------|
| **看板名称** | 全渠道经营分析看板 |
| **名称解读** | 同 v1.1：产品线视角看 **BP 达成与结构偏差**，与区域本地执行差异对照。 |

### 4.2 产品生命周期管理看板（合并原「产品与项目健康 + 新品导入与切换」要点）

| 项目 | 内容 |
|------|------|
| **看板名称** | 产品生命周期管理看板 |
| **名称解读** | 与 **第二章 2.3** 为同一主题在 **产品 GTM 主责视角** 的展开：除 **产品×国家×店铺、标签、状态** 外，将 **GR 与项目健康、新品导入、新老品切换/EOM** 作为生命周期内的 **关键控制点指标**，避免多张「健康/导入」看板割裂。 |
| **主责 / 共阅** | 产品 GTM **主责**；PD/项目办 **共阅**；需求计划、区域 **共阅**切换与备货窗口。 |
| **关键指标** | **（信息库）** 字段完整率、状态与标签准确率、与 SKU 技术信息关联一致率；**（GR/项目）** GR1～GR5 准时率与阻塞项、Roadmap/One Page 更新及时率、里程碑物料齐套率、在研/在上市风险分布；**（导入与切换）** 首单需求收集完成率、首批到货满足率 vs 上市窗口、切换月度刷新执行率、老品 EOM 状态、上市后 90 天达成 vs 预测。 |

### 4.3 价格展示看板（由原「首销期定价与促销规则看板」调整）

| 项目 | 内容 |
|------|------|
| **看板名称** | 价格展示看板 |
| **名称解读** | 侧重 **各渠道、各区域可见的价格展示与规则说明**（含首销期 RRP/促销价及生效范围），与 **2.2 Baseline 管理**、**5.1 实际 vs baseline 对标** 形成 **「规则（baseline）— 挂牌/成交价展示 — 对标监控」** 链条；名称含义：**让业务与审计一眼看到「当下该怎么展示价、实际卖多少」**。 |
| **主责 / 共阅** | 产品 GTM **主责**规则与版本发布；区域 GTM **共阅**执行与异常反馈。 |
| **关键指标** | RRP/促销价/渠道挂牌价版本与生效范围；各渠道价格展示抽检一致性；首销复盘结论闭环率；与 baseline 版本联动关系（变更同步率）。 |

|------|------|
