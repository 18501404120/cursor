GTM系统架构（业务模块版）v6.1

在 v6.0 上收敛呈现口径：六阶段 × 四角色仍是业务全链路职责的参照；本页方格优先写准备在系统里落地的能力，口语化、避免「大版本」「全年目标」等易歧义说法。本系统 为 GTM 域要建或已纳入排期的功能；他系统 为外域主责、本域对接；报表/看板 为复盘与达成对比的看数与下钻分析，不单列为与 PSI 同级的业务模块。暂保留 表示边界或方案仍待澄清，先占位不删。

命名与边界（按最新口径）：BP 目标管理为本系统功能（目标、打和、版本留痕等在系统里管起来）。Baseline 管理统一用「Baseline」说法，含新建、调整与留痕，不再用「建立与调整口径」等拗口描述。半年度 / 年度复盘仍以经营复盘报表 / 分析看板承载对比与归因。市场扫描类能力已从架构清单中移除（基本不做）。洞察侧仅保留结论/系数/机会的结构化接入；说不清是否上的条目标 暂保留。

v6.1 本轮修订（命名、删减、暂保留）

  • BP 目标管理：纠正「全年目标 / 大版本」等易误解说法，在 l1 统一为系统功能表述（目标、打和、变更在系统里留痕管理）。
  • Baseline 管理：统一用 Baseline 一条线说清（新建、调整、留痕），不再用「建立与调整口径」等拗口词。
  • 市场扫描：已从清单中移除（基本不建设）；洞察模块只保留轻量结构化接入。
  • 暂保留：SP 衔接视图、竞品/VOC 录入细化、PSI 情景测算、策略动作台账等边界仍待业务拍板，先占位不删，标 暂保留。
  • 复盘：半年度/年度对比与归因仍在 l5 经营复盘报表 / 分析看板，与 BP 目标管理区分「管目标」vs「看结果」。

分期建设建议（与 v6.0 一致，边界更清晰）

  • P0：PSI + 关键数据接入 + 库存 / 订单可读；复盘类需求优先以固定报表 / 看板落地，而非扩 l1 模块。
  • P0+：价格与促销经营平台，与管报 / 复盘看板口径对齐。
  • P1：PIM 深化 + GTM 项目与 GR + 洞察轻量接入（不做市场扫描类平台）。
  • P2：FP&A 建制、营销深度编排、iPaaS 自动化。
