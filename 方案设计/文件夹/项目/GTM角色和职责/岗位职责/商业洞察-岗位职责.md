# 商业洞察岗位职责

> 依据：《会议-GTM全流程》全渠道流出会议纪要整理。会议中职能表述为 **「市场洞察」**，在全渠道 GTM 链路中 **最早行动**，为 BP 与产品规划提供 **外部 + 内部** 结构化输入。

## 1. 定位与范围

- 支撑公司 **从 BP 启动到年度收官** 的 **规划—跟踪—达成** 闭环，在 **6 月前后启动** 的年度规划周期中，优先输出 **市场与竞争认知**，驱动 **明年上什么、资源投哪里、策略怎么定**。
- 与 **五看四定** 等框架对齐：**看行业、PEST、用户、竞争、自己**；输出可落到 **4P（产品、价格、渠道、营销/推广）** 的策略讨论素材。

## 2. 核心职责

### 2.1 扫描（Scan）

- 基于多数据源 **扫描市场份额变化、竞争格局、行业与区域指标**。
- 推动 **外部数据系统化**：如平台/行业数据的接入与留存（会议提到亚马逊等数据仅保留 12 个月、需入系统而非长期手工 Excel），保证 **可追溯与可比**。
- **看竞争 / 看市场**：收录行业 listing、评论、VOC、爬虫聚合信息等 **外部声音**，形成可分析的结构化输入。

### 2.2 预测（Forecast）

- 在 **连续 2～3 年历史数据** 基础上，对 **下一年市场体量、结构变化** 做预测，为销量与资源规划提供 **系数与假设**。
- 与 **产品 Roadmap、营销预算、定价** 等前置信息结合，支撑 **明年整体预期** 的闭环（会议：预测模型系数来自市场 + 产品 + 营销 + 定价等前置模块）。

### 2.3 挖掘（Dig / SWOT）

- 在扫描与预测基础上做 **SWOT**：外部机会威胁、内部优劣势与改进点。
- 提炼 **明年需解决的核心问题** 与 **机会清单**，明确 **需要补充的能力或数据**，并 **对接产品规划**（明年上什么、节奏如何）。

### 2.4 看用户

- 与 **用户中心** 等内部数据结合，分析 **新品上市后一定周期内** 的用户反馈与行为，支撑短期迭代与中长期规划。
- 会议提及：用户侧数据导入报表，供 GTM 看 **新品上市结果**。

## 3. 产出物（示例）

- 年度/滚动 **市场扫描报告、竞争地图、份额与趋势分析**。
- **预测假设说明**（含数据口径与局限）。
- **SWOT 与战略议题清单**、对 BP/产品会的 **输入简报**。
- VOC/评论/外部情报的 **定期汇总**（形式可含 AI 辅助，但需口径统一）。

## 4. 协同关系

- **→ 产品 GTM / 产品线**：产品机会、上新方向与节奏建议。
- **→ 区域 GTM**：竞争与价格带、渠道结构判断，支撑 **定价与渠道策略**。
- **→ 销售计划**：市场假设与预测系数，进入 **PSI / 销量预测** 上游。
- **→ 营销**：大事件与预算投向的 **市场依据**（与营销指标、预算模块衔接）。

## 5. 边界说明

- 商业洞察 **产出观点与数据输入**，**不替代** 各业务 Owner 做最终 **定价签批、销量承诺、渠道签约** 等决策。
- 外部数据 **准确度与规则** 可能不稳定时，会议建议至少保留 **趋势与比例** 的基准（Benchmark），并在文档中注明口径。
