# 当 EOM 退市同时有新老品切换和常态退市时，时间和待办该怎样拆开？

2026-09-23 退市管理会上，新老品切换和销量、毛利驱动的常态退市还在同一条链上收。按「都是退市」收成一种立项，再给每个节点一条待办，半年大约 50 个 SKU、多数要八个月、需求计划执行只有两人，待办会先于清库失控。有明确上市时间的，嵌进已经在跑的 GTM 上市项目；没有统一截止日的，走退市流程；流程里只留会改变阶段的确认。

## 1. 按有没有明确时间目标拆开

a. 新老品切换有新品上市时间。嵌在 GTM 上市项目里，按上市时间倒推。不另拆项目，仍是同一班人。

b. 销量、毛利驱动的常态退市没有严格统一的截止日。按渠道承受能力和物料情况决定消耗、转卖或报废，走这条退市流程。

c. 主动、被动留作发起类型，只用来区分要不要维护新品衔接。不据此生成两套节点。

## 2. 时间放在哪，和后半段怎么执行，分开看

后半段仍是同一条链：

线下评估后发起 → 核料（系统算呆滞，计划确认）→ 方案决策 → 执行清库 → 库存清完闭环。

两类事项共用这条执行链。触发方式和时间放在项目里还是放在流程里，先分开。

## 3. 流程里不放催办，只留两个会卡住的确认

a. 原方案里「核料超过 7 天再提醒」不按流程待办落地。时间目标放在 GTM 项目里排。

b. 流程上留下的确认只有两个：计划按自己负责的 SKU 确认核料；发起人确认方案。全部 SKU 确认后，才进入方案决策。

c. 销售刷新预测只发提醒，不卡住核料。

d. 销售、采购、PMC 的清尾进度看台账。系统按库存和在途回写，不要求他们在 GTM 里点完成。

## 4. 量级先写上，再决定要不要按 SKU 立项

半年大约 50 个 SKU。从发起到清完，最快约半年，多数约八个月。需求计划业务执行只有两人，撑不住每个 SKU 再组一套班子，也撑不住每个节点再挂一条待办。

有明确时间、并且和上市绑在一起的，放进已有项目排期。没有统一截止日的，走退市流程，用计划确认核料和发起人确认方案卡住。催办留在项目排期里。
