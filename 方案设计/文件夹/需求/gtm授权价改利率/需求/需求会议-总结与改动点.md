# GTM 授权价 / 采购价差异 — 需求会议总结与改动点

> 来源：`需求会议`（会议逐字稿整理）  
> 整理日期：2026-04-17

---

## 一、会议背景与目标（摘要）

1. **现状**：财务侧已有「即时采购价 vs 授权采购价」差异数据（约 4 月可导出）；此前群内约定「约 3% 波动需刷新」但**无人认领执行**，与 Kris 等对齐后需产品/系统落地。
2. **业务目标**（反复对齐的结论）：
  - **出货授权价（FOB 口径）对渠道尽量稳定**，渠道侧看到的是相对稳定的价格带。
  - 采购成本变化时，通过 **GTM 预留（企业预留毛利率/额）** 等变量吸收或暴露「包不住」场景，必要时再进入涨价与渠道沟通。
  - 需要系统**固化计算逻辑**，避免业务手工在表里绕算、易错。
3. **会议性质**：前半段争论「是否自动把即时刷成授权」，后半段收敛为「**风控列表 + 建议值 + 人工确认后一键应用**」，并与授权价维护页面、标签、排期对齐。

## 二、相对原方案 / 口头约定的**需求改动点**（按优先级）

### 2.1 波动阈值与抓取规则


| 项     | 原/讨论中口径                 | **会后收敛**                                                                  |
| ----- | ----------------------- | ------------------------------------------------------------------------- |
| 阈值    | 曾讨论 3%、也有「一审说 1%」       | **默认 ±2%**：差异 **> +2% 或 < -2%** 才进入风险范围（正负两端都要处理，不是只处理涨价）。                |
| 阈值可配置 | 未明确                     | 风险列表的**判断参数可配置**（如 2% / 3% / 1%），**全公司统一**一条规则；是否按品类拆分需再议（小家电等场景在会上点到为止）。 |
| 数据量级  | 全表约 1.3 万行级，有差异的 SKU 上千 | 用阈值**过滤**后每月典型量级为**百级**（会中举例约 188 条），避免运营被几千行淹没。                          |


### 2.2 「自动刷新授权采购价」——**改为不单独自动落主表**


| 项     | 早期诉求                              | **会后改动**                                                                                                 |
| ----- | --------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 即时→授权 | 财务刷即时后，系统**自动**把授权采购价更新为即时，以免无人维护 | 若**先**把授权改成与即时一致，因页面公式**联动**，出货授权价会立刻变，**差异被「刷没」**，无法再做预留对冲判断；也无人明确负责「点自动同步」。                            |
| 新流程   | —                                 | **不在授权价主数据上静默自动改**；改为在**独立「风险/风控列表」中展示差异与建议变更**，用户勾选、可改建议预留率后，**一键应用**，**同时**写入建议的授权采购价与 GTM 预留等，再回写主页面。 |
| 历史留痕  | —                                 | 应用前在风控侧保留「当时即时 vs 授权」等**可追溯**信息（会中强调先拉出再改，避免看不出曾经差多少）。                                                   |


### 2.3 新建能力：风控列表（预警列表）+ 一键应用

1. **独立模块/页**：从授权价维护主模块**入口**进入（如「有风险项」按钮）；列表内展示本月需处理的 SKU（满足阈值）。
2. **列表字段/逻辑（要点）**：
  - 展示即时采购价、当前授权采购价、差异；**建议授权采购价**（默认=即时，应用时**强制**落为该值，**不允许在应用环节改采购价建议**——会末对齐）。
  - 按规则计算 **GTM 预留能否吸收成本波动**（「包得住 / 包不住」两类标签，名称可再优化）。
  - **建议预留毛利率（率/额）**：系统算出建议值；业务可在应用前**手工改**建议预留（如建议 4% 仍改为 5%），再点应用。
3. **交互**：
  - 支持筛选、分页、批量勾选、全选后取消部分行。
  - **应用 / 忽略**：不应用的行沿用旧授权采购价等（会中明确「公司自负盈亏」边界）。
4. **与主列表筛选项对齐**：风险列表页需带主页面**同等筛选项**（渠道、SKU 等），避免「另开一页无法按原习惯筛选」。

### 2.4 授权价主列表上的「波动」标签

1. 在现有授权价列表增加筛选项（或标签），标识**当月波动超阈**的 SKU（会中命名倾向：**与年月口径一致**，名称如「当月波动」等，避免歧义）。
2. **二级标签**：在包得住/包不住基础上，会末补充若应用将导致**出货授权价上涨**，需有**可筛选标签**，便于导出名单通知销售（程序通知可后做）。

### 2.5 业务规则补充

1. **关税**：与 Grace / Ethan / Mike 对齐——**按稳定值处理**，政策或内部核算波动由公司承担，**不传导给渠道**；计算时主要关注采购价与预留变化对 FOB 的影响。
2. **粒度**：不能简单按单一 SKU 忽略关税差异；**不同 MSU/区域关税不同**，计算需落到正确维度。
3. **三种场景**（预留调整策略）：
  - **包得住**：下调（或上调）预留率/额，使出货授权价不变。
  - **包不住**：预留耗尽仍无法吸收 → 需涨价等**业务决策**（系统只打标、不替业务自动涨价）。
  - **业务主动**：即使包得住也选择涨价等 → **走委员会/上报**流程，系统不自动改预留。
  - 差异值变化100%的代表新品有授权价格但是财务那边还没有刷新 所以这种也要排除掉 不然把预估的授权采购价刷新成0了

### 2.6 数据范围排除与基础数据清洗

以下类型**不进入本套预留博弈逻辑**（会中明确要求）：

- 客服、GPM 配件、GPM 店铺、退货（及会中提到的「-7」类）等。
- 处理原则：**企业预留毛利率统一刷为 0**（含新增与存量调整）；可提供**店铺清单**供系统过滤。

### 2.7 排期与运行节奏

1. 财务约**每月 10 号**刷新即时采购价；系统可在 **11–12 号**抓差异跑批（具体日期待与财务确认）。
2. **上线节奏**：开发侧认为「不急」；业务侧曾希望 4 月前，会末可接受 **4 月整月不动、5 月再启动** 等折中（以最终排期为准）。

### 2.8 待产品化 / 待澄清（会中未完全闭合）

- 风险项处理完成后，**标签是否移除 / 是否增加「已完成」**，与「仍要筛历史风险」的平衡（会中有来回，实现时需定稿）。
- 阈值是否**全局唯一** vs 按事业部配置（小家电举例）。
- **出货授权价上涨**后的销售通知：先做 **Excel 导出 + 筛选标签**，系统消息可二期。
- 与**广告/预算**联动、Sherry 等链路：明确**本期不做**，待广告与财务链条打通后再迭代。

## 三、验收关注点（便于排期与测试）

1. 仅当 |差异| **大于** 配置阈值时进入风险列表；边界值（恰好 2%）按产品定义写入规则说明。
2. **一键应用**同时更新：**授权采购价（= 建议即时）** + **业务确认后的预留毛利率**，且主列表联动结果符合「FOB 尽量不变」的验算样例。
3. 排除类店铺/SKU **不出现在风险列表**且预留为 0 的规则生效。
4. 风控列表与主列表**筛选器一致**，批量选择与分页行为符合运营习惯。
5. 配置项：阈值百分比可改，保存后对**下一批次**抓取生效（需写明是否回溯当月）。
