# 商超 3P「买一送一」促销 — 需求解决方案

## 1. 背景

### 1.1 业务场景

- 制冰机等新品上市时，需要开展「买 A 送 B」类促销（例如：**买一个制冰机送一台空气净化器**）。
- **天猫、亚马逊等部分平台**可在店铺后台直接配置「买一赠一」或等价促销能力，订单与履约路径相对清晰。
- **沃尔玛等商超 3P 店铺后台不具备**与上述平台同等的「买一赠一」配置能力，无法依赖平台侧规则自动拆分主品与赠品行并闭环到财务。

### 1.2 历史做法与问题

- 历史上曾采用 **「样品发送」** 等方式，由业务侧根据订单地址人工处理赠品发货。
- **财务不认可**该方式：主订单无法与赠品在系统内形成可追溯、可核算的关联，难以满足收入确认、成本结转与审计要求。
- 业务侧希望：**在用户购买主品（A）时，系统能自动、规范地生成与主单关联的赠品（B）的 0 元销售单据**，并与后续发货、签收、库存出库一致，而不是长期依赖人工扒地址、样品单等变通手段。

### 1.3 需求提出方关注点

- **财务**：需要 ERP（及对接 **金蝶**）侧能体现「主单 + 关联的 0 元销售订单」，便于账务与合规。
- **业务**：希望该能力可复用于商超 3P 场景，必要时作为**长期功能**建设，减少每次新品促销的临时方案成本。

---

## 2. 问题与痛点归纳

| 痛点 | 说明 |
|------|------|
| 平台能力缺失 | 商超 3P 后台无法像其他平台一样配置买一送一，促销策略仍要做，系统侧需补位。 |
| 变通方案不合规 | 样品单、人工发赠品难以满足财务对订单链路、金额与关联关系的要求。 |
| 履约与库存割裂 | 若仅有主品订单，赠品无正式单据，发货、签收、调拨、出库难以在 ERP 内闭环。 |
| 主赠关联缺失 | 缺少「与原订单关联」的金蝶销售订单，影响对账与追溯。 |

---

## 3. 价值点

1. **财务合规与可追溯**：主品订单与赠品 0 元订单关联，满足核算、审计对「业务实质与系统单据一致」的要求。
2. **减少人工与差错**：避免扒地址、线下表格跟踪赠品，降低漏发、错发与重复劳动。
3. **履约与库存一体化**：发货、签收环节可驱动调拨、销售出库等单据，库存与成本路径清晰。
4. **能力复用**：同一套「主单触发关联 0 元子单」模式可扩展到其他商超 3P、类似无后台促销能力的渠道。
5. **与金蝶对齐**：按财务要求推送**与原订单关联**的销售订单，便于总账与业务单据对齐。

---

## 4. 目标与范围

### 4.1 目标（定性）

- 当识别到符合「买一送一」规则的电商订单进入 ERP 时，**自动生成**与主订单关联的、**单价与金额为 0** 的赠品销售订单（或系统等价单据，以金蝶与 ERP 最终设计为准）。
- 在订单 **发货、签收** 等节点，能够按规则 **触发调拨单、销售出库单** 等，保证实物与账面一致。

### 4.2 建议范围边界

- **本期建议明确**：适用渠道（如沃尔玛 3P）、适用 SKU/活动（制冰机送空净等）、赠品是否 always 固定 SKU、是否允许同一主单多赠品等。
- **待产品/业务确认**：活动是否在 ERP 侧以「促销规则」配置，还是仅针对单次活动硬编码（影响长期复用）。

---

## 5. 解决方案

### 5.1 业务方案（概要）

1. **促销定义**：在 ERP（或运营配置）中维护「主 SKU + 赠 SKU + 生效渠道/店铺 + 生效时间」；与平台实际上架价、页面说明一致，避免客诉。
2. **订单解析**：平台订单入 ERP 后，根据规则判断是否命中「买一送一」；命中则 **主订单保留原价行**，并 **生成关联的赠品 0 元销售订单**（行项目为赠品，单价/金额均为 0）。
3. **关联关系**：赠品单与主单建立 **唯一关联**（主单号/平台单号/关联 ID），便于查询、对账与金蝶推送。
4. **履约**：按财务确认的节点（发货/签收），对赠品行触发 **调拨、销售出库** 等，与主品物流策略协调（同仓/分仓、合单发运等需业务规则）。

### 5.2 系统方案（ERP + 金蝶）

以下为实现方向描述，具体以架构评审与金蝶接口能力为准。

| 环节 | 说明 |
|------|------|
| 推单 | 电商订单同步至 ERP 后，命中规则则生成主订单数据 + **关联的 0 元赠品销售订单**。 |
| 金蝶 | 按财务要求，将赠品以 **销售订单** 形式推送到金蝶，且与主单 **可关联查询**（关联字段或单据体关系以接口设计为准）。 |
| 发货/签收 | 主品与赠品订单在允许合并的场景下协调出库；若分开发运，各自触发相应 **调拨单、销售出库单**。 |
| 配置与审计 | 保留规则版本、命中日志，便于复盘促销期内的订单与金额。 |

### 5.3 与沟通记录的对齐说明

沟通中明确提到：

- ERP 需支持：**每个参加活动的订单**都能在 ERP 创建 **单价、金额为 0** 的销售订单；
- **发货、签收** 时触发 **直接调拨单** 和 **销售出库单**；
- 财务侧期望推 **与原订单关联的金蝶销售订单**，而非仅内部台账。

上述内容应作为方案验收的**核心口径**。

---

## 6. 待澄清项（建议在开发前排期会确认）

1. **触发时机**：是「平台订单入 ERP 即刻」生成赠品单，还是审核/锁单后生成？
2. **部分退款/取消**：主品或赠品任一退款、部分签收时，关联单如何联动作废或冲销？
3. **库存**：赠品是否预留库存、是否允许负库存、多仓如何分配？
4. **金蝶接口**：现有销售订单接口是否支持 0 金额行、主子单关联字段；是否需要新增接口或单据类型？
5. **多渠道扩展**：除沃尔玛外，是否统一用同一套规则引擎？

---

## 7. 风险与依赖

- **平台订单字段**：若平台侧无法区分活动订单，需依赖 SKU 组合、活动 ID 或运营标注，存在漏识别风险。
- **金蝶与 ERP 双写一致性**：需定义失败重试、补偿与对账机制。
- **跨仓履约**：主赠品分开发运时的运费与成本归属需财务定规则。

---

## 8. 验收要点（建议）

1. 指定店铺、指定活动期间，命中规则的订单在 ERP 中 **必现** 主单 + **关联 0 元赠品销售订单**，金额与单价为 0。
2. 金蝶侧可查询到对应销售订单，且 **能与主单关联**。
3. 发货/签收流程下，可生成符合财务要求的 **调拨单、销售出库单**（以实际流程设计为准）。
4. 抽样对账：平台订单、ERP、金蝶三边数量与关联关系一致。

---

## 9. 实施节奏说明

沟通中提出 **「如需开发大概需要多长时间」** — 具体工期依赖：金蝶接口改造范围、ERP 订单引擎改动面、是否先做沃尔玛单渠道 MVP。建议在完成第 6 节澄清项与接口评估后，由研发给出 **人天评估与里程碑**（需求沟通阶段未锁定排期）。
